SELF-EVOLUTION / SEAM

递归改进的执行交给 Harness²，
平台只留下判据、台账与人签。

本页不是又一套自进化循环。平台把候选任务包交给 Harness² 的 Propose–Probe–Compose，收回的是一份harness2-run-0.1 产物：预算恒等式、被采纳的组件改动、经验条目与留出检查。平台只做三件事——提供数据基础、把产物映射成受治理的候选、在门下等人签字。

RECURSION BUDGET—R = 4k · P = 3k
ADOPTED EDITS—按组件去重
HELD-OUT—提案者没见过
CONFORMANCE—契约 / 预算 / 边界

00 / SEAM

谁做什么，一次说清

实线 = 前向交付；虚线 = 回指。任何"改进"都要以候选身份重新过门，不能从执行侧直接改写平台。

这张图标的是职责边界，不是实现地图：左侧全部已在本仓库实现（modules/rsi），中间是外部依赖（harness2-main），右侧是两边唯一允许交换的格式。

04 / GOVERNANCE

产物怎么变成一条待签记录

右侧清单是本次运行的机器自检；左侧是它在平台里必须走完的路。任何一步缺失，episode 停在 pending_human。

从产物到租约

候选只写台账，不写代码；真正生效要等下一次运行消费租约。

  1. 归一化schema / 预算恒等式 / 任务状态 / 经验证据，任一不满足即拒绝入库
  2. 映射候选按组件去重 → Candidate(kind, target, patch)；不可变面命中则 blocked
  3. dry-run + public改进分片的回执；没有它不算测过
  4. hidden / 留出集提案者没见过的任务；缺这一项就不能声称泛化
  5. 具名人签 + scope人只在门禁与验收交互，签的是准入理由，不是代码
  6. 租约与撤销到期失效；上游变更会传播失效并回指复验

对应命令：python -m research_agent.cli rsi harness2 run → ... record → ... admit（admit 需要 public/hidden 回执、dry-run、具名人）。页面只读产物，不提供任何签核按钮。

本次运行的自检

全部为真才允许写 episode；有一条失败，CLI 的 run 就以非零退出。

05 / INTERFACE CHECK

接口算不算「正常」，按这五条判

每条都有可复现的入口与可判定的输出；只看页面截图不算验收。命令在仓库根目录执行。

入口通过判据失败时说明什么
rsi harness2 probeavailable: true，并给出 checkout、3.12 解释器、桥路径与补丁找不到 checkout / 没有 3.12 / 桥缺失，三者分别报出
rsi harness2 run --k 2 --mode bothR == expected_R、P == expected_P、checklist_ok: true；否则非零退出预算恒等式不成立或阶段回退，说明这次递归不算完成
rsi harness2 record每个去重后的采纳组件写一条 pending_human；leases: []conformance 未全过时直接拒绝写入，不产生半批台账
GET /api/rsi/harness2200 + harness2-story-0.1；?record=true 只返回 would_record404 说明本机没有产物，不是接口坏
rsi story --ledger …simulation_episodes ≥ 1，并带「重建的是被演练的回路，不是被改进的回路」警告缺这条警告，说明模拟证据被当成了真实增益

06 / BOUNDARY

这条证据能证明什么

把"接口通了"和"能力涨了"分开写，是这个项目唯一不能让步的地方。

确定性执行 = 接口证据，不是能力证据。 本轮的执行器与提案者都是确定性脚本（deterministic-science-fixture），所以产物强制标 simulation=true、claim_eligible=false，台账里也不会出现 capability claim。它证明的是：任务包能被 Harness² 消费、预算恒等式成立、采纳树能被映射成受治理的候选、留出检查能跑通。它不证明科研能力提升。

下一步（未实现，写在这里而不是写成已支持）：把确定性执行器换成 DeepSeek 基座上的真实 agent 执行器，接一个真实科研任务包（论文投稿反馈处理 / Skill 提炼），再跑同样的 k 与留出集；那时才允许讨论增益，且仍需 hidden + 人签。
