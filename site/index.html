FEATURES / 四个判定

不是再做一个论文生成器。

差异在四个判定的交集：资格、完成、失效、供给。稳定的是证据与门禁，可变的是工具、流程与接入方式。

1资格判定 · 证据闭合

句子必须落到已持有 span 或人签实验证据；claim 只由 Evidence 创建，摘要不能当全文证据。

2完成判定 · 可复现

RunCapsule + 独立重跑 + EA；Work 与 Judge 分离，失败也留下可审计的运行胶囊与成本。

3失效判定 · 变更传播

spec/data/code/evidence/claim 以 SHA-256 串联；输入变了沿链标 stale，导出 fail-closed。

4供给判定 · 受治理自改进

模型可换（含无 key 的 host-model），但证据资格不可移植；经验准入/租约/撤销，升级人签、降级自动。

研究主线 · 四条策略 × 三个方向 × 四个可证伪问题（1110 组会口径）

一句话主张：不做端到端「自动写论文」——做两件事：让过程可信，让判定真正改变下一步行动。四条策略都是待验证的计划，不是已实现的功能；每条带一个能把它证伪的入口。新颖性只落在四处：证据链复现 · 失效传播 · 判定消费 · 学习证据准入。

策略① 过程可信底座方向 B · 守内核三层可验证（结果 / 过程 / 证据链）+ 溯源数据 + 失效传播。验证入口：留出集改上游，看系统能否推准失效范围。
策略② 反馈 → 行动（判定消费）Q2 · 第一个诊断实验同一任务给真实 / 打乱 / 过时 / 含噪 / 矛盾五类反馈，看下一步行动是否按证据质量变。反馈敏感性与信息价值一致 → 切口不成立。
策略③ 学习证据准入方向 A · 第一切口已验证技能什么时候能安全用到新任务：直接复用 / 先测一轮 / 拒绝。验证入口：全存 / 全不存 / 重放后存 / 独立验证后存，四存储策略对照。
策略④ 多样性保持 + 证伪 / 信念修订方向 C · 后续前沿盯群体同质化 + 反事实证伪；证据打架时决定修订信念、保留不确定或再激活被否决假设。评测环境自建，成本高放后面。
顺序

B 守内核，A 做第一个切口，C 放后面；②始终作为诊断实验贯穿。读图顺序 ③ → ① → ② → ④。

里程碑

M0 最小证据闭合实例（能签署且变更锁导出）→ M1 五类反馈对照（Q2）→ M2 四存储策略 + 失效探针（Q3/N4）→ M3 论文与外部评审。每步的验收都是「可失败的」：达不到就重述口径，不换指标。

四不做

不追端到端生成（42% 实验失败、基线幻觉 90% 的赛道）；不重造度量（ARS / CCFA 信封借来用）；不照搬静态 skill 目录；不放开无约束自主执行——人工门留在假设选择、设计批准、签署三处，自动化只跑门与门之间。

工程借鉴

控制面 / 执行面分离、两级过滤（程序快层 → 语义慢层）、任务线程直通、异步推理、存算分离、独立外部监督——来自 DeepSeek 两篇工程文章（非同行评审，只作设计参照）。

接下来做什么 · 一个总线 + 四个端口（71 号设计文档 · 2026-11-10 立项）

四图对照的结论：四条反馈环只有「溯源 / 失效传播」一条真实自动闭环，其余是审计项或 roadmap。解耦设计把"判定改变下一步行动"做成可插拔、可单独开关与测量的对象——这正是四条策略的实验台。

第一步 · 判定总线（Verdict Ledger）✅ 已落地 · verdict-ledger 0.1.0append-only 判定账本：三态判定 / closure blockers / lineage stale / rsi regressed / 护栏拦截统一入账；消费者（next_actions、反馈环、autopilot）只读总线。生产者不变、门禁语义不变、缺失 fail-closed。实测已抓到真实缺陷：autopilot 代签后 capsule 快照仍报 CLOSURE_UNSIGNED——漂移从静默变为一等行（verdicts collect）。
第二步 · FeedbackPort（反馈环一等化）默认拒绝observe → propose → gate → apply → record；T6b 证伪 / 信念修订 / 溯源失效 / 同质化各为一个可开关实现。可失败的验收：关闭全部环 = 与今日行为逐字节一致。
第三步 · M1 五类反馈对照Q2 · 诊断实验真实 / 打乱 / 过时 / 含噪 / 矛盾五类反馈跑在 FeedbackPort 上——反馈敏感性与信息价值一致 → 切口不成立，如实记录。
第四步 · MemoryWritePort + M2方向 A · 第一切口记忆写入收敛一个端口，全存 / 全不存 / 重放后存 / 独立验证后存四策略可插拔对照；类型化记忆图谱等 M2 结果出来再定型，不提前固化。
第五步 · ExecPort + waitpoints图③ 骨架三执行面（平台 3.8 / Harness² 3.12 桥 / 外部 host）统一抽象；事件进 waitpoint → 程序快层相关性检查 → 判定总线 → 下一次 run 消费。不引入常驻进程，autopilot 单次委托语义不动。
贯穿 · 接入面收尾Zcode / Qoder / CodexSKILL.md 第 0 步 = 先比 build fingerprint 再读结果（宿主里"测过"默认测的是历史快照）；接入矩阵随发行同步，产品仓自证 46 工具 ready + 零签名入口。

SCOPE / 平台边界

这是平台，不是 RSI 基础设施。

本平台负责「科研过程 + 证据 + 自改进判据」；流水线编排、版本回滚与评测调度可以下沉到独立的 RSI 基础设施。边界写清楚，两边才好对接。

本平台负责

  • 模块契约与产物：QueryPlan / Span / EA / Claim / Closure
  • 数据基础：文献、实验、图表、稿件、基金的 artifact 与哈希
  • 自改进判据：准入理由、租约、撤销传播、留出增益
  • 人签门：G1 / G2 / S5b / G5，升级人签、降级自动

可委托 RSI 基础设施

  • 流水线编排与重试、阶段级 checkpoint
  • 版本 / 回滚 / 租约生命周期
  • 细粒度反馈：知识原子级的冲突与污染检测
  • 评测调度：小数据集、Token 预算、DeepSeek 基座
接口现状：MCP / HTTP / CLI 三入口共用 framework_api.dispatch；递归改进的执行已接到外部 Harness²（自进化接缝），平台只消费 harness2-run-0.1 产物并做准入；流水线编排 / 版本回滚 / 评测调度的其余部分仍是 roadmap。不把「已实现的控制面」说成「已完成对接」。
分工口径：自迭代的执行下沉到 RSI 服务；平台只保留判据（准入理由 / 租约 / 撤销传播）与数据基础，不为每个循环重造一遍基础设施。
边界与诚实声明 本公开站为静态镜像：无真实 LLM、实验执行、claim 签名或 runtime job；数值来自 CACHED 快照或 SIM 演示。人工门（G1/G2/claim/closure/export）只在本地 CLI。本仓库（research-agent）定位为早期 demo / 展示项目，智能体产品本体在 Wellspring-Agent，开发一律以产品仓库定位为准。fixture 与模拟分数不得当作真实证据；不提供代写、伪造数据/引用、规避检测或自动投稿。AI 生成内容是草稿，科学决策与署名责任由作者/PI 保留。
