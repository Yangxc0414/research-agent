# 可执行改进搜索研究

## Purpose

补上闭环里最实质的空洞：想法阶段生成的是**关于搜索的假设**（档案、接受门控、单位算力改进率），
而 S5 此前只能对表格数据做一次固定拟合，没有接受事件、没有血缘、没有可归一的验证成本，
于是这些假设在本系统里**根本无法检验**，实验计划等于虚构。

本模块提供一个确定性的、本地可运行的改进搜索台：被优化的对象是流水线配置（不是智能体源码），
两个可独立开关的因子是**记忆（archive）**与**接受门控（gate）**，首要指标是想法阶段真正在讲的
**单位验证算力上的改进率**。

不解决：不复现 DGM / SICA / ACE / SIFT，不主张任何外部效度。

## Contract

- 输入：`dataset`（iris / breast_cancer / wine / digits）、`seeds`、`budget`（验证评估次数）、`min_delta`。
- 输出：
  - `SearchStudy`：2×2 每格的多种子运行、节点血缘、`study_sha256`；
  - `SearchEvidence`：与本地实验包同形状的 `metrics_summary` 与 `comparison`
    （`mean_diff` / `ci95_low` / `ci95_high`），加 `directional_supported` 与
    `interval_covers_zero`；
  - `ExecutableProfile`：运行时**能**与**不能**执行什么。
- 判定规则：只有 95% 区间不跨零的比较才进入 `directional_supported`；种子过少导致全部跨零时，
  产物必须明确报告"无方向性结论"，不得用点估计冒充结果。
- 失败：预算或种子不足不是错误，而是"underpowered"结论；数据缺失则拒绝运行。
- 可比性规则（复现分组与护栏都依赖它）：两个包算"同一个实验"当且仅当**变化因子集合**、
  非在任水平的固定控制、`budget`、`metric`、`min_delta` 都一致。停在**在任水平**（incumbent，
  = `SEARCH_FACTORS[f]["levels"][0]`，且必须等于 runner 默认值）的单水平因子**不进入**比较键：
  新增一个因子时，老包从未声明它，新包把它声明为在任水平，两者是同一个实验；若让它进键，
  注册表每加一个因子就开一个"证据纪元"，新旧包互相不再复现、护栏同时对彼此失明。
  离开在任水平的固定因子（如 `operators=feature_only`）仍然进入键——那是另一个实验。
- 裁决独立性（新增可见字段，不改变判定）：`overturned` 条目带 `shared_seeds` 与
  `arbiter_independent`——裁决包与被判定的包共用了多少粒种子。种子集合不相交的裁决是**独立证据**，
  超集式（1..16 对 1..128）只是同批数据的再加采样；两者过去只能靠种子数猜测，现在写进产物。
  包缺种子清单时两字段为 `null`（未知，不得当作独立）。此字段只增加可见性，不改变任何拦截判定。
- 签署门（复现护栏）：本包被同设计同数据集的更高功效研究否定的比较，不进入可签署断言，
  而是落进 `not_signable` 并附 `decided_at_seeds` / `superseded_by`；全部被否定时直接拒绝，
  不产出空草稿。护栏只能减少可签署内容，永不新增。
- 反事实臂（测量用，不是门）：`closure guard-audit --project` 只读统计开火率；
  `study claim --no-guard` 只用于观察"没有护栏会递给人签什么"，草稿落
  `claim-draft-unguarded.json`，并在 `verification.replication` 里原样保留被拦下的条目，
  同时**拒绝**与 `--sign` 同时出现——反事实臂不能产生签名，签署仍是人的行为。
- 指标有效性披露：closure 读取记录中的 `best_score`/`root_score`，当有界指标 [0,1] 上
  ≥10% 运行触顶时给出 `metric.headroom` 警告（不阻断、不重算指标），提示
  `improvement_per_evaluation` 的右删失风险，并要求在主张效率差异前报告 headroom 归一化曲线。
- 签核决策简报由产物投影（`study brief --study-dir`）：`build_study_brief` 只读 `study-evidence.json` /
  `study-spec.json`（以及包内 `tuned-baseline.json`，若已绑定），输出可签署比较表、
  **被判不可判定/拒绝的比较表**（两者都必须出现，简报不得只报好消息）、分解读数、度量警告原样转录、
  复现护栏与功效读数、外部强基线的 sha 与 digest，以及"主张 → 命令 → 产物"的复现路径。
  复现命令由记录参数**重建**（包内不存原始调用），因此它本身是关于可重跑性的主张，须由
  `study closure --verify-repro` / lineage 支撑，简报的 boundary 里就这么写。
  不变量：简报里出现的每个小数必须能在包内产物里找到（`test_study_brief` 逐 token 比对，
  防止投影自己造数）；未绑定基线时必须明写"只与研究内部参照格比较"。
  简报是给人做签署决定的文档：不是 claim、不是签名、不是证据，MCP 面不暴露（签核相关一律留 CLI）。
- 强基线必须在跑之前声明（预注册 `baseline` 槽）：`study-preregistration.json` 可选带
  `baseline = {kind: tuned_cv | external_file | none, file?, budget_matched?, why}`。
  `kind=external_file` 而 `file` 为空 → 载入时直接拒绝；`kind=tuned_cv|external_file` 而文件不存在 →
  拒绝启动（"要跟谁比"不能是一句空话）。闭包新增 `baseline.declared` 三态：
  **声明了 A 却绑了 B**（或声明 `none` 却绑了文件）= blocker，理由写进判定文本：
  对手必须在看到结果之前定下来，否则就是 post-hoc comparison；
  **没有声明**（老包或未填该槽）= warning，不追溯判死；一致 = pass 并复述 kind/file。
  `study brief` 把"声明的对手"与"实际绑定的对手"并排打印，不一致时签核人第一眼就看到。
  边界：预注册只保证"比较对象是事前选的"，不保证对手真的强；`budget_matched` 的分母仍由
  `study baseline` 自己算并报出（§82），本层不因声明存在而免除该披露。
- 算力与环境披露（`study-spec.json` 的 `environment` 与每格 `elapsed_seconds`）：外部 rubric 直接问这些
  （AAAI design："Report compute, hardware, data access, model size, and training/inference cost"；
  NeurIPS reproducibility："State exact data splits, preprocessing, hyperparameters, selection
  criteria, compute resources"），而此前包内**任何一层都没有**耗时/版本/硬件字段
  （逐键核对 spec/cell/run 三层确认；此前一次粗查被 `schema_version` 里的 "version" 骗过，已逐键重查）。
  现在写包时记录：python / numpy / scipy / sklearn 版本、platform 与 machine、逻辑 CPU 数、
  每格 wall-clock 秒数与整包总秒数。
  口径必须写死：`evaluations` 是**唯一的算力度量口径**，wall-clock 只是可复现性披露，
  **不参与任何判定、不做争用校正**——同一份代码在争用机器上实测 1082.6s、空闲时 202.2s（5.3 倍，见 58 §142），
  所以任何跨机器的耗时比较都没有意义；`environment.boundary` 里就写这句话。
  老包没有这些字段：closure 只在缺失时给 `environment.recorded` **warning**，不作 blocker，
  历史结论不因新增披露项被追溯判死（与 `preregistration.present` 同一处理方式）。
- 指标敏感性可复现（`study saturation --study-dir`）：只读已记录 nodes，输出 ceiling share 与
  raw / headroom-normalized anytime 交互；它不重跑、不签署、不替代注册指标，也不是预注册证据，
  只用于暴露 ceiling 右删失风险。
- 强基线绑定（可选的第四份包内产物）：`study claim --baseline-file <tuned-baseline.json>` 把该文件
  **按字节原样**复制进研究包为 `tuned-baseline.json`（不经重新序列化，所以记录里的哈希就是文件本身），
  claim 的 `evidence_refs` 追加 `tuned-baseline.json#<sha12>`，`verification` 记录
  `baseline_sha256` 与 `baseline_digest`（dataset / folds / grid_size / baseline_fits_per_seed /
  study_budget / budget_matched / seeds），使主张自带"对手花过多少算力"的分母。
  `claim_id` 的哈希输入在提供基线时追加该 sha；**未提供时哈希输入逐字不变**，历史 claim 的 ID 与
  evidence_refs 不漂移。文件的 `dataset` 与本包不符、或与本包种子无交集时直接拒绝——绑错基线比不绑更糟。
  闭包新增 `baseline.bound`：claim 记录了 sha，包内 `tuned-baseline.json` 必须存在且字节哈希一致，
  否则 blocker；未记录 sha 只给 warning，本层不强制每份主张都必须有外部强基线（那是人的决定）。
  `tuned-baseline.json` 同时进入 `CHAIN_FILES`，与研究同生共死：改基线字节即让链失效。
- 表格投影必须由代码直出：`study baseline --table-from <r1,r2,……> --markdown <path>` 只读已有报告渲染
  跨环境表格，表头与数据行共用同一份 `baseline_lab.TABLE_COLUMNS`，每个值按它的**真实键名**读取——
  列名 `study_mean_best` 只会拿到方法分数而不是对手分数，区间只会读 `ci95_low`/`ci95_high`。
  必需键缺失时抛错而不是留空；区间整体缺失写 `not computed`，因种子不足被扣住写 `withheld(low power)`，
  两者不得混为一谈（前者是产物版本问题，后者是功效结论）。动因：此前两张论文表格由一次性脚本手工拼接，
  实际出现过表头 8 列而数据行 7 列、digits 的 CI 被渲染成 `[null, null]`、把 `baseline_mean_held_out`
  标成 `mean_best` 三处失真。
- 链完整性分层与覆盖率分母（`research_agent/study_integrity.py` 的 `package_integrity` / `integrity_layers`）：
  只读一次 spec/study/evidence，重算三处内容哈希并回答一个问题——**这份包现在还能不能被验证**。
  `state` 三值：`derivable`（记录哈希与盘上字节在当前规则下逐一相符）、`non_derivable`（至少一条不符，
  即早于计时字段剥离（0.46.0）或早于哈希规范化的包：没有任何重跑能重现它记录的 `study_sha256`）、
  `incomplete`（三份必需产物缺失，`missing` 列出缺哪份）。`failures` 逐条点名失败的绑定
  （`study.self_hash` / `spec.binds_study` / `evidence.binds_study` / `evidence.binds_spec` /
  `evidence.self_hash`）。代码指纹是**另一根轴**，单独报 `code_fingerprint = match | stale | absent`：
  它说"跑这份包的那版代码还在不在"，不说"这份包能不能验证"，两者过去被混在 `code.unchanged` 一个
  blocker 里，于是一次纯元数据改动与一次哈希规则变更看起来完全相同。
  `artifacts` 记录 origin / preregistration / baseline / claim 四份包内文件与 environment /
  code_fingerprint 两个 spec 字段是否存在。`integrity_layers` 把这些按层聚合成覆盖表，
  每个 artifact 同时给 `all` 与 `derivable` 两个分母及其比率，并写出规则文本：
  谈论"可引用证据的覆盖率"只能用第二个。`study replicate` 报告新增 `chain_layers`（作用域与
  `scope` 同一批包），闭包盘点的每个研究行新增 `chain`。
  边界：这一层不重跑、不签核、不解除任何门禁——`code.unchanged` 仍是 blocker，
  `non_derivable` 的包在门禁上既不更重也不更轻，它只是第一次让"我们的覆盖率里有多少是不可验证的"
  成为读者看得见的数字，而不是只有作者知道的秘密。

## Current Implementation

- `research_agent/search_lab.py`：`run_condition`（单格搜索）、`run_study`（2×2 分解）、
  `build_evidence_package`、`write_study_package`（落盘 + 交叉哈希绑定）、
  `study_profile_summary`（可执行面声明）。
- CLI：`python -m research_agent study profiles` / `study search`。
- 是否联网：否。仅使用 sklearn 公开表格数据集。
- 依赖：numpy / scikit-learn（可选 scipy 用于 t 分位数，缺失时退回 2.0 并在边界内说明）。
- 当前实测（iris, 8 seeds, budget 60）：门控主效应 +0.156，CI [+0.042, +0.271] 不跨零；
  档案单独主效应跨零；档案×门控交互 −0.275，即**保留档案会抵消门控带来的单位算力收益**。

## Boundaries

- 被改进的是配置而非智能体代码：这是**结构类比**，任何关于自改进智能体的外部效度都不成立；
- 不创建 Claim / EA / Verdict；`status: verified` 只表示研究产物内部一致且哈希绑定；
- 不自动签署：想让论文报告这些数字，必须走既有的 `experiment claim` / 人签路径；
- 不把 fixture 或合成结论写成真实结果；`analogue=true`、`exploratory=true`、
  `significance_claimed=false` 必须始终为真。

## Minimal Change Workflow

1. 新增因子或数据集：先扩 `study_profile_summary()` 的 `supports` / `does_not_support`，
   因为想法阶段的可行性校验依赖它；
2. 改指标口径：同步改 `build_evidence_package` 的 `primary_metric` 与测试；
3. 任何"缩小区间"的改动（如换成分位数方法）必须在 boundary 中说明，不得静默提高显著性；
4. 跑 `python -m unittest tests.test_search_lab`。
