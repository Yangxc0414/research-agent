# research-agent plugin bundle

Generated by `python -m research_agent plugin export`; do not edit by hand.

This bundle lets an agent host drive the research runtime. It is a transport plus a description of entrypoints: 46 MCP tools, 215 CLI commands, and one file-drop path for hosts that cannot call tools.

## Install per host

- **Qoder**: merge `mcp.qoder.json` into the app's MCP server settings, then reload the connector.
- **Codex**: append `mcp.codex.toml` to `~/.codex/config.toml`.
- **Zcode / WorkBuddy / other MCP clients**: use `mcp.zcode.json` / `mcp.workbuddy.json`.
- **No tool calling at all**: keep the CLI on disk and exchange files through `handoff export|import`.

Replace `<RESEARCH_AGENT_ROOT>` with the checkout root, or regenerate with `plugin export --root <path>`.

## Model supply: no API key on a platform host

On Qoder and similar platform hosts the agent you are talking to **is** the model: it answers pending turns, and no API key is configured anywhere. On a plain CLI client with no agent to answer turns, bind a keyed profile once instead (`python -m research_agent host-model bind ...`). If neither holds, the run stops with `blocked=model_stages_suspend_without_a_host_model` rather than drafting something weaker. `manifest.json` records both modes under `model_supply`.

## First thing to run

    python -m research_agent handoff contract --capabilities can_call_tools,can_write_files

It reports which transports are live, which stages will suspend waiting for the host model, and what stays human-only.

## What this bundle cannot do

the plugin is a transport and a description of entrypoints only: it contains no research logic and no gate authority; claim signatures, gate decisions, protocol freeze, closure signatures, publishing and export approval stay CLI operations, run by a human or by a human-authored autopilot policy that the plugin may invoke but never create or widen
