# 42 · 后端反思与创新路线：从对象接线到可验证证据运行时

> 日期：2026-10-25  
> 依据：`research_agent/`、`modules/*/SPEC.md`、`tests/`、39–41 文档；外部调研见 30（RSI 百篇）、38（AGENT4SCI）、40（Claude Code 分层）。  
> 边界：本文是后端反思与创新路线，不是“已实现”；当前代码仍是证据治理原型 + 可复现纵切，不是自主科研系统。

## 0. 判断先说

后端最值得保留的不是阶段数量，而是**对象契约**：SourceHit / Span / CoverageReceipt / RunCapsule / EA / Claim / Closure / Signature / Lease 这条链。它让“结果能不能被声称、能不能被导出”第一次成为代码对象。

但当前后端有三个结构性问题：

1. **信任边界不成立**：claim 的“人签”只是普通 JSON；closure 读 demo 内嵌 capsule；protocol 在 run 之后才冻结；lineage 的 dataset/code 哈希来自 capsule 字段而不是文件重算。
2. **语义证据缺失**：closure 只检查 ID/哈希/槽位，不判断 claim 是否被 span 支持；检索没有全文；LLM 没有接进科研流程。
3. **评估与 RSI 仍停在控制面**：hidden 只是同一 CSV 的不同 `test_size`；RSI 只改 seeds/budget；`claim_eligible` 默认 True，可绕过“harness 证据不写 capability claim”。

因此，**创新不应再是“再加一个阶段/Agent/技能”**，而应围绕三件事：

- **可验证的运行身份**：预注册 → run → EA → claim → closure，每一步可签名、可复现、可校验；
- **变更后的证据维护**：数据/代码/论文变化后，哪些 claim/图/句/导出失效，并能重新闭合；
- **受治理的 harness 改进**：候选只能改白名单旋钮，必须在 sealed public/hidden/near-OOD/regression 上评估，租约准入，负结果保留。

一句话：

> 后端要从“对象接线”升级为“可验证证据运行时”；创新单位是**不变量 + 测量**，不是模块数量。

## 2. 哪些底座是好的，不要推倒

- **SPEC-first**：`modules/*/SPEC.md` + `SpecStore` 的原子更新，是比大多数毕设更可靠的契约源；
- **端口/适配器**：Retriever/Parser/Judge/Writer/Exporter 的边界已经出现，虽然很多未接实；
- **对象契约**：`contracts.py` 统一信封（artifact_id/type/version/status/inputs/produced_by/verified_by/content_hash）；
- **不自动写 Claim**：这是最重要的产品边界，必须保留；
- **closure sign 前重跑**：`closure.sign` 会从当前输入重算检查，旧报告不能直接复用；
- **lineage CLI**：哈希图 + stale 传播 + export_allowed 的骨架是对的，只是事实源不对；
- **诚实标注**：fixture_mode、SIM、not peer review、claim_eligible 等字段说明作者知道边界。

这些不是创新，但它们是创新的地基；如果为了“做得更多”把它们拆掉，会失去最可信的部分。

## 3. 七个必须补的后端缺口

### 3.1 信任边界：签名、身份、append-only

**现状**：`ClaimRecord` 只有 `human_reason`；`closure.sign` 生成普通 `SignatureRecord`；任何能写文件的人都能手写 claim + signature 让系统“看起来闭合”。

**需要**：Ed25519/公钥签名覆盖 canonical claim/EA/closure checks；signer 身份；append-only 审计日志；签名验证失败必须 block。  
**创新性**：不是算法创新，但它是“可问责证据”的前提；没有它，后续所有“人签/闭合”叙事都站不住。

### 3.2 Closure 事实源与预注册

**现状**：`closure.check` 从 `demo["modules"]["run"]["capsule"]` 读 status，只对 capsule 文件做哈希；测试用空 `{}` capsule 也能通过。`run/SPEC.md` 写“没有冻结 protocol 不执行”，但 `RunAgent.execute` 不校验 protocol；ProtocolCard 要求 run 完成后才冻结。

**需要**：closure 从真实 capsule/EA 文件读取并校验 run_id/status/scope；run 前必须冻结 protocol，并把 design/dataset/metric/seeds/test_size 绑定进 capsule。  
**创新性**：预注册本身不新，但“预注册 → 运行 → claim → closure”的强制链在开源科研 Agent 里仍不常见；这是可以测量的结构不变量。

### 3.3 内容寻址的变更传播

**现状**：lineage 的 dataset/code 节点哈希直接取 `capsule.dataset_sha256/code_sha256`，不重算真实文件；closure 不调用 lineage；`export_allowed` 只要求存在未 stale 的 signature。

**需要**：重算 dataset/code/config/env 文件哈希；变更 → 下游 claim/figure/slot/signature stale → export blocked；提供“重新闭合”任务。  
**创新性**：这是最强的差异化候选：主流 deep research 报告是一次性的，不做“半年后数据/代码/论文变化后哪一句还成立”。

### 3.4 语义支持与校准 abstention

**现状**：closure 只做结构检查；没有 `supported/partial/contradicted/insufficient` 的支持判定；摘要-only 被正确排除，但没有“证据不足”的正式对象和指标。

**需要**：`SupportVerdict`（claim × span × relation × confidence × reviewer）与 `Abstention`；LLM 只能建议，人工复核；报告 precision/recall/abstention，而不是把 LLM judge 当真理。  
**创新性**：claim-level support + abstention 是市场稀缺层；但必须用标注集和 κ 评估，不能只靠 demo。

### 3.5 评估隔离与 sealed hidden

**现状**：S5 hidden 只是同一 ChemLab demo CSV 的不同 `test_size`；hidden 在仓库内；admission 不要求 near-OOD/regression；judgment 未 sealed。

**需要**：独立的 evaluator/auditor 进程；public/hidden/near-OOD/regression 固定任务；hidden 只在最终评估访问一次；结果先封存再解封；候选选择不可见 hidden。  
**创新性**：这是 RSI 研究里最常被忽略、也最容易证伪的部分；做到就能支撑“受治理”的论文主张。

### 3.6 RSI：从两个旋钮到 typed patch

**现状**：lease 只覆盖 `literature.retrieval.budget` 与 `experiment.run.seeds`；patch 是自由文本；immutable 检查是 target 子串；`claim_eligible` 默认 True；没有 code/prompt/skill patch 执行器。

**需要**：typed patch（白名单 target + 操作 + 值/模板），dry-run 执行器，public/hidden/near-OOD/regression，sealed hidden，human admission，lease 消费，rollback/revoke，negative retention。  
**创新性**：不是“模型自进化”，而是“harness-only RSI 的准入与证据协议”；必须明确不训练模型、不改 claim/gate。

### 3.7 真实检索、LLM 工具循环与运行时

**现状**：OpenAlex 只返回摘要；无 PDF 解析；LLM 未接 literature/idea/experiment/paper；runtime 无 auth、内存 job、JSON 无锁、依赖不全。

**需要**：
- FAISS/BM25/OpenAlex/Crossref/Unpaywall + PDF/HTML 解析 + 页码/字符偏移；
- 模型通过 typed tools 提议 `SourceHit/Span/ClaimDraft`，不能直接写 Claim/EA/gate；
- SQLite/Postgres + append-only events + idempotency + cancel/timeout + token auth；
- 结构化日志、token/成本、artifact GC；
- 依赖锁与端到端测试。

这些不是“创新点”，但不做就无法称为可用的科研 Agent。

## 4. 创新矩阵：什么值得押，什么不该押

| 方向 | 新颖性 | 可行性 | 证据形式 | 风险 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| A. 签名 + 预注册 + closure 事实源 | 低（工程） | 高 | 篡改/伪造注入测试 | 低 | P0 |
| B. 内容寻址变更传播 + reclose | 高（差异化） | 中 | 真实 CSV/code 改动 → stale/blocked | 中 | P0/P1 |
| C. SupportVerdict + abstention | 高（研究） | 中 | 100–300 claim 标注，P/R/abstention | 标注成本 | P1 |
| D. Sealed hidden + harness RSI | 高（研究） | 低–中 | 预注册多轮对照，hidden 一次 | 算力/时间 | P1/P2 |
| E. 内置 Skill runtime + typed tools | 中（工程） | 中 | 技能执行审计、工具边界测试 | 低 | P1 |
| F. Evidence Debt / 双轴审计 | 中–高（测量） | 中 | 债务指标与修复前后对照 | 指标设计 | P1 |
| G. 全文检索/PDF 解析 | 低（必需） | 中 | 真实主题 coverage/span | 数据许可 | P0/P1 |
| H. 多 Agent DAG / 更多阶段 | 低（易同质） | 中 | 并行/预算/失败恢复 | 高协调成本 | 暂缓 |

**判断**：

- A 不是创新，但**不做就没有可信的创新**；
- B 是最适合作为“系统贡献”的差异化：变更后哪一句还成立、哪个导出必须拦住；
- C 是研究贡献，但必须用标注与 κ 证明，不要用 LLM judge 自评；
- D 是 RSI 论文的硬门槛，成本高；没有 sealed hidden 就不要写“自进化”；
- E/F 是把“证据运营”变成可测产品能力的中间层；
- H 容易变成“更多 Agent”的演示，研究价值最低，暂缓。

## 5. 建议的后端结构（不要上微服务）

### 5.1 模块化单体 + worker

```text
research_agent/
  domain/        # contracts, IDs, policy, invariants
  knowledge/     # retrieval, parsing, spans, source registry
  execution/     # run capsule, harness, evaluator
  evidence/      # claim, support, debt, lineage
  closure/       # closure, signature, export
  improvement/   # RSI candidate, eval, lease
  runtime/       # FastAPI, jobs, auth, SSE
  adapters/      # OpenAlex/Crossref/PDF/LLM/Skill runtime
```

- 按证据对象/用例拆，不按阶段/Agent 拆；
- 毕设阶段一个部署单元 + 一个 worker 足够；
- 不要为了“架构完整”上 10 个容器。

### 5.2 持久化

- SQLite（单机）/ Postgres（部署）：runs、claims、evidence、events、leases、jobs；
- 事务 + 唯一约束 + append-only `audit_events`；
- artifact 文件放对象存储/本地目录，内容寻址；
- JSON 只用于快照/导出，不作为主状态。

### 5.3 任务与并发

- SQLite/Redis 队列；job 状态机 `queued/running/succeeded/failed/cancelled`；
- idempotency key；超时/取消；单 worker 起步，按阶段并行；
- SSE 从持久事件表读，不依赖内存；
- 无 auth 不暴露；本地 token + CORS 白名单。

### 5.4 契约

- Pydantic/JSON Schema 生成 OpenAPI；前端类型从 schema 生成，避免手写双份；
- ID 前缀 + 版本；`schema_version` + 迁移；
- 失败必须 typed error，不用 `Dict[str, Any]` 兜底。

## 6. 12 周路线

### 第 1–2 周：完整性 P0

1. Ed25519 签名 claim/EA/closure；append-only log；伪造 claim 测试失败。
2. closure 从 capsule/EA 文件读取；空 capsule 必须 fail。
3. protocol 先于 run 冻结；run 绑定 design/dataset/metric/seeds/test_size。
4. lineage 重算真实 dataset/code 文件哈希；closure/export 查询 impact。
5. 修 `claim_eligible` 默认与 RSI admission；更新 README/39 的过度表述。

### 第 3–4 周：变更维护

6. ChangeSet 对象：changed files、affected claims/figures/slots、dispositions（accept/re-run/downgrade）；
7. reclose 任务：从变更到新 closure/signature；
8. Evidence Debt 指标：无 span、无 EA、stale、摘要-only、未闭包；
9. 真实 CSV/code 变更 demo，不再改合成哈希。

### 第 5–8 周：真实纵切

10. PDF/HTML 解析 + 页码/字符 span + 原文高亮；
11. OpenAlex/Crossref/Unpaywall 适配器 + 去重 + 全文获取；
12. LLM typed tool loop：模型只能提议 SourceHit/Span/ClaimDraft；
13. 内置 Skill runtime：白名单 check 函数 + 审计；
14. SQLite + token auth + idempotency + cancel/timeout。

### 第 9–12 周：研究实验

15. SupportVerdict/Abstention：100–300 claim 标注，2 人复核，报告 P/R/κ/abstention；
16. sealed hidden + public/near-OOD/regression；candidate 不可见 hidden；
17. typed RSI patch + dry-run + lease + rollback + negative retention；
18. 变更传播基准：stale recall、false block、reclose time；
19. 成本指标：cost per verified claim、p95 latency、failure rate。

## 7. 实验与指标

| 主张 | 实验 | 指标 |
| --- | --- | --- |
| no span/EA/signature → no export | 失败注入：空 capsule、伪造 claim、删图、改 CSV | 阻断率 100%，无误放行 |
| 变更后维护 | 改 dataset/code/论文版本 | stale recall、false stale、reclose 时间 |
| support/abstention | 100–300 claim 标注 | precision、recall、abstention、κ |
| sealed RSI | public/hidden/near-OOD/regression | hidden 访问 0/1、Δ、成本、负结果保留 |
| 运行时质量 | 并发/重启/超时 | p95、失败率、幂等、恢复 |

**负结果也要保留**：如果 hidden Δ 为负、support 判定不稳定、变更传播误报高，就写成边界；不要为了“好看”删掉。

## 8. 可宣称 / 不可宣称

**可以 defend（结构或测量）**：

- “span-only / no-span-no-claim”的准入规则；
- “run-bound evidence + pre-registration + closure”的结构不变量；
- “内容寻址的变更传播与 reclose”；
- “harness-only、sealed hidden、human lease 的 RSI 控制面”；
- “Evidence Debt / 双轴审计”的测量。

**不能宣称**：

- “自主科学家 / 端到端科研”；
- “claim 语义为真”；
- “自进化/越跑越强”（没有 sealed hidden 与多轮对照）；
- “人签/密码学签名”（在 Ed25519 落地前）；
- “真实 held-out / 真实实验隔离”（在 evaluator 独立前）；
- “真实检索/写作”（在全文与 LLM 接通前）。

## 9. 结论

后端下一步不是“再加一个模块”，而是把三件事做实：

1. **签名的、预注册的 run**：从 protocol 到 EA 到 claim 到 closure，任何一步不可手写绕过；
2. **内容寻址的变更图**：数据/代码/论文变化后，claim/图/句/导出能自动 stale，并能重新闭合；
3. **sealed evaluator + typed RSI**：候选只能改 harness 白名单旋钮，hidden 只评估一次，人签租约，负结果保留。

如果这三件事做成，项目就可以从“证据治理原型”升级为“可验证证据运行时”；如果继续加阶段、加 Agent、加面板，只会扩大演示与真实之间的裂缝。
