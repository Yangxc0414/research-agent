# 35 · 前端工程化架构：可部署的对话式科研工作台

> 本文记录 2026-10-24 的工作台迁移：把 `site/agent/` 的单文件静态页升级为 `apps/web/` 的 Vite + React + TypeScript 应用。目标不是“换一个框架”，而是让工作台具备四件原来缺失的能力：**可维护的模块边界、可替换的状态适配器、可分发的构建产物、可容器化的部署入口**。

## 0. 先给判断

旧版 `site/agent/`（`agent.js` 约 2.3k 行、`agent.css` 约 0.7k 行）作为交互试验是有效的，但它有三类结构性问题：

1. **状态、视图与业务动作混在一个脚本里**。一次点击可能同时修改 DOM、`localStorage`、任务状态与 toast；要加一个状态字段需要跨多个渲染函数手动同步。
2. **交付物只有 HTML/CSS/JS 三个文件**。它适合静态预览，不适合接到真实 API、做多页面部署、加权限或做前端增量发布。
3. **“人工门”与“静态模拟”只能靠注释和文案约束**。没有 adapter 边界，接入 runtime 时容易把模拟路径与真实路径混在一起。

因此新版采用 **static-first + adapter boundary**：

- 页面默认使用 `StaticWorkspaceAdapter`，所有数据在浏览器本地，明确显示 `SIM · STATIC`；
- UI 与业务动作只依赖 domain/store，不直接读 `localStorage`；
- 将来接真实 runtime 时实现同一个 `WorkspaceAdapter` 接口，替换持久化/事件来源，而不是重写页面；
- 构建产物为带哈希的静态资源，可由 Nginx、对象存储或 GitHub Pages 托管；API 通过 `/api/` 反向代理进入，不把密钥放进前端。

这仍然是**受治理工作台的演示层**，不是“前端已经接上 LLM/实验执行”的证明。

### 为什么用 Zustand

工作台的状态不是一棵只读树：任务切换、自动运行 timer、指导队列、工具审批、弹窗与偏好会交错更新。Zustand 提供单一 store 与直接调用 action，避免 Context 深层重渲染；同时保留“每个 action 就是一次显式状态迁移”的可审计性。复杂视图通过 selector 取所需切片，数组 selector 使用 `useShallow` 防止 React 19 下的快照不稳定。

## 2. Domain 对象

新的 domain 只保留工作台真正需要的对象，并与后端契约保持同名语义：

| 对象 | 关键字段 | 边界 |
| --- | --- | --- |
| `ResearchTask` | id/name/goal/mode/workspace/stage/completedStages | 一个工作区内的任务；`updatedAt` 驱动“最近任务” |
| `Gate` | id/status/reason | 只展示与记录，不在前端产生真实签名 |
| `EvidenceItem` | gap/hypothesis/claim + refs | `claim` 的 `unsigned → signed` 只由显式“模拟签核”按钮触发 |
| `AutoStage` | id/label/cmd/output/gate | 9 阶段运行轨迹；`gate` 标记 claim 人工门 |
| `Guidance` | text/status/pending→applied | 只影响执行策略，不写 claim/EA/gate |
| `Plugin` / `ToolCall` | transport/auth/readonly/toolsets/status | 连接器登记与逐次审批；没有真实网络 |
| `Skill` | id/name/description/instructions/tools/activation/source/version | 内置与自定义只读检查技能；`activation=auto/manual/off`，目录常驻、按需加载，调用只生成卡片 |
| `AccessMode` | read_only / ask / full | 会话级权限；只读拦截执行，ask 逐次确认，full 仍不越过 claim 人工门 |
| `PermissionRequest` | kind/taskId/title/detail/targetId | 仅在前端 UI 中存在；允许/取消都写入本地 trace |
| `EvaluationState` | baselinePaper/Reproduced、hiddenAccessCount、validationSelections、evalRuleHash、audit、cost、interventions | EVAL 控制面；held-out 一次访问、复现基线与过程审计的静态对象 |
| `Intervention` | label/kind(engineering/domain)/note | 方法台账；区分工程组合与回应领域结构的干预 |
| `ShortcutMap` | action → canonical shortcut | 设置页录制、全局键盘分发、Preferences 持久化；Mod 在 Windows 映射 Ctrl、在 macOS 映射 ⌘ |
| `ModelSettings` | profile/contextLimit/maxReply/thinkingStop/compression | 能力上限来自 `ModelProfile`，UI 只选已声明档位 |

`ModelProfile` 是能力层（例如 400k context、16k output、支持 `reasoning_effort` 或 `thinking.budget_tokens`）；`ModelSettings` 是本次策略层。保存时 `clampModel` 强制：

- `contextLimit ≤ context_window`；
- `maxReply ≤ max_output_tokens`；
- `thinkingStop` 只在模型声明支持时生效；Anthropic budget 档位还必须小于 `maxReply`（`max_tokens > budget_tokens`），超出时由前端裁剪或退回 `off`。

## 3. 状态机与动作

`workspaceStore` 将动作按语义分组：

- **欢迎与导航**：`openWelcome`、`startSession`、`selectTask`、`activateWorkspace`、`toggleWorkspace`、`toggleRecent`、`setContextTab`；
- **会话**：`sendMessage`、`runResearch`、`designExperiment`、`freezeProtocol`、`runExperiment`、`signClaim`；
- **访问控制**：`setAccess`、`confirmPermission`、`cancelPermission`；高权限动作先经过 read_only/ask/full 门；
- **Skills**：`createSkill`、`setSkillActivation`、`deleteSkill`、`invokeSkill`；`skillRouting.ts` 负责会话内按需选择，欢迎页调用会先创建会话；
- **评估隔离**：`submitEvaluation`、`runEvaluationAudit`；一次 held-out、复现基线、验证选择与过程审计；
- **快捷键**：`setShortcut`；设置页录制/校验/冲突检测后写入 Preferences，App 键盘分发读取同一映射；
- **工作区管理**：`addWorkspace`、`deleteWorkspace`、`createNewTask`、`deleteTask`；
- **受治理运行**：`startAuto`、`pauseAuto`、`resumeAuto`、`stepAuto`、`autoStep`、`stopAuto`；
- **自进化**：`previewCandidate`、`approveCandidate`、`rejectCandidate`、`rollbackHarness`；
- **模型与工具**：`saveModel`、`registerPlugin`、`togglePlugin`、`proposeToolCall`、`approveToolCall`、`denyToolCall`；
- **系统**：`exportWorkspace`、`resetWorkspace`、`notify`。

新会话从欢迎页的 `startSession` 进入：用首条消息生成名称/目标/初始计划卡，沿用选中的工作区与访问级别。欢迎页不是单独路由，而是 `UIState.welcomeOpen`；点击任务、发送消息或表单创建都会关闭它。删除当前任务会回到欢迎页，而不是自动跳到另一个无关任务。

### 自动运行

自动运行不是 React 组件内的 `setInterval`，而是 **纯 reducer + 外部时钟**：

1. `startAuto` 将 `auto.running=true`、`index=0`，重置 9 阶段；
2. `App.tsx` 在 `running && !paused` 时设定 1.1s timer，调用 `autoStep`；
3. `autoStep` 走 `advanceAuto`，完成一个阶段、追加 trace、更新 gate/budget，并把下一个阶段标为 running；
4. 到 `S5b` 时 `paused=true`、`gate="claim"`，界面停止 timer，显示人工门；
5. `signClaim` 只把 claim 标记为 `signed`，不自动继续；用户必须点“继续”；
6. 完成后停在 closure 9/11，候选进入 `proposal`，等待批准/拒绝/回滚。

这条路径的关键不是动画，而是**任何自动推进都不能越过 `claim` 人工门**。前端用 gate 检查、按钮禁用与文案三层表达同一不变量；真实运行时仍必须由后端强制。

### 运行中指导

自动运行时，普通输入被写入 `Guidance` 队列而不是追加为普通对话；`advanceAuto` 在下一阶段边界把 pending guidance 标为 applied，并追加一条“已按指导调整”的 trace。指导不修改既有 span/claim，也不会追写 EA；这与 `33-` 设计的 `POST /api/runs/{id}/guidance` 语义一致。

### 4.1 字体缩放

左下角“设置与工具 → 个性化”提供 **小 / 标准 / 大 / 特大** 四档（90% / 100% / 110% / 120%），写入 `Preferences.fontScale` 并随任务状态持久化。实现不是用 `zoom` 缩放整个应用，而是：

- `.ra-app` 暴露 `--font-scale`，所有 CSS `font-size` 使用 `calc(Npx * var(--font-scale))`；
- 图标、卡片宽度、三栏网格与断点不变，只改变文字大小与由字体撑开的行高；
- 在 390 / 1024 / 1440 下实测 120% 无横向溢出；顶栏模型 chip 已移除，Composer 的模式/权限/模型触发器加 `white-space: nowrap`，避免大字号换行；模式浮层锚定输入框左下并向上展开。

### 4.2 各模型 Token 用量

`ResearchTask.usage: Record<profileId, TokenUsage>` 记录三个字段：

```ts
interface TokenUsage { prompt: number; completion: number; requests: number }
```

- 种子任务带有 SIM 历史用量，便于直接看到三模型的差异；
- 每次 store mutation 若新增了消息，按消息文本与卡片 JSON 的长度做本地 token 估算，累加到**当前 `profileId`**；切换模型后只记到新模型；
- 设置面板显示三模型的总量、in/out 与当前模型标记；模型窗口显示每模型占用条、`used / context_window`、占比、in/out 与请求数；
- 顶栏模型 chip 已移除；Composer 右下角 `ModelPicker` 既显示当前模型/思考档位，也能切换 profile；详细上下文设置仍进模型小窗。
- 所有数值明确写 `SIM`，不读取真实 API usage，也不伪装成计费数据。

### 4.3 设置中心的分组、返回路径与后端落点

参考 ZCode 的设置页后，只吸收适合本项目的结构，不照搬“远程设备 / 浏览器控制 / 电脑控制 / 升级 / 邀请好友”：

- **返回语义**：`UIState.settingsOrigin` 在 `openSettings` 时记录来源（欢迎页或具体任务名）；左上角品牌按钮、侧栏返回按钮和 Esc 都走 `closeSettings`，回到原任务/欢迎页。侧栏按钮显示“返回任务 · 钙钛矿界面钝化”或“返回欢迎页”，不再固定写“返回工作区”。移动端顶栏新增设置入口，不依赖隐藏侧栏底部的个人按钮。
- **分组（最终 5 组 / 16 项）**：基础设置（常规 / 外观 / 快捷键 / 命令 / 模型设置）、Agent 能力（记忆 / 子智能体 / 插件与 MCP / 自进化）、运行与证据（执行环境 / 使用统计 / 证据沿袭）、数据与归档（归档管理 / 数据与备份）、支持（快速引导 / 关于与边界）。命令与快捷键相邻；归档从运行组拆出，避免“运行状态”和“数据处置”混在一起。欢迎页隐藏模型/插件/自进化等任务级分节。
- **不照搬的项**：没有远程设备、浏览器控制、电脑控制这些执行面，就不做假开关；用“执行环境”展示真实本地 runtime 的健康、队列、模型网关与 RSI 只读状态。没有 hook 执行器，就不放“钩子”面板。
- **数据来源**：子智能体读取 `AgentRegistry`（`modules/*/SPEC.md` 的只读投影）；命令读取 `CommandRegistry`；两者优先请求 runtime `/api/workspace/*`，失败时回退到 `apps/web/public/agent-registry.json` / `command-catalog.json` 并标 `SPEC SNAPSHOT`。记忆与归档先写 localStorage，连接 runtime 后可同步到本地存储。
- **后端落点**：`research_agent/workspace.py` 提供 AgentRegistry / CommandRegistry / MemoryStore / ArchiveStore；CLI 增加 `workspace agents|commands|memory|archive|export`；runtime 增加 `/api/workspace/agents|commands|memory|archive`。这些对象不创建 Claim/EA/Closure/Signature，归档拒绝 secret 字段，单条上限 2MB。
- **验证边界**：静态站点仍可在没有 Python 的情况下展示 SPEC 快照与本地记忆/归档；`LIVE RUNTIME` 只在本地 runtime 启动时出现。

### 4.4 全屏设置子页与使用统计

左下角“设置与工具”不再打开小浮层，而是进入 **全屏设置子页**（`settingsOpen` + `settingsSection`，z-index 90）。设计参照桌面客户端的设置窗口：

- 顶栏保留品牌、全局 `SIM · STATIC` 与关闭按钮；
- 左侧“返回工作区”+ 分组导航：基础设置（常规 / 外观 / 模型设置）、Agent 能力（插件与 MCP / 自进化）、数据与统计（使用统计 / 数据与备份）、支持（快速引导 / 关于与边界）；
- 右侧内容区最大宽度 1060，卡片化布局；移动端导航变成横向滚动条，返回按钮固定，活动项自动滚入视野；
- 模型小窗、插件审批抽屉仍可从设置页打开，层级在设置页之上；关闭后回到设置原位。

**使用统计**默认页整合了 `usage` 与 `usageDays`：

- 顶部五张汇总卡：累计 Token、峰值 Token、累计请求、当前/最长连续活跃天数；
- 52 周 Token 热度图：按每日全部模型输入 + 输出着色，悬停显示日期与数量；未来日期留空；
- 时间范围独立一行（近 7 日 / 近 30 日），作用于每日趋势图；趋势线用平滑贝塞尔曲线，窄屏横向滚动；
- 模型用量：环形图显示总 token 与各模型占比，右侧图例列出模型、tokens、请求数和当前模型标记；
- **证据沿袭**：加载真实 closed-loop 的 17 节点快照，展示 dataset→run→EA→claim→slots→paper→closure→signature 的依赖；点击“模拟数据集变更”会把 14 个下游节点标为 stale，并在页面顶部锁定导出。它对应后端 `lineage build/verify/impact`，不是手工画的静态图。
- 所有数字均来自本地消息/卡片长度估算，页面持续标注 `SIM`，不冒充 API 计费或真实 token usage。

设置页也遵守全局 `fontScale`，并额外使用 `--settings-font-scale = fontScale × 1.15`，让桌面设置页保持比三栏工作台更接近阅读界面的字阶；在 390 / 1024 / 1440、100% / 120% 下均验证无横向溢出。

### 4.5 欢迎页、访问级别、Skills 与回答渲染

**欢迎页**：`UIState.welcomeOpen` 默认为 true，渲染 `WelcomeHome` 而不是会话。采用参考桌面 Agent 壳的布局：大留白、线稿水印、动态问候，Composer 居中。工作区选择在输入框左上，访问级别与 Skills 在左下，`ModelPicker` 与发送在右下；发送后 `startSession` 用首条消息生成任务名称/目标/计划卡，并写入选中的工作区、访问级别与 `draftProfileId` 对应的模型设置。品牌、侧栏“新建任务”和每个工作区的 `+` 都回到这个入口；工作区 `+` 会预先选中该工作区。需要命名/领域/起始模式时，欢迎页仍可打开原有 `NewTaskDialog`。

欢迎页下没有可见会话，因此任务级设置与动作要主动收口：设置导航隐藏模型 / 插件 / 自进化分节；快速引导里的任务动作、侧栏“自动化 / 插件”会提示先进入会话；Skills 仍可管理并从欢迎页创建新会话。

**访问级别**：`ResearchTask.access` 存在会话上，三档语义如下：

- `read_only`：允许检索、查看证据、写作预览与只读 Skills；`startAuto`、`stepAuto` 的首次启动、`runExperiment`、`approveCandidate`、`approveToolCall` 直接拒绝并提示。
- `ask`：上述动作先写入 `PermissionRequest`，由 `PermissionDialog` 只允许本次；允许/取消都会追加 system trace。
- `full`：高权限动作直接执行，但 claim 签名、EA、closure、导出与签名的人工门仍然保留。

自动运行中禁止切换访问级别；模式与权限触发器同时锁定，避免后台 run 与界面权限分叉。前端的访问级别只是 UI 策略层，真实 runtime 必须在服务端再做同一 policy 校验。

**Skills（按需加载，不预启用）**：`PersistedWorkspace.skills` 保存内置与自定义 Skill。内置 10 个只读检查（文献速览、文献覆盖审计、假设收敛、协议体检、证据边界审计、写作槽位草拟、自进化预检，以及研究构思、实验管理、探索巡检、评估隔离）；自定义 Skill 由 `createSkill` 写入名称、说明、指令、工具集与 `v0.1.0`。

每个 Skill 用 `activation` 表示可调用性：`auto`（可被路由器选择，不等于已加载）、`manual`（只能 `/skill-id` 或面板手动调用）、`off`（停用）。导入与自定义 Skill 默认 `off`/`manual`，防止未审阅 instructions 被自动注入。会话内的加载顺序是：

1. **首轮只出计划**，不预加载 Skill；欢迎页的 `/skill-id` 仍可显式创建带技能卡的会话。
2. **动作完成后加载**：`runResearch` → `literature-brief`，`designExperiment` → `protocol-review`，`freezeProtocol` → `protocol-review`，`runExperiment` → `evidence-audit`，`signClaim` → `evidence-audit`，`prepareWriting` → `paper-slots`。此时任务已有真实的前端状态，技能卡才能显示有用的 summary 与检查项，而不是空任务上的 0/6。
3. **后续消息按意图路由**：只有包含“检查 / 审计 / 覆盖 / gap / 边界 / 收敛 / 评估”等 inspection 意图时，`skillRouting.ts` 才在 `auto` 内置技能中选最多 1 个；普通动作句交给动作层，不强行套 Skill。
4. **自动运行按阶段标注**：`advanceAuto` 在每个阶段开始时用 `skillForStage` 标注对应 Skill（S1 文献速览、S2–S3 假设收敛、S4 协议体检、S5a 实验管理、S5b/S6/S13–S16 证据边界审计、S8–S12 写作槽位、META 自进化预检），但不执行工具。

调用不会执行任意代码或外部工具，而是由 `skillCardFor` 读取当前 `ResearchTask` 状态生成只读检查。自动加载使用紧凑的 `skill-use` 卡，显示加载原因、summary 与前三条检查；`/skill-id` 或面板手动调用仍生成完整 `skill` 卡。所有路径都不写 claim/EA/gate，自动运行中禁止手动调用。`SkillsDrawer` 用“按需 / 手动 / 停用”三态替代原来的全局启停开关，并用 `<details>` 折叠完整 instructions，避免把 10 个技能全文一次性摊开。

**Commands vs Skills**：`commandCatalog.ts` 把用户显式动作与过程性 Skill 分开。`/` 菜单现在先按 `RUN / WORK / VIEW / TOOLS` 显示命令，再显示 `SKILLS`；命令直接执行，Skill 插入 `/<skill-id> ` 以便补充检查重点。命令包含 `/start /pause /resume /step /stop`、`/research /experiment /freeze /run /writing /sign`、`/evidence /eval /evolution /lineage`、`/skills /agents /files /memory /new /model /plugins /export /settings /help`。菜单只显示当前任务状态可执行的命令：无 span 时隐藏 experiment/freeze/run，无未签 claim 时隐藏 sign，只读时隐藏所有写动作；`/help` 仍列出全部命令。`skillRouting.ts` 只在 inspection 意图下自动选 Skill，不把命令误判为技能。

**回答渲染**：`RichText` 解析消息中的 Markdown 子集：标题、无序/有序列表、引用、行内代码、围栏代码块与复制按钮；用户消息保持纯气泡。Agent 的结构化回答、技能结果与证据卡按“标题 → 列表/引用 → 卡片动作”的顺序呈现，避免把模型输出全部塞进一段文字。

### 4.6 按钮到后端动作层

- **自动化按钮**：会话内点击会先切到全自动并打开 RUN，再请求 `POST /api/workspace/actions/automation-plan`。后端返回 9 阶段、4 个人工门、`stop_at=S5b`、六面向覆盖策略、预算与 `sha256:` 指纹；前端把计划写入 `ResearchTask.autoPlan`，在 RUN 卡片显示 `BACKEND PLAN`。runtime 离线时回退本地阶段计划并提示。
- **技能动作**：`research_agent/actions.py` 直接编排现有模块，不另造一套假算法：
  - `literature-brief` 调用 `LiteratureAgent(coverage_plan=True)`，返回 `LiteratureBrief`、饱和度、gap 与 span-only 边界；
  - `hypothesis-triage` 调用 `IdeaAgent` 的 span 聚类/否证卡，不自动 G1；
  - `protocol-review` 检查 hypothesis/baseline/metric/seeds/controls，G2 仍由人冻结；
  - `evidence-boundary` 只读检查未签 claim、无 refs claim 与 gap，不修改证据。
- **接口**：`POST /api/workspace/actions/automation-plan`、`POST /api/workspace/actions/skill`；CLI `python -m research_agent action automation-plan ...` / `action skill --id ...`。计划与技能结果都是建议/审计摘要，不是 claim、EA 或门禁决定。
- **仍未后端化的按钮**：搜索、导入文件夹、预览文件是浏览器 File API 行为；任务列表/消息仍以 localStorage 为准；插件启用仍是本地状态。下一步可把任务快照与插件 manifest 接入 runtime 持久化，但不能把本地文件读取搬进后端。

### 4.7 本地文件预览

- **状态**：`previewStore` 是非持久化 Zustand store，保存 `File[]`、当前 tab 与打开状态；刷新页面即清空，不写入 localStorage、不上传。侧栏文件选择、导入文件夹、顶栏眼睛按钮与拖入窗口共享同一 store。
- **窗口**：支持浮动与停靠两种位置。浮动窗最大 460×660；停靠后成为右侧 440px 分栏并暂时隐藏 RUN/EVIDENCE/EVOLUTION/EVAL，点上下文按钮关闭预览并恢复右栏。窗口小于 1301px 时强制浮动/全宽。顶部是浏览器式 chrome（状态点、`LOCAL PREVIEW`、停靠、选择/清空/关闭），第二行是地址栏（`local://<相对路径>`、前进/后退、复制、重新读取），多文件时显示 tab。
- **渲染**：Markdown 复用 `RichText`（安全白名单），JSON 格式化后按纯文本显示，代码/CSV/文本用等宽 `<pre>`；图片用 object URL 缩放；PDF 交给浏览器内置查看器；二进制提供下载/打开。文本单次最多读 512KB。
- **入口与关闭**：侧栏任务列表的预览图标、导入文件夹后自动登记、顶栏眼睛按钮；Esc 关闭，再次点击顶栏眼睛恢复上次选中文件。
- **边界**：浏览器不暴露绝对路径、目录遍历或文件变更；HTML 按纯文本显示，不执行脚本；预览窗不进入证据链，也不改变 Claim/EA/gate。后端不参与本地文件读取——浏览器 File API 是唯一入口；runtime 归档/产物后续可复用同一窗口，用 `runtime://` 地址区分来源。

**EVAL 评估隔离**：参考 AGENT4SCI 的三阶段协议，右侧新增 EVAL 标签。`EvaluationState` 记录 paper/reproduced baseline、held-out 访问次数、验证选择次数、评价规则哈希、审计状态、训练/推理成本与 engineering/domain 干预台账。Improve / Evaluate / Audit 三段并列显示；提交评估要求已有 S5 run，且一次运行只允许 one-shot held-out；审计在提交后运行，会把验证选择过多、规则未冻结、复现基线缺失标为风险。所有动作写 system trace。该面板是控制面演示，真实 held-out 隔离、训练与密码学审计必须由服务端执行。

**研究治理 Skills**：在原有 Skills 之外新增 `research-scout`（双线文献 / Tier-1-2 / 新颖性对照）、`experiment-manager`（预算 / 短程 smoke / 失败分诊）、`exploration-check`（验证选择压力 / 探索收窄）、`eval-integrity`（held-out / 规则 / 复现基线 / 审计 / 成本）。它们只读当前 ResearchTask 与 EvaluationState，生成 `ok / needs_input / blocked` 检查卡，不执行训练、不写 claim。

**S1 覆盖与 S2 收敛**：`domain/researchBrief.ts` 把当前任务状态映射为两组只读检查。`literatureCoverage(task)` 计算来源广度（目标 6）、全文可读（目标 3）、可定位 span（目标 12）、摘要隔离、缺口登记，并给出 saturation、coverage score 与下一步建议；`hypothesisConvergence(task)` 计算候选数、引用 ≥2 条证据的候选数、总引用数、否证条件、novelty 未核验与 G1 人工收敛。S1/S2 阶段展开与 `literature-brief` / `hypothesis-triage` 两个 Skill 复用同一函数，避免“阶段面板”和“技能卡”各算一套。六面向（core/survey/method/evaluation/limitation/recent）逐面向 source/span 由 runtime `LiteratureBrief` 提供，静态适配器不伪造。后端 `LiteratureAgent` 的六面向轮转预算与 `IdeaBrief` 聚类见 `modules/literature/SPEC.md` 与 `modules/idea/SPEC.md`。

**快捷键**：`shortcuts.ts` 定义 9 个动作的默认值、canonical 录制、格式化、校验与冲突检测；`Preferences.shortcuts` 持久化到 localStorage。设置页“快捷键”分节按全局/视图/工具分组，点击键帽进入录制：下一组组合键保存，Esc 取消，Backspace 恢复该项默认；与已有动作冲突或使用无修饰键字母时拒绝。App 的全局 keydown 只读取这一映射，因此自定义后立即生效；单字符快捷键在输入框聚焦时不触发，Esc/Enter/Tab/Backspace/Delete 固定。左侧“新建任务”与顶栏提示也读取映射显示当前组合。

**阶段轨展开**：RUN 面板的 9 个阶段行改为按钮式单展开，不再只靠 `<details>`。S1 展示 sources/spans/gaps/abstract-only；S2–S3 展示候选假设与 G1；S4 展示 baseline/metric/seeds/control；S5a/S5b 展示 run/EA/claim 签核；S6 与 S8–S12 展示图 manifest 与写作槽位；S13–S16/META 展示 closure 与候选。当前/下一阶段在状态列显示蓝色圆点：自动运行且未暂停时为 `stage-live-pulse` 脉冲，空闲/手动模式保留静态蓝点；行按钮带 `aria-current="step"`，减少动效时关闭脉冲。pending 显示计划输出，skipped 说明 manual mode 并提供“回到调研补证据”；若任务已有证据但自动阶段状态未推进，展开仍显示真实证据。自动运行且“运行中自动展开”开启时当前阶段自动展开，用户可手动收起；移动端通过上下文抽屉使用。

**左侧栏管理**：顶部是“新建任务”主操作卡 + 自动化/技能/插件三列工具格；新建任务在有会话时回欢迎页、在欢迎页时直接打开表单；自动化在有会话时切到全自动并打开 RUN、在欢迎页时打开表单并预填 auto；插件在无会话时允许登记但禁用启用。下面是“任务 + 数量”与胶囊工具条：搜索按需展开过滤、文件夹导入本地工作区、眼睛直接选择文件预览。工作区激活有左侧蓝条与数量胶囊，任务选中态使用渐变底+左蓝条；底部个人栏是独立圆角卡片。项目/任务默认全部展开，任务单行显示标题与相对时间。工作区行拆成 `workspace-head` 与独立的 `workspace-actions`，避免按钮嵌套；悬停/聚焦/激活时显示“新建任务 / 删除工作区”。任务行外层 `task-row-wrap` 提供独立删除按钮。删除任务/工作区进入 portal `confirm-layer`，说明影响任务数与不可撤销；删除当前任务回到欢迎页，最后一个工作区禁止删除。底部个人栏提供设置与站点入口；折叠展开带 160ms 动效，触屏设备始终显示操作按钮。导入文件夹只登记根目录名/文件数/大小，同时把 File 句柄交给预览窗；只有打开预览时才在浏览器内存读取内容，不上传、不持久化。

### 4.8 存储位置与本地文件夹

- 默认仍写 `localStorage`；设置 → 数据与备份 → 存储位置可选择本地文件夹（File System Access API，Chromium 安全上下文）。
- 目录句柄保存在 IndexedDB；选择后立即写入 `workspace.json`，并写 `storage.json` 记录 schema/saved_at；刷新时若权限仍为 `granted`，自动读取并恢复该文件。
- 双写：文件夹是主副本，localStorage 保留启动缓存与权限失败回退；断开文件夹只清除句柄，不删除磁盘文件。不支持该 API 的浏览器可用导出/导入 JSON 兜底。
- 边界：只写两个文件，不扫描目录、不持有绝对路径、不写 API 密钥；存储位置是浏览器本地能力，不经过 runtime。
- 实测：1440 存储位置卡显示浏览器本地 ACTIVE / 本地文件夹 OPTIONAL；导入改名后的 workspace JSON 后设置关闭、首任务更新、toast 为“已从 JSON 恢复工作区”；390 布局为单列，无横向溢出。

### 4.9 自进化证据故事与右侧 EVOLUTION

- 后端 `ledger_story(ledger)` 把真实 RSI ledger 归一为只读 `RSIStory`：episode、dry-run、public/hidden/near-OOD/regression、人签、lease/TTL/scope、消费 actuals、sealed confirmation，以及逐指标预测校准。CLI `rsi story` 可生成 `apps/web/public/rsi-story.json`；runtime `/api/rsi/story` 读实时账本。
- 右侧 EVOLUTION 顶部显示 `RSI STORY`：`LIVE LEDGER` 或 `SEALED SNAPSHOT` 来源、3 episodes / 1 approved / 2 rejected / 1 lease / 1 confirmed / 0 capability claims、11 步准入时间线、四类 gate 指标、预测-实际校准、S5 阶段过程记忆、负结果和 warnings/next questions。
- ChemLab seed-budget 故事：seeds=4 与 seeds=3 被拒并保留原因；seeds=2 通过 public/hidden/near-OOD/regression，人工准入后发出 `LEASE-be5d21dc84`，消费 actuals，sealed holdout confirmed（mean Δ=+0.00566，cost Δ=-12）；仍 `claim_eligible=false`、capability claims=0。预测审计显示 cost MAE=0、方向 100%，mean R² MAE=0.009、方向 0%——把“预测不准但成本与方差可接受”的局限也保留在故事里。
- 下方 `LOCAL DEMO CANDIDATE · SIM` 仍是当前任务的本地演示候选，和真实 ChemLab harness 证据臂分开，避免把全局 RSI 账本误读成当前任务的进化结果。
- 边界：故事是审计重建，不是能力评估；自动准入、claim 签署与导出仍分开；负结果与缺失门禁不隐藏。

### 4.10 多供应商模型目录与自动参数匹配

- 模型不再固定为三个静态 Profile。`domain/modelCatalog.ts` 维护 7 个可编辑预设：GLM-5.3-Flash、GPT-5、GPT-5 mini、Claude Sonnet 5.5、Gemini 2.5 Pro、DeepSeek V3.2、Qwen3.7 Max；每个预设包含 provider、API 格式、Base URL、环境变量、context/output、input types、capabilities、reasoning 参数与来源 URL。
- 设置 → 模型设置 → 模型供应商：左侧供应商列表（内置 + 自定义），右侧 Base URL / API 格式 / API Key 环境变量 / 仅会话 API Key / 模型列表；可添加供应商、添加模型、删除自定义模型。模型卡与 Composer ModelPicker 读取 `allModelProfiles()`，自定义模型立即出现在选择器。
- 添加模型时输入模型 ID 会 `matchModelPreset()`：例如 `glm-5.3-flash` 自动填 1,048,576 context、131,072 output、effort low/high/max、text/image/video/pdf、结构化输出/系统消息/函数调用，并显示规格来源；所有字段仍可手改。
- 欢迎页与 Composer 的模型弹层内嵌“思考强度”原生 range 滑块：档位来自 `ModelProfile.stops`，effort 显示中文最低/低/中/高/最高，budget 显示 1k/2k/4k；选择模型后弹层保持打开并重建滑块。欢迎页草稿把 thinkingStop 带入新会话，Composer 拖动时 silent save 到当前任务模型；`unsupported` 或 budget 超出最大回复长度时禁用并说明原因。
- 保存时本地模型注册表写 `researchAgent.models.v1`（不含 API Key）；连接 runtime 时尝试 POST `/api/models/providers` 与 `/api/models/profiles`，失败则保留本地并提示。API Key 只进 React 会话状态或 runtime session 内存，不写 localStorage / 工作区导出。
- 边界：预设参数来自公开规格但可能随供应商/端点变化；Responses API 仅登记，runtime 网关仍走 Chat Completions；openai-compatible 的 budget 推理需要供应商特定 extra_body，未配置时仅本地保存。

### 4.11 多智能体编排与文献过程记忆

- 后端新增 `research_agent/orchestrator.py` 与 `research_agent/literature_memory.py`：S1 按 `core+survey` / `method+evaluation` / `limitation+recent` 三组 fan-out，每组只拿到自己的 `facet_subset`；`ThreadPoolExecutor` 并行后按 `source_id`/`span_id` fan-in，IdeaAgent 在合并 span 上只跑一次，随后停在 G1 前。S4/S5/写作/闭包只在计划中可见，不自动执行。
- `literature_memory` 按 `topic hash × mode × facet` 记录 attempts、covered_runs、queries、sources、spans、gap 与 saturation；`advise()` 只调整下一轮面向顺序和预算。记忆不保存摘要或 span 文本，fixture 模式与 real 模式隔离，避免合成数据污染真实检索。
- 记忆派生的候选分两类：facet 级重复缺口 → `literature.query_planner` skill candidate；预算/全文持续受限 → `orchestrator.facet_budget` process candidate。两者都带 `status=pending_human`、`auto_admitted=false`、`dry-run/public/hidden/regression` 要求与不可变面 `Claim/EA/gate/rubric/export/signature`。
- 新增 `research_agent/custom_agents.py`：用户可手动注册 advisory 子智能体；只能选择 coverage/citation/hypothesis/protocol/evidence/figure/closure 白名单 checks，`stages/tools/outputs` 由 checks 派生，`writes=[]`。orchestrator 在 S1–S3 执行前三类确定性检查，其余返回 `deferred`；不接收任意 prompt、不执行代码、不调用外部工具。
- 新增 `research_agent/evolution_policy.py`：master switch + `literature.memory_order` / `literature.query_planner` / `orchestrator.facet_budget` 三个安全 scope；Claim/EA/gate/rubric/held-out/closure/signature/export 为 locked。关闭 master 时 orchestrator 使用均衡 facet groups 并抑制新候选，`rsi propose`/`propose-model`/`research-cycle` 拒绝新增；已有 lease/confirmation 不追溯撤销。

## 5. 适配器与 runtime 接入

```ts
interface WorkspaceAdapter {
  kind: "static" | "runtime";
  label: string;
  load(): PersistedWorkspace | null;
  save(snapshot: PersistedWorkspace): void;
  clear(): void;
}
```

当前只有 `staticAdapter`。它做版本校验（`version===1`）、基础结构校验、将 auto 的 `running/paused` 在加载时归零，防止刷新后无主 timer 继续跑。所有状态写盘前经过 `persistedSnapshot`，**UI 浮层状态不进入持久化**。

接到 runtime 时建议新增 `runtimeAdapter`：

- `load()` → `GET /api/workspace`，返回可验证的 snapshot；
- `save()` 不再整包覆盖，而是把动作发到具体 endpoint（如 `POST /api/runs/{id}/guidance`）；
- SSE 事件驱动 stage/trace 更新，前端只显示服务端 state；
- claim、sign、approve 等人工门仍由 CLI/后端 API 承担，浏览器不提供真实签名端点（与 `AGENTS.md` 的 `runtime/` 边界一致）。

此外，前端只在 `/api/` 同源代理后调用 runtime；密钥只从服务端 env/session 读取，永不进入构建产物。

- 离线新增子智能体或关闭自进化只写 localStorage（LOCAL DRAFT）；必须在 runtime 在线时保存到 `/api/agents/custom` 与 `/api/evolution/policy`，才会进入 CLI/编排读取的文件。关闭 master 不撤销历史 lease/confirmation，显式 `rsi fixture/real-trial/s5-trial` 仍作为人工实验命令存在。
- 未实现多用户、鉴权、数据库、多标签同步；Zustand 持久化是单浏览器、单写入者。
- 未做前端签名/审批端点；任何“签核”都是显式模拟按钮，真实 claim 必须由 CLI 或受控后端完成。
- 未做完整 i18n、无障碍审计或虚拟列表；任务量很大时需要再评估。
