## 0. 给导师的一页结论

| 问题 | 结论 |
| --- | --- |
| 做什么 | 一个**覆盖科研全流程的智能体工作台**：文献调研 → Idea 发散与收敛 → 实验设计 → 执行/分析 → 图表 → 长文写作 → 核验与评审；产出的是**每个事实性陈述都绑定证据、每次 AI 参与都可追溯**的草稿 |
| 为什么现在 | 科研 agent 的单项能力已经成熟（检索、假设锦标赛、代码执行、长文生成、自动评审都有强基线）；Co-Scientist 证明了"假设—实验—手稿"闭环，ScientistTwo 又把它推进到"局限驱动—先子集后全量—消融规划—返修补实验"；OpenRSI-Index 与 PaperBenchX 则证明"独立 Judge + 干净重跑 + 私有 rubric"可以把执行可信度变成可测属性。但"能写"与"写得可信、可复现、可审计"之间仍是断层。01 的判断是：写作与生成已拥挤，**验证、失效追踪与记忆协调**最缺 |
| 首发场景 | **中文核刊（自科）论文 + 项目申报书**：中文长文结构复杂、证据要求高，现有工具在证据链上最弱；但能力层不绑定场景，可迁移到学位论文、研究报告、英文稿件 |
| 差异化 | 不是“写作助手 + 聊天框”，而是**全流程编排 × 句子级证据槽 × 跨版本失效传播 × 复现级判定 × 可审计导出**的闭环；单点能力（中文基金、数字审计、盲审、失效边、Work/Judge、三阶段复现评分）已有参照，差异在跨对象统一契约与 **RWJT 复现—写作联合判定**（§4.2） |
| 需要多少人 | **推荐 9 名学生 + 1 名兼职顾问**（P0 215 人周，约占 8 个月名义产能 220 人周的 98%；全量 229 人周需 10+1；8+1 的 196 人周装不下，见 §4.2.6）；最小可行 5+1（压缩版，不做完整复现层）；上限 10+1（详见 §10） |
| 8 个月交付 | 可演示系统 + 中文科研全流程评测基准（含 4 个复现/RWJT 任务）+ 2 篇可投稿成果（1 篇系统/评测，1 篇 HCI 或科研管理） |
| 最大风险 | 生成质量与评测效度。对策：把"好"拆成可测指标；先做证据接地与核验，再放开生成自由度；所有指标配基线与人工盲评 |

**一句话定位**：把 01 文档里"过程可信"的研究判断，落成一个**能自动写出长文、又让每句话都可被追问来源、每个结果都可被重跑**的科研智能体平台——中文核刊与项目申报书是第一个验证场，不是能力边界。

## 1. 背景与判断依据

### 1.1 能力侧：科研 agent 已从"问答"走向"长程执行"

过去两年，科研智能体的能力栈已经基本齐备，且每一层都有公开强基线：

| 能力 | 代表工作 | 对本项目的含义 |
| --- | --- | --- |
| 文献检索与综合 | PaperQA2、OpenScholar、SciNet、SciArena | 检索与综述可复用，不必从零造 |
| 文献阅读与核验 | ARIS `research-lit` / `paper-claim-audit` / `citation-audit` / `citation-crosscheck` | 本地优先、检索前身份核验、引用三层审计、零上下文数字审计已成熟；缺中文版面、阅读深度路由与 claim 级账本（见 `06-`） |
| 构思与假设搜索 | AI Scientist、Co-Scientist、AutoDiscovery、IdeaScientist | 生成不缺，缺的是多样性与可证伪性约束 |
| 假设收敛 | **Co-Scientist**（反思/辩论/Elo/进化/邻近去重/元评审） | 可直接借鉴"锦标赛"机制，但需加覆盖度约束防趋同 |
| 实验/分析执行 | MLGym、MLE-bench、DS-Agent、ScienceAgentBench | 代码沙箱与任务环境有成熟接口 |
| 长程编排 | AI Scientist v1/v2、Kosmos、AutoResearchClaw、AutoSci | 线性流水线、树搜索、世界模型、跨 run 记忆均已出现 |
| 闭环科研 | **Co-Scientist 端到端扩展**（假设→实验→手稿 + 数值核验） | 证明闭环可行；中文长文、证据账本、失效追踪仍是空位 |
| 端到端返修 | **ScientistTwo**（arXiv:2609.19644） | 局限抽取、先子集后全量、消融规划、评审→补实验可借鉴；自动评审分不作质量证明 |
| 评审与复现 | AgentReview、DeepReview、PaperBench、REPRO-Bench、MLR-Bench | 终态与过程评测已有基线，但缺"写作质量"的细粒度评测 |
| 复现级执行验证 | **OpenRSI-Index / RSI-Harness**（持久 Work + 一次性干净 Judge + 快照 + 私有测试 + oracle）；**PaperBenchX**（独立重跑 + 三阶段 rubric；项目口径） | 证明"执行可信"可以被工程化判定；但都不写中文长文，也不把运行证据接到稿件句子（见 `07-`） |
| 自进化与记忆 | ScienceClaw、SkillFoundry、Evidence-Informed LLM Beliefs | "经验→技能"有实现，缺适用域判定与负迁移控制 |

结论：**再做一个端到端系统不再稀缺；稀缺的是让端到端系统产出的内容可信、可查、可修。** Co-Scientist 解决了"假设怎么收敛、闭环怎么跑"，ScientistTwo 解决了"如何从局限走到返修"，但都没有解决"中文长文怎么写得可审计、证据怎么跨版本失效、阅读过程怎么可复现"。

### 1.2 产品侧：写作工具停在"辅助"，科研 agent 停在"英文/代码域"

- 中文写作工具（知网研学、沁言学术、秘塔写作猫、MedPeer、玉京等）主要卖"检索—生成—润色—降重"，生成粒度多为段落或模板填空，**缺少 claim 级证据绑定与版本失效追踪**。
- 英文科研 agent（AI Scientist、AutoResearchClaw、AutoSci 等）证明了全流程可行，但**不处理中文长文的体裁、引用规范与版面结构**，也普遍没有"改一个实验，哪些结论失效"的机制。
- 两条路线之间有一个明确空位：**面向中文长文、以证据为中心、生成与核验一体**的工作台。

### 1.3 中文场景的四个结构性空白

| 空白 | 现状 | 为什么难 | 本项目的解法 |
| --- | --- | --- | --- |
| 中文长文结构 | 期刊论文、基金本子、学位论文的章节功能差异大 | 通用模型只会"像论文"，不懂论证义务 | 体裁 schema + 论证链检查 |
| Claim 级证据 | 现有工具最多做到题录或段落高亮 | 中文 PDF 双栏、公式、图表、脚注解析难 | 版面解析 + 证据图谱 + 人工确认 |
| 结论失效追踪 | 几乎无人做 | 需要数据/代码/文本的版本联动 | provenance + 变更传播 |
| 写作质量评测 | 只有通用作文或英文论文评测 | 中文科研写作缺标注集与评分标准 | 自建 benchmark + 专家盲评 |

### 1.4 合规与伦理：作为设计约束，而不是叙事中心

中文学术出版与基金申报的共识正在形成：**作者对 AI 辅助内容负责，使用情况应可说明、可核查**。这带来三条产品约束，写进架构即可，不需要作为卖点放大：

1. 生成内容默认是**草稿**，关键科学判断（研究问题、方法选择、结论、署名）由人确认。
2. 每个生成片段保留**模型、提示词、证据、人工修改**记录，可导出使用说明。
3. 不提供"规避 AI 检测""代写代投""伪造数据/引用"类能力。

> 具体规范条目与来源见 `03-` §2.2；产品不绑定任何单一机构的具体条款，规则以可配置模板存在。

## 2. 产品定义

### 2.1 一句话

> **Research Agent = 研究过程的操作系统 + 长文写作的编译器**：输入研究问题、数据与文献，输出结构完整、证据可查、可继续修改的长文草稿。

### 2.2 自动化等级

| 等级 | 系统做什么 | 人做什么 | 本期 |
| --- | --- | --- | --- |
| A0 检索问答 | 找文献、答问题 | 全部研究与写作 | 已有工具覆盖 |
| A1 片段辅助 | 提纲、段落建议、润色 | 结构、论证、成文 | 现有写作工具 |
| A2 分节草稿 | 按节生成带引用的草稿 | 设计研究、审阅每节 | 可做 |
| A3 全流程草稿 + 自检 | 文献→Idea 收敛→实验设计→执行→图表→全稿→核验→评审模拟 | 定问题、选方向、确认设计、终审、署名 | **本期目标（干实验）** |
| A4 无人值守 | 自主选题、执行、湿实验、投稿 | 事后审核 | 不在本期 |

A3 的含义是"**高自动化，但不是无人化**"：机器承担 80% 以上的检索、收敛、设计草案、起草、绘图、核对与修订工作量；人保留科学判断、实验安全与最终责任。

> 复现级验证层（RWVH，`07-`）不提高自动化等级：它只把“确证运行 → 结果 claim → 稿件槽”的判定独立出来；人仍然批准确证协议与终稿。

### 2.3 用户与场景

| 用户 | 典型任务 | 当前痛点 | 本期价值 |
| --- | --- | --- | --- |
| 研究生 / 博士生 | 核刊投稿、返修、学位论文 | 初稿耗时、引用易错、改实验后全文不同步 | 2 万字初稿从周级降到小时级，且改动可追踪 |
| 青年 PI / 讲师 | 基金申报、论文产出 | 本子结构复杂、立项依据难写、时间碎片化 | 按体裁生成可改的本子，证据缺口一眼可见 |
| 课题组 / 科研秘书 | 多项目、多稿件管理 | 版本混乱、合规检查靠人工 | 统一证据库、模板与审计报告 |
| 期刊 / 机构（后续） | 形式审查、一致性检查 | 逐篇人工抽查 | 结构化核验报告 |

### 2.4 核心工作流

```
研究问题 / 数据 / 文献（G0 人确认）
        ↓
① 文献调研（Q0 自动 + 抽样）：文献地图 + claim 卡 + 争议矩阵 + gap 卡
        ↓
② Idea 发散：20–50 条候选，每条带机制、证据、可证伪条件
        ↓
③ Idea 收敛：反思 → 辩论 → Elo → 邻近去重 → 进化 → 查新 → 组合覆盖（G1 人确认短名单）
        ↓
④ 实验设计：变量/对照/样本量/指标/消融矩阵/停止规则/可证伪条件（G2 人确认）
        ↓
⑤ 执行与分析：E 探索（试跑/调参）→ 检查 → C 确证（冻结协议 + Work/Judge 干净重跑）；干实验沙箱；湿实验只生成协议、由人执行（P2）
        ↓
⑥ 图表：图 brief → 数据映射 → 代码 → 渲染 → QA → caption
        ↓
⑦ 论证骨架与体裁大纲：章节 × 论证义务 × 证据需求（G3 人确认）
        ↓
⑧ 证据卡 → 逐节生成（引用槽位 + 数字槽位 + 图表绑定 + 结果/运行槽）
        ↓
⑨ 多角色批判 → 定向修订
        ↓
⑩ 核验：引用 / 数字 / 图表 / 跨节一致 / 论证链 / 复现证据与槽位（Q1 自动）
        ↓
⑪ 评审模拟与返修准备（P1）
        ↓
⑫ 人工终审（G4）→ 导出 Word / LaTeX / PDF + provenance（G5）
```

**五个固定人工检查点**：问题定义、Idea 短名单、实验设计、大纲、终稿。其余环节可自动，但可随时暂停介入。

### 2.5 首发场景与迁移场景

| 场景 | 为什么先做/后做 | 迁移难度 | 计划 |
| --- | --- | --- | --- |
| 中文核刊论文（自科） | 全年高频、结构稳定、证据要求明确 | — | **首发 P0** |
| 项目申报书（国自然/国社科等） | 结构强、季节性高峰、现有工具生成质量参差 | 低（换 schema 与论证规则） | **首发 P0** |
| 学位论文 | 篇幅长、章节多、与学生强相关 | 中（增加章节管理与查重衔接） | P1 |
| 研究报告 / 白皮书 | 企业与智库需求、无固定模板 | 中（弱化学术引用，强化数据） | P1 |
| 英文期刊稿件 | 市场大但竞争强（PaperQA2/OpenScholar 等） | 中（换语言与期刊规范） | P2 |
| 多模态成果（图表、海报） | 价值高但依赖图表理解 | 高 | P2 |

> 产品边界由**能力层**定义（研究闭环 + 证据 + 写作 + 核验），场景只是不同的体裁插件。

## 3. 边界与非目标

### 3.1 明确不做

| 不做 | 理由 |
| --- | --- |
| 不可审计的"一键整篇代写" | 生成必须绑定证据与人工确认；否则无法保证质量与责任 |
| 降 AIGC 率、洗稿、规避检测 | 与"可说明、可核查"的方向相反 |
| 替代知网/万方/维普查重 | 无数据授权，也不是价值点 |
| 承诺录用、中标、分区 | 不可承诺 |
| 未授权抓取商业数据库全文 | 版权风险；改为用户上传 + 机构授权 + 开放元数据 |
| 全自动投稿 | 署名、责任、治理未解决 |

### 3.2 学术伦理边界

- 生成默认是**草稿**；研究问题、方法、结论与署名由人决定。
- 系统保留完整操作日志；用户与机构均可导出审计。
- 对明显用于代写/造假的请求拒绝执行，并记录拒绝原因。
- "好效果"以**证据支持与专家评审**衡量，不以"像人写的"或"检测率低"衡量。

### 3.3 数据边界

- 只处理用户上传、机构授权或开放获取的文献与数据。
- 默认不把未公开稿件用于训练；私有化部署可选。
- 对外部元数据源（Crossref/OpenAlex/PubMed/arXiv 等）只做字段核验，不做全文抓取。

#### 4.2.2 仍然成立的结构性差异（每条都要有验收实验）

**一句话**：现有系统分别有“判定”（OpenRSI / PaperBenchX）或“审计”（ARIS / Auto-Empirical），但没有把判定结果变成稿件句子的准入条件；有“失效提示”（AutoSci 的 `invalidates` 只到 dashboard），但没有让失效阻断导出。我们补的是**运行时、句级、可阻断**的闭合层。

| # | 差异 | 开源停在哪（本轮快照/公开材料） | 我们的增量 | 验收实验 |
| --- | --- | --- | --- | --- |
| D1 | 契约粒度：阶段/文件 → claim/句/槽 | AutoResearchClaw 已做 23 阶段 I/O 契约；ARIS/Auto-Empirical 有事后审计，但未见把每个事实句、数字、图表作为可解析槽位并在导出时硬阻断 | 六类槽（E/R/N/F/X/C）+ 未解析即阻断 + `manuscript_claim` 覆盖率检查 | 导出时 100% 事实句有 `manuscript_claim` 且槽位可解析；删除任一被引表格 → 阻断并列出受影响句 |

#### 4.2.3 对外表述纪律

| 机制 | 持久 Work + 一次性干净 Judge + 文件系统快照 + 私有测试 + oracle + best-of-N；16 个任务，最高 256×H100 | 93 任务 / 12 方向 / 10 原生环境 / 3,168 rubric；独立无网重跑；Modeling/Execution/Validation 三阶段评分 | 我们借生命周期、隔离与评分结构，不借任务负载与规模 |
| 证据 | `final_result.json`、`report.json`、`reward.json`、`test_output.txt`、轨迹 | 只认重跑产物；日志/原始数据/派生指标只读固定 | 证据必须是“重跑产生”，不是 agent 自报 |
| 失败处理 | `verifier_error / verifier_timeout / infrastructure_error / submission_error` 与 `no_valid_submission` 分开 | 成功 / 部分 / 无效校准；阶段分定位短板 | 基础设施失败不得记 0 分，也不得静默重试 |
| 写作 | 无 | 无（rubric 判断复现是否成立） | **空位：复现结果如何进入中文长文** |
| 中文 | 无 | 无 | 中文核刊/申报书体裁、GB/T 7714、页—段—句锚点 |
| 失效 | 无 | 无 | run → result claim → 稿件句的跨版本传播 |

**它们证明了三件事**：长程任务可以用“持久 Work + 一次性 Judge”评测，而不共享可写状态；评测可信度来自接口与证据固定（唯一产物、固定 source、receipt、预算上限、隐藏轨迹）；“最佳提交”必须从有效提交中选，无效/超时/基础设施失败不能当 0 分或成功。PaperBenchX 的项目口径还给出一个关键信号：验证阶段（42.80%）显著弱于建模（62.70%）与执行（61.84%），说明“把结果验证到可写进论文”是最值得补的环节。

**它们没有解决的三件事**：不判断论文陈述是否被运行证据支持；不做中文长文与中文版面；规模与算力（8×H100 / 13 小时 Judge、93 任务 / 10 环境）不适合 8 个月团队照搬。

**采纳 / 改造 / 拒绝。**

| 参照机制 | 决定 | 本项目的改造 | 理由 |
| --- | --- | --- | --- |
| Work / Judge 分离与快照 | **采纳** | 引入 S5c 确证车道；Judge 只读快照，不读 Work 可写状态 | 没有独立判定，“过程可信”不可测 |
| 干净重跑、只认重跑产物 | **采纳** | `EA` 必须 `source=rerun`；候选生成物一律不计分 | 直接挡住“伪造数字/旧结果” |
| 私有测试 / rubric 与反馈边界 | **采纳** | 反馈只给失败类别与可改进方向，不泄露阈值与参考解 | 防止刷分与过拟合评测 |
| oracle / nop / best-of-N | **采纳** | v1 四任务全部跑 oracle；nop 作为下界；best-of-N 限 5 次提交 | 先证明 Judge 能给分、不会给空答案分 |
| 三阶段复现评分 | **改造** | 保留 M/E/V，增加 W（写作证据）与 J（联合分）；权重见 `07-` §8 | 复现成立不等于写对 |
| 原生科学环境 | **暂缓（P1/P2）** | v1 只做 CPU / 单卡；P1 选 1 个开源求解器（PySCF/Meep/ABACUS） | 许可、镜像、算力成本高 |
| 93 任务 / 10 环境公开榜 | **拒绝照搬** | v1 只做 4 个任务，P1 扩到 6–8 个；开放/封闭划分 | 规模不是我们的贡献，证据链才是 |
| “General AI Scientist / RSI”叙事 | **拒绝** | 只写“可审计的科研写作与轻量实验闭环” | 目标、规模与证据都不支持 |
| 外部效果数字 | **拒绝借用** | PaperBenchX / OpenRSI 数字只作参照，不进我们的结果 | 未在本地复现 |

**D8：复现—写作联合任务（RWJT）。** 这是我们相对两个参照系统的净增量：agent 先复现论文中的一个表/图，再把结果写成中文核刊“结果与分析”一节；Judge 同时看 **R（建模/执行/验证）** 与 **W（claim 覆盖/数字追溯/图表追溯/引用有效/体裁合规）**，任一伪造数字/引用、未解析槽位、探索性 run 冒充确证 run，直接判 `invalid`。v1 四个任务（T2 为 P1）：T1 复现 ML 结果、T2 复现计算科学结果、T3 从冻结产物写一节、T4 复现并写作（旗舰）。

**不宣称清单**：不说“首个独立 Judge”“首个复现 benchmark”“首个中文科研 benchmark”；不说“达到 PaperBenchX 的复现率”；不把 Work/Judge 机制本身当作研究贡献。我们的贡献是**把复现判定接到中文写作证据链**，并用预注册指标证明它有效。

### 4.3 五条护城河

1. **证据图谱与失效追踪**：一旦用户的稿件、数据、代码、图表都挂在同一张图上，"改实验→定位失效结论"就成为刚需工作流，迁移成本随时间上升。
2. **中文长文的体裁与论证数据**：期刊/基金/学位论文的章节义务、评审关注点、常见缺陷，需要标注与规则沉淀；英文端到端系统默认英文论文，中文工具则少有证据链。
3. **生成—核验一体的评测体系**：不是比"谁写得像"，而是比"谁写的事实更站得住、改动后更可维护"；这套 benchmark 本身是学术产出。
4. **全流程收敛与设计资产**：Idea 锦标赛记录、实验设计卡、图表 provenance 会形成项目级资产；用得越久，越难替换。
5. **复现—写作联合判定（RWJT）**：把干净重跑、结果 claim 与中文核刊句子/数字/图槽接成一条硬门；OpenRSI 停在 reward，PaperBenchX 停在 rubric 分，本轮公开材料中未见把两者接到中文写作的实现。

## 5. 功能需求

优先级：**P0 = 首个毕设周期必须交付；P1 = 关键路径允许时进入里程碑；P2 = 后续迭代**。
能力覆盖：文献调研 → Idea 发散 → Idea 收敛 → 实验设计 → 执行/分析 → 图表 → 写作 → 核验 → 评审返修。逐阶段对照见 `05-` §3。

### 5.1 P0

#### FR-1 项目接入、文献调研与阅读审计（Q0）

- 新建研究项目，导入 PDF、数据、代码、笔记；支持 DOI/arXiv/OpenAlex 元数据回填。
- **检索**：本地优先（Zotero / 笔记 / 本地 PDF）→ 外部多源（arXiv / OpenAlex / Semantic Scholar / 中文元数据）；按 arXiv ID、DOI、规范化标题去重；单源失败降级并记账，本地库为空时显式警告。
- **身份核验**：存在性、字段、版本三层核验，并检查撤稿/更正；未核验文献可保留为线索，但不得进入证据图谱。
- **阅读深度路由**：D0 元数据 / D1 速读 / D2 方法与结果 / D3 复现 / D4 对抗性阅读；每篇记录深度、理由与预算。
- 解析中文论文的标题、作者、摘要、章节、图表标题、参考文献、脚注；允许人工校正。
- 生成文献地图：主题簇、支持/批评/扩展关系、时间线、争议矩阵、gap 候选；gap 必须带"缺席证据"与可检验推论。
- **Q0 出口审计**：来源覆盖、覆盖率回执、span 完整性、核心 claim 独立复核（≥ 20%）、争议矩阵完整性、抽样人审（核心 claim 10%）。
- **增量监测（P1）**：定期/订阅新文献进入候选池；默认只通知，显式开启且高置信才可申请入图谱；入图前必须重走核验、抽取与 Q0 增量检查，候选与证据图谱物理隔离。
- **验收**：200 篇中文核刊论文上，章节边界 F1 ≥ 0.85，参考文献抽取准确率 ≥ 0.90，图表标题召回 ≥ 0.85；100 条人工标注关系上，关系抽取 precision ≥ 0.80；100 条伪造/错字段引用上，伪造召回 ≥ 0.98、字段准确率 ≥ 0.95；30 组争议对上，争议召回 ≥ 0.85；可引用文献 100% 已核验，覆盖率回执 100%；增量自动纳入误报 0。

#### FR-2 证据图谱（Evidence Ledger）

- 以 claim、span、figure、dataset、commit、run 为节点，建立"支持/反驳/派生"边；节点带来源、置信度、时间戳、版本。
- **claim 卡**：claim 文本、可定位 span（页码 + 字符区间）、章节、claim 类型、支持类型、条件（样本/数据/指标/设置）、强度、反向证据、反证条件、阅读深度、版本。
- **争议矩阵**：同一 claim 簇下按来源记录支持/反对/混合/不清，写清条件差异；未解释的冲突标 `unresolved`，涉及核心结论时升级人工裁决。
- 支持人工确认/否认；未找到证据的 claim 必须显式标为"待证"，不得静默通过。
- **验收**：300 条人工标注 claim 上，对齐 F1 ≥ 0.80；核心 claim 的 span 覆盖率 100%；争议矩阵覆盖全部已发现反向证据；图谱可导出为 JSON，字段完整率 100%。

#### FR-3 Idea 发散与收敛

- **发散**：从 gap 卡、争议矩阵与反向证据出发，按机制/方法/场景/数据四个维度生成 20–50 条候选；每条包含主张、机制、证据、可证伪条件、所需资源，并能回溯到至少一条 gap 或反向证据。
- **收敛**：反思（正确性/新颖性/可检验性/可行性）→ 证据化辩论 → Elo 排序 → 邻近聚类去重 → 对 top-k 进化（保留 ≥ 20% 原始种子）→ **查新**（最近工作、delta、verdict）→ 组合选择（覆盖度 + 新颖性 + 可行性 + 成本）。
- **输出**：候选卡、Elo 曲线、机制簇图、查新报告、组合理由、风险清单、3–5 条人工短名单。
- **验收**：50 个研究主题上，专家 top-3 有用率 ≥ 70%；同簇换皮候选占比 ≤ 15%；每个主题至少 3 个机制簇；进化后原始种子保留率 ≥ 20%；每条候选都有可证伪条件与至少 1 条证据边；Elo 重跑一致性 ≥ 0.70；最近工作命中率 ≥ 0.85；无据 `ABANDON` 为 0；短名单查新报告字段完整率 100%。

#### FR-4 实验设计与执行（干实验）

- **设计卡**：研究问题、假设、变量、对照、**基线复现**、**消融矩阵**、样本量/功效、混杂因素、主/次指标、分析计划、停止规则、**试跑与扩量条件**、资源、风险与安全、可证伪条件。
- **自动检查**：混杂清单、样本量—检验匹配、主指标唯一性、停止规则存在性、基线复现计划、消融矩阵完整性、试跑—扩量条件、可证伪条件完整性。
- **执行**：同协议复跑基线，记录与论文报告的偏差；先子集试跑并检查，再全量运行；代码沙箱记录环境、依赖、随机种子、数据版本；产出结果卡。湿实验只生成机器可读协议，由人执行（P2）。
- **探索/确证分离**：探索性搜索（超参、候选、消融搜索）在隔离目录运行，使用不可变候选快照，不写 claim、不入证据图谱；确证性运行必须冻结 protocol 并经人批准，只有确证性结果可进入结果卡与写作。
- **判定与回环**：执行者不判定成败；独立 Evaluator 按 G2 冻结的成功判据给出 `support / refute / inconclusive`（`partial_support` 归入 `inconclusive` 并强制补实验），并判定子集结果是否值得扩量。消融因子分为 essential / contributing / marginal / harmful，后两类触发方法简化与重规划，最多 2 轮；失败原因写入负结果记忆。
- **验收**：30 个设计任务上，专家检查表通过率 ≥ 80%，消融矩阵完整率 100%；20 个可执行任务复现率 100%，基线复现记录覆盖率 100%；试跑→全量决策记录覆盖率 100%；设计→运行→结果→claim 追溯覆盖率 100%；探索性 run 污染 claim/稿件率 0；判定与人工复核一致率 ≥ 90%；消融回环记录完整率 100%。

#### FR-5 体裁感知的长文生成

- 支持两种首发体裁：**中文核刊论文**（摘要/引言/方法/结果/讨论/结论）与**项目申报书**（立项依据/研究内容/目标/方案/创新/基础/计划）。
- 流程：体裁 schema → 论证骨架 → **独立大纲评审（领域主席视角）** → 证据卡 → 逐节草稿 → 全稿组装；支持篇幅、语气、术语表约束。
- 生成时使用"引用槽位""数字槽位""图表槽位"：没有证据的槽位必须留空或标"待证"，不得编造。
- 每个事实句在 S9 生成一条 `manuscript_claim`（绑定上游文献/结果 claim 与句 span），S10 只绑定槽位、不新建 claim；Q1 检查覆盖率 100%、越级 0、孤儿 0。
- **验收**：2 万字稿件全稿草稿 ≤ 20 分钟；结构完整率 100%；大纲评审通过率 ≥ 80%；专家写作质量 ≥ 3.5/5；草稿阶段未绑定证据的事实性句子占比 ≤ 10%，导出阶段必须为 0（未绑定句只能删除或降级为非事实表述）。

#### FR-6 图表生成与图文一致性

- 图计划在 S8 与大纲一起冻结（G3）：S6a 在 S5c 后只生成候选数据图，S6b 只定稿进入图计划的图，并逐图绑定 claim/run。
- 从结果卡/claim 生成**图 brief**（这张图要证明什么、放在哪节、给谁看）；自动选择图型并生成绘图代码（固定随机种子）。
- 图表 QA：数据—图一致、坐标轴与单位、误差棒、显著性标注、可读性、误导性缩放；caption 自动生成并与正文数字核对。
- 图表进入证据图谱：`figure → dataset/run → code → claim` 双向可追。
- **验收**：100 张图上，数据—图一致率 100%，caption—正文对齐率 ≥ 90%，专家视觉质量 ≥ 3.5/5，图表溯源覆盖率 100%。

#### FR-7 引用核验与上下文支持

- 核验参考文献是否真实存在、字段是否一致、正文引用与文后条目是否对应、是否符合 GB/T 7714。
- 进一步判断**引用是否真的支持该句**（上下文支持），输出"支持/部分支持/不支持/无法判断"。
- **验收**：500 条参考文献上，真实文献判定准确率 ≥ 95%，伪造文献召回 ≥ 98%；上下文支持判定 F1 ≥ 0.80；三态输出，禁止把不确定判为确定。

#### FR-8 批判—修订闭环

- 多角色 critic：证据 critic、方法/设计 critic、结构 critic、图表 critic、语言 critic。
- 输出可定位的问题清单；支持自动定向修订与逐条接受/拒绝；保留 diff。
- **验收**：在 100 条人工注入缺陷上，修复率 ≥ 70%；修订引入的新事实错误 ≤ 5%；平均 ≤ 2 轮达到可提交状态。

#### FR-9 研究工作台、导出与 provenance

- 项目视图：文献、证据图谱、Idea 锦标赛、设计卡、结果卡、图表、大纲、草稿、问题清单、版本历史。
- 每个生成片段记录：模型与版本、提示词哈希、证据、生成时间、人工修改；可导出"AI 使用说明"。
- **产物信封**：所有阶段产物记录 `inputs / version / status / produced_by / verified_by / content_hash`；冻结后修改必须升版本；上游失效自动标记下游为 `stale`。
- 支持 Word / LaTeX / PDF 导出；模板可配置；导出前必须通过质量门。
- **验收**：10 名目标用户可在无工程师协助下完成"导入→收敛→设计→生成→修订→导出"全流程，完成率 ≥ 90%；provenance 字段完整率 100%，产物信封完整率 100%，导出文件可被模板校验器解析。

#### FR-18 复现执行底座（P0）

- **两条车道**：E 探索（试跑/调参/找方向，不进 Judge、不进 claim）与 C 确证（产生可写进稿件的结论，进 Judge，仅 `scored` verdict 可创建 `confirmed` 结果 claim）。
- **Work / Judge**：Work 持久可写；提交时暂停并快照文件系统；Judge 每轮从干净镜像启动，只读挂载快照，注入私有测试，跑完销毁；Judge 不可被 Work 修改或影响。
- **生命周期 X0–X7**：任务编译 → Work 启动 → 研究循环 → 提交/快照 → 干净重跑 → verdict → 恢复/迭代 → 收尾。
- **运行记录**：`final_result.json`（status / best_score / best_rewards / best_round / total_rounds / timed_out / runtime_seconds）、`submissions/agent-N/report.json`、`test_output.txt`、`feedback/agent-N.log`、`verifier/agent-N/reward.json`、`run-plan.json`。
- **约束**：提交上限 5 次；Agent 超时 2 小时、Judge ≤ 30 分钟（v1）；单任务成本 ≤ 50 元；最多 2 个并发任务。
- **验收**：4 个任务 oracle 全部跑通；Work 修改 `/tests` 不影响 Judge；快照外文件 0 个进入 Judge；运行与提交状态字段完整率 100%；E 车道运行进入 claim 图 0 次。

#### FR-19 任务包、私有 rubric 与静态检查（P0）

- **任务包**：`task.toml`、`instruction.md`、`environment/`、`tests/`、`solution/`；`schema_version`、资源、网络策略、超时、`clean_image`、rubric digest、canary 必须显式声明。
- **私有 rubric**：Work 不可见测试与参考解；Judge 只读挂载；反馈只给失败类别与可改进方向，不泄露阈值、rubric 条目与参考解。
- **静态检查**：字段完整性、绝对路径、超时、网络策略、测试文件引用、canary、密钥扫描、symlink、镜像 digest、pip 固定、verifier 工具预置。
- **验收**：4 个任务包 100% 通过静态检查；`/tests`、rubric、参考解在 Work 中可见性 0；反馈泄露阈值 0；任务包字段与 digest 完整率 100%。

#### FR-20 独立重跑与证据固定（P0）

- Judge 在无网/隔离环境重跑；删除候选生成的输出与临时状态；只有重跑产生的产物算证据；日志、原始数据、轨迹、收敛记录、派生指标只读固定。
- **证据产物 `EA`**：path、sha256、source（`rerun` / `literature`）、run_id、产生者、捕获时间、单位/精度；`source=rerun` 才可准入 `result_claim`。
- 重跑一致性检查：确定任务要求一致；不确定任务固定种子/数据切片、设容差，必要时重复 2 次取中位数并记录。
- **验收**：每个计分数字 100% 绑 `EA`；候选生成物被当证据 0 个；重跑不一致 100% 有 `FailureRecord`；证据包可离线复核。

#### FR-21 分阶段评分与失败归因（P0）

- **复现分**：`R = 0.30 M + 0.30 E + 0.40 V`（Modeling / Execution / Validation）；**写作分**：`W = 0.30 C + 0.25 N + 0.15 F + 0.15 Cite + 0.15 G`（claim 覆盖 / 数字追溯 / 图表追溯 / 引用有效 / 体裁合规）；**联合分**：`J = 0.55 R + 0.45 W`。
- **失败分类**：`candidate_invalid / incomplete / diverged / verifier_error / verifier_timeout / infrastructure_error / submission_error / scored`；科学失败再标 modeling / execution / validation / writing / genre。
- **报告**：R/W/J、有效/无效提交、成本、轮次、失败分布、阶段短板；基础设施失败不得记 0 分。
- **验收**：与人工复核一致率 ≥ 90%；infra 失败误记 0 分 = 0；失败分类覆盖率 100%；同一 rubric 重跑分数漂移在容差内。

#### FR-22 RWJT 联合任务与中文写作审计（P0）

- **T4 旗舰任务**：复现论文中的一个表/图，再写中文核刊“结果与分析”一节；T1 复现 ML 结果、T3 从冻结产物写一节；T2 计算科学复现为 P1。
- **写作审计**：每个数字/图/结果 claim 使用 `R/X/N/F` 槽；GB/T 7714；结构、字数、页—段—句锚点；核心 result claim 覆盖率与 claim 证据绑定。
- **硬门**：伪造数字/引用、未解析槽位、探索 run 冒充确证 run、Judge 篡改，任一触发即 `invalid` 并阻止导出。
- **失效传播**：run/claim 变 `stale` 时，相关稿件句、图、表自动标 `stale`，导出阻断。
- **验收**：计分数字追溯率 100%；核心 result claim 覆盖率 ≥ 90%；伪造数字/引用 0 个通过；结构完整率 100%；未解析槽位 0 个导出。

### 5.2 P1

#### FR-10 结论失效追踪（差异化核心）

- 当数据、代码、实验或图表更新时，沿证据图谱计算受影响的 claim、图表、统计量与摘要数字。
- 输出"需同步修改"清单与传播路径；支持一键生成修订任务。
- **验收**：50 个人工构造的变更场景上，受影响结论召回 ≥ 85%，误报 ≤ 20%。

#### FR-11 技能/模板复用与适用域判定

- 从成功项目中抽取可复用技能（写作策略、修复策略、分析脚本、图表模板），存入技能库。
- 复用前做适用性检查：领域、数据分布、体裁、依赖版本；不满足则先小样本测试或拒绝复用。
- **验收**：50 个跨任务复用案例上，复用决策准确率 ≥ 75%；相比"总是复用"，负迁移率下降 ≥ 30%。

#### FR-12 评审模拟与返修准备

- 模拟方法、领域、统计、写作、伦理五类审稿人，各自独立上下文，基于证据缺口提出问题；输出严重度与所需证据。
- **意见原子化**：每条意见编号并映射到 claim、章节或实验；回应前做证据追溯与"审稿人追问"压力测试；无法映射到证据的意见不得生成回应。
- **返修规划（Rebuttal Planner）**：把意见分为"可用现有证据回应 / 需补实验 / 无法支持应降级结论"；需补实验的进入新设计卡并回到 FR-4，不得直接改写文本。
- **失败分流**：文本层回 S12；证据层回 S9/S1；实验层回 S4；贡献层回 S2/S3 并重新过 G1；分流记录必须保留原短名单与淘汰理由。
- 生成回应草稿：每条回应必须绑定证据或补充实验；不生成虚假评审意见、不伪造引用；不承诺录用。
- **验收**：20 篇稿件上，专家认为"覆盖主要问题"的比例 ≥ 70%；意见—证据映射率 100%；失败分流记录覆盖率 100%；回应中的引用真实率 100%；"需补实验"意见中完成设计卡闭环的比例 ≥ 80%。

#### FR-13 体裁扩展

- 新增学位论文、研究报告、英文稿件中的至少一种；复用同一证据层、图表层与质量门。
- **验收**：新体裁的结构完整率 ≥ 95%，专家质量不低于首发体裁的 90%。

#### FR-23 任务构建、校准与开放/封闭集

- 扩展到 6–8 个任务，覆盖 ML 复现、计算科学复现、冻结产物写作、RWJT；开放集与封闭集分开，封闭任务不进任何 prompt/示例。
- **校准**：oracle（参考解）≥ 0.90；nop（空提交）≤ 0.10；gold/partial/invalid 三类样例；至少一个基线落在中间区间；两位独立领域专家复核，Cohen's κ ≥ 0.60。
- **负结果与退役**：报告任务难度、区分度、失败分布与不可复现任务；任务退役需记录原因与替代任务。
- **验收**：6–8 个任务包通过发布检查；oracle ≥ 0.90、nop ≤ 0.10；κ ≥ 0.60；任务泄漏 0；至少 1 个基线在中间；负结果报告完整。

**关键设计决策**

1. **证据图谱是一等公民**：正文、图表、数字、结论都是图的视图；没有证据的生成只能进入"待证"状态。
2. **生成与核验分离**：Writer 不允许自证；Verifier 独立检索与判定，降低自我确证。
3. **规则优先**：格式、字段、对应关系、数字一致性用规则；语义支持、论证质量才用 LLM。
4. **人类检查点固定在五处**：问题定义、Idea 短名单、实验设计、大纲、终稿；导出前再做一次完整性检查。其余环节可自动，但可随时暂停介入。
5. **失败可路由**：执行失败、证据不足、设计缺陷、论证断裂分别进入不同修复路径，而不是笼统重试（对应 00 D2）。
6. **全流程共用一张图**：Idea 锦标赛、设计卡、图表流水线与写作不是四个独立工具，而是同一编排层调度、同一证据图谱承载。
7. **复现判定独立成层**：Work 执行、Judge 判定、人做科学决策；Judge 只读快照、只认重跑产物，不接受 Writer 上下文（见 `07-`）。

## 8. "好效果"如何定义与评测

### 8.1 十个质量维度

| 维度 | 含义 | 主要指标 |
| --- | --- | --- |
| 文献阅读 | 找得全、引得真、读得够、冲突看得见 | 来源覆盖、伪造召回、claim 抽取 F1、span 准确率、争议召回、Q0 通过率 |
| Idea 质量 | 候选新颖、可检验、覆盖多个机制 | 专家 top-3 有用率、机制簇数、去重率、可证伪条件完整率、最近工作命中率 |
| 设计有效 | 变量、对照、样本量、指标、消融、停止规则成立 | 设计卡完整率、消融矩阵完整率、混杂检查通过率、专家评分 |
| 复现可信 | 结果确实由重跑产生，失败可归因 | oracle 通过率、nop 得分、泄漏 0、`EA` 绑定率、infra 误记 0、失败分类覆盖率 |
| 事实性 | 每个事实性陈述有可靠证据 | claim 支持率、无证据 claim 占比 |
| 引用可信 | 文献真实、字段正确、引用不歪曲 | 伪造召回、字段准确率、上下文支持 F1 |
| 图表可信 | 图由数据与代码生成，图文一致 | 数据—图一致率、caption 对齐率、溯源覆盖率 |
| 结构完整 | 体裁要求的章节与论证义务齐全 | 结构完整率、论证链断裂数 |
| 一致性 | 数字、术语、图表、结论跨节一致 | 数字冲突率、术语不一致率 |
| 写作与可维护 | 逻辑、表达、学术风格；改动后可定位 | 专家盲评、修订轮次、失效召回 |

### 8.2 评测设计

- **黄金集**：30 篇中文核刊论文（开放获取/授权）+ 15 份脱敏申报书；保留原始数据/代码/结果，构造"给定材料写论文/本子"的任务。
- **文献阅读集**：100 篇中文版面 + 50 篇英文方法论文 + 20 篇撤稿/更正记录 + 30 组争议对 + 100 条伪造/错字段引用；评检索覆盖、身份核验、claim 抽取、span 定位、争议识别与 Q0。
- **Idea 评测集**：20 个研究问题，每个配 5–10 篇核心文献与已知后续工作；评候选的新颖性、可检验性、可行性、覆盖度与查新命中率。
- **设计评测集**：30 个"给定假设与数据，写实验设计"的任务；用检查表 + 专家评分，含消融矩阵与试跑—扩量条件。
- **图表评测集**：100 张图，覆盖常见图型与易错点（双轴、误差棒、显著性、样本量）。
- **复现 / RWJT 评测集**：v1 四个任务（T1 ML 复现、T2 计算科学复现（P1）、T3 冻结产物写作、T4 复现+写作旗舰）；每任务配 oracle、nop、gold/partial/invalid 样例与私有 rubric；P1 扩到 6–8 个并划分开放/封闭集。评 R/W/J、计分数字追溯率、核心 claim 覆盖率、失败分类与 infra 误记。外部系统（OpenRSI / PaperBenchX）只作机制对照，不作效果对标。
- **自动指标**：引用核验、claim 支持、数字/图表一致性、结构完整、生成耗时与成本、oracle/nop、`EA` 绑定率、Judge 泄漏。
- **专家盲评**：5–7 位有发表/评审经验的教师，对"本项目 vs 基线"的稿件做双盲比较（事实、结构、表达、可用性）；借鉴 Co-Scientist 的双盲设计，但规模缩小；同时报告自动评审分与人工分的相关性（ICC/κ）。复现 rubric 另由 2 位领域专家独立复核，κ ≥ 0.60。
- **用户研究**：15–20 名研究生/青年教师完成真实任务，测完成时间、修订轮次、信任度与接受度。
- **基线**：通用大模型直接写、通用模型 + 检索、PaperQA2/OpenScholar 式流程、ARIS 文献阅读流程（强工程基线）、AutoResearchClaw 类流水线（能力允许时）、OpenRSI 式 Work/Judge（只借机制，不比效果）、Co-Scientist / ScientistTwo 公开能力（只做定性对照）、现有中文写作工具（仅做可用性对照）。
- **消融**：去掉阅读深度路由、去掉 Q0 独立复核、去掉争议矩阵、去掉 Idea 收敛、去掉查新、去掉设计卡/消融矩阵、去掉同协议基线复现、去掉评审失败分流、去掉探索/确证隔离、去掉三权分立、去掉产物信封、去掉证据图谱、去掉图表 QA、去掉 critic、去掉核验、去掉失效追踪、去掉独立 Judge/干净重跑、去掉私有 rubric、去掉 oracle/nop 校准、去掉 RWJT 写作审计，分别测质量与成本变化。

### 8.3 可发表的成果点

1. **Paper A（默认主篇，系统/评测，W1+W3，MPU 79–85 人周）**：定义 RWJT 任务与 ECM 契约，交付 Work/Judge harness、中文核刊 benchmark、R/W/J 与 C1–C4。**这是主贡献，不与其他方向并列。**
2. **Paper B（方法，W2，25 人周）**：跨版本证据失效传播，回答“哪些 claim/句/图失去支持、该重跑还是重写”，对应 01 方向 B / 00 D1。它的贡献不依赖生成质量，适合作为第二篇。
3. **Paper C（可选资源篇）**：只有在任务规模、双专家 κ、开放/封闭集划分达标时才独立成篇；否则并入 Paper A 的附录。
4. **HCI/科研管理（可选）**：高自动化写作工具下研究者的信任、责任与工作流变化。
5. **不单独成篇**：Idea 收敛、技能复用、失败归因只作为 Paper A 的模块或消融，不拆成并列论文。

> 论文轨道与产品轨道的取舍、Kill criteria 与双轨决策规则见 [`08-反思与差异化工作方案.md`](08-反思与差异化工作方案.md) §5–§6。
>
> **创新点评审（2026-10-19）**：以上层级已由 [`13-创新点评审与主张收敛`](13-创新点评审与主张收敛-需求对齐、开源对照与验证顺序.md) 复核。RWJT/ECM 是主贡献；claim 契约与硬门是支撑；自进化四问/租约/过程协议是待验证扩展（E7/E8 未跑），不与 Paper A 并列；9 阶段、可调工作流与 demo 是工程能力。215 人周是产品轨道预算，不用于证明论文创新。见 `13-` §0/§6/§9。

### 10.4 可拆分的毕设题目（招募用）

1. 中文科研 PDF 的结构化解析与证据单元抽取

7. 图表生成、图文一致性与结论失效追踪
8. 中文科研全流程 benchmark 与专家盲评
9. 复现级 Work/Judge 与 RWJT 联合判定（任务包、干净重跑、rubric 校准）

> 每个题目对应一个可独立答辩的交付物，同时拼成同一系统；避免"一个大系统、九个空模块"。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 生成质量不稳定 | 演示好看、实际不可用 | 证据先行 + 质量门 + 人工检查点；先窄体裁再扩展 |
| 评测主观 | "好"无法证明 | 自动指标 + 专家盲评 + 用户研究三线；预注册评分标准 |
| 中文 PDF 解析难 | 上游拖垮全链路 | 200 篇评测集；允许人工校正；版面模型与规则结合 |
| 范围过大 | 8 个月做不完 | P0 锁定"干实验全流程 + 中文核刊/申报书"；湿实验、技能复用、机构版放 P2；Idea 收敛先用简化版 |
| Idea 收敛趋同 | 选出的都是主流想法 | Elo + 机制簇覆盖 + 与主流相似度惩罚；保留高风险配额 |
| 实验设计不严谨 | 生成"看起来像实验"的方案 | 设计卡 + 检查表 + 专家复核；无设计卡不得进入执行 |
| 复现任务选不到"30 分钟可复现"的论文 | v1 任务不足、里程碑拖延 | M1 前 3 选 1；不满足则缩为 T1/T3/T4 三任务；T2 后置 |
| 重跑不确定 | 同一提交分数漂移 | 固定种子/数据切片；设容差；不确定任务重复 2 次取中位数并记录 |
| 专家时间不足 | rubric 校准与 κ 拖延 | 顾问 0.2 FTE + 2 位外部专家按小时计费；先校准 20% 样本 |
| 私有数据合规 | 产品模式不能外送 | 私有部署；Judge 内网；数据只读挂载；证据包不出项目库 |
| 过度宣称 | 被质疑"又一个 benchmark" | 只报本地 4 任务结果；不称"首个"；外部数字不进我们的结果 |
| 图表误导 | 图好看但数据错 | 图必须由数据+代码生成；规则 QA + VLM QA + 图文数字核对 |
| 外部依赖 | API/数据源不稳定 | 多源降级；关键模型可替换；缓存与本地化 |
| 版权与隐私 | 无法使用全文 | 用户上传 + 机构授权 + 开放获取；私有化部署 |
| 伦理争议 | 被误解为代写工具 | 产品边界、日志、拒绝策略；对外表述强调"可审计草稿" |
| 团队流失 | 关键路径断 | 双人 review；文档与数据入库；模块接口先行 |

## 附录 A：术语

| 术语 | 含义 |
| --- | --- |
| Claim | 文中可被证据支持或反驳的事实性陈述 |
| Claim 卡 | claim + 可定位 span + 条件 + 强度 + 反向证据 + 版本 |
| 阅读深度 D0–D4 | 元数据 / 速读 / 方法与结果 / 复现 / 对抗性阅读五档 |
| Q0 | S1 出口的文献审计：覆盖回执、身份核验、span、争议矩阵、独立复核 |
| 争议矩阵 | claim × source 的条件化冲突表，记录支持/反对与条件差异 |
| 查新 verdict | `PROCEED / PROCEED_WITH_CAUTION / ABANDON`；`ABANDON` 必须点名论文 |
| 消融矩阵 | 每个性能增益对应的消融组、负对照与预期方向 |
| Evidence Graph | 以 claim、span、figure、dataset、commit、run 为节点，以"支持/反驳/派生"为边的有向图 |
| Provenance | 结论从数据到陈述的完整来源链 |
| 引用槽位 / 数字槽位 | 生成时预留的、必须由证据填充的位置；无证据则标"待证" |
| R / X 槽 | 结果 claim 槽与运行槽；分别绑定 `result_claim` 与 `RUN`，只有确证运行可填 |
| Work / Judge | 持久执行容器 / 一次性干净判定容器；Judge 只读 Work 快照，不可被 Work 修改 |
| RWVH | 复现级验证 Harness（Research Agent Verification Harness），本项目验证层 |
| TaskSpec | 复现任务包：`task.toml` + `instruction.md` + `environment/` + `tests/` + `solution/` |
| EA | EvidenceArtifact：重跑产生的证据产物，含 path、sha256、source、run_id |
| RWJT | 复现—写作联合任务；同时评 R（复现）与 W（写作证据） |
| oracle / nop | 参考解上界 / 空提交下界，用于验证 Judge 能给分且不白给分 |
| rubric | 私有评分细则；含 M/E/V 三阶段与 W 五维；Work 不可见 |
| verdict | 一次提交的判定：`scored / candidate_invalid / verifier_error / ...` |
| κ | 两位专家评分一致性（Cohen's kappa） |
| 体裁 schema | 某类长文（核刊/申报书/学位论文）的章节、论证义务与格式约束 |
| Idea 锦标赛 | 多候选经反思、辩论、Elo 排序、进化与去重后收敛的机制 |
| 设计卡 | 实验设计的结构化产物：变量、对照、样本量、指标、停止规则、可证伪条件 |
| 图 brief | 一张图要证明什么、用哪些数据、放在哪节、给谁看的说明 |
| 质量门 | 导出前必须通过的核验与评分检查点 |
| 三态判定 | 通过 / 存疑 / 不通过，禁止二值化的"幻觉式确定" |
| 适用域 | 一项技能或模板可安全复用的任务/数据/环境范围 |
