# 27 · 创新逻辑对账：从全部设计文档到底层实现

> 本文把 `00-` 到 `26-` 全部设计/反思/调研文档的创新主张收敛成**一张可对账的总账**：每条主张 → 机制 → 仓库落地点 → 证据 → 缺口。机器可读镜像是 `research_agent/web/data/innovations.json`，由 `scripts/verify-innovation-claims.py` 对仓库事实逐条校验（当前 22/22 通过）；工作台「创新逻辑」视图只读展示。这本身遵守我们自己的纪律：**主张必须绑证据**——包括对我们自己创新主张的证据。

## 0. 定位与判语

- 13- 的收敛结论仍然有效：**主贡献 = N1 任务定义（RWJT/证据闭合）+ N4 测量**；支撑 = N2 契约 + N3 机制；**自进化（Lease-Gated RSI）是待验证的扩展贡献，不抢标题**。
- 20- 的一句话定位：SciToolAgent 解决 tool use，我们解决 **evidence closure**。
- 19- 的判语仍然成立：我们缺的不是第五问，而是**让四问有东西可问的运行底座**。本文 §3 按此口径汇总缺口。
- 26- 的口径：对外只能说「**受控改进准入与过程协议继承**」，不宣称 RSI/自进化能力增益。

## 1. 三大支柱如何互相咬合（底层逻辑链）

```
证据闭合（骨架，流程簇 02/06/07/08/13）
  span-only S1 → 结果槽 pending → scored verdict + rerun EA → 人签 Claim → 导出硬门
        ▲ 谁来改进这条链？                         ▲ 改坏了怎么办？
Lease-Gated RSI（动力，RSI 簇 10/11/19/23/25/26）  失效传播（14/15，RWMT，设计阶段）
  observe → propose → dry-run → public 预筛        ChangeSet → 影响闭包 →
  → hidden/near-OOD/regression → 人签准入           rerun/rewrite/recheck →
  → Lease(scope+TTL) → 研究运行消费                重过导出硬门 → 人签闭包报告
  → sealed 复核（不回流）→ 负结果归档
        ▲ 在什么底座上强制？
证据运行时（底座，工程簇 09/16/17/21/22/24）
  Spec-Driven 模块（SPEC.md 唯一契约源，最小 diff）
  artifact/gate 中介（不共享对话上下文；一对象一写者）
  真实性三态（fixture_mode / simulation / claim_eligible）+ fail-closed 门
```

一句话：**证据闭合定义"什么能被留下"，Lease-Gated 准入定义"什么能被改进"，证据运行时保证"这两条没人能绕过"**。

**分层说明（一个容易被误读的点）**：SPEC 声明的"同一 benchmark 的 target+patch 不得重复 propose"目前在 **trial 层**（`rsi_fixture/real_eval/s5_eval` 的 skipped_deduplicated）强制，`RSIController.propose` 保持原语不查重——这是刻意的分层（控制面提供记账原语，纪律由 trial 编排强制）。若要在控制面强制，属于契约变化，需按最小修改流程单独提出并重写受影响测试。

## 3. 文档自认缺口汇总（按优先级）

来自 12-/19-/21-§9.9/22-§4/26- 的共同口径，按"先对账再动工"排序：

1. **阶段级固定实例评测**（21-：S1/S2–S3/S4–S5/S6/S8–S12/S13–S16 各需固定实例、incumbent baseline、主指标、隐藏集与租约范围；当前只有 S1 预算与 S5 seed 两个旋钮，26- 已指出"第二轮即收敛"）。
2. **E 层执行契约**（12-：E1 run identity 已有雏形（capsule 的 protocol/dataset/code sha256）、E3 stage receipt、E4 attempts、E7 cost ledger 部分（metrics 内 cost）、E8 no-update path 未显式化）。
3. **运行件**（19- 四件：固定实例、LeaseSupervisor 硬门、可见性隔离、CandidateRun 步账）。
4. **验证证据**（C1–C4、E7/E8、扩展性评估、绕过测试——22- 定为"必须有"）。
5. **RWMT 对象**（14- 六对象 + 三类处置 + 签署流）。
6. **真实检索 adapter**（OpenAlex 只读无 key / 授权中文库；24- §6 第一优先）。

## 4. 最小补齐路线（静态层优先原则下）

- **已做（本轮）**：创新主张的机器可校验账本（innovations.json + verify 脚本 + 工作台视图）——把 22- 的"架构测试作为论文证据"落成最小形态：主张漂移即校验失败。
- **下一步（仍不接 API）**：① E8 no-update 显式字段（report 增加 no_update 汇总，契约 patch 升级）；② S1 检索旋钮之外加第二个可验证过程旋钮（如 screening_order）供多周期 RSI；③ RWMT 的 ChangeSet/影响闭包数据结构与 closure 检查打通。
- **接 API 前**：先完成 ①② 的固定实例与 E7/E8 复评；GLM-5.3-Flash adapter 接入时必须在 literature SPEC 登记权限/限流/错误，且输出仍受 span-only/不创建 Claim 约束。

## 5. 不可宣称清单（从各文档收敛，对外统一口径）

- 不宣称 RSI / 自进化能力增益 / SOTA / 首个（能说的上限：**受治理的改进控制面 + 受控改进准入**）。
- 不引用未复现的外部效果数字；外部证据按 已核验/作者口径/厂商口径/未找到 分级。
- fixture/SIM 数字不写成真实结果；`capability_claims` 为空是设计行为。
- 不宣称"公开材料里没人做过"（未见 ≠ 不存在，13- 已收窄表述）。
- 绑定/溯源本身已商品化（ScientistOne/CoE/ARIS），只宣称**变更后维护 + 人签导出**这条剩余交集。
