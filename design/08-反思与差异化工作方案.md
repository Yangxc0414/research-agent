## 0. 一页结论

v0.1 正确诊断了"平台大于研究"，但药方仍偏工程：它把 W1–W3 写成三个工作包，再用"三个包相加"证明研究量；这既重复计算，也没有回答"审稿人为什么必须承认这是一个新任务"。

v0.2 的结论是：

1. **创新的正确单位不是模块，而是任务与判定。** 我们定义 **RWJT（Reproduction–Writing Joint Task，复现—写作联合任务）**：给定研究问题、代码/数据快照与冻结协议，系统必须同时交付一次可复核的复现和一份**证据闭合稿件（Evidence-Closed Manuscript, ECM）**；稿件中的每个经验句、数字、图都必须绑定到 `confirmed` 运行与 `EA(source=rerun)`，否则导出被阻断。
2. **新意在于"耦合改变可行集"，不在于又加了一个 Judge。** 单做复现（OpenRSI / PaperBenchX）不判"写对"；单做写作（AI Scientist / Co-Scientist）不判"做对"；事后审计（ARIS / Auto-Empirical）不阻断导出。RWJT 把"做出来"与"写进去"变成同一个被评分对象，因而产生了新的失败模式与新的指标。
3. **创新栈的四层主贡献是任务（N1）、契约（N2）、机制（N3）、测量（N4）。** 主贡献是 N1+N4——任务定义与测量；N2/N3 是使任务可判定、可复现的支撑；N0（Work/Judge、快照、图谱、UI）是集成、N5 是经验发现，二者都不单独宣称。
4. **W1–W3 不是三篇论文，而是"一个旗舰 + 一个方法 + 一个评测底座"。** W3 不是可选的第三包，而是 W1 的评测基础；没有 W3，W1 只有 4 个任务的演示，不能支撑 κ 与泛化主张。最小可发表单元（MPU）是 **W1+W3**；W2 是独立方法论文；资源论文只在 benchmark 达到规模与校准门槛时才单列。
5. **工作量要按重叠计，不能按包相加。** W1 核心 55 人周，含共享评测 67；W2 25（其中 4 与 W3 共享）；W3 18–24；三者不重复计约 **94–100 人周**，加集成 6–12 为 **100–112**。完整论文轨道要 **5–6 人 / 100–112 人周**；MPU（W1+W3）约 **79–85**；只做 W1+lite 约 **73**，仅支撑 C2。9+1 的 215 人周是**产品轨道**，不是论文轨道的必要条件。
6. **一句话**：我们不是再做一个论文生成器；我们定义并测量"只写已经复现的内容"这一任务，并把"写错"变成可阻断、可传播、可评分的失败。

| --- | --- | --- |

## 2. 创新的正确单位：任务与判定，而不是模块

### 2.1 从"生成一篇论文"到"构造一份证据闭合稿件"

现有系统的评分对象可以归纳为四类：

| 对象 | 代表系统 | 它能回答的问题 | 它不能回答的问题 |
| --- | --- | --- | --- |
| 任务 + reward | OpenRSI / RSI-Harness | 这个任务做出来没有 | 结果有没有被正确写进稿件 |
| 论文 + rubric | PaperBenchX（项目口径） | 这篇论文的核心结果复现没有 | 复现者自己写的稿件是否忠于结果 |
| 论文 + 自动评审 | AI Scientist-v2 / Co-Scientist 扩展 | 稿件像不像论文、评审分高不高 | 数字是否来自独立重跑 |
| 文档 + 事后审计 | ARIS / Auto-Empirical | 稿内数字与账本是否一致 | 运行时能否阻断、变更能否传播 |

我们增加第五类对象：**（确证运行，证据闭合稿件）对**。定义如下。

给定确证运行集合 `R`、证据产物集合 `A`、结果 claim 集合 `C` 与稿件 `M`，称 `M` 是**证据闭合**的，当且仅当：

1. 每个经验句 `s ∈ M` 都存在一个 `confirmed` 的 `result_claim c ∈ C`，且 `c` 由某个 `r ∈ R` 产生、由某个 `a ∈ A` 测量，`a.source = rerun`；
2. 每个文献句都存在可定位的 `literature_claim`（span + 来源 + 版本），且未 `stale`；
3. 每个数字、图、表都有 `N/F/X` 槽绑定；所有 `R/X/N/F` 槽可解析；无 `stale/orphan/blocked`；
4. 导出硬门全部通过；否则 `Export(M)` 被阻断，并列出受影响句子。

这套定义把"写作"从**生成问题**改成了**约束满足问题**：不是"写得像不像"，而是"写进去的每一句是否有资格存在"。RWJT 则是这个约束满足问题的任务化：

> 在冻结协议与预算下，同时产出一个可复核的复现和一个证据闭合的稿件；评分必须同时覆盖 `R`（复现）与 `W`（写作），并报告 `J`（联合），但不允许 `J` 掩盖 `R` 的失败。

### 2.2 RWJT 的任务契约

| 维度 | 定义 |
| --- | --- |
| 输入 `I` | 研究问题；代码/数据快照；冻结协议；预算与时限；体裁契约（中文核刊 / 申报书）；允许的网络与工具策略 |
| 输出 `O` | 复现报告（Modeling / Execution / Validation）；证据闭合稿件（节或全稿）；证据包（run 账本、`EA`、verdict、图包、AI 使用记录） |
| 约束 `C` | 干净重跑；Judge 不可被 Work 修改；提交上限；单任务 Judge ≤30 分钟；CPU 或 1 卡；私有数据只读挂载 |
| 评分 `S` | `R = 0.30M + 0.30E + 0.40V`；`W = 0.30C + 0.25N + 0.15F + 0.15Cite + 0.15G`；`J = 0.55R + 0.45W`；R/W 分开报告 |
| 失败 `F` | `candidate_invalid / incomplete / diverged / verifier_error / verifier_timeout / infrastructure_error / submission_error / scored`；基础设施失败不记 0 分 |
| 准入 | 只有 `scored` verdict 可创建 `confirmed` 结果 claim；探索 run 不得进入稿件；未解析槽位阻止导出 |

这个契约与 07 §5–§10 一致；本节只把"任务"从工程接口提升为可对外表述的研究对象。

### 2.3 为什么"联合"不是拼接

把两个系统接起来，不等于定义了一个新任务。RWJT 的新意体现在三处：

1. **可行集变了。** 在"论文生成"任务里，一份没有运行证据但写得很顺的稿件是可行解；在 RWJT 里它不是。在"复现"任务里，一个 reward 很高但没有被写进任何 claim 的运行是完整解；在 RWJT 里它不计入 `W` 的覆盖。可行解从"稿件"或"运行"变成"满足闭合约束的对"。
2. **失败模式变了。** 出现了一类只在耦合后存在的失败：**claim 过度外推**（运行只支持"在设置 A 下提高 3%"，稿件写成"普遍提高 3%"）、**证据孤岛**（运行存在但无 claim 使用）、**跨版本失配**（运行更新而稿件未更新）、**写作—复现错位**（稿件引用的图不是该 run 生成）。这些失败无法被单侧评分捕捉。
3. **研究问题变了。** 至少产生五个可研究问题：
   - **Q1 claim 条件化复现**：在预算下，应该优先复现哪些 claim，才能使稿件的证据闭合率最高？这是一个预算分配/选择问题，不是"把所有实验都跑一遍"。
   - **Q2 闭合—覆盖权衡**：硬门会降低无证据句比例，但也可能降低 claim 覆盖；二者的 Pareto 前沿是什么？
   - **Q3 失效传播稳定性**：数据/代码/协议变更后，哪些 claim、句、图必须重跑/重写/仅复核？三类处置能否自动预测？
   - **Q4 R/W 可分性**：R 与 W 是否捕捉不同失败，还是 W 只是 R 的代理？若高度相关，J 的联合评分就没有额外信息。
   - **Q5 中文体裁效应**：中文核刊的章节义务、GB/T 7714 与页—段—句锚点，是否带来超出英文体裁的可测难度？

这五个问题中，Q1 是 P1 研究问题，v1 不要求实现；Q2–Q5 是 W1/W3 的评测内容。把它们写出来，是为了说明"平台"之外确实有研究，而不是把工程包装成研究。

### 2.4 与五个参照的对象级差异

**创新不在 18 个阶段，而在 5 条接缝。** 18 阶段是工程实现；论文主图应画接缝，不画流水线。

| 接缝 | 阶段 | 补的是什么 | 对应差异 | 验收 / 论文图 |

## 3. 创新栈与可宣称边界

### 3.1 创新栈：N0–N5

| 层 | 内容 | 我们的工作 | 是否主贡献 | 对外表述 |
| --- | --- | --- | --- | --- |
| N0 集成 | Work/Judge、快照、干净重跑、图谱、UI | 复用与适配 | 否 | "我们复用 OpenRSI 式执行底座" |
| N1 任务 | RWJT / 证据闭合稿件 | 定义任务、输入输出、约束、失败分类 | **是** | "我们定义了一个联合复现—写作任务" |
| N2 契约 | claim–run–artifact 三角；六类槽；三类 claim 统一 ID；失效边 | 形式化并运行时化 | 支撑 | "我们给出证据闭合的契约与不变量" |
| N3 机制 | 只认重跑；导出硬门；三类处置；claim 条件化复现（P1） | 实现并消融 | 支撑 | "我们实现并测量硬门与传播的效果" |
| N4 测量 | 中文核刊 RWJT benchmark；R/W/J；5 项预注册过程指标 | 建集、校准、盲评 | **是** | "我们测量闭合约束对写作与复现的影响" |
| N5 发现 | 验证瓶颈；闭合代价；R/W 可分性 | 报告效应与负结果 | 经验 | "我们报告可复现的实证发现" |

**主贡献的准确说法**：不是"我们发明了 Work/Judge"，也不是"我们发明了证据槽"，而是"我们把'复现—写作'定义成一个联合任务，并给出使该任务可判定、可复现、可测量的契约与评测"。

### 3.2 可以宣称 / 不可以宣称

| 可以写进论文 | 不可以写 | 原因 |
| --- | --- | --- |
| "We define RWJT, a joint task that requires a confirmed reproduction and an evidence-closed manuscript." | "首个复现—写作系统" | "系统"容易被理解为又一个 pipeline；任务定义才是贡献 |
| "We formalize evidence closure and enforce it at export time." | "首创证据槽 / 首创硬门" | ARIS 有账本、Auto-Empirical 有 CSV；我们的是运行时闭包 |
| "We build a Chinese core-journal RWJT benchmark with N tasks and expert calibration." | "首个中文科研 benchmark" | 中文评测与中文写作已有；限定在"核刊 + 证据闭合 + 联合判定" |
| "We measure the effect of rerun-only admission and slot gating on unsupported claims." | "我们的写作质量达到 SOTA" | 没有同协议盲评就不能说 |
| "We report R, W, J separately and release negative results." | "J 代表论文质量" | J 是联合判定，不是质量本身 |
| "In our surveyed scope, we did not find a public implementation that closes the run→claim→sentence→export chain." | "公开材料里没有人做过" | 未见 ≠ 不存在；并发工作需持续检查 |
| "We are an RSI system / general AI scientist." | 我们优化的是证据准入与闭合，不是自我改进循环；"通用"会触发与 Co-Scientist/ScientistTwo 的正面比较 | "We study the admission and evidence-closure layer for scientific improvements." |

**表述纪律**：所有"首次/首个"必须先过 §3.3 的三问；不能过，就改成"我们定义/我们测量/在本轮核验范围内未见"。

### 3.3 三条 novelty gate

任何一条差异，在写进论文前必须回答：

1. **去掉它，基线还能解这个任务吗？** 如果还能，它是工程优化，不是任务贡献。
2. **有没有基线与效应量？** 如果只有"我们实现了"，没有对照，它是功能描述。
3. **能不能不提系统名字，用一句话说清贡献？** 如果不能，它是集成工作。

用这三问检验 W1–W3：

| 包 | 去掉后的基线 | 是否有对照 | 一句话贡献 | 判定 |
| --- | --- | --- | --- | --- |
| W1 | 自报 + 事后审计（ARIS 式）仍能"写完"，但不能保证闭合 | B0–B5 | 定义并测量"只写已复现内容"的联合任务 | 过 |
| W2 | 手工 diff + STALE 哈希仍能发现部分过期 | B0–B3 | 把失效从"边/哈希"变成"运行→claim→句"的传播与处置 | 过 |
| W3 | 终稿分/自动评审仍能给分 | 6 个基线 | 用预注册过程指标替代单一终稿分 | 过（但需规模） |

### 5.2 W2（方法论文）｜跨版本证据失效传播

**研究问题**：数据/代码/实验任一变更时，哪些 claim、图表、统计量与摘要句失去证据支持？能否以"需重跑 / 需重写 / 仅复核"三类处置自动识别，召回 ≥85% 且误报 ≤20%？

**核心件与人周**：

| 件 | 人周 |
| --- | ---: |
| L3 证据图谱（三类 claim 统一 ID + 4 类边语义 + 孤儿/环检测） | 11 |

**可证伪主张 C3**：50 个变更场景上受影响 claim/句召回 ≥85%、误报 ≤20%，三类处置准确率 ≥80%，且显著高于 B1。若不成立：收窄到"结果变更→摘要句"这一子场景，如实报告退化。

### 5.3 W3（评测底座）｜中文核刊 RWJT benchmark 与预注册指标

**研究问题**：中文核刊场景下，能否用 5 项预注册过程指标（Q0 通过率、claim 支持率、失效召回、人工干预次数、体裁合规）替代"单一自动评审分"来证明写作质量，并与专家盲评校准？

### 6.1 四条主张

| 主张 | 干预 | 基线 | 指标 | 成功阈值 | 不成立时 |

**关于基线的纪律**：v0.1 写"无证据事实句从 10% 降到 5%"，但 10% 是占位假设，不是实测。v0.2 改为：**M0 的 pilot 先测基线比例，再登记阈值**；预注册的是"相对降低 ≥50%"，不是拍脑袋的绝对值。

### 6.2 预注册与负结果

1. M0 结束前冻结：任务集、指标、基线、阈值、排除规则；之后只允许"增加任务"，不允许"改指标"。
2. 所有 run 进账本；`infrastructure_error` 与 `verifier_error` 不计入 0 分，单独报告。
3. 任何一条主张不成立、任务退役、κ 不达标，都写入负结果报告；不删失败 run。
4. 4 个 v1 任务只用于校准；论文主张必须跑 W3 的 ≥12 个任务与 ≥2 位专家。
5. 并发工作检查：M0 前与投稿前各做一次检索；若发现同任务定义，先修订 C1–C4 再继续。

| --- | --- |
| C1 不成立（κ <0.60 或 R–W 高度相关） | 不做"联合判定"旗舰；保留 R/W 分开报告；转 W2 |
| C2 不成立（硬门只挡语法，不降无证据句） | 硬门降为工程贡献；论文转 W2 或 W3 |
| C3 不成立（传播不如 STALE） | 收窄场景；或承认"传播只在结果→摘要句有效" |
| C4 为零结果 | benchmark 仍可发表；删除"验证瓶颈"的强叙事 |
| 并发工作先发表 RWJT | 转向 W2/W3；或在任务定义上增加"claim 条件化复现"作为增量 |

## 7. 风险、并发工作与可辩护性

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| 并发工作 | 他人先定义 RWJT / evidence closure | 持续检索；保留日期戳与检索记录；准备 W2/W3 fallback |
| RSI 并发 | Dream-RSI / Karl / MASS / SkillCAT 等把外部验证或证据账本纳入循环，差异收窄 | 持续检索；把差异锚在 claim 级闭包 + 中文核刊 + 可测准入；准备 W2 fallback（见 `10-` §7） |
| 语义支持不足 | 槽位能绑到 claim，但 claim 不支持该句 | 专家抽样审计；把"无证据事实句"与"语义不支持句"分开报告；不把语法绑当语义真 |
| 中文效应弱 | 中文体裁不产生可测差异 | 设英文对照集；若无效，把中文降为"领域实例"，不把中文当主卖点 |
| 专家 κ 不达标 | 双专家分歧大 | 先做 20% 抽样预校准；不达标时降为单专家 + 自动一致性检查 |
| 复现不确定性 | 同代码不同结果 | 容差带；固定 seed/环境；报告方差；不把微小差异当效应 |
| benchmark 过拟合 | 任务被针对性优化 | 开放/封闭集；留出集；canary 只作污染控制 |
| 4 任务功效不足 | κ 与泛化不可信 | W3 扩到 ≥12 任务；4 任务只作校准，不作主张 |
| 平台吞噬研究 | 集成占用关键路径 | 双轨道；论文关键路径 5–6 人；M0 第 2 周契约互传硬门 |
