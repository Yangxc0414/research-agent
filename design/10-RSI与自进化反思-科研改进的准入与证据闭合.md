## 0. 一页结论

用户列出的七项工作（外加邻近的 RRSI 与多域 RSI-Anything）把"改进"本身变成了优化对象：Dream-RSI 改进探索策略，Karl Workbench 改进研究状态，RSIAgent 改进外部记忆，MASS 改进多智能体工作流与权重，SkillCAT 改进技能文档，两篇综述给出领域地图，RRSI 改进 agent harness，RSI-Anything 改进"预测—选择—保留"的任务运行时。**它们证明的是系统可以在某一层变强；它们没有回答的是：变强之后，哪一部分改进有资格被保留、复用、写进论文，并对读者负责。** 更准确地说，Karl 的研究状态覆盖了"保留"、SkillCAT 的克隆验证覆盖了"复用"的一段、RSI-Anything 的 promotion gate 覆盖了"任务级准入"的一段；但没有一个把"准入—复用—写入—导出"接成可判定闭环。

本文的结论是：

1. **RSI 家族的共同结构是"内部改进循环"，不是"科研证据循环"。** 反馈信号主要来自模拟世界、同基座评估者、框架内 verifier、源任务克隆、世界模型预测或基准分数；判定对象是 task / reward / policy / memory / workflow / skill / harness / checkpoint，而不是 `(确证运行, 稿件)` 对。RSI-Anything 的 hidden judge 与判定封存是目前最接近"干净任务判定"的工程实现，但判定对象仍是任务成功与成本。
2. **三个结构性缺口最值得做，也最接近我们的现有设计：改进准入、证据闭合、适用域判定。** 其余缺口（反事实因果、多样性、治理）或为设计约束，或为后续工作，不应在 v1 一并宣称。
3. **我们的定位不是"又一个 RSI 系统"，而是 RSI 的准入层与证据层。** 一句话：**RSI 让 Agent 更会做；我们让做出来的东西有资格被留下、被复用、被写进论文。**
4. **Karl Workbench 是最接近的工业参照，不是可以轻视的对手。** 它公开的五层 RSD 已包含记录、失败路径、研究产物、证据链关联与人类监督；我们的差异必须收窄到**claim 级语法、跨版本失效传播、导出阻断、独立重跑与可测准入**，而不是"我们有研究状态"。
5. **MASS / SkillCAT / RSIAgent 的证据要分开看。** MASS 的 1.2–1.6× 是"每输出 token 的基准得分"，且作者自己报告了 SWE-bench / Terminal-Bench 的 0.94–0.96×；SkillCAT 的验证主要在源任务克隆；RSIAgent 的记忆在测试时冻结。它们都**没有**报告四维准入、负迁移拒绝或 claim 级闭合。
6. **我们目前只有设计与模拟，没有结果。** C1–C4 未实测，demo 全部是 SIM；因此只能说"设计上对应 + 有可证伪实验"，不能说"已经解决"。如果 E2/E3/E5 跑不出来，本文的强版本主张应撤回，退守 W2 或工程结论。
7. **"Brench 2026-08"本轮未找到可核验原文。** 可核验的同类综述是 Chen/Wang/Qu（arXiv:2607.07663，2026-07，1,250 篇）；Karl Workbench 只有厂商/媒体材料。两者都必须按证据等级降级，不能当同行评审基线。

### 1.2 Karl Workbench：最接近，也最需要克制

厂商/媒体宣称其在 SciAgentArena 的单细胞与空间组学场景登顶，击败 Claude Code / Codex 等系统；这是产品口径，本轮未独立复现，也没有论文/代码可核。`[厂商/媒体口径]`

**公开材料给出的五层 RSD**（`[厂商/媒体口径]`）：

| 层 | 厂商描述 | 与我们机制的表面重叠 | 公开材料未展示的部分 |
| --- | --- | --- | --- |
| 记录层 | 全量保存任务输入、数据版本、代码与参数，链路级可追溯 | 产物信封、run 账本 | 字段级 schema、ID/版本规则、第三方复现 |
| 积累层 | 记录失败路径与被证伪假设，转化为约束 | 假设/证据记忆、失败归因 | 失败路径的失效条件、再激活判据 |

| 监督层 | 审查分析逻辑与置信度，人类保留最高决策权 | 三权分离、人类终审 | 审查协议、评分一致性、导出阻断 |
| 进化层 | 识别成功路径与能力瓶颈，优化后续规划 | 适用域判定、技能准入 | 四维准入、负迁移拒绝、成本核算 |

**判断**：Karl Workbench 的公开叙事与我们的方向高度重叠，尤其在"研究状态 + 失败路径 + 证据链 + 人类监督"四点。任何"他们没有证据链"的说法都不成立；正确的说法是：

> 公开材料展示了这些层的**设计意图**，但没有给出 claim 级语法、失效传播的可执行规则、导出硬门、独立重跑协议或第三方复现。我们做的是把这些意图变成**可判定、可阻断、可测量**的契约；这不是"从无到有"，而是"从架构描述到运行时闭包"。

这也意味着：如果 Karl 或同类产品后续公开了 claim 级闭合与独立评测，我们的差异会迅速收窄。**不能把"他们目前没公开"当成长期护城河。**

### 1.3 Dream-RSI：改进的是探索策略，不是科学证据

- **题名/出处**：*Dream-RSI: Recursive Self-Improvement through Evolving Worlds*，Tong Zheng 等，arXiv:2609.14858，2026-09-14。`[已核验/元数据]`
- **机制**：从历史发现树构建可回放的"世界"，在线探索产生轨迹，世界随之演化，再用离线模拟与 off-policy 反馈改进探索策略；不更新基础模型权重。评估覆盖 9 个任务、4 个域，公开材料列出的域包括算法工程、数学优化与 GPU kernel 工程。`[作者口径]`
- **作者报告的效果**：相比 SimpleTES 最多减少 162× agent 调用，相比固定探索基线 1.7×。`[作者口径，未复现]`
- **它证明了什么**：探索策略可以在一个可回放的世界里被递归改进；历史轨迹可以变成策略更新的训练信号。
- **它没有证明什么**：模拟世界里的收益是否等于真实科学收益；改进是否可迁移到新域；产生的结论是否有 claim 级证据；能否写成一份可审计的稿件。它的判定对象是 policy，不是 manuscript。
- **与我们的接口**：Dream-RSI 产生"候选改进"；RWJT 判定"哪些改进能被写进论文"。我们不重建它的世界模型，只把它的轨迹当作输入，并要求**独立重跑 + 证据闭合**后才能进入 `result_claim`。这是一个上下游关系，不是替代关系。

### 1.4 RSIAgent：冻结记忆是优点，也是准入问题的来源

- **题名/出处**：*RSIAgent: Autonomous Exploration for Recursive Self-Improvement in New Environments*，Sibo Zhu 等，arXiv:2609.15364，2026-09-14。`[已核验/元数据；完整题名以 arXiv 页面为准]`
- **机制**：training-free 多智能体框架；curriculum agent 安排任务，actor agent 执行，verifier agent 核对；先广后深（BRS → DRS）；把环境知识、可复用流程与教训写入外部记忆；测试时冻结记忆，不更新模型参数。`[已核验/摘要 + 二手报道]`
- **作者/二手报告的效果**：二手报道称开源模型在 OSWorld 2.0 与 Agents' Last Exam 的部分指标上超过闭源旗舰（示例：OSWorld 2.0 78.98% / ALE 84.82%，对比 GPT-6 Astra 72.60% / 82.26%）；同时二手分析指出 README 的聚合包含重试、不同预算 checkpoint 与协议变体，**不是严格受控的重复运行**，且 ALE 的 Binary 指标并未全面领先。`[二手报道，未核验；数字只作现象参照，不作基线]`
- **它证明了什么**：不更新参数，仅靠自主探索与外部记忆，也能在陌生数字环境中获得可测提升；"先广后深"是一种有效的探索课程。
- **它没有证明什么**：记忆条目是否值得长期保留；换域后是否负迁移；错误记忆如何撤销；verifier 的错误率与成本；记忆中的结论能否绑定到可复现的运行与稿件。
- **与我们的接口**：RSIAgent 的记忆是"候选经验库"；我们的四维准入是"入库闸门"，适用域判定是"复用闸门"。冻结记忆避免了漂移，但也意味着**坏条目不会被自动纠正**；我们的 `stale/orphan` 传播与再验证正是补这一点。

### 1.5 MASS：同模型自监督的上限，作者自己也看到了

- **题名/出处**：*MASS: Recursive Self-Improvement through Multi-Agent Self-Supervision*，Hyunin Lee 等（Sakana AI + UC Berkeley），arXiv:2610.12176，2026-10-08。arXiv 题名可能不含 `MASS:` 前缀。`[已核验/元数据]`
- **机制**：同一基座模型（公开报道为 Qwen3.6-27B）轮流担任 executor、optimizer、evaluator；内循环在冻结权重下搜索多智能体工作流，外循环把选中的执行轨迹蒸馏回共享权重；两轮循环。`[已核验/摘要 + 二手报道]`
- **作者报告的效果**：每输出 token 得分相对基座为 MLR-Bench 1.60×、DSBench 1.35×、AstaBench E2E-Hard 1.28×、ScienceAgentBench 1.20×；SWE-bench Verified 0.94×、Terminal-Bench 2.0 0.96×。`[作者口径/二手报道，未复现]`
- **一个关键细节**：二手报道提到，作者把 evaluator/optimizer 换成更强的外部模型（GPT-5.5）后，工作流搜索更快覆盖任务；只换 evaluator 的收益较小。**这恰好说明同质闭环有上限，外部判定有独立价值。** `[二手报道，未核验]`
- **它证明了什么**：在多智能体工作流层面做自监督，可以提高单位 token 的研究任务得分；组织能力与执行能力可以在一定程度上分开学习。
- **它没有证明什么**：得分提升等于科学有效性；同一模型的系统性偏差已被消除；跨域提升是均匀的（0.94–0.96× 就是反例）；结果有 claim 级 provenance；稿件数字可审计。
- **与我们的接口**：MASS 的工作流搜索可以作为候选生成器；我们的独立 Judge、三权分离与 R/W/J 是判定层。我们不与它在 MLR-Bench / DSBench 上比分数；我们比的是"同一协议下，哪些结论能被独立重跑并写进稿件"。

### 1.6 SkillCAT：源任务克隆验证，是准入的半步

- **题名/出处**：*SkillCAT: Contrastive, Assessment-Augmented and Topology-Aware Skill Self-Evolution for LLM Agents*，Kunfeng Chen、Qihuang Zhong、Juhua Liu、Bo Du，arXiv:2606.13317，2026-06-11。`[已核验/元数据]` 作者列表已核验；用户提供单位为武汉大学 + 南洋理工，arXiv 摘要页未显示，标 `[待核]`。
- **机制**：CCE（对比成功/失败轨迹，提取关键差异）、AAE（评估并进化技能补丁）、TTE（按任务拓扑路由子技能）；在 SpreadsheetBench、WikiTableQuestions、DocVQA 上评估，并报告跨模型/OOD 泛化。`[已核验/摘要]`
- **效果口径**：arXiv 摘要显示"up to 49.69%"，此前二手材料写"40.40%"；两者口径不同或有一处误引，本文**不引用该数字作比较**。`[作者口径；数字待核]`
- **它证明了什么**：成功/失败轨迹的对比可以提取可复用的技能补丁；在源任务克隆上验证，比"直接写入"更可靠。
- **它没有证明什么**：补丁在分布变化、长时程、跨任务组合下是否仍有效；是否会负迁移；保留率与退化率；演化成本；技能是否有执行契约与 provenance。
- **与我们的接口**：CCE 可以作为"失败—成功差异"的特征提取器；我们的四维准入与适用域判定是它缺失的验收层。**源任务克隆验证是必要不充分条件**，不能直接升级为"长期经验"。

### 1.7 两篇综述：地图有了，判定还没有

**S6 Self-Evolving Agents 综述**：

- 题名/出处：*A Survey of Self-Evolving Agents: What, When, How, and Where to Evolve on the Path to Artificial Super Intelligence*，Huan-ang Gao 等，TMLR 2026，arXiv:2507.21046（v1 2025-07-28，v4 2026-01-16）。`[已核验/元数据]`
- 贡献：作者自述为首个系统性综述；用 What / When / How / Where 四维组织领域；把评测、安全、可扩展性列为开放问题。`[已核验/摘要]`
- 局限：它回答"领域怎么分类"，不回答"某项改进是否值得进入科学记录"；"谁来评分"仍是开放问题，而不是已解决问题。

**S7 RSI 综述**：

- 题名/出处：*Recursive Self-Improvement in AI*，Chen、Wang、Qu，arXiv:2607.07663，2026-07-08。`[已核验/元数据]`
- 贡献：调研 1,250 篇 arXiv 论文；按"改进什么"与"闭环程度"两轴组织；区分 bounded self-refinement 与 open-ended RSI；把评测与闭环作为核心问题。`[已核验/摘要]`
- 局限：它是地图，不是任务定义；没有给出科研 claim 的准入、证据链闭合或跨版本传播方案。

**与我们的接口**：这两篇综述证明"RSI 已经是一个有地图的领域"，因此**再写一篇泛泛的 RSI 综述或再加一个自进化循环，不足以构成贡献**。我们的机会在"把综述指出的评测/闭环问题实例化为一个可测任务"。

### 1.8 RRSI：harness 级 RSI 的邻近证据

- **题名/出处**：*RRSI: Regularized Recursive Self-Improvement of Agent Harnesses*，Peng Xia 等，arXiv:2609.24972，2026-10-04。`[已核验/元数据]`
- **机制**：把 harness 作为递归改进对象；用正则化偏向可复用机制，而不是 benchmark-specific 的噪声；公开摘要提到正则化与可复用机制，二手材料补充了退火预算、critic 与 pruner 的工程细节。`[作者/二手口径]`
- **它证明了什么**：harness 层可以被系统地递归改进；"可复用机制"可以作为正则项。
- **它没有证明什么**：harness 改进是否对应科学有效性；是否有 claim 级证据闭合；是否会在新基准上过拟合。作者自己把过拟合/记忆化列为限制。`[作者口径]`
- **与我们的接口**：我们的导出硬门可以看作一种"证据正则化"——不是让 harness 更会刷分，而是让 harness 更会保留可审计的证据。两者目标不同，但可以互相借鉴 budget/critic/pruner 的工程做法。

### 1.9 RSI-Anything：把"预测—选择—保留"做进运行时，但仍停在任务层

- **出处**：*RSI-Anything*（题名以 arXiv 页面为准），arXiv:2610.13912；代码 `Gen-Verse/RSI-Anything`，Apache-2.0。`[已核验/元数据]`
- **快照**：本地 `oss/RSI-Anything-main/`，默认分支 `main`，commit `8ba44cd73ec6f57b151ec06e2f71a0726adfb687`（2026-10-13），573 个文件 / 18,229,117 bytes；GitHub 元数据 797 stars，2026-10-19 核对。`[已核验]`
- **六阶段循环**：Propose → Predict → Select → Evaluate → Learn → Retain。世界模型基于 JEPA-Anything，先预测候选动作的后果，再决定评估顺序；外部任务反馈用于学习和评价。领域覆盖代码修复、GUI 交互、实验室规划、反应优化与免疫科学。`[作者口径 + 工程参考]`
- **作者/项目口径结果**（**未复现，不得当成本项目结果**）：CodeContests 31.2% hidden-test success；APPS Introductory 46.37%；LiveCodeBench v6 33.05%；MiniWoB++ `click-checkboxes` 99%、动作数减少 39.4%；OSWorld 相对初始 Agent +18.4%；LabHorizon F200 Level 2 46.01%；Suzuki flow LC–MS 96.15% mean best yield。`[作者口径]`

**代码里真正可核对的机制**（`[工程参考]`，未执行）：

| 机制 | 代码入口 | 做什么 | 对我们的意义 |
| --- | --- | --- | --- |
| 运行身份与恢复 | `src/rsi_anything/workflow/runner.py` | 锁、run state、输出哈希、source identity、resume、attempts、进程组清理 | 对应我们两个账本的"可审计运行"；证明运行时回执可以工程化 |
| 阶段继承 | `src/rsi_anything/tasks/code_repair.py` | `initial → semantic → expanded → incumbent` 四阶段，记录 parent checkpoint、rows、steps、hash | 对应跨循环继承包；但继承对象是 checkpoint，不是 claim 级技能资产 |
| incumbent 保护 | `tasks/code_repair/src/development.py` | 按预测 utility 选候选；若候选预测不优于当前 incumbent，则保留 incumbent | 直接支撑 EV2/EV4：候选必须相对当前 active 资产有增益 |
| 判定封存 | `tasks/code_repair/src/evaluation.py` | 先写 `public_seal.json` 封存全部决策，再开 hidden judge；断言 `all_decisions_sealed_before_hidden_judge=True`；重算 hidden results | 对应我们的"留出集开启前冻结候选与判据"，防事后改判 |
| cohort 隔离 | `tasks/gui/docs/PROTOCOL.md` | 训练 / 开发 / 确认 / RSI test 使用互斥 cohort seeds；proposal 在 RSI test 开启前训练、选择、冻结 | 对应留出集污染控制；应写进 EV4 的执行前置检查 |
| 相对成本门槛 | `tasks/gui/docs/PROTOCOL.md` | promotion gate：development success gain ≥0.04 且 cost ≤1.2× incumbent；hybrid candidate gain ≥0.04 且 cost ≤4× baseline | 成本必须相对 incumbent，而不是绝对成本；可直接借为租约成本条款 |
| 拒绝也评估 | `tasks/gui/docs/PROTOCOL.md` | 被拒绝候选仍做 crossed evaluation 并报告 | 对应我们的 `rejected` 理由库与假拒绝审计 |

**它证明了什么**：一个通用 agent 可以在多域任务上把"预测候选后果 → 选择 → 评估 → 学习 → 保留 checkpoint"做成统一运行时；预测可以降低评估成本；incumbent 保护与判定封存可以写进代码，而不只是实验约定。`[工程参考]`

**它没有证明什么**：

1. **保留对象是 world/policy checkpoint，不是 claim 级技能资产。** 没有租约、适用域护照、依赖快照、撤销传播，也没有"资产 → run → claim → 句/图"的失效链。
2. **判定停在任务/能力层。** hidden judge 判的是任务成功与成本，不判稿件中的数字、引用与结论是否有证据支撑；没有导出硬门。
3. **预测不是证据。** 世界模型只用于候选排序/选择；预测校准误差没有被纳入准入理由，也没有"预测高但真实失败"的保留记录。
4. **没有中文长文与句子级证据槽。** 不覆盖中文核刊体裁、GB/T 7714、版面锚点或 AI 使用披露。
5. **效果数字是作者/项目口径。** 本轮未复现，不能当我们的基线，也不能用它反推"通用科研能力"。

**与我们的接口**：RSI-Anything 的候选与保留机制可以作为我们的**上游候选生成器与预筛器**；我们的 EV1–EV4 与租约是它缺失的**准入与证据闭合层**。正确的上下游表述是：

> RSI-Anything 让 agent 更会预测和选择任务动作；我们判定这些改进是否值得进入科学记录，并把判定结果接到 claim、稿句与导出。

**我们明确借的三件事**（写进 [11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md)）：

- **EV0 影子预筛**：预测只影响候选排序与预算分配，不作为准入证据；必须记录预测值与真实结果的校准。
- **incumbent guard**：候选必须相对当前 `active` 资产有增益；未超过则保留 incumbent，并写 `INCUMBENT_GUARD` / `NO_INCUMBENT_GAIN` 理由码。
- **判定封存 + cohort 隔离**：留出集开启前冻结候选、判据与排序，记录 `seal_hash`；训练/开发/确认/留出使用互斥任务或 seed。

**我们不借的三件事**：不把任务分数当科学有效性；不把 checkpoint 当 claim 级资产；不复用其效果数字。

**v0.3 深读补正**：上述三点借用仍成立，但上一版漏了两个面。第一，**执行契约**：runner 用 `digest(config + source_identity + plan + files)` 定义 run identity，逐 stage 记录 expected artifacts 与输出哈希，resume 前重算 completed receipts，失败重试把不完整输出归档到 `attempts/`，并用文件锁阻止双 owner；这比我们文档层的“可复现”更可执行。第二，**交叉/条件确认**：GUI 在两代 pair 冻结后用 old_old/old_new/new_old/new_new 2×2 分离 world 与 policy 贡献，pilot 过阈值才开 630-instance confirmation，并有独立 `audit.py` 从 raw transitions 重算动作、谱系、校准、冻结时间与成本。我们的差异因此应收窄为 **claim 级租约、护照、撤销传播、稿件槽与导出硬门**，而不是“它没有准入/审计”。逐项代码入口、四种 retain 与 E/C/A 修订见 [12](12-RSI-Anything深读-执行契约、保留层与领域不对称.md) §2–§6。

## 2. 共同结构：它们都在优化什么

### 2.1 按优化对象分类

| 类别 | 工作 | 优化对象 | 反馈来源 | 判定对象 | 产物 |
| --- | --- | --- | --- | --- | --- |
| 科研过程 RSI | Dream-RSI | 探索策略 | 回放世界 + off-policy | 策略表现 | policy / 轨迹 |
| 科研过程 RSI | Karl Workbench | 研究状态与假设空间 | 人工监督 + 系统审查（厂商口径） | 假说质量（未公开协议） | 研究状态 / 产物 |
| 通用自进化 | RSIAgent | 外部记忆 | 框架内 verifier | 任务成功 | 环境知识 / 流程 / 教训 |
| 通用自进化 | MASS | 工作流 + 权重 | 同模型 evaluator（可换外部） | 每 token 得分 | workflow / 权重 |
| 通用自进化 | SkillCAT | 技能文档 | 源任务克隆评估 | 任务成功 | 技能补丁 / 路由 |
| 通用自进化（多域） | RSI-Anything | 世界模型 + 候选策略 | 预测后果 + 外部任务反馈 + hidden judge | 任务成功 / 成本 | checkpoint / policy / 任务结果 |
| 邻近 | RRSI | harness | 正则化基准反馈 | 基准稳健性 | harness |
| 综述 | S6 / S7 | 领域分类 | 文献 | 无 | 地图 |

### 2.2 共同循环与缺失的半环

```text
历史轨迹 / 环境
      │
      ▼
[改进对象：策略 / 状态 / 记忆 / 工作流 / 技能 / harness]
      │
      ▼
[内部评价：reward / verifier / self-score / clone validation / benchmark]
      │
      ▼
更新 ──────────────► 下一轮
      ▲
      │
  缺失的四件事：
  1) 独立外部判定（不是同一个模型、不是同一个模拟器）
  2) 改进准入（迁移 / 保留 / 退化 / 成本）
  3) 证据链闭合（run → claim → 句/图 → 导出）
  4) 人类责任与贡献归因
```

**读法**：这不是说 RSI 家族"没有价值"；它们把左半环做得很好，而且有真实收益。问题是右半环——**什么值得留下、凭什么留下、留下后谁来负责**——在它们的优化目标里基本不可见。

### 2.3 一个关键区分：能力改进 vs 科学改进

| 维度 | 能力改进（RSI 家族的主战场） | 科学改进（我们关心的对象） |
| --- | --- | --- |
| 成功标准 | 任务分数、reward、每 token 得分 | 结论可复现、证据可追溯、陈述与证据一致 |
| 判定者 | 模拟器、同模型 evaluator、框架内 verifier | 独立重跑 + 外部专家 + 导出硬门 |
| 时间尺度 | 一轮/两轮/若干轮 | 跨版本、跨数据、跨代码、跨稿件 |
| 失败模式 | 分数不升、成本高、过拟合 | 无证据句、过度外推、证据孤岛、跨版本失配 |
| 可复用单位 | 策略、记忆、技能、工作流 | 带适用条件与 provenance 的 claim / 证据包 |
| 责任归属 | 通常不讨论 | 作者、机构、AI 使用记录、人类终审 |

这张表是本文的核心：**RSI 的"强"与科学写作的"可信"不是同一个坐标轴。** 一个系统可以在左列持续变强，同时在右列毫无保障。

## 3. 七个结构性缺陷

> 本节机制描述以 §1 的来源卡为准；效果数字均为作者/厂商/二手口径，未独立复现。凡写“它们做到了”均指公开材料/论文自报，不指本项目复现。

> 以下七条不是"七篇论文各挑一个错"，而是把它们的共同优化目标放在科研场景下检验后，暴露出的**结构性缺口**。每条都给出：表现、为什么加模块不够、我们的对应机制、可证伪指标、不能宣称什么。

### G1 判定锚点：内部信号 ≠ 科学有效性

**表现**

- Dream-RSI 的改进发生在可回放世界里；世界本身是从历史发现树构建的，收益是"在世界里更会探索"。
- MASS 让同一个基座模型同时当 executor / optimizer / evaluator；虽然作者做了外部 evaluator 的消融，但默认闭环仍是同质自评。
- RSIAgent 的 verifier 是框架的一部分；SkillCAT 的验证主要在源任务克隆；RRSI 的反馈仍是基准分数。

**为什么不是"再加一个 evaluator"**

再加一个 LLM evaluator，仍然是"模型评模型"；只要 evaluator 与 executor 共享训练数据、基座或盲区，错误就是相关的。真正的问题是**判定对象**：它们判定的是 task success，不是"这份稿件里的这句话有没有证据"。

**我们的对应**

- 三权分离：提议、执行、判定在不同角色、不同上下文中完成（[04](04-自动化研究与写作流水线.md) §2.10、[02](02-需求书-科研自动化与写作平台.md) FR-4）。
- 独立 Judge + 干净重跑：结果 claim 只接受 `scored` verdict 与 `EA(source=rerun)`（[07](07-复现级验证与执行Harness设计.md) §5/§10）。
- RWJT 分开报告 `R`、`W`、`J`，不允许 `J` 掩盖 `R` 的失败（[08](08-反思与差异化工作方案.md) §2.2）。
- 导出硬门：未解析槽位、`stale/orphan/blocked` 阻止导出（[04](04-自动化研究与写作流水线.md) §2.14）。

**可证伪指标**

- 无证据事实句占比；伪造数字/引用通过数；核心 result claim 覆盖率；R–W 相关；专家盲评 κ。
- 对应 C1/C2/C4 与 E2/E3（见 §6）。

**不能宣称**

- 我们的 Judge 是"客观真值"；它只是**上下文独立、可审计**。
- 独立重跑一定比自评更准；这需要实验证明，不是定义。

---

### G2 准入标准：单次成功被当作长期经验

**表现**

- RSIAgent 把探索得到的经验写入记忆，测试时冻结；冻结避免漂移，但没有"这条记忆是否该保留"的准入协议。
- SkillCAT 在源任务克隆上验证技能补丁；这比直接写入好，但仍不是跨分布、长时程的准入。
- MASS 把"自评最优"的轨迹蒸馏进权重；最优是当前 evaluator 的最优，不是独立验证的最优。
- Karl 记录失败路径，但公开材料没有给出"何时重新启用被否决假设"的判据。

**为什么加模块不够**

"记忆/技能"不是越多越好。一个在源任务上成功的补丁，可能在分布变化后负迁移；一个高奖励轨迹，可能只是过拟合了 evaluator。**没有准入，改进会累积成技术债。**

**我们的对应**

- 四维学习证据准入：跨任务迁移、知识保留、退化检测、演化成本（[01](01-组会纪要-核心判断与优先方向.md) 判断 1）。
- 适用域判定：直接复用 / 先行测试 / 拒绝复用（[01](01-组会纪要-核心判断与优先方向.md) 方向 A）。
- 类型化技能记忆 + 执行契约 + provenance；技能条目必须带适用条件与失效条件。
- 我们的 W2/FR-10 把"变更→失效"作为传播问题；这与准入是同一枚硬币的两面。

**可证伪指标**

- 负迁移率；保留率（retention@k）；退化率；每个被接受技能的成本；拒绝精度/召回。
- 对应 E1（见 §6）；当前 C1–C4 **没有**直接覆盖这条。

**不能宣称**

- 四维准入一定优于源任务克隆；需要同一任务集上的对照。
- "冻结记忆"是错的；它是有意的稳定性设计，我们补的是撤销与再验证。

---

### G3 记忆结构：类型混杂，缺协调与 provenance

**表现**

- RSIAgent 的记忆同时包含环境知识、可复用流程与教训，但没有类型化本体，也没有"哪条记忆被谁消费、何时复验"的协议。
- Karl 的研究状态包含结论、证据、失败路径、方法边界；这是最接近类型化记忆的公开描述，但仍是厂商口径。
- Dream-RSI 的世界模型是领域特定的；MASS 把经验压进权重；SkillCAT 把经验压进技能文档。
- 两篇综述把 memory 作为一个组件，但没有给出跨类型协调协议。

**为什么加模块不够**

四类记忆（文献关系、领域知识、假设与证据、执行经验/技能）的**失效方式不同**：文献会过期，领域知识会被新证据修订，假设会被证伪，技能会负迁移。把它们塞进同一个向量库或同一个上下文，无法判断"这条记忆为什么可信、何时失效、被谁用过"。

**我们的对应**

- 类型化记忆图谱：文献关系、领域知识、假设与证据、执行经验/技能（[01](01-组会纪要-核心判断与优先方向.md) 判断 5）。
- 协调协议：准入证据、执行契约、provenance、消费关系、复验状态。
- claim–run–artifact 三角；三类 claim 统一 ID；孤儿/环检测；失效沿下游传播（[09](09-系统架构与流程编排设计.md)）。
- 与 Karl 的差异：不是"有研究状态"，而是状态条目**可被 claim 级语法引用、可被失效传播命中、可阻断导出**。

**可证伪指标**

- 跨类型冲突检测率；`stale/orphan` 比例；跨类型查询成功率；一次变更影响的 claim/句/图召回。
- 当前只有 schema 设计，**没有实验**；这是 W2/W3 的基础设施工作。

**不能宣称**

- 一套本体适合所有学科；我们只承诺"可扩展的类型化 schema + 协调协议"。
- Karl 没有类型化记忆；公开材料不足以判断，不能这样说。

### G4 复现层级：结果复现 ≠ 过程复现 ≠ 证据链复现

**表现**

- RSI 家族主要报告 task success / reward / 每 token 得分；即使做复现，也停在"结果是否对上"。
- RRSI 的 harness 正则化、Dream-RSI 的世界回放，都是过程级机制，但没有把"运行→claim→句/图→导出"串起来。
- Karl 的产物层声称关联证据链，但公开材料没有 claim 级语法与传播规则。

**为什么加模块不够**

一份稿件可以"结果复现成功"但"写错"：数字来自另一次运行、图来自旧版本、结论外推到未支持的条件、引用与正文不匹配。**结果复现只覆盖三层中的第一层。**

**我们的对应**

- 三层可验证：结果复现、过程复现、证据链复现（[01](01-组会纪要-核心判断与优先方向.md) 判断 2）。
- RWJT/ECM：每个经验句绑定 `confirmed result_claim`，claim 绑 `RUN` 与 `EA`；每个数字/图/表有 `N/F/X` 槽；未解析槽位阻止导出（[08](08-反思与差异化工作方案.md) §2.1、[07](07-复现级验证与执行Harness设计.md) §10）。
- 六类槽与 claim 生命周期：S9 Claim Composer 只绑定不新建；Q1 做覆盖率/越级检查（[09](09-系统架构与流程编排设计.md) §5/§6）。
- 跨版本失效传播：数据/代码/协议变更 → claim/句/图三类处置（重跑/重写/仅复核）。

**可证伪指标**

- 计分数字 100% 绑 `EA(source=rerun)`；未解析槽位导出阻断率 100%；篡改数字/删图阻断率 100%；传播召回 ≥85%、误报 ≤20%。
- 对应 C2/C3 与 E2/E5（见 §6）。

**不能宣称**

- "首个复现 benchmark"；复现评测已有 PaperBench/REPRO-Bench 等。
- 语法绑定等于语义支持；槽位能绑到 claim，不代表 claim 支持该句。必须加专家抽样审计，把"无证据句"与"语义不支持句"分开报告。

### G5 反事实与信念修订：失败路径存而不用

**表现**

- Karl 把失败路径与被证伪假设写入研究状态，但公开材料没有给出"新证据出现时，何时重新启用旧假设"的判据。
- RSIAgent 把教训写入记忆，但冻结记忆意味着它不会主动撤销或重评。
- 两篇综述把反事实/因果列为开放问题；T6（验证、证伪与复现）在 [01](01-组会纪要-核心判断与优先方向.md) 中被标为空白最大的模块。

**为什么加模块不够**

存失败路径是"记忆"，不是"推理"。真正的难点是：新证据与旧结论冲突时，系统要能判断这是**噪声、条件变化、还是旧结论真的错了**；并决定修订信念、保留不确定性，或重新探索被否决的假设。这需要条件化的证据表示与可审计的决策记录，而不是再存一条"失败"。

**我们的对应**

- 证据冲突下的信念修订与假设再激活（[01](01-组会纪要-核心判断与优先方向.md) 方向 C）。
- 变更传播 + 三类处置；把"哪些 claim 失去支持"与"哪些假设值得再试"分开。
- 置信度与适用条件随 claim 一起存储；再激活必须带新证据与触发条件。
- 这是设计，不是已实现的因果引擎；我们不宣称解决因果推断。

**可证伪指标**

- 种子冲突场景上的再激活 precision/recall；信念校准；决策审计完整率；与"从不再激活"和"全部再激活"两个基线的对照。
- 对应 E4（见 §6）；当前 C3 只覆盖传播，不覆盖再激活。

**不能宣称**

- 我们的协议能区分"合理修订"与"无效反复探索"；这需要评测环境，尚未构建。
- 我们解决了反事实推理；我们只做证据记账与决策流程。

### G6 探索多样性：局部优化会收窄

**表现**

- Dream-RSI、MASS、SkillCAT 都在当前任务分布内做局部搜索/进化；RRSI 明确把"benchmark-specific"作为要抑制的对象。
- [01](01-组会纪要-核心判断与优先方向.md) 已引用两条反面证据：37,802 条 AI 生成想法的研究、Si et al.（ICLR 2025）的"个体新颖、群体趋同"。
- 两篇综述都把评测与开放式探索列为开放问题。

**为什么加模块不够**

多样性不是"加一个 temperature"或"加一个 diversity reward"就能解决；它涉及**问题选择**、**文献覆盖**、**失败路径的再利用**与**群体层面的同质化监测**。RSI 的局部改进越强，越可能把探索锁死在当前范式里。

**我们的对应**

- 群体同质化监测 + 多样性约束的探索奖励（[01](01-组会纪要-核心判断与优先方向.md) 主线二）。
- 与 T2 的 Idea 收敛、gap 卡、争议矩阵联动；在 S1/S4 阶段记录"被排除的方向"。
- 但这不是我们的旗舰；v1 不应把"解决同质化"作为主主张。

**可证伪指标**

- 语义多样性、不同研究问题数、novelty/feasibility 权衡、长时程探索收窄曲线。
- 对应 E6（可选）；如果零结果，如实报告并降级为"领域观察"。

**不能宣称**

- 我们的多样性护栏能解决群体趋同；这最多是一个待测机制。
- "多样性越高越好"；科研还要求可行性与证据支持。

### G7 治理、成本与责任：改进的代价与归属未入环

**表现**

- MASS 报告每 token 得分，RSIAgent 讨论成本，RRSI 用预算/剪枝；但都没有把**作者贡献、AI 使用披露、人类终审、错误责任**纳入循环。
- RSI 系统的输出越像论文，越需要回答"谁写的、谁验的、谁负责"；这不是模型能力问题，是科研治理问题。
- 我们的合规边界明确：AI 是草稿与检查工具，科学决策、实验安全、署名与最终责任在人；不代投稿、不伪造评审、不规避 AIGC 检测。

**为什么加模块不够**

在循环里加一个"伦理检查"按钮，不会产生责任链。责任链需要**产物级 provenance、角色分离、人类签核、可追溯的 AI 使用记录**，并且这些记录要能随稿件导出。

**我们的对应**

- 三权分离 + 人类终审；探索性运行不得写入证据图谱（[04](04-自动化研究与写作流水线.md) §2.10、[02](02-需求书-科研自动化与写作平台.md) FR-4）。
- 证据包包含 run 账本、`EA`、verdict、图包、AI 使用记录（[08](08-反思与差异化工作方案.md) 附录 A）。
- 评审模拟只作自检，不作为真实同行评审；不生成假评审、不自动投稿。
- 导出前人类签核；未解析槽位阻断。

**可证伪指标**

- provenance 覆盖率；人类签核覆盖率；AI 使用披露完整率；无 fake review；无自动投稿。
- 这些是**合规/工程指标**，不是论文主张；不要把它们包装成"科学发现"。

**不能宣称**

- 我们通过了法律/伦理认证；这只是设计约束。
- 人类终审等于没有责任问题；责任分配仍需机构政策与作者协议。

### 3.8 七条缺陷的覆盖度：哪些我们真的能接住

这张表是本文最重要的自我约束。**"设计上对应"不等于"已经解决"。**

| 缺陷 | 我们是否有对应机制 | 当前证据状态 | 是否被 C1–C4 覆盖 | 需要补的实验 |
| --- | --- | --- | --- | --- |
| G1 内部判定 | 独立 Judge、三权分离、R/W/J、导出硬门 | 设计 + SIM 演示 | C1/C2/C4 部分 | E2、E3 |
| G2 改进准入 | 四维准入、适用域判定、技能 provenance | 设计 | **未覆盖** | E1 |
| G3 记忆协调 | 类型化图谱、协调协议、claim ID、失效边 | 设计 | 未覆盖（基础设施） | schema 验证 + 传播测试 |
| G4 证据链闭合 | RWJT/ECM、六类槽、导出硬门、跨版本传播 | 设计 + SIM 演示 | C2/C3 覆盖 | E2、E5 |
| G5 信念修订 | 再激活判据、三类处置、条件化证据 | 设计 | C3 部分 | E4 |
| G6 多样性 | 同质化监测、探索约束 | 设计（非旗舰） | **未覆盖** | E6（可选） |
| G7 治理责任 | 三权分离、人类终审、AI 使用记录 | 约束 + 流程设计 | 非实证主张 | 合规审计清单 |

**结论**：我们目前能诚实地说"设计上覆盖 G1/G3/G4，部分覆盖 G5，尚未覆盖 G2/G6 的实证"。任何"七条都解决了"的说法都是过度承诺。论文的旗舰应锚在 **G1 + G4**（C1/C2/C3），G2 作为 W2/W3 的扩展，G5 作为方法论文的候选，G6/G7 作为限制与未来工作。RSI-Anything 的 promotion gate 是 G2 在**任务层**的强参照：它证明"增益 + 相对成本 + 冻结判定"可以工程化，但没有回答"这个改进是否值得写进论文、能写在哪句话里、撤销后哪些句子失效"。

## 4. 我们在坐标系里的位置

### 4.1 2×2：判定来源 × 判定对象

|  | 判定对象：任务 / 策略 / 技能 | 判定对象：科研证据链 / 稿件 |
| --- | --- | --- |
| **内部判定**（同模型、模拟器、框架内 verifier） | Dream-RSI、RSIAgent、MASS、SkillCAT、RRSI、RSI-Anything（世界模型预筛 + 任务内判定） | Karl（厂商口径；含人工监督）、ARIS / Auto-Empirical（事后审计） |
| **外部 / 独立判定**（独立重跑、外部专家、导出门） | OpenRSI / PaperBenchX（只判 R，不判 W） | **RWJT / ECM（本项目，设计）** |

**读法**：

- 左上角是 RSI 家族的主战场：它们把"能力"做得越来越强，但判定仍在内部。RSI-Anything 的 hidden judge 与判定封存提高了任务判定的干净度，但判定对象仍是任务成功/成本，不是稿件证据链。
- 左下角是执行验证：OpenRSI/PaperBenchX 有独立重跑，但停在 R 分，不写稿件。
- 右下角是事后审计：ARIS/Auto-Empirical 有账本/审计，但不阻断导出；Karl 有监督与产物，但公开材料没有 claim 级硬门。
- 右上角是空的：**独立判定 × 稿件证据链**。这就是 RWJT 要占的位置。
- "空"只代表本轮核验范围内未见完整实现，不代表永远没人做；Karl 已经离得很近。
- ARIS 的跨模型评审不是独立重跑；Karl 的人工监督是否构成独立判定，取决于未公开的流程。把它们放在"内部/事后"一格，是因为公开材料没有给出"独立重跑 + claim 级导出"的组合。

### 4.2 逐项接缝：它们停在哪，我们接在哪

| RSIAgent | 免训练记忆 + 先广后深探索 | 记忆准入、负迁移、撤销、verifier 成本 | 四维准入 + 适用域判定 + stale 传播 | 课程/探索器 |

**一句话**：我们不是把它们的循环再跑一遍，而是给它们的产出加一个**科学记录的准入与闭合层**。

## 5. 我们真正能主张的差异

### 5.1 三层主张

| 层 | 主张 | 为什么不是"加模块" | 证据状态 |
| --- | --- | --- | --- |
| N1 任务 | 定义 RWJT：在冻结协议与预算下，同时交付可复核复现与证据闭合稿件 | 改变了可行集：没有证据的稿件不再是可行解 | 设计；C1 未跑 |
| N2 契约 | claim–run–artifact 三角、六类槽、导出硬门、跨版本传播 | 把"可信"变成可判定、可阻断的运行时约束 | 设计 + SIM；C2/C3 未跑 |
| N3 测量 | R/W/J 分开、5 项过程指标、κ、B0–B5/A1–A5 | 让"联合判定是否有效"成为可证伪问题 | 设计；未跑 |

N0（Work/Judge、快照、图谱、UI）是集成，N5（验证瓶颈、闭合代价、R/W 可分性）是经验发现；二者都不单独宣称。这与 [08](08-反思与差异化工作方案.md) §3.1 一致。

### 5.2 四条主张与 RSI 缺陷的对应

| 主张 | 内容 | 主要对应缺陷 | 成功阈值 | 不成立时 |
| --- | --- | --- | --- | --- |
| C1 任务效度 | J 能区分 gold/partial/invalid，并与专家盲评一致 | G1、G4 | κ ≥0.60；R–W 相关 ≤0.7 | 拆报 R/W，J 降为参考 |
| C2 机制效应 | rerun-only + 槽位硬门降低无证据句，且不压垮覆盖 | G1、G4 | 无证据句相对降低 ≥50%；伪造通过 = 0；覆盖 ≥90% | 硬门退为工程结论 |

### 5.3 不可以宣称

| 不可以写 | 原因 | 可以改成 |
| --- | --- | --- |
| "We are an RSI system / general AI scientist." | 我们优化的是证据准入与闭合，不是自我改进循环；"通用"会触发与 Co-Scientist/ScientistTwo 的正面比较 | "We study the admission and evidence-closure layer for scientific improvements." |
| "首个复现—写作系统 / 首个证据账本 / 首个硬门." | ARIS/Auto-Empirical/Karl 都有账本或审计；"首个"无法在公开材料内证明 | "We define a joint task and formalize evidence closure at export time." |

## 6. 把"能解决"变成"已证明"：六个最小实验

> 这些实验与 [08](08-反思与差异化工作方案.md) 的 W1–W3 重叠，不新增一套人周口径。优先级：E2/E3/E5 是 W1/W2 的核心；E1/E4 是 W2/W3 的扩展；E6 可选，零结果也接受。

### E1 准入消融：单次成功 vs 四维准入

| 项 | 设计 |
| --- | --- |
| 针对缺陷 | G2 |
| 干预 | 五种策略：全部存储 / 全部不存储 / 仅重放 / 源任务克隆验证（SkillCAT 式）/ 四维准入 + 适用域判定 |
| 任务 | 源任务、相似任务、分布变化任务、跨任务组合；技能/经验条目统一格式 |
| 指标 | 迁移增益、负迁移率、retention@k、退化率、每个被接受条目的演化成本、拒绝精度/召回 |
| 基线 | 源任务克隆验证；RSIAgent 式冻结记忆；RSI-Anything 式 promotion gate（增益 + 相对成本；只作机制参照，不复现其系统） |
| Kill | 四维准入与克隆验证无显著差异，或拒绝精度过低导致可用经验被大量误杀 |
| 对应 | W2/W3；不直接对应 C1–C4 |

### E2 证据闭合消融：自报 / 事后审计 / 无硬门 / 完整 RWJT

| 项 | 设计 |
| --- | --- |
| 针对缺陷 | G1、G4 |
| 干预 | B0 自报；B1 事后审计（ARIS 式）；B4 有 R/W 但无硬门；B5 完整 RWJT（rerun-only + 槽位 + 导出门） |
| 指标 | 无证据事实句占比、伪造数字/引用通过数、核心 result claim 覆盖率、导出阻断率、人工干预次数 |
| 基线 | B0/B1/B4；不用外部系统的效果数字当基线 |
| Kill | 硬门只挡语法，不降低无证据句；或覆盖率跌破 90%，说明闭合靠"少写"而非"写对" |
| 对应 | C2；W1 |

### E3 同质 Judge vs 独立 Judge

| 项 | 设计 |
| --- | --- |
| 针对缺陷 | G1 |
| 干预 | 同一模型执行+评估（MASS 式默认闭环） vs 独立上下文 Judge + 干净重跑；可加"外部模型评估"作为中间条件 |
| 指标 | 假接受率（unsupported claim 被判通过）、相关错误率、评分与专家盲评的一致性、成本 |
| 基线 | 同模型自评；外部模型评估 |
| Kill | 独立 Judge 不改变假接受率，或成本高到不可用 |
| 对应 | C1/C2；W1。**注意**：MASS 已经报告外部 evaluator 的收益；我们不是重复它，而是测"独立重跑 + claim 绑定"是否进一步降低假接受 |

### E4 信念修订与假设再激活

| 项 | 设计 |
| --- | --- |
| 针对缺陷 | G5 |
| 干预 | 种子冲突场景：新证据支持/反驳/条件化旧结论；三种策略：从不激活 / 全部激活 / 条件化再激活（我们的协议） |
| 指标 | 再激活 precision/recall、信念校准、无效探索率、决策审计完整率 |
| 基线 | 从不激活；全部激活；简单阈值规则 |
| Kill | 条件化再激活不优于简单阈值，或收益被无效探索抵消 |
| 对应 | W2 扩展；C3 只覆盖传播，不覆盖再激活 |

### E5 跨版本失效传播

| 项 | 设计 |
| --- | --- |
| 针对缺陷 | G4、G5（部分） |
| 干预 | 50 个种子变更场景（数据/代码/协议/统计方法）；三类处置（重跑/重写/仅复核） |
| 指标 | 受影响 claim/句/图召回、误报、处置准确率、人工复核时间 |
| 基线 | 手工 diff；ARIS 式输入哈希 STALE；dashboard 边（只提示不传播） |
| Kill | 传播不如 STALE 哈希，或误报高到不可用 |
| 对应 | C3；W2 |

### E6 多样性护栏（可选）

| 项 | 设计 |
| --- | --- |
| 针对缺陷 | G6 |
| 干预 | 长时程构思：普通迭代 vs 同质化监测 + 探索约束 |
| 指标 | 语义多样性、不同研究问题数、novelty/feasibility、最终可验证收益 |
| 基线 | 普通迭代；Si et al. 式主题集（只作参照，不复现其结论） |
| Kill | 多样性提升但可行性/证据支持下降，或无可测差异 |
| 对应 | 非旗舰；零结果也写入负结果报告 |

**E7/E8（延伸，见 [11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md) §6）**：E7 测租约到期、依赖漂移与撤销传播下的跨循环继承与回滚；E8 测冻结留出集上的有/无资产对照与能力增益纵向归因。它们补上本文 E1–E6 没覆盖的"保留"与"增益"部分，不改变上述优先级。

**我们建议的最小可发表证据**：E2 + E3 + E5 + W3 的 κ 校准，足以支撑 Paper A（W1+W3）的核心主张；E1/E4 是 Paper B/W2 的扩展；E6 是可选的经验章节。**在这些实验跑出来之前，本文的所有"能解决"都应读作"设计上对应"。**

## 7. Steelman：如果审稿人站在这些工作一边

| 反方观点 | 我们的回应 | 我们承认什么 |
| --- | --- | --- |
| "RSI 系统有真实结果，你们只有设计。" | 正确。我们不在它们的基准上比分数；我们的贡献是任务定义与测量，必须先跑 C1/C2。 | 当前没有 empirical superiority；只有概念清晰度。 |
| "加一个外部 judge 不是研究。" | 研究点不是 judge，而是 `(run, manuscript)` 对的联合任务与导出闭合；judge 只是使能件。 | 如果 C1/C2 失败，这就退化为工程。 |
| "Karl 已经有研究状态、证据链、人工监督。" | 同意；我们的差异收窄到 claim 级语法、传播、导出硬门、独立重跑与可测准入。 | 公开材料不足以判断 Karl 的内部实现；不能贬低。 |
| "MASS/SkillCAT 已经能提升，为什么还需要准入？" | 它们提升的是 task-level；准入回答的是"哪些提升能长期保留、跨域复用、不产生负迁移"。 | SkillCAT 的克隆验证是准入的半步；我们不是从零开始。 |
| "证据闭合可以靠少写 claim 来刷。" | 所以必须有覆盖率约束、R/W/J 与专家审计；否则闭合是平凡的。 | 这是一个真实的可攻击点，E2 的覆盖率指标就是为此设计。 |
| "你们的机制是 workflow engineering，不是科学贡献。" | 任务定义 + 测量 + 失败分类是贡献；如果 C1/C2 不成立，我们接受"工程结论"的降级。 | 需要 W3 的规模与 κ 才能支撑"研究"而非"系统"。 |
| "RSI 系统很快会自己加上证据闭合。" | 可能。我们的护城河只能是交集（独立重跑 × 稿件写作 × 句级绑定 × 传播 × 中文核刊 × 导出门）+ 快速实验。 | 没有永久护城河；必须持续检索与迭代。 |

**最重要的自我批评**：我们目前最强的证据是"逻辑上确实缺一个联合判定"，最弱的证据是"我们的联合判定真的更好"。前者可以靠论证，后者只能靠 E2/E3/E5 与 κ。**不要把前者当成后者。**
