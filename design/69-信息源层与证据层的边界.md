# 69 · 信息源层与证据层的边界

> 2026-11-07。参考设计：「从 arXiv 关键词、Hugging Face Daily Papers 和 Trending
> 入口抓取候选论文，这一步解决的是**信息源**问题」。本轮核实这一判断对本项目是否成立，
> 并把缺的那一层补齐。

## 1. 判断：说得对，但只覆盖了链路的第一段

本项目的真实链路是：

```
候选发现(信息源) → 下载公开全文 → 本地解析成 span → S1 覆盖判定 → S2 候选 → G1 人签
     ↑ 本轮补这一层          ↑ 已有            ↑ 已有           ↑ 已有
```

**「抓到候选论文」不等于「有证据」**。这是本运行时相对期刊 skills 库的核心不变量：
span-only，摘要不能当全文证据。`--source openalex` 只返回摘要、`full_text()` 恒 None，
S1 会记 `full_text_unavailable`、0 span、Q0 blocked；`research_literature_fetch` 只下载
PDF，下载后仍须 `--source local --corpus-dir` 解析。所以信息源层必须**显式自称线索**，
否则「抓得多」很容易被误读成「证据够」。

## 5. 边界（不粉饰）

- **未实测联网抓取**：端点形态依据 Hub API 文档，本环境 `curl` 超时；不宣称「已能从 HF 抓到真实论文」。
- **不自动下载 HF 全文**：候选只给 arXiv id / 页面链接，需确认许可并自行取得；无付费墙绕过。
- **线索≠证据**：不生成 span、不改 Q0、不改 S1 默认行为、不写 Claim/EA/gate/signature。
- **MCP 侧无对应工具**：WorkBuddy 的 46 工具表未新增 `paper_discover`，属契约变化，本轮未做。
- 三路信号是**发现通道**，不是质量排序；`trending` 的热度不参与任何证据资格判定。
