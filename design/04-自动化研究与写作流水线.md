## 0. 设计原则

1. **证据先于文字（Evidence before prose）**：先有证据卡与论证骨架，再生成句子；不允许"先写漂亮话，再找引用"。
2. **先发散后收敛（Diverge then converge）**：Idea 阶段先生成大量候选，再用反思、辩论、Elo、去重与覆盖度组合收敛；不允许"一次生成一个方案直接执行"。
3. **先规划后写作（Plan then write）**：大纲不是目录，而是"每节要完成什么论证、需要什么证据"的契约。
4. **生成与核验分离（Generate–verify separation）**：Writer 不自证；Verifier 用独立检索与独立模型判定。
5. **人类检查点固定（Human gates）**：问题定义、Idea 短名单、实验设计、大纲、终稿五处必须人工确认；其余可自动。
6. **失败可归因、经验可准入（Failure routing & memory admission）**：失败按类型路由修复；成功经验通过验证后才写入长期记忆。

这六条分别对应 01 的判断 2（三层可验证）、判断 3（可证伪）、判断 4（功能分化）、判断 1（学习证据准入）、主线二（多样性）与 00 的 D1/D2。全流程对照见 `05-`。

## 1. 端到端状态机

```
S0 接入 ──[G0 人]──────────► 研究问题卡 + 资源/伦理约束
 │  问题 / 数据 / 代码 / 文献 / 目标体裁
 ▼
S1 文献调研 ──[Q0 自动+抽样]─► 文献地图 + claim 卡 + 争议矩阵 + gap 卡
 ▼
S2 Idea 发散 ─────────────► 20–50 条候选（机制/证据/可证伪条件）
 ▼
S3 Idea 收敛 ─[G1 人]─────► 反思→辩论→Elo→去重→进化→查新→组合→短名单
 ▼
S4 实验设计 ─[G2 人]──────► 设计卡（变量/对照/消融/样本量/指标/停止规则）
 ▼
S5e 探索执行 ─────────────► 试跑/调参/中间结果（不进 Judge、不进 claim）
 ▼
S5c 确证执行 ─────────────► Work→快照→干净 Judge 重跑→Verdict→结果卡 + EA
 ▼
S6a 候选图 ───────────────► 数据映射→代码→渲染→规则 QA（不绑定 claim）
 ▼
S7 论证骨架 ──────────────► 论证图（问题→gap→方法→证据→结论）
 ▼
S8 体裁大纲 ─[G3 人]──────► 章节 × 论证义务 × 证据需求 × 图计划 × 篇幅
 ▼
S6b 图计划定稿 ───────────► 选图→视觉 QA→caption→绑定 claim/run
 ▼
S9 证据卡组装 ────────────► Claim Composer：manuscript_claim + claim ↔ evidence
 ▼
S10 逐节生成 ─────────────► 引用槽/数字槽/图表槽草稿（只绑定，不新建 claim）
 ▼
S11 多角色批判 ───────────► 问题清单（证据/设计/结构/图表/语言）
 ▼
S12 定向修订 ─────────────► 修订稿 + diff + 修复记录
 ▼
S13 全稿核验 ──[Q1 自动]─► 引用/数字/图表/一致性/论证链报告
 ▼
S14 评审模拟 ─────────────► 审稿人式问题 + 证据化回应（P1）
 ▼
S15 人工终审 ─[G4 人]─────► 接受/退回/局部重写
 ▼
S16 导出与留痕 ─[G5]─────► Word/LaTeX/PDF + provenance + 使用记录
```

**增量环（P1）**：S1.8 定期检索新文献，只写入候选池；候选通过核验、抽取与 Q0 增量检查后才进入主链，不改变状态机主干。

## 2. 关键机制

### 2.1 证据接地生成（Grounded Generation）

**问题**：直接让模型"写一节"，模型会先产出流畅文本，再补引用；引用与句子往往是"事后贴合"，容易出现断章取义或伪造。

**做法**：把生成倒过来。

```
大纲中的一节
  → 拆出该节必须完成的 claim（3–7 条）
  → 为每条 claim 检索证据（文献段落 / 结果卡 / 数据表）
  → 生成"证据卡"（claim + 证据 + 支持强度 + 反证）
  → 按论证顺序组织证据卡
  → 生成散文：每个事实句必须挂引用槽或数字槽
```

**槽位语法（内部）**

| 槽位 | 含义 | 未填充时 |
| --- | --- | --- |
| `[[E:evidence_id]]` | 文献/结果证据 | 标 `[[TODO:claim_id]]`，不得编造 |
| `[[N:number_id]]` | 来自运行或数据表的数字 | 禁止模型自行生成数字 |
| `[[C:claim_id]]` | 跨节复用的结论 | 必须与图谱一致 |
| `[[L:limitation_id]]` | 限制/反例 | 讨论节必须至少一条 |

**解码约束**：生成后做一次"槽位审计"——事实句无槽位、槽位指向不存在证据、数字不在数字表中，均判为不合格并退回重写。

### 2.2 论证骨架（Argument Skeleton）

大纲只写"引言/方法/结果"不够，必须写清每节的**论证义务**：

| 章节 | 论证义务 | 常见失败 |
| --- | --- | --- |
| 引言 | 从领域重要性推到具体 gap，再推到本文做法 | 只堆背景，gap 不成立 |
| 方法 | 说明"为什么这样做能回答研究问题" | 方法罗列，缺选择理由 |
| 结果 | 每个结论对应一个可核查的结果 | 数字与图表不一致 |
| 讨论 | 解释机制、边界、反例 | 引入新 claim 却无证据 |
| 结论 | 回收研究问题，不夸大范围 | 范围膨胀（scope inflation） |

**论证图检查**（自动）：

- 孤立 claim：没有任何证据边；
- 断裂链：从 gap 到方法、从结果到结论缺边；
- 范围膨胀：结论覆盖范围大于证据覆盖范围；
- 循环论证：claim A 支持 B，B 又支持 A；
- 证据冲突：同一 claim 存在支持与反驳边但未讨论。

**大纲评审**（参照 AutoSci `paper-plan` `[工程参考]`）：G3 前增加独立 Reviewer，以领域主席视角检查"每节是否真的支撑某条 claim、图计划与引用计划是否齐全、篇幅是否匹配体裁"；大纲评审是 G3 的输入，不替代人审。

### 2.3 多角色编排

| 角色 | 职责 | 输入 | 输出 | 是否可被同一模型兼任 |
| --- | --- | --- | --- | --- |
| Planner | 拆解任务、排预算、定检查点 | 项目对象 | 计划 DAG | 否（与 Writer 分离） |
| Librarian | 检索、去重、元数据核验 | 查询 | 文献与片段 | 可 |
| Analyst | 执行代码、产出结果卡 | 数据/代码 | 运行记录、图表 | 可 |
| Architect | 论证骨架与大纲 | gap/结果 | 论证图、大纲 | 否（与 Writer 分离） |
| Writer | 逐节生成 | 证据卡/大纲 | 草稿 | — |
| EvidenceCritic | 检查 claim 是否有支撑 | 草稿/图谱 | 问题清单 | 否（独立上下文） |
| MethodCritic | 检查设计与结论匹配 | 方案/结果 | 问题清单 | 否 |
| StructureCritic | 检查章节义务与论证链 | 大纲/草稿 | 问题清单 | 可合并 |
| StyleCritic | 术语、时态、学术风格 | 草稿 | 问题清单 | 可合并 |
| Verifier | 引用/数字/一致性核验 | 草稿/外部源 | 三态报告 | **必须独立** |
| Editor | 汇总问题、执行修订、维护 diff | 问题清单 | 修订稿 | 可 |

**关键约束**：

1. Writer 与 Verifier 不共享上下文，避免"自己写、自己批"。
2. 高风险判定（引用真实性、数字一致性）优先用规则与外部源，不交给 LLM 单独决定。
3. 难度路由：普通段落用便宜模型，方法/讨论/创新点等高风险段落升级到强模型；由 Planner 按预算分配。
4. 所有角色调用记录 token、耗时、成本，进入项目账本（参考 SoL-Pi 对 token 经济的处理思路 `[工程参考]`）。

### 2.4 批判—修订闭环

**问题对象**

```json
{
  "id": "ISS-0042",
  "type": "evidence_gap | method_mismatch | structure | consistency | style",
  "severity": "P0 | P1 | P2",
  "location": {"section": "discussion", "span": [120, 180]},
  "claim": "该机制在低资源场景下仍有效",
  "evidence": ["E-118", "R-07"],
  "suggested_fix": "补充低资源子集结果，或缩小结论范围",
  "confidence": 0.78
}
```

**路由规则**

| 问题类型 | 修复路径 |
| --- | --- |
| evidence_gap | 回到 S1 补检索、S9 补证据卡；仍找不到则改写成限制或删除 claim |
| method_mismatch | 回到 S4 改设计卡或 S5c 重跑；不允许只改措辞 |
| structure | 回到 S7/S8 重写论证骨架或大纲，再调整段落顺序 |
| consistency | 以数字表/结果卡/图谱为准，批量修正 |
| style | 局部编辑，不改事实 |

**停止条件**（满足其一）

- 无 P0 问题且 P1 ≤ 阈值；
- 达到 2 轮修订；
- 边际收益低于成本阈值；
- 预算耗尽（此时输出"未完成清单"，不得伪装完成）。

**防回归**：每轮修订后重跑核验；新增事实错误率 > 5% 则回滚该轮。

### 2.5 质量门

| 门 | 时点 | 类型 | 检查 | 不通过时 |
| --- | --- | --- | --- | --- |
| Q0 | S1 之后 | 自动 + 抽样人审 | 来源覆盖、身份核验、覆盖率回执、span 完整性、争议矩阵、gap 可检验性 | 回补检索/抽取，禁止进入 S2 |
| G0 | S0 之后 | 人 | 问题是否清晰、材料是否足够、体裁是否支持、伦理与数据边界 | 退回补充材料 |
| G1 | S3 之后 | 人 | 候选是否够多、机制簇是否覆盖、可证伪条件与证据边是否齐全 | 重做发散/收敛 |
| G2 | S4 之后 | 人 | 变量—对照—样本量—指标—停止规则—资源是否闭环 | 改设计卡，禁止进入执行 |
| G3 | S8 之后 | 人 | 章节义务、论证链、证据需求、篇幅是否齐全 | 重规划大纲 |
| Q1 | S13 | 自动 | 引用、数字、图表、跨节一致性、无证据 claim、结构；span 锚定诚信审计（BLOCK/WARN） | 回 S12 定向修订 |
| G4 | S15 | 人 | 科学价值、结论边界、责任、署名、AI 使用声明 | 退回 |
| G5 | S16 之前 | 自动 + 人签核 | provenance/使用记录完整、模板可解析、导出字段齐全 | 阻止导出 |

**门的所有权**：G0–G4 的通过必须由具体的人签字（记录 user_id 与时间）；Q0/Q1/G5 由规则与独立 Verifier 判定，人只处理例外与抽样。任何门不得由生成该内容的同一角色自行放行（对应 01 判断 4）。

### 2.6 失败归因与修复路由

失败不笼统重试，先归类（对应 00 D2 的失败归因）：

| 类型 | 典型信号 | 判定方式 | 修复 |
| --- | --- | --- | --- |
| 数据失败 | 缺失、版本错、分布异常 | 检查数据卡与运行日志 | 换数据/补数据 |
| 代码失败 | 异常、超时、结果不稳定 | 重放最小用例 | 修代码/固定种子 |
| 假设失败 | 结果与预期相反 | 反事实重放：改假设后是否复现 | 改假设/缩小结论 |
| 证据失败 | 引用不支持、来源冲突 | 独立检索 + 上下文判定 | 换证据/降级 claim |
| 写作失败 | 结构断裂、范围膨胀 | 论证图检查 | 重写大纲/段落 |
| 评测失败 | 指标定义错、泄漏 | 审查评测协议 | 重设指标 |

**反事实重放**：对候选原因做最小干预，重跑受影响的最小单元；若失败消失，则该原因是根因。归因结果写入失败记忆，按"任务特征 + 失败类型 + 修复动作"索引。

### 2.7 记忆与技能复用

四类记忆（对应 01 判断 5）：

| 类型 | 内容 | 写入条件 | 消费方 |
| --- | --- | --- | --- |
| 文献关系 | 论文、主题、支持/批评/演化关系 | 元数据核验 + 关系证据 | 检索、综述、引言 |
| 领域知识 | 概念、方法、指标、常见陷阱 | 多源一致或专家确认 | 规划、写作 |
| 假设与证据 | 假设、支持/反驳证据、置信度 | 证据边 + 时间戳 | 构思、讨论 |
| 执行经验/技能 | 脚本、修复策略、写作模板 | 通过验证门槛 | 执行、修订 |

**写入门槛**（对应 01 判断 1）：原任务成功只是必要条件，还需

1. 重放可复现；
2. 在至少一个相似任务上有效；
3. 在分布变化任务上无严重负迁移；
4. 演化/维护成本可接受。

**适用域判定**（对应 01 方向 A）：复用前检查领域、数据分布、体裁、依赖版本、评价口径；不满足则"先小样本测试"，测试不过则拒绝复用。技能卡必须记录适用条件与否决案例。

### 2.8 多样性与反趋同（P2）

- 构思阶段以"一组候选"为单位优化：覆盖度（机制簇）、新颖性、可行性、成本。
- 显式惩罚与主流方向的语义相似度；保留"高风险高回报"配额。
- 评测不只看单条最佳，还看组合覆盖（对应 01 主线二与 00 D3）。

### 2.9 Idea 发散与收敛（S2–S3）

**发散：要的是机制多样性，不是措辞多样性。**

- 输入：问题卡、文献地图、**claim 卡、争议矩阵、gap 卡**、负结果、数据与资源约束。
- 生成角色分工：机制型（从因果机制出发）、类比型（跨领域迁移）、反主流型（挑战默认假设）、工程型（从可执行性反推）、交叉型（相邻学科方法）、**局限驱动型（从论文局限反推）**。
- 每条候选写成 **Idea 卡**：

```json
{
  "id": "I-017",
```

### 2.10 实验设计卡与执行 provenance（S4–S5e/S5c）

**设计卡是一等产物**，不是方法节的草稿。没有设计卡不得执行，也不得开始写作。

| 字段 | 内容 | 缺失后果 |
| --- | --- | --- |
| 假设 | H0/H1，方向明确 | 结果无法判定支持/反驳 |
| 变量 | 自变量、因变量、控制变量 | 混淆无法排除 |
| 对照 | 基线、阴性/阳性对照 | 竞争解释无法区分 |
| 基线复现 | 人类 SOTA / 官方实现的代码、数据、超参与环境；同协议复跑 | "打赢 SOTA"不可信；只能标"未复现" |
| 消融矩阵 | 每个增益对应哪组消融；负对照；预期方向 | 增益不可归因；G2 不通过 |
| 试跑与扩量 | 子集、成功判据、扩量条件、终止条件 | 全量浪费；早期错误被掩盖 |
| 样本量/功效 | 先验估计或最小可检测效应 | 结论超出统计效力 |
| 数据与预处理 | 版本、划分、泄漏检查 | 不可复现 |
| 指标与检验 | 主指标、次指标、统计方法 | 事后挑指标 |
| 停止规则 | 成功、失败、无效、提前停止 | 无限试错 / p-hacking |
| 混杂与偏差 | 已知混杂、选择偏差、标注偏差 | 结论脆弱 |
| 可证伪预测 | 什么结果会推翻假设 | 假设不可检验 |
| 资源与安全 | 算力、时间、伦理、数据权限 | 执行中断或越界 |

**执行规则**

1. 设计卡编译成机器可读 protocol（YAML/JSON），执行器只认 protocol，不认自然语言。
2. **同协议基线复现**：可比任务必须在同一数据划分、指标与环境下复跑基线；基线结果与论文报告不一致时，记录偏差并同时报告两套数字，不得只挑有利的一套。
3. **先子集试跑**：在小规模子集上验证代码、指标与停止规则；试跑失败不得扩量。是否扩量由独立 Evaluator（Subset Critic）判定，执行者不得自决。
4. 全量运行后产出 **结果卡**：`run_id`、代码 commit、镜像/依赖、参数、随机种子、指标、图表、日志、异常、试跑与基线复现记录。
5. 结果判定保持三态：`support / refute / inconclusive`；`partial_support` 归入 `inconclusive`，并强制生成补充实验设计卡。判定由独立 Evaluator 按 G2 冻结的成功判据执行，执行者不得自判。
6. 指标定义在 G2 后冻结；确需修改则新建版本并重跑全部对照与消融。
7. 湿实验只生成 protocol、材料清单与人执行记录表，由人执行并回填（P2）；系统不伪造湿实验数据。
8. **探索与确证分离**：探索性运行（如候选搜索、超参扫描）在隔离目录进行，使用不可变候选快照，不写 claim、不写证据图谱；确证性运行必须冻结 protocol 并经人批准。只有确证性结果可进入结果卡、图表与写作。
9. **确证运行走 RWVH**：S5c 使用**人工冻结的 TaskSpec**（v1；任务作者提供 environment/tests/rubric，经 oracle/nop 校准）→ Work 执行 → 提交快照 → 干净 Judge 重跑 → `Verdict` → 结果卡 + `EA`。只有 `scored` verdict 能创建 `result_claim`；`verifier_error/infrastructure_error` 不记 0 分，写 `FailureRecord` 后重试或路由（见 §2.14.1）。设计卡 → TaskSpec 自动编译属于 P1，不进入 v1。
10. **S5e 回环**：探索结果若改变变量、对照、指标或停止规则，必须新建设计卡并重签 G2；旧 protocol、TaskSpec 与 run 标 `superseded`，不得在旧 G2 下继续 C 车道。

**消融回环**（参照 AutoSci `/exp-design` `[工程参考]`）：消融不是一次性表格，而是闭环。每批消融把因子分为 `essential / contributing / marginal / harmful`；`marginal` 或 `harmful` 触发方法简化与重新规划，最多 2 轮；每轮保留版本、删除的因子与理由。禁止"消融失败后只改措辞"。

**试跑判定分离**（参照 AutoSci `/exp-pilot-run` 与 `/exp-pilot-eval` `[工程参考]`）：执行试跑的上下文不判定成败；独立 Evaluator 按预注册成功判据给出 `pass / fail / inconclusive`。失败时把 `failure_reason` 写入负结果记忆，防止同一假设被反复提出。

**provenance 链**：设计卡 → protocol → TaskSpec → 基线复现 → run → verdict → `EA` → 结果卡 → 图表 → `result_claim` → 稿件句。任一环缺失，下游 claim 自动降级为"待证"；探索性 run 不在链上。

### 2.11 图表流水线（S6a/S6b）

图表按"结论—数据—代码—图—文"的顺序生成，不允许先画图再解释。S6a 在 S5c 后生成候选数据图，只证明"数据能画出什么"，不绑定 claim；S6b 在 G3 后按大纲的图计划定稿，只保留支撑论证的图并逐图绑定 claim/run。

| 阶段 | 步骤 | 产物 | 检查 |
| --- | --- | --- | --- |
| S6a | 数据映射 | 字段 → 轴/颜色/分组/误差 | 字段缺失则拒绝生成 |
| S6a | 绘图代码 | 可复现脚本 + 数据快照 + 代码哈希 | 固定版本与种子 |
| S6a | 渲染 + 规则 QA | SVG/PDF/PNG + 源数据 | 分辨率、字号、字体、轴标签、单位、误差棒、样本量 |
| S6b | 图 brief + 图计划 | 这张图支撑哪条 claim、读者应得出什么结论 | 无 claim 的候选图不进入图计划 |
| S6b | 视觉 QA | 遮挡、截断、图例歧义、误导性尺度 | VLM 只做初筛，人做终判 |
| S6b | Caption | n、误差定义、统计检验、数据来源 | 与图、正文数字一致 |
| Q1 | 图文一致 | 正文/摘要/caption 的数字与图数据比对 | 冲突列为 P0 |

**边界**：示意图与结果图分开标注；示意图不得伪装成实验图；所有定稿图记录 `figure_id → data → code → render → claim → run`，供结论失效追踪（FR-10）使用。S6b 之后不得临时加图；新增图必须回 S8 更新图计划并重过 G3。

### 2.12 评审模拟与返修准备（S14，P1）

- **多角色**：方法评审、领域评审、统计评审、写作评审、伦理评审；各角色独立上下文。
- **意见必须可定位**：每条意见绑定章节、段落、claim 与证据；禁止"创新性不足"这类无定位意见。
- **三分类**：可直接回应（有证据）、需补实验（列入计划）、无法支持（降级结论）。
- **意见原子化**（参照 AutoSci `/rebuttal` `[工程参考]`）：每条意见编号为 `Rv-C`，映射到 claim、章节或实验；回应前先做证据追溯，再做"审稿人追问"压力测试。未映射到证据的意见不得直接生成回应。
- **对抗评审**（参照 ARIS `kill-argument` `[工程参考]`）：关键稿件增加双线程演练——线程 A 写最强的 200 字拒稿备忘录，线程 B 逐点防守并列出仍未解决的问题；用于发现"礼貌性评审"漏掉的方法论问题。
- **Rebuttal Planner**：把"需补实验"转成新设计卡（回 S4），把"无法支持"转成降级/删除 claim；不得用措辞改写替代证据。
- **失败分流**：不同层级的问题回到不同阶段，不能都用改写解决。

| 失败层级 | 典型意见 | 回退 | 重过门 |
| --- | --- | --- | --- |
| 文本层 | 结构、表达、格式 | S12 | Q1 |
| 证据层 | 引用不支持、数字不一致、条件扩大 | S9 证据卡 / S1 claim 卡 | Q1；改证据则重过 Q0 |
| 实验层 | 缺对照/消融、子集失败、不显著 | S4 新设计卡 → S5c | G2 |
| 贡献层 | 增量不足、被最近工作覆盖 | S2/S3 重新收敛 | G1 |

贡献层回退必须保留原短名单与淘汰理由，防止"评审不过就换故事"；同时触发受影响 claim 的失效传播（F5），不得保留已失效结论继续导出。三级的完整失效范围、重签门禁与次数上限见 [`09-系统架构与流程编排设计.md`](09-系统架构与流程编排设计.md) §6.8。

- **回应只用已有证据**：需补实验的写成"计划补做"，不得写成"已完成"。
- **安全门**（参照 ARIS `[工程参考]`）：无伪造 claim、不过度承诺、覆盖全部主要意见。
- **校准**（ScientistTwo 教训）：评审器与生成器尽量异构；自动评审分只作初筛，质量结论必须报告人工盲评与 ICC/κ。
- **定位**：评审模拟是自检工具，不模拟真实同行评审、不代替期刊审稿、不生成虚假审稿意见。

### 2.13 文献阅读技能契约（S1）

完整调研、机制拆解与指标见 [`06-文献阅读技能与综述流程.md`](06-文献阅读技能与综述流程.md)。这里只定义流水线必须遵守的接口。

**七个产物**：`reading_plan`、`source_record`、`paper_card`、`claim_card`、`contradiction_matrix`、`gap_card`、`review_memo`。

**三条硬规则**：

1. 未通过身份核验的文献不得生成可引用的 claim 卡；
2. 没有可定位 span 的 claim 不得作为写作证据；
3. claim 的抽取者与复核者必须独立上下文，Q0 不得由抽取者或综合者放行。

**阅读深度**：D0 元数据 / D1 速读 / D2 方法与结果 / D3 复现 / D4 对抗性阅读；深度由文献在论证图中的角色决定，不由论文重要性决定；升级需写理由，降级需删除依赖该深度的 claim。

**Q0 出口检查**：来源覆盖 ≥ 2 类、覆盖率回执完整、核心 claim span 100%、反向证据全部入矩阵、gap 有可检验推论、核心 claim 独立复核 ≥ 20%、抽样人审 10%、claim 边无断链。

**增量监测（P1）**：新文献先入候选池，默认只通知；只有显式开启且高置信的候选才可申请入图谱，并入图谱前必须重走核验、抽取与 Q0 增量检查。发现、写入、体检三权分离（参照 AutoSci `discover / ingest / check`）。

**与下游的接口**：

- S2 的候选必须引用 `claim_id` 与 `gap_id`；
- S3 的短名单必须附查新报告（最近工作、delta、verdict、复活条件）；
- S9 的证据卡从 `claim_card` 派生，保留条件与反向证据；
- S13 发现正文扩大条件范围时，回写 claim 卡并触发失效标记。

### 2.14 全链路接口契约与不变量

阶段之间不能靠"自然语言交接"，否则证据会在传递中丢失。所有产物共用一个信封：

```json
{
  "artifact_id": "D-0007",
  "type": "design_card | result_card | claim_card | evidence_card | outline | draft | issue | review | figure_package | task_spec | run | submission | verdict | evidence_artifact",
  "project_id": "P-001",
  "stage": "S4",
  "version": 3,
  "status": "draft | frozen | superseded | invalid",
  "inputs": ["I-017", "G-007", "CL-0042"],
  "produced_by": {"role": "architect", "run_id": "run-20261019-004"},
  "verified_by": [{"role": "verifier", "run_id": "run-20261019-009", "gate": "G2"}],
  "created_at": "2026-10-19T10:00:00Z",
  "content_hash": "sha256:..."
}
```

**ID 约定**：`P` 项目、`PR` 问题卡、`SR` 来源记录、`PC` 论文卡、`CL` claim、`G` gap、`I` Idea、`D` 设计卡、`R` 结果卡、`F` 图包、`S` 大纲/章节、`E` 证据卡、`ISS` 问题、`RV` 评审/回应。RWVH 追加：`T` TaskSpec、`RP` RunPlan、`RUN` 运行、`SUB` 提交、`V` verdict、`RI` rubric 条目、`EA` 证据产物、`FR` 失败记录。

**八条不变量**：

1. **无上游 ID 不生成**：任何产物必须列出 `inputs`；没有来源的段落只能进入"待证区"，不得混入正文。
2. **冻结即版本**：G0–G5/Q0/Q1 绑定产物的 `version + content_hash`；冻结后的修改必须升版本，禁止原地改写。
3. **失效向下传播**：上游变为 `invalid/superseded` 时，下游自动标 `stale`，必须重验或重算，不得静默继续。
4. **生成/执行/判定分离**：同一上下文不得既产出又放行；Q0/Q1 由独立 Verifier 判定，实验由独立 Evaluator 判定。
5. **无重跑证据不做结果 claim**：`result_claim` 只能由 `scored` verdict 创建，证据必须是 `EA(source=rerun)`；候选生成物、旧日志、Work 自报不算证据。
6. **无结果 claim 不写数字**：稿件中的数字、图、实验结论必须绑定 `R / X / N / F` 槽；未解析槽位阻止导出。
7. **无冻结协议不做确证运行**：C 车道运行必须绑定 G2 冻结的 protocol 与 TaskSpec；E 车道运行不得进入 Judge，也不得进入 claim 图。
8. **判定不可被被判定者修改**：Judge 只读快照；Work 不可见 `/tests`、rubric、参考解；`verifier_error / infrastructure_error` 不记 0 分。

**关键转移规则**：

| 转移 | 前置条件 | 冻结对象 | 不满足时 |
| --- | --- | --- | --- |
| S0 → S1 | G0 签署；问题、材料、体裁、资源与伦理边界齐全 | 问题卡 | 回 S0 补材料 |
| S1 → S2 | Q0 通过；claim/gap 卡冻结 | 文献地图、claim 卡、gap 卡 | 回补检索/抽取 |
| S2 → S3 | 候选 ≥ 20；每条有证据边与可证伪条件 | 候选全集 | 补发散 |
| S3 → S4 | G1 签署；短名单 ≤ 5；每条附查新报告 | 短名单 | 回 S2/S3 |
| S4 → S5e（探索） | G2 签署；protocol 冻结；试跑成功判据已登记；E 车道不进入 Judge | 设计卡、protocol | 禁止执行 |
| S4 → S5c（确证） | G2 签署；protocol + TaskSpec 冻结；oracle 通过 | 设计卡、protocol、TaskSpec | 禁止确证运行 |
| S5c → S6a | verdict 为 `scored`；`EA` 已绑定；探索性 run 已排除 | 结果卡 + `EA` | 不得作图或写作 |
| S6a → S8 | 候选图有数据映射、代码哈希与规则 QA；未绑定 claim | 候选图包 | 不得直接引用 |
| S7 → S8 | 论证图无孤立 claim、无循环、无范围膨胀 | 论证图 | 重规划 |
| S8 → S6b | G3 签署；每节有论证义务与证据需求；图计划列明每图支撑的 claim | 大纲 + 图计划 | 不得临时加图 |
| S6b → S9 | 定稿图冻结；数据快照、代码哈希、claim/run 绑定齐全 | 图包 | 不得被引用 |
| S9 → S10 | 每个事实句有 `manuscript_claim`；每个数字/图有 `N`/`F` 槽；无 claim 越级 | `manuscript_claim` + 证据卡 | 退回 S9；S10 不得新建 claim |
| S12 → S13 | P0 问题全部关闭或有显式例外 | 修订稿 | 不得声称完成 |
| S13 → S14 | Q1 通过；槽位解析率 100%；事实句 claim 覆盖率 100%；越级/重复 span 0；无 stale 句 | 核验报告 | 回 S12 |
| S14 → S2/S3（研究级回退） | 评审判定贡献不成立；有最近工作或反证证据 | 新候选版本 | 重过 G1；禁止直接改写结论 |
| S15 → S16 | G4/G5 签署；provenance 完整；导出硬门通过（槽位、重跑证据、引用、stale） | 终稿、交付包 | 阻止导出 |

**失效传播示例**：

| 上游事件 | 直接失效 | 下游动作 |
| --- | --- | --- |
| 论文撤稿/更正 | 依赖该 span 的 claim | 证据卡降级；正文替换或删除 |
| 确证 run 变为 `invalid/superseded` | 该 run 产生的 `result_claim`、图、表 | 下游句子标 `stale`；重跑或重写；旧版本保留 |
| Judge 返回 `candidate_invalid` | 该提交不计分 | 回 S5c 修复候选并重新提交；不得写成结果 |
| Judge 返回 `verifier_error/infrastructure_error` | 该提交不记 0 分 | 修复环境后重跑；写入 `FailureRecord` |
| protocol 变更 | 结果卡、图、相关 claim | 重跑并重算，旧版本标 `superseded` |
| 数字变化 | 图表、摘要、结果节 | 触发 Q1 数字核对 |
| G3 后大纲变更 | 受影响章节 | 重生成对应节，保留 diff |
| claim 降级（含 `manuscript_claim` 越级被 Q1 驳回） | 论证图、摘要、结论 | 缩小结论范围并重写；越级时先改 claim 等级，不得只改措辞 |
| 评审要求补实验 | 新设计卡 | 回 S4，完成后重新进入 S5c–S13 |

### 2.14.1 RWVH 接入：S5c 确证运行、S13 核验与 S16 导出

> 完整设计见 [`07-复现级验证与执行Harness设计.md`](07-复现级验证与执行Harness设计.md)；这里只定义流水线必须遵守的接口。

**两条执行车道**：

| 车道 | 目的 | 是否进 Judge | 是否可进 claim | 对应状态 |
| --- | --- | --- | --- | --- |
| E 探索 | 试跑、调参、找方向 | 否 | 否 | S5e |
| C 确证 | 产生要写进稿件的结论 | 是 | 是（仅 `scored`） | S5c / X0–X7 |

**新增对象**：

| 对象 | ID | 作用 | 关键字段 |
| --- | --- | --- | --- |
| TaskSpec | `T-` | 任务包契约 | `task.toml`、instruction、environment、tests、solution、rubric digest、canary |
| RunPlan | `RP-` | 一次运行的计划 | 资源、网络策略、超时、提交上限、成本上限 |
| Run | `RUN-` | 一次 Work/Judge 运行 | status、best_score、rounds、timed_out、runtime |
| Submission | `SUB-` | 一次提交 | snapshot、report、exit_code |
| Verdict | `V-` | 判定结果 | R/W/J、status、failure_class、rubric 版本 |
| EvidenceArtifact | `EA-` | 重跑证据 | path、sha256、source、run_id、单位/精度 |
| FailureRecord | `FR-` | 失败归因 | 类别、阶段、重试、人工路由 |

**RWVH 契约**：

1. **TaskSpec 冻结**：任务包与 rubric digest 在运行前冻结；Work 不可见 `tests/`、rubric、参考解。
2. **提交快照**：`rsi-submit` 等价动作暂停 Work，快照文件系统；Judge 只读挂载；快照外文件不得进入 Judge。
3. **干净重跑**：Judge 从干净镜像启动，删除候选生成物，只认重跑产物；`EA.source=rerun` 才可准入。
4. **判定独立**：Judge 不读 Work 可写状态；`candidate_invalid / verifier_error / verifier_timeout / infrastructure_error / submission_error` 分开记录；infra 失败不记 0 分。
5. **结果回写**：只有 `scored` verdict 能创建 `result_claim`；`R` 槽绑定 `result_claim`，`X` 槽绑定 `RUN`，`N` 槽绑定 `EA`，`F` 槽绑定图包。
6. **导出硬门**：所有 `R/X/N/F` 槽可解析；计分数字 `source=rerun`；无 `stale/orphan/blocked` 句；引用真实率 100%；证据包完整；否则阻止导出。
7. **失效传播**：run 失效 → result claim 失效 → 稿件句/图失效；旧版本保留，不原地改写。
8. **claim 创建边界**：S1 只建 `literature_claim`，S5c 只建 `result_claim`，S9 由 Claim Composer 建 `manuscript_claim`；S10 只绑定槽位、不新建 claim。Q1 检查事实句 claim 覆盖率 100%、越级 0、重复 `sentence_span` 0、孤儿 `manuscript_claim` 0。

**评分与失败**：`R = 0.30M + 0.30E + 0.40V`；`W = 0.30C + 0.25N + 0.15F + 0.15Cite + 0.15G`；`J = 0.55R + 0.45W`。科学失败标 modeling / execution / validation / writing / genre；基础设施失败与候选失败分开。

**v1 任务**：T1 ML 复现、T2 计算科学复现（P1）、T3 从冻结产物写一节、T4 复现 + 写作（RWJT 旗舰）；单次 Judge ≤ 30 分钟、CPU 或 1 卡、单任务成本 ≤ 50 元。

## 3. 体裁适配

### 3.1 三种体裁的结构与义务

| 体裁 | 核心章节 | 特有义务 | 证据类型 |
| --- | --- | --- | --- |
| 中文核刊论文 | 摘要/引言/方法/结果/讨论/结论 | 贡献可复现、图表自洽、引用规范 | 文献片段 + 运行结果 |
| 项目申报书 | 立项依据/研究内容/目标/方案/创新/基础/计划/预期成果 | 内容—目标—方案—成果对齐；创新点可落到内容 | 文献 + 前期结果 + 可行性证据 |
| 学位论文 | 绪论/综述/方法/实验/讨论/结论 | 系统性、章节衔接、工作量可见 | 文献 + 多章结果 |

### 3.2 核刊论文的生成规则

- **摘要**：数字必须来自结果卡；结论强度不超过结果覆盖范围；不出现正文没有的贡献。
- **引言**：至少 3 层——领域问题、已有工作及其不足、本文做法与贡献；每个"不足"必须有引用或结果支撑。
- **方法**：每个关键选择给出理由；可复现信息（数据、参数、环境）完整；不得省略失败尝试而不说明。
- **结果**：每个数字挂 `[[N:...]]`；图表标题与正文数字一致；统计检验与样本量匹配。
- **讨论**：限制与反例至少一条；新 claim 必须有证据；不得把相关性写成因果。
- **结论**：逐条回收研究问题；不引入新结果。

### 3.3 申报书的生成规则

- **立项依据**：从国家/领域需求到具体科学问题，再到 gap；"国际领先/首次"类表述必须有证据或删除。
- **研究内容**：每条内容对应一个目标、一个方法、一个可交付结果；禁止"内容—目标"两张皮。
- **创新点**：每条创新点必须能映射到研究内容与证据；区分"方法创新"与"应用场景"。
- **可行性**：前期基础必须可追溯（论文、专利、预实验、数据）；不能只写"团队实力强"。
- **预期成果**：可量化、可验收；不与研究内容脱节。
- **论证链检查**：问题→内容→方法→创新→成果，五段必须连成一条链；断链处标 P0。

### 3.4 体裁插件接口

```yaml
genre: cs_journal_cn
sections:
  - id: intro
    obligations: [field_context, gap, approach, contributions]
    evidence: [literature_span]
    max_ratio: 0.15
  - id: method
    obligations: [design_rationale, reproducibility]
    evidence: [literature_span, run_record]
rules:
  citation_style: GB/T 7714
  number_policy: from_run_only
  claim_strength: bounded_by_evidence
```

新增体裁只写 schema 与规则，不改核心流水线（对应 02 FR-11）。

## 5. 质量评测与实验设计

### 5.1 任务构造：从材料到长文

不做"给标题写论文"（无法验证事实），而做**材料约束写作**：

- 输入：研究问题、数据、代码、运行结果、相关文献（含干扰项）；
- 任务：生成该研究的论文/申报书；
- 参考：原作者稿件（不提供给系统）；
- 评测：事实支持、引用可信、结构、一致性、专家偏好。

这样"好"才有客观锚点：**说的每件事都能在材料里找到依据**。

全流程评测不能只评终稿，还要评过程产物：

| 任务集 | 输入 | 评什么 | 主要指标 |
| --- | --- | --- | --- |
| 阅读集 | 100 篇中文版面 + 50 篇英文方法论文 + 30 组争议对 + 100 条伪引 | 能否找全、核验、抽取 claim、定位 span、识别冲突 | 来源覆盖、伪造召回、claim F1、span 准确率、争议召回、Q0 通过率 |
| Idea 集 | 50 个研究主题（含领域与资源约束） | 候选的新颖性、可行性、可证伪性、机制覆盖 | 专家 top-3 命中率、重复率、机制簇数、查新命中率 |
| 设计集 | 30 个假设 + 数据/资源约束 | 设计卡能否被专家认可、能否执行 | 检查表通过率、消融矩阵完整率、可复现率 |
| 图表集 | 100 组结果数据 + claim | 图是否正确表达结论、图文是否一致 | 数据一致率、caption 对齐率、专家视觉分 |
| 写作集 | 材料约束的真实稿件 | 事实、引用、结构、一致性 | 引用真实率、claim 支持率、专家分 |
| 失效集 | 人为变更数据/代码的稿件 | 受影响结论是否被找出 | 失效召回、误报率 |

### 5.3 基线

1. 通用强模型直接生成（无检索、无证据约束）；
2. 通用模型 + 检索增强（RAG）；
3. PaperQA2/OpenScholar 式"先检索后写作"；
4. ARIS 文献阅读流程（`research-lit` + `citation-audit`，强工程基线，见 `06-`）；
5. AutoResearchClaw 类阶段化流水线（若可跑通）；
6. Co-Scientist / ScientistTwo 式流水线（仅作定性/小样本对照）；
7. 现有中文写作工具（只做可用性与质量对照）；
8. 人工写作（作为质量上界与时间基线）。

| 消融 | 观察 |
| --- | --- |
| 去掉证据卡，直接写 | claim 支持率、伪造率变化 |
| 去掉阅读深度路由 | 阅读成本、claim 条件完整率、核心文献召回 |
| 去掉 Q0 独立复核 | 伪引/错误 claim 漏检率、下游返工率 |
| 去掉争议矩阵 | 冲突识别率、结论条件化比例 |
| 去掉查新 | 最近工作命中率、短名单新颖性 |
| 去掉消融矩阵 | 增益归因准确率、专家设计评分 |
| 去掉论证骨架 | 结构完整率、专家分变化 |
| 去掉独立 Verifier | 引用错误率、数字冲突率 |
| 去掉 critic 循环 | 修订轮次、专家分 |
| 去掉 Idea 辩论/Elo | 短名单专家 top-3、机制覆盖变化 |
| 去掉覆盖度约束 | 候选同质化程度、最佳 Idea 是否被漏掉 |
| 去掉设计卡 | 执行可复现率、结论—设计匹配度 |
| 去掉同协议基线复现 | 增益可信度、与论文报告的偏差率 |
| 去掉评审失败分流 | 贡献层问题被误当文本问题、返工轮次 |
| 去掉图表 QA | 图文冲突率、caption 错误率 |
| 去掉失效追踪 | 变更场景召回 |
| 去掉探索/确证隔离 | 结论污染率、复现率、审稿人质疑数 |
| 去掉三权分立 | 自证错误率、评审与生成同源导致的漏检率 |

| 去掉增量候选隔离/置信门 | 脏数据入图率、下游错误传播 |
| 去掉干净重跑（改用 Work 自报） | 伪造数字通过率、计分产物可信度 |

| 换便宜模型 | 质量—成本曲线 |

### 5.5 专家评分锚点（5 级）

| 分数 | 事实与证据 | 结构 | 表达 | 可直接修改使用 |
| --- | --- | --- | --- | --- |
| 5 | 几乎全部有支撑 | 完整、论证闭合 | 达发表水平 | 小修 |
| 4 | 少量弱支撑 | 基本完整 | 流畅 | 中修 |
| 3 | 有明显证据缺口 | 有断链 | 可读 | 大修 |
| 2 | 多处无支撑 | 结构混乱 | 难读 | 重写 |
| 1 | 大量错误/伪造 | 不成立 | 不可用 | 废弃 |

### 5.6 统计与协议

- 盲评：隐藏系统来源，随机顺序；同一稿件至少 3 人评。
- 一致性：报告 Cohen's κ 或 ICC；低于 0.5 时先校准评分标准。
- 比较：配对比较 + 自助法置信区间；不只看均值。
- 预注册：指标、排除规则、停止条件在实验前写入 `03-` 或实验日志。

> 本节给 v1 默认技术栈与构建顺序；分层职责、Agent 角色、门禁服务、调度/预算/失败路由与五类流程编排见 [`09-`](09-系统架构与流程编排设计.md)。两份文档冲突时，以 09 的组件边界与 04 的阶段语义为准，并同步修正。

### 6.1 技术栈

| 层 | 建议 | 理由 |
| --- | --- | --- |
| 后端 | Python + FastAPI | LLM/数据生态 |
| 编排 | 自研状态机（或 LangGraph 类） | 需要可控检查点与预算 |

### 6.2 最小数据模型

```json
{
  "project_id": "P-001",
  "claim": {
    "id": "C-102",
    "text": "该方法在低资源场景下保持稳定",
    "section": "discussion",
    "status": "supported | disputed | unsupported | pending",
    "confidence": 0.72,
    "version": 3,
    "updated_at": "2026-10-19T10:00:00Z"
  },
  "evidence": {
    "id": "E-118",
    "type": "paper_span | run_record | dataset | figure",
    "source_id": "DOI:...",
    "locator": {"page": 7, "span": [120, 180]},
    "supports": "support | refute | partial",
    "strength": 0.8,
    "retrieved_by": "librarian-v2",
    "verified_by": "human | verifier-v1",
    "verified_at": "2026-10-19T10:05:00Z"
  },
  "edge": {"from": "E-118", "to": "C-102", "relation": "supports"}
}
```

### 6.3 成本控制

- 证据卡与大纲用强模型；普通段落用中档模型；格式与一致性用规则。
- 检索结果缓存；同一证据不重复摘要。
- 长稿分段生成，但全局论证图只保留结构化摘要，避免上下文爆炸。
- 预算硬上限：超出时停止并输出未完成清单，不静默降质。

### 6.4 可观测性

每次运行记录：阶段耗时、token、成本、失败类型、重试次数、人工干预点。用于：

- 失败归因（哪一阶段最常失败）；
- 成本优化（哪些调用可降级）；
- 论文实验（消融与对比）。

### 6.5 构建顺序：先纵向切片，再逐段加深

不要按 S0→S16 顺序把每段做满再进入下一段，否则半年内看不到端到端效果。采用"一条细纵切 + 逐段加深"：

| 阶段 | 目标 | 交付 | 完成判据 | 依赖 |
| --- | --- | --- | --- | --- |
| M0 骨架 | 项目、产物、状态机、日志、RWVH 对象模型 | 产物信封、状态迁移、ID/版本、运行账本、TaskSpec/Run/Verdict/EA schema（H1） | 任一阶段可重放；产物可追溯；快照/干净镜像可跑通 | — |
| M1 证据闭环 | S0–S1 + Q0 + H2 | 解析、检索、claim 卡、span、争议矩阵、gap 卡；任务包格式与静态检查（H2） | 50 篇真实论文 Q0 通过；伪造召回 ≥ 98%；任务包校验全过 | M0 |
| M2 想—设闭环 | S2–S4 + H3/H4 | 候选集、锦标赛、查新、设计卡（含消融/试跑）；oracle/nop 与 rubric 校准（H3/H4） | 20 候选 → 3–5 短名单；设计卡专家通过 ≥ 80%；oracle ≥ 0.90、nop ≤ 0.10 | M1 |
| M3 做—图闭环 | S5e/S5c–S6 + H5 | 沙箱、protocol、Work/Judge 确证运行、结果卡、图包、导出硬门（H5） | 同 protocol 重放一致；计分数字 100% 绑 `EA`；图与数据 100% 对齐 | M2 |
| M4 写—核闭环 | S7–S13 | 论证图、大纲、证据卡、逐节草稿、critic、Q1；`R/X/N/F` 槽位 | 2 万字全稿；槽位违规 ≤ 1%；引用伪造 = 0；未解析槽阻止导出 | M1–M3 |
| M5 评审—交付闭环 | S14–S16 + 评测 + H6 | 评审模拟、返修、导出包、RWJT（H6）、benchmark | 主要意见覆盖 ≥ 70%；导出字段 100%；RWJT 的 J 可复现 | M4 |

**纵向切片**：M1–M4 始终用同一篇真实论文、同一套数据、同一个研究问题贯穿；每加深一段，都重跑上一段的验收，防止"局部最优、整体断裂"。

**演示优先级**：M1（证据可审计）→ M4（全稿可生成）→ M2/M3（想—做闭环）→ M5（评审与评测）。先证明"写得可信"，再证明"想得新、做得真"。

## 8. 风险、停止条件与备选路线

| 风险 | 早期信号 | 应对 | 停止/转向条件 |
| --- | --- | --- | --- |
| 生成质量不达标 | 专家分 < 3，修订 > 3 轮 | 缩窄体裁、加强证据卡、换强模型 | M5 后仍 < 3 → 转为 A2 分节辅助 |
| 引用上下文判定不准 | F1 < 0.7 | 人工规则 + 小模型微调 + 人工复核 | 长期 < 0.7 → 只做真实性核验，不做支持判定 |
| 中文解析拖累 | 章节 F1 < 0.75 | 人工校正 + 版面模型 | 改为"用户上传结构化稿"降低依赖 |
| 成本过高 | 单篇 > 20 元 | 缓存、分流、压缩 | 仍高 → 限制篇幅/分阶段生成 |
| 评测做不完 | 标注进度 < 50% | 缩小黄金集、先做子集 | 改为"专家小样本 + 自动指标" |
| 复现任务选不出 | 3 个候选里 2 个跑不通 | 先 CPU/单卡小任务；用 oracle 筛 | 只保留 2 个任务，RWJT 合并进 T1 |
| 重跑不确定 | 同 protocol 两次结果差 > 容差 | 固定种子/镜像/依赖；报告置信区间 | 改判"区间重叠"而非点值一致 |
| Judge 泄漏 | Work 能读到 `/tests` 或 rubric | 只读快照、私有挂载、静态检查 | 暂停确证车道，修隔离后再开 |
| 专家校准做不完 | κ < 0.60 或复核积压 | 缩 rubric 条目、先双人 20% 抽样 | 降为单专家 + 自动一致性检查 |
| 范围蔓延 | P0 延期 > 4 周 | 砍 P1、冻结体裁 | 保"核刊全稿 + 引用核验"最小闭环 |

**备选路线**：若全稿生成质量短期无法达标，退守"**分节高自动化 + 全稿一致性核验**"（A2+），仍是可用产品，且证据层与失效追踪不受影响。

## 10. 结论

这条流水线的核心不是"让模型写得更多"，而是**把一次研究变成可检查、可复现、可追责的过程**：

- 每个 idea 有机制、证据与可证伪条件；
- 每个设计有变量、对照、停止规则与执行记录；
- 每个 claim 有证据；
- 每个结果 claim 来自一次可干净重跑的确证运行；
- 每个数字有来源；
- 每张图有数据与代码；
- 每次修改有记录；
- 每次失败有归因；
- 每次复用有适用域。

只要这些成立，"自动化完成文献调研、Idea 收敛、实验设计、绘图与长文写作"才不是一个演示，而是一个可以交付、可以评测、可以发表的研究系统。执行侧的可信度不靠声明，而靠一次独立、干净、可复核的重跑；写作侧的可信度不靠措辞，而靠句子、数字、图与这次重跑之间的可追溯绑定。
