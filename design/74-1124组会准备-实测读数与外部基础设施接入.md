## 5. 外部自进化基础设施接入（本周期新验证）

### Harness²（已接入 = bridge 面）

- 3.12 桥进程真跑：预算恒等式 R=4k/P=3k 成立、6 组件采纳、10 项 conformance
- 双轨世代 GEN-fe35c781b1（agent_tree_sha × platform_fingerprint 互链）验证 clean

### Harness²（已接入 = bridge 面，深入理解）

- **预算恒等式是账本不变式**：`harness2/core/ledger.py` 在记录时 `raise unless the recorded entries show exactly R=4k and P=3k with no duplicate`——不是报告字段而是硬约束，任何预算偏离直接抛错
- **完整轨迹不截断是显式设计决定**：`harness2/core/context.py` 明文 "no prompt-budget truncation... not an oversight"——与我们的 span-only 证据边界同构（两者都拒绝用截断换预算）
- **采纳对象是文件级**：skills/、systemprompt.md、guardrails.md、LongTermMEMORY.md、tool_descriptions/ → 类型化为 skill/prompt/process 三类；我们的桥接把每个采纳映射为受治理候选（evidence 分类 + simulation 标记 + 不可申领能力）
- **10 项 conformance 逐项可否证**：contract 形状 / 桥进程 exit=0 / 全任务 ok / 无阶段回退旧 harness / ≥1 采纳组件 / lessons 带证据 / simulation 标记 / shims 显式声明 / **产物不含签名准入动作**（human_gate）——最后一项与我们的人工门边界互为镜像
- **core 五模块**：context（轨迹）/ judge（评分）/ ledger（预算账本）/ library（经验库）/ prompts+proposer（提案生成）——结构与我们的 propose→gate→record 反馈端口同型

### FlashRSI（人大 RUC-NLPIR，新考察 = 潜在 flashrsi 面）

- **定位**：13 种 RSI 算法（OPRO/GEPA/ACE/SkillOpt/Evo-Harness/ADAS/DarwinX…）× 31 benchmark × 7 harness 的统一演化框架，Apache-2.0，Python 3.11+
- **安装跑通**：3.12 venv + `pip install -e .` 完成，CLI `flashrsi run/evaluate` 可用；自测套件在 Windows/无 Docker 环境有缺口（web_retrieval/workbench 若干失败——容器化是其可复现性根基）
- **与本平台的关系（两种互补接入模式）**：
  1. **我们消费它**：ExecPort 注册 `flashrsi` 面（conda/venv 解释器 + 授权边界），Harness² 与 FlashRSI 的演化产出进入同一世代台账对比——**多引擎对照实验的地基**
  2. **它消费我们**：FlashRSI 的 harness snapshot 版本化与我们的人工门/判定总线互补——我们的 gate/claim 审计可作其演化的接受判据
- **Zcode 额度接入**：MiniAgent runtime 的 LLM 层是薄 AsyncOpenAI 封装（base_url 可配）——桥接方案 = 本地 OpenAI 兼容 shim → HostModelPort（Zcode 作答）；本轮已验证接口形状，实际 shim 待建
- **对照结论**：Harness² 递归改 harness 代码（深），FlashRSI 广度对比 13 算法（广）——两者正交，ExecPort 双面注册后可在同一判定总线上做「同一 benchmark × 多引擎」的受控对比
