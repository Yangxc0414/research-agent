# 前端模型设置：上下文压缩、最大上下文、回复长度与思考强度

> 目标：让前端像成熟 coding agent 一样提供模型设置，但**滑块不能凭空创造能力**。上下文窗口、最大输出、可用思考档位由接入模型的配置/文档决定；平台只决定使用多少、何时压缩、保留多少历史。
> 本轮仍是静态 UI：滑块改变本地状态并写入请求预览，不调用 API、不真实压缩、不真实计费。

---

## 0. 结论

1. **先有能力，再有滑块。** 每个模型档案声明 `context_window / max_output_tokens / thinking_supported / thinking stops`；UI 只在这些范围内取值。模型未声明思考能力时，滑块禁用并写明原因，不伪造 `low/medium/high`。
2. **思考强度按模型类型映射。** OpenAI 是 `reasoning_effort`；Anthropic 是 `thinking.budget_tokens`；兼容端点必须由 `extra_body` 声明。前端只展示模型已声明的档位与对应字段。
3. **上下文压缩是平台策略，不是模型参数。** 它由平台决定：`off / auto / aggressive`、触发阈值、保留最近轮数、摘要 tokens。压缩不能绕过“超限失败”：关掉压缩且超过上下文时应报错/阻断，而不是静默截断。
4. **最大上下文与最大回复是两层上限。** 用户可把“本次最大上下文”设低于模型窗口；最大回复不得超过模型最大输出；二者共同决定一次请求的预算。
5. **设置必须可见、可回退、可解释。** 顶部 model chip 显示当前模型/上下文/思考档；弹窗有请求预览；应用后写入一条本地系统消息；刷新后保持。
6. **静态不是假装。** 页面明确写“能力值来自示例配置”；接真实 Provider 后，能力值来自 `/api/models` profile 或模型文档，UI 不改。
7. **本次不改 claim/EA/gate。** 模型设置只影响生成预算与上下文策略，不改变证据准入；这仍是产品控制面，不是能力证明。

---

## 1. 两类设置，不能混

### 1.1 模型侧能力（capability）

| 字段 | 含义 | 来源 | 约束 |
|---|---|---|---|
| `context_window` | 模型最大上下文 tokens | 模型文档 / Provider 配置 | 8k–2M；用户不可超过 |
| `max_output_tokens` | 模型最大输出 tokens | 模型文档 / Provider 配置 | ≥16；不得大于 context_window |
| `thinking_supported` | 是否声明可调思考 | 模型文档 / profile | false 时 thinking 必须 off |
| thinking stops | 可用档位 | 模型文档 / profile | OpenAI effort；Anthropic budget；无声明则空 |
| `json_mode` | 是否支持 JSON mode | Provider 能力 | 只是 best-effort，不保证结构 |

### 1.2 平台侧策略（policy）

| 字段 | 含义 | 默认 | 边界 |
|---|---|---|---|
| `contextLimit` | 本次请求可用上下文 | min(128k, model window) | 8k–model window |
| `maxReply` | 本次最大回复 | min(8k, model max output) | 256–model max output |
| `compression` | 上下文压缩策略 | auto | off / auto / aggressive |
| `threshold` | 触发压缩的比例 | 70% | 50–95% |
| `keepRecent` | 保留最近完整轮数 | 6 | 2–20 |
| `summaryTokens` | 历史摘要 token 上限 | 512 | 256–4096 |
| `thinkingStop` | 选中的思考档位 | 模型默认 | 必须属于模型 stops |

**原则**：capability 是“模型能做什么”；policy 是“本次打算怎么用”。前者不可由滑块突破，后者是用户可调。

## 2. 前端交互

### 2.1 顶部 model chip

在 `site/agent/` 顶栏显示：

```text
MODEL  GPT-5  197k · high
```

- `GPT-5`：当前模型短名；
- `197k`：本次上下文上限；
- `high`：当前思考档位（模型未声明时为 `off`）。
- 点击打开设置弹窗。

### 2.2 设置小窗

模型设置是一个 **440px 浮动小窗**，不是独立大页面：默认只显示模型选择、上下文/回复、思考强度、压缩策略和一行预览；压缩细节折叠在“压缩细节 +”里；Provider/Profile 的完整配置走底部“高级配置 ↗”链接到 `site/models/`。这样聊天主界面不会被设置页占满。

```text
┌ MODEL SETTINGS / STATIC ─────────────────────────────┐
│ 模型能力先于滑块。                                     │
│ ┌ GPT-5 ┐ ┌ Claude ┐ ┌ Qwen ┐  (能力示例；可替换)      │
│ │ ctx 400k · out 16k · thinking effort/budget/off      │
│ ├─────────────────────────────────────────────────────┤
│ │ 最大上下文   [====----] 197k / 模型上限 400k          │
│ │ 最大回复     [======--] 12k / 模型上限 16k            │
│ │ 思考强度     [--|--|--|--] minimal low medium high   │
│ │              当前映射 reasoning_effort=high           │
│ │ 上下文压缩   off | auto | aggressive                  │
│ │ 触发阈值     [=======--] 55%                         │
│ │ 保留最近轮数 6   摘要 tokens 512                      │
│ │ 请求预览：context 197k / reply 12k / thinking high    │
│ └─────────────────────────────────────────────────────┘
│ 能力值来自接入配置/模型文档；滑块只选择已声明档位。      │
│ [取消] [应用设置]                                    │
└──────────────────────────────────────────────────────┘
```

### 2.3 滑块规则

- **离散滑块**：`input[type=range]` 的每一步对应一个已声明 stop，不允许任意小数。
- **模型切换重置**：切到 Claude 时，contextLimit 重置为 min(128k, 200k)，maxReply 重置为 min(8k, 16k)，thinking 回到模型默认 stop。
- **不支持思考**：Qwen 示例 `thinking_supported=false`，滑块禁用，显示“模型未声明可调思考强度”，不显示假档位。
- **请求预览**：显示本次 context / reply / thinking 映射 / compression 触发点；不显示未经计算的实际 token 数。
- **应用反馈**：应用后写入一条系统消息 `MODEL CONFIG · ...`，并在 chip 上更新；刷新后保持（localStorage）。
- **取消**：不修改当前项目设置（使用 draft 对象，只有 Apply 落盘）。

### 2.4 模型页（管理员）

`site/models/` 的 ModelProfile 增加：

- 上下文窗口；
- 最大输出；
- 是否声明支持思考；
- thinking 模式/effort/budget；
- max_tokens ≤ max_output_tokens；
- context_window ≥ max_output_tokens。

这些字段由接入者按模型文档填写；不是平台猜测。

## 3. 上下文压缩设计（静态版）

### 3.1 策略

| 策略 | 行为 | 适用 |
|---|---|---|
| `off` | 不压缩；超过 contextLimit 直接阻断 | 调试、复现、短会话 |
| `auto` | 达到 threshold 时压缩较早历史，保留最近轮 + 摘要 | 默认 |
| `aggressive` | 更早触发、更短保留，适合长工具轨迹 | 长会话、成本敏感 |

### 3.2 未来实现（接 runtime 后）

```text
token estimate
  → if estimated > contextLimit * threshold:
      keep = last N complete turns
      old = earlier turns + artifacts
      summary = summarize(old, max=summaryTokens)
      new context = summary + keep + current request
  → if still > contextLimit:
      block with actionable error; do not silently truncate
```

- 摘要不是证据：压缩后的摘要只能作为对话上下文，不能生成 claim/EA。
- 压缩必须保留 artifact 引用（ID/路径），不能把证据对象摘要掉。
- 压缩策略记录在 session trace 中；回放时可解释“哪些历史被压缩”。

### 3.3 静态版

- 只计算并展示“约在 X tokens 触发、保留 N 轮 + S tokens 摘要”；
- 不执行压缩、不计费；
- 页面明确 `SIM`；不把预览当真实 token 计数。

## 4. 思考强度映射

### 4.1 OpenAI

```json
{"reasoning_effort": "high", "max_completion_tokens": 12000}
```

- stops：`minimal / low / medium / high`（仅模型声明支持时）；
- 启用时不发送 temperature/top_p；
- 非 reasoning 模型不显示这些 stops。

### 4.2 Anthropic

```json
{"thinking": {"type": "enabled", "budget_tokens": 8192}, "max_tokens": 12288}
```

- stops：`1k / 2k / 4k / 8k / 16k`（按模型允许范围）；
- `max_tokens > budget_tokens`；
- 启用时不发送 temperature/top_p；
- 前端显示“budget token”而不是“思考等级”，避免把 8k 当文本长度。

### 4.3 OpenAI-compatible

- effort：透传 `reasoning_effort`（如果 provider 声明支持）；
- budget：必须由 `extra_body` 指定 provider 字段，例如 `enable_thinking/thinking_budget`；
- 未声明时滑块禁用；不猜测 provider 私有参数。

## 5. 静态状态与未来 API

| UI 设置 | 静态行为 | 未来 runtime |
|---|---|---|
| 模型选择 | 切换本地 profile | `GET /api/models` + profile |
| contextLimit | 本地 state + 预览 | 请求参数 / context builder |
| maxReply | 本地 state + 预览 | `max_tokens` / `max_completion_tokens` |
| thinking stop | 本地 state + 映射预览 | provider gateway 翻译 |
| compression | 本地 state + 触发点 | context compactor + trace |
| Apply | 写 localStorage + 系统消息 | 保存 session config；不写密钥 |
| 刷新 | 保持 | 从 runtime 读取（未来） |

**边界**：静态设置不会改变真实模型调用；接 runtime 后也必须由 gateway 按 Profile 校验，不能只信浏览器。

## 7. 边界与不可宣称

- 不宣称“滑块越大模型越聪明”：思考档位只是模型已声明的参数，不等于能力提升。
- 不宣称“上下文压缩无损”：摘要会丢信息；证据对象必须保留引用。
- 不宣称“最大上下文 = 实际可用”：还要扣除输出预算、系统提示、工具结果与安全余量。
- 不把示例能力值写成模型真实规格；真实值以接入配置/官方文档为准。
- 不把静态压缩预览写成真实 token 计数或账单。
