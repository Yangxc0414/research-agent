# 让闭环产出真结论：可执行面注册表与记忆×门控研究

> 状态：2026-10-29 实现并实测。模块契约见 [`modules/search-study/SPEC.md`](modules/search-study/SPEC.md)，
> 架构位置见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。本文记录一项由本系统**自己的想法**提出、
> 由本系统**自己的实验台**完成的研究，以及为了让它成为可能而必须修掉的结构性缺陷。

## 1. 结论

上一轮实测暴露的最严重问题不是流程跑不通，而是**流程跑通了却产不出结论**：S2/S3 生成的是关于
"搜索"的假设（档案、接受门控、单位算力改进率），而 S5 只能对表格数据做一次固定拟合——没有接受
事件、没有血缘、没有可归一的验证成本。于是想法的实验计划字段只能填成口径混淆的内容，
把文献语料写进 `dataset`。想法越像样，实验段越假。

补上搜索实验台之后，三个由本系统自己生成的假设得到了异质结果：

| 假设 | 判定 | 证据 |
| --- | --- | --- |
| **档案的收益依赖门控存在**（记忆 × 门控负交互） | **可判定支持（3/3 数据集，64 种子）** | iris −0.165 CI [−0.233,−0.097]；wine −0.109 CI [−0.176,−0.042]；breast_cancer −0.082 CI [−0.144,−0.020]，区间均不跨零 |
| **接受门控提升单位算力改进率** | **仅 iris 可判定，作为一般性主张被推翻** | iris +0.171 CI [+0.045,+0.297]；breast_cancer 点估计 −0.030；wine 不可判定 |
| **谱系更深即累积更多改进** | **不支持** | 档案使谱系深度约 2.3 倍，单位算力改进率几乎不动 |

主结论因此是：**保留被接受的历史被体，在开启接受门控之后不再提升单位验证算力的改进率——反而抵消门控带来的收益**；这在三个数据集上都可判定，而不是 8/16 种子时那个没有区间配套的点估计。

> 这条结论的得出过程本身就是本系统的价值证明，两处都是它逼出来的：
> ① 8/16 种子时交互项**只有点估计、没有区间**，等于不能签署也不能反驳；补上配对交互推断后它才可判定。
> ② 我第一次跑高功效时看到交互项"变号"，差点据此宣布结论翻转——核对后发现是**我自己把
> difference-of-differences 写成了镜像形式**（同幅值反符号）。符号约定现在被测试钉住
> （`test_interaction_interval_matches_the_sign_of_the_point_estimate`），翻转的只是我的错误，不是数据。

## 2. 为什么这次能出结论：三处结构性修复

### 2.1 可执行面成为一等对象

`research_agent/executable.py` 把"本运行时能检验什么"变成**单一权威注册表**，每个档位必须同时声明
`supports` 与 `cannot_test`：

| profile | 能检验 | 明确不能检验 |
| --- | --- | --- |
| `protocol_run` | 固定协议上的种子波动、两固定配置的均值比较 | 任何搜索/档案/门控效应；智能体自我修改 |
| `local_tabular_experiment` | 用户 CSV 上若干估计器的监督对比与配对差区间 | 生成式或智能体行为；长程搜索 |
| `search_factorial` | 记忆 × 门控主效应与交互、被接受谱系深度、单位验证算力改进率 | 智能体源码自改；任何已发表系统复现 |

想法生成现在必须把实验计划绑到其中一个 profile，且 `dataset`/`metric` 必须属于该档位；
`profile` 缺失或选了不存在的档位，想法在校验阶段直接被拒。
**提示词同时注入各档位的 `cannot_test`**，让模型在生成时就看不到"随手编一个大规模基准"的空间。
效果是可观察的：同一语料、同一目标，上一轮产出的实验计划填的是"两个公开小规模任务/跨种子方差"，
这一轮产出的是 `profile=search_factorial, dataset=iris, metric=improvement_per_evaluation` 并要求
"区间跨零即判定为无方向性结论，不追加种子"。

### 2.2 评审独立性被披露而不是被假设

同一宿主模型依次回答 novelty/evidence/feasibility 三个角色，实测中**仅把阈值从 8.0 调到 5.0
就把结论从 `needs_more_work` 翻成 `reviewed`**。这说明"三方评审"没有独立支撑，只是三段提示词。

`innovation-review.json` 现在带 `independence` 区块（`critic_calls`、`distinct_model_ids`、
`single_author_review`、`admission_eligible: false`），写作提示词进一步禁止把这三个角色写成
"三位独立审稿人"，也禁止用其分数支撑"已通过评审"。这不是自贬，是把不能成立的主张提前拦在 prose 之外。

> 后续更新（2026-10-29）：写死 `admission_eligible: false` 虽然诚实，但它是**不可解除的常量**，
> 于是没有信息量。该状态已被改造成可解除的供给面板，见 `52-独立评审-从披露到可解除.md`。

### 2.3 写作契约从"装饰"变成"可强制"

`目标 6000-8500 汉字`此前只存在于提示词常量里，4740 字的稿子照样 `ready_for_human_review`。
现在 `LENGTH_TARGETS` 是 writer 与 audit 的**同一来源**，pack 记录 `length_target`，
audit 输出 `han_character_count` 与 `length.chinese_characters`（默认告警级，契约标 `strict`
即升级为阻断）。同时"多样性检查 skipped"改成显式 `sources.diversity = not_assessable`
并写进 warnings——**4 篇语料时招牌多样性保证不成立，必须看得见，不能悄悄没有**。

### 2.4 结论能被签署，因此才能被写进论文

一条发现如果进不了 `allowed_result_numbers`，它对论文就等于不存在。`study claim` 把研究产物转成
`ClaimRecord` 形状的**草稿**，并加了两条硬规则：

- **只有 95% 区间排除零的比较才成为断言**；功效不足的比较不静默丢弃，而是进入
  `verification.not_signable` 并带原因（`interval covers zero: not signable`）；
- 若没有任何可判定比较，**拒绝生成草稿**，提示"增加种子或收窄主张"，而不是产出一份空的
  或点估计驱动的 claim。

iris 研究实际产出的结果是：1 条可签署断言（`observed=0.170833`，即门控带来的单位算力改进率提升）
与 2 条被拒比较。草稿绑定 study / evidence / spec 三个不同哈希（evidence 现在带自哈希
`evidence_sha256`，此前它错指 study 哈希，已修）。**签署仍然是既有人工 claim 路径上独立的一步**，
本模块既不写签名也不写闭包。

### 2.5 结论被闭包与沿袭追踪（第三套 closure profile）

`search_study` 成为 `canonical_run` / `local_experiment` 之外的第三套人签闭包 profile，
把 `study-spec → study → study-evidence → claim → closure-report → signature` 用规范化 JSON
哈希串成一条链，并且**把两件科研上真正会出事的东西写进闭合条件**：

- `power.sufficient` / `has_decidable_comparison`：区间全部跨零的研究**不能被关闭成结论**；
- `code.unchanged`：spec 记录搜索代码指纹，改动 `search_lab.py` / `executable.py` /
  `study_claims.py` 之后旧结论不再可引用（实测伪造指纹即被阻断）。

`study closure --build-lineage` 与 `--verify` 是只读的：把 spec 的种子从 8 个改成 3 个，
验证立刻报 `stale` 并点名 `study-spec` 节点；签名在报告不再 ready 时直接拒绝。
`closure profiles --project` 与 `research_status` 复用同一函数，因此研究会出现在项目盘点里，
且已签名的研究不会被误报成"还等着签"。

实测整条链：`study search`（iris, 8 seeds）→ `study claim --sign`（1 条可签署、2 条因功效不足被拒）
→ `study closure` = `ready_for_human_signature` → `study closure --sign` → `lineage` = `fresh`
→ 项目盘点 `present_profiles: [search_study]`、`next: closed; report is signed`。

### 2.6 不可判定被当成结果呈现，而不是被藏起来

区间规则原先只在签署路径里算一次，展示路径另有自己的判断——这正是"看起来一致的指标被各自
解释"的温床。现在 `study_claims.comparison_verdicts(evidence)` 是三态的唯一来源
（`positive / negative / undecidable / unavailable`），`decidable_assertions` 消费它，
只读盘点 `detect_project_profiles()` 的 `search_study` 行也消费它，工作台按项渲染。

本机对已签名的 iris 研究核验（HTTP 响应原文）：

```
undecidable  memory_off_gate_on         +0.0563  [-0.011237, 0.123737]
undecidable  memory_on_gate_off         +0.0120  [-0.034932, 0.05889]
negative     memory_on_gate_on          -0.0969  [-0.148089, -0.045661]
negative     memory_x_gate_interaction  -0.1651  [-0.233363, -0.096846]
decidable=2  undecidable=2
```

前两项的点估计是**正的**——在任何只看排行榜或点估计的界面里它们会被写成"提升 5.6%"。
现在它们与交互项一起出现，且当区间跨零而点估计为正时，页面额外写一句
"点估计为正但区间跨零：不算提升，只是还没判定"。把不可判定显示为不可判定，
比把 4 个数字都显示成结论更接近这项研究的真实状态。

## 3. 复现```bash
python -m research_agent study profiles                      # 本运行时能检验什么
python -m research_agent study search --project . --dataset iris --budget 60 --seeds 1,2,3,4,5,6,7,8
python -m research_agent study claim --study-dir <上一步输出目录> \
  --statement "开启接受门控提高了单位验证算力的改进率" \
  --scope S5/search/iris --human-reason "checked the paired interval and the lineage log"
python -m unittest tests.test_search_lab tests.test_executable tests.test_study_claims \
  tests.test_review_independence
```

产物为 `study-spec.json` / `study.json` / `study-evidence.json`，三者以哈希交叉绑定；
`study.json` 保留每个种子的完整节点血缘，因此谱系深度不是汇总数字而是可回溯对象。
evidence 采用与本地实验包相同的 `metrics_summary` / `comparison` 形状：**在人签 claim 之前，
这些数字不会进入 `allowed_result_numbers`，也就进不了论文结果节**。

## 4. 边界：这次研究不能说什么

**一个我自己引入、又靠实测抓到的缺陷。** 接入 `study claim` 时，用 2 个种子跑 wine 竟然返回了
"方向性支持"。原因是配对差在两个种子上恰好相等 → 组内方差为 0 → t 区间塌缩到点估计上，
于是一次偶然被判为可签署。**这恰好是本系统存在的理由**：一个看起来严谨的区间，在小样本退化情形下
会生产假结论。现在 `MIN_DECISION_SEEDS = 4`：种子不足时**不给区间**（`ci95_low/high = None`）、
标 `underpowered=true`、并且不产出可签署断言。修后 wine/2 种子返回空，而 iris/16 种子的
门控效应（+0.171，CI [+0.045, +0.297]）不受影响——**去掉假阳性而不是降低门槛**。

（其余边界见下。）

- 被改进的对象是**流水线配置**，不是智能体源码。这是结构类比。它检验的是"保留被体 vs 严格接受判据"
  这一控制在有无收益上的相互作用，**不提供任何关于 DGM / SICA / ACE / SIFT 的经验结论**；
  产物里 `analogue=true`、`not_a_reproduction_of=[...]` 恒为真。
- 区间不跨零不等于显著性检验通过：`exploratory=true`、`significance_claimed=false` 始终为真，
  多重比较未校正。
- 16 个种子在 wine 与 breast_cancer 上未产生任何可判定比较。wine 的 `best_score≈0.97` 提示天花板效应，
  这是可解释的功效不足，但**"能解释"不等于"结论成立"**。
- 负交互项跨三个数据集同号是本项目前最强的模式，但仍未达到可判定阈值，因此它是**下一步该验证的假设**，
  不是已得结论。
