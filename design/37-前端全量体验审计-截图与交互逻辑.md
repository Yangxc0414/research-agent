## 2. 截图证据

### 2.1 欢迎页与居中会话入口

<img src="docs/frontend-audit/13-welcome-1440.png" width="760" alt="欢迎页与居中会话入口">

- 默认进入欢迎页；左侧是快捷入口（新建任务 / 自动化 / 技能 / 插件）与按项目分组的任务列表，底部是个人栏。
- 主区使用大留白 + 淡蓝线稿水印 + 动态问候；聊天框居中，工作区在左上、访问级别与 Skills 在左下、模型与发送在右下。
- 项目默认展开，任务单行显示标题与相对时间（如 `11小时` / `1天`）；任务选中时高亮，悬停显示删除。
- 欢迎页不再使用默认模型；模型选择会写入 `draftProfileId`，发送后应用到新任务的 `ModelSettings`。
- 从欢迎页打开设置时，模型 / 插件 / 自进化三个任务级分节隐藏；快速引导里的任务动作会提示“先开始一个会话”，侧栏“自动化 / 插件”同样被拦截。

### 2.2 访问级别

<img src="docs/frontend-audit/14-welcome-access-1440.png" width="760" alt="访问级别选择">

- 三档：只读 `READ`、每次询问 `ASK`、完全访问 `FULL`；每档有独立颜色、说明与当前勾选。
- 菜单明确写出边界：`claim / EA / closure / signature 的人工门不受此设置影响`。
- 欢迎页选择会写入新会话；会话内切换会追加一条 system trace；自动运行中禁止切换。

### 2.3 结构化回答与会话状态

<img src="docs/frontend-audit/15-session-rich-1440.png" width="760" alt="结构化回答与会话状态">

- Agent 回答按 Markdown 子集渲染：标题、无序/有序列表、引用、行内代码与代码块；用户消息保持普通气泡。
- 任务头 chip 同时显示模式、阶段数、运行状态、访问级别与模型；`ASK` 不再挤成第二行。
- Composer 底部是模式 + 权限 + Skills + 模型；建议动作随证据/协议/claim 状态变化。
- 顶栏不再重复任务下拉与模型 chip；任务切换由左侧任务列表承担。

### 2.4 每次询问的权限确认

<img src="docs/frontend-audit/16-permission-ask-1440.png" width="760" alt="每次询问的权限确认">

- 启动全自动、单步、运行实验、工具批准、候选准入都可能触发确认；弹窗显示动作、影响范围与当前访问级别。
- “允许本次”只执行一次，不改变后续权限；“取消”会写一条 trace，不产生任何高权限动作。
- 只读模式不会弹窗，而是直接说明禁止原因；完全访问不再逐次确认，但仍停在 claim 人工门。
- 只读模式现在覆盖设计/冻结协议、运行实验、签署 claim、提交 held-out 评估、批准工具/候选与启动全自动；ask/full 仍不能绕过 claim/EA/closure/signature 的人工门。

### 2.5 Skills 面板与创建

<img src="docs/frontend-audit/17-skills-drawer-1440.png" width="320" alt="Skills 面板">
<img src="docs/frontend-audit/18-skill-create-1440.png" width="320" alt="创建 Skill">
<img src="docs/frontend-audit/107-skill-drawer-1440.png" width="320" alt="Skills 三态与按需加载说明">
<img src="docs/frontend-audit/109-skill-drawer-mobile-390.png" width="180" alt="移动端 Skills 三态">

- 内置 10 个只读技能：文献速览、文献覆盖审计、假设收敛、协议体检、证据边界审计、写作槽位草拟、自进化预检，以及研究构思、实验管理、探索巡检、评估隔离。
- 每个技能是三态 `按需 / 手动 / 停用`，不再用全局“启用”表示已加载；目录常驻，但 instructions 默认折叠，只有匹配或显式调用时才进入本轮。
- 首轮只出计划，不预加载 Skill；检索、设计、冻结、运行、签署、写作动作完成后，再按动作加载对应技能，卡片带当时的 summary 与检查项。
- 后续消息只在出现“检查 / 审计 / 覆盖 / gap / 边界 / 收敛 / 评估”等 inspection 意图时自动选最多 1 个内置技能；导入与自定义技能只能手动调用。
- 新建表单包含名称、说明、指令与工具；创建后版本为 `v0.1.0`，保存到 localStorage。欢迎页调用会从当前工作区新建会话。

### 2.6 Skills 调用结果

<img src="docs/frontend-audit/19-skill-result-1440.png" width="760" alt="Skills 调用结果">
<img src="docs/frontend-audit/106-skill-routing-1440.png" width="760" alt="检索完成后按需加载文献速览">
<img src="docs/frontend-audit/108-skill-routing-mobile-390.png" width="220" alt="移动端 Skill 加载与执行">

- `/literature-brief` 在已有 span 时返回 `ok`；没有 span 时返回 `needs_input`，不会伪造证据。
- 自动加载使用紧凑 `skill-use` 卡：加载原因、summary、前三条检查（来源 / 全文 / span / gap 等），并给出“查看 Skill”；手动调用仍生成完整 `skill` 卡。
- 首轮不预加载，避免在空任务上显示 0/6；检索完成后再加载 `文献速览`，此时 summary 会变成 4 篇来源 / 12 span / 2 gap，并提示来源广度仍未达标。
- 技能只读：不新增来源、不写 claim、不调用外部工具；这一点同时写在回答引用和卡片注释里。
- 1440/390 实测：自动加载、动作后加载、普通“你好”不误触发、`/paper-slots` 显式调用均通过；无 console error 与页面横向溢出。

<img src="docs/frontend-audit/20-slash-skill-1440.png" width="760" alt="斜杠调用 Skill">
<img src="docs/frontend-audit/111-slash-commands-1440.png" width="760" alt="命令与 Skill 分组">
<img src="docs/frontend-audit/112-slash-commands-mobile-390.png" width="220" alt="移动端命令与 Skill 分组">

- 显式 `/skill-id` 绕过按需路由，直接生成完整 `skill` 卡；这也是用户对自动选择不满意时的可控兜底。

### 2.14 阶段轨展开

<img src="docs/frontend-audit/39-stage-trace-s1-1440.png" width="360" alt="S1 文献检索展开">

- STAGE TRACE 的每一行现在都是按钮，不再只有 `details` 的隐式行为；点击展开，再点收起，同一时间只展开一个阶段。
- 展开内容按阶段区分：

市场基线（2026-10）：

- Agent Skills 的通用格式是“目录 + `SKILL.md`”：YAML frontmatter 至少包含 `name`、`description`，可选 `allowed-tools`；按发现 → 激活 → 执行的渐进式披露加载（[agentskills.io](https://agentskills.io/)、[阿里云 Agent Skills](https://docs.aliyun.com/zh/skillsportal/understand-agent-skills)、[Agent Skills 6 字段规范](https://cloud.tencent.com/developer/article/2701717)）。
- Claude Code 从用户级 `~/.claude/skills/` 与仓库级 `.claude/skills/` 发现技能（[Claude Code Skills 2026](https://www.totalum.app/blog/claude-code-skills-totalum)）；Codex 使用 `.agents/skills/` / `~/.agents/skills/`，并提供内置 `skill-creator` 对话入口（[Codex skills](https://test.runoob.com/codex/codex-agent-skills.html)）；Kimi Code 同时支持目录 `SKILL.md` 与扁平 `.md`（[Kimi Code Skills](https://www.kimi.com/code/docs/kimi-code-cli/customization/skills.html)）。
- 我们的取舍：浏览器不能直接读 `~/.claude` 绝对路径，所以用文件夹选择读取；导入项先列为 `IMPORTED` 且默认停用，不执行 scripts，不把 `allowed-tools` 声明当成权限。
- 后端补齐了同一份格式的 `research_agent/skill_registry.py`：CLI `skill scan|list|enable|disable|delete|export` 可直接扫描 `~/.claude/skills` / `.agents/skills`；runtime 只暴露 `/api/skills*` 目录与校验端点，`execution=not_available`，没有 execute/claim/sign。前端导入/对话保存后会在 runtime 在线时同步目录清单。

对话创建：

- 在欢迎页“创建技能”建议、输入框自然语言或 `/skill-creator` 中，进入 `/skill-creator` 流程；本地的确定性 parser 提取名称/描述/指令/工具，生成草稿并在 Skills 面板预填，**确认后才保存**。
- 不调用模型、不自动启用、不执行导入指令；Agent 回复明确标注“静态草稿 / 保存前不会启用”。

本地导入：

- `导入技能文件夹` 使用 `showDirectoryPicker({ mode: "read" })`，递归查找 `SKILL.md`，也兼容根目录扁平 `.md`；解析 frontmatter 的 `name`、`description`、`allowed-tools`、`license`、`version`。
- 跳过缺 `name`/`description` 的文件；默认停用，可切换手动/停用或删除；技能卡标注 `IMPORTED`，调用时只生成静态检查占位，不执行 scripts。
- 上限：50 个 Skill、单文件 128KB、最多扫描 200 个目录；`.md` 直接导入最多 50 个。

实测：欢迎页“创建技能” → 技能草稿任务 → Skills 面板预填 → 保存；导入 `citation-check/SKILL.md` + 根目录 `flat-review.md` 得到 2 个 IMPORTED 技能，默认关闭，启用开关可用；runtime 在线时导入同步 1 个、聊天保存同步 1 个，runtime 目录显示 `execution=not_available`；无 pageerror。

## 4. 仍然存在的体验风险（没有假装解决）

1. **权限只由前端静态 store 强制**：真实 runtime 必须在服务端按同一 access policy 再校验；浏览器里的确认不能当作安全边界。
2. **Skills 是静态只读技能**：自定义 Skill 不会执行任意代码或真实工具，只生成检查卡；真实技能执行需要 runtime、沙箱与工具审批。
3. **无 URL 路由**：欢迎页、当前任务、设置分节、Skills 抽屉都不是可分享 URL；刷新后回到欢迎页。
4. **欢迎页每次刷新都会重新出现**：这是当前“首页”语义的选择；如果用户期望恢复上次会话，需要额外持久化 route。
5. **欢迎页的模型只选 profile**：可以选 OpenAI / Anthropic / 本地模型，但上下文、最大回复和压缩细节要进入会话后调整。
6. **删除没有 undo**：只有确认层；没有软删除/回收站。
7. **焦点陷阱仍不完整**：Modal/抽屉/模式浮层可以用 Tab 跳出；Esc 可关闭，但缺少完整的 focus trap 与焦点归还。
8. **文件夹只提供相对路径与 File 句柄**：浏览器不暴露绝对路径，也没有变更监听；预览内容在内存中读取，刷新后需重新选择；同名文件夹不会去重。
9. **技能不可编辑**：创建后可切换按需/手动/停用或删除，但没有版本化编辑/导入导出。
10. **项目树默认全展开**：任务很多时会变长，当前没有虚拟列表；后续可加“收起全部”或按活动项目折叠。
11. **真实 runtime 未接**：工作台仍为 `SIM · STATIC`；模型、工具、Skill 执行没有真实网络/密钥。
12. **EVAL 是控制面演示**：held-out 隔离、评价规则冻结、审计轨迹都没有在服务端真实执行；EVAL 数值与干预台账是 SIM。
13. **没有重复运行与人类对照**：不记录首次提交成功率、多次运行方差或领域专家基线；不能从 EVAL 页面推出系统能力排名。
14. **干预分类没有自动推断**：engineering/domain 台账目前是示例数据，后续需要从 run diff 与实验记录生成并人工复核。
15. **快捷键只处理应用内冲突**：无法检测浏览器/操作系统保留组合键；用户若绑定到浏览器快捷键，可能不会触发或被浏览器拦截。
16. **六面向覆盖只在 runtime 逐面向展示**：静态预览只显示来源/全文/span/gap 与 5 项检查；facet 级 source/span 统计需读取 `LiteratureBrief`，前端没有伪造逐面向状态。
17. **OpenAlex 只返回摘要线索**：实时检索能扩大来源面，但 `full_text=false` 不会生成 span；需要人工按 OA 链接取全文，或接入受控全文抓取后才会出现可定位证据。2026-10-24 本机实测共享免费额度已耗尽（429）；适配器支持免费 `OPENALEX_API_KEY`（仅 Bearer header），未配置 key 时不宣称实时检索可用。
18. **阶段蓝点不是 worker 心跳**：静态适配器只根据任务阶段状态计算当前/下一步；真实执行进度、重试与阻塞原因必须来自 runtime SSE，不能用前端动效代替。
19. **记忆与归档是本地记录**：localStorage 或本地 runtime 存储，不是云端同步；没有多用户、权限或冲突合并。它们不进入 Claim/EA/gate/export。
20. **SPEC 快照可能过期**：`agent-registry.json` / `command-catalog.json` 需要规格变化后运行 `python -m research_agent workspace export --output-dir apps/web/public`；runtime 在线时优先读实时注册表。
21. **没有 hooks / 远程设备 / 浏览器控制 / 电脑控制**：这些需要真实执行面和审批边界；当前用“执行环境”展示本地 runtime，不提供假开关。
22. **预览不支持绝对路径与目录遍历**：浏览器安全模型只给 `File` 与相对路径；地址栏显示 `local://<name>`，不是真实磁盘路径。预览内容不持久化，刷新后需重新选择。
23. **PDF/大文件受浏览器限制**：PDF 依赖内置查看器；文本超过 512KB 只显示前半段；二进制文件只提供下载/打开，不在页面内解码。
24. **本地文件不经过后端**：浏览器 File API 是唯一入口，runtime 不能读取用户磁盘；未来若预览 runtime 归档/产物，应使用独立 `runtime://` 地址与只读端点，不能把本地路径伪造成服务器路径。
25. **文件夹存储依赖浏览器能力**：File System Access 只在 Chromium 系安全上下文可用；其他浏览器使用导出/导入 JSON。目录句柄存在 IndexedDB，清理站点数据会丢失句柄（磁盘 workspace.json 仍在）。
26. **RSI 故事不是当前任务的进化结果**：右侧默认展示 ChemLab seed-budget 真实 harness 账本，当前任务仍是本地 SIM 候选；两者必须分开读，不能把全局账本当成当前任务的能力增益。
27. **故事快照可能过期**：`apps/web/public/rsi-story.json` 需在账本变化后运行 `python -m research_agent rsi story --ledger ... --output ...`；runtime 在线时优先读 live ledger。
28. **模型目录参数可能随供应商变化**：预设来自公开规格（GLM、GPT-5、Sonnet 5.5、Gemini 2.5、DeepSeek、Qwen），但托管端点可能裁剪 context、JSON 或工具能力；保存前应核对供应商文档。
29. **Responses API 与部分 budget 模型未接入 runtime**：UI 可登记 Responses 格式；runtime 网关仍走 Chat Completions；openai-compatible 的 thinking budget 需要供应商特定 extra_body，未配置时模型只保存在本地。
30. **编排执行只在 CLI**：S1 fan-out 是本地 `ThreadPoolExecutor`，runtime 只暴露只读 topology/plan/memory；没有 per-scout 队列、断点续跑、跨机 worker 或定时调度。
31. **OpenAlex 未接入并发 fan-out**：三 scout 若同时联网会放大共享配额与 429 风险；当前编排器只接受 `fixture` / `real`，OpenAlex 仍走单路 `literature run`，且摘要不会变成 span。
32. **文献记忆是计数记忆，不是语义记忆**：按 topic hash × mode × facet 记录 attempts/coverage/spans/queries/gap，不保存摘要或 span；不做跨主题迁移、来源去重记忆或 embedding 聚类。
33. **候选不等于进化**：真实语料当前触发的是 `orchestrator.facet_budget` process candidate；`literature.query_planner` skill candidate 需要 facet 级重复缺口（fixture dry-run 已覆盖该路径），且还没有自动 dry-run 产物、public/hidden 评分与人工准入记录。
34. **fan-in 不是结论**：合并只去重 hits/spans 并生成候选帧；IdeaAgent 的 novelty 仍未核验，G1 不会自动通过，UI 不能把 3 个候选帧读成研究结论。
35. **快照会过期**：`orchestration-topology.json` 由 `workspace export` 生成，`literature-memory.json`/`orchestration-run.json` 由真实运行后导出；记忆或代码变化后需要重新运行导出命令，否则页面显示的是上一次快照。
36. **自定义子智能体不是通用 Agent**：只接受白名单 checks，不接收任意 prompt、不执行代码、不调用外部工具；protocol/evidence/figure/closure 在当前 S1–S3 stop point 只返回 deferred。
37. **本地草稿不会自动治理 CLI**：离线时新增子智能体或改 policy 只写 localStorage；必须在 runtime 在线时通过 `/api/agents/custom` 与 `/api/evolution/policy` 保存，才会进入 CLI/编排读取的文件。
38. **关闭自进化不撤销历史**：master off 只阻止新的自动候选与 memory_order，不 revoke 已有 lease/confirmation；显式 `rsi fixture/real-trial/s5-trial` 仍可作为人工实验命令运行，需与生产开关区分。
39. **策略不是安全边界**：它只控制过程/技能候选的可见性；Claim/EA/gate 的不可绕过仍靠模块 SPEC、运行器和人工流程，不能把“开关关闭”当作安全证明。
40. **自定义检查可能误导**：coverage/citation/hypothesis 是确定性计数/引用对齐，不等于语义支持或同行评审；advisory note 不能进入 Claim/EA 或代替 G1。
41. **本地 JSON store 不是数据库**：agents/policy/memory 仍是单写入者优先的原子文件替换，没有跨进程锁或事务；CLI 与 runtime 同时修改同一文件时仍可能 last-write-wins。需要并发写入时应升级为 SQLite/带锁 store，而不是继续在 JSON 上叠补丁。
42. **路径统一不等于权限边界**：默认路径已收敛到 repo-root `paths.py`，但显式 `--policy-path`/`--custom-agents-path` 仍可指向别处；换路径会得到另一份状态，页面不会自动识别。
43. **思考滑块只改本地 ModelSettings**：档位来自 Profile 声明的 stops，前端不验证供应商真实是否支持该 effort/budget；runtime 发送时仍按 profile 参数与供应商能力，若托管端点裁剪能力，需要用户在高级设置或供应商侧确认。
44. **上下文“+”只带元数据**：文件夹最多扫描 500 个文件、文件最多登记 12 个；只记录名称/数量/大小，不读取内容、不进入证据链。`showDirectoryPicker` 主要支持 Chromium，其他浏览器回退 `webkitdirectory`；目录句柄不持久化，刷新后需重选。
45. **上下文入口只在欢迎页**：会话内 Composer 还没有同款 `+`；工作区文件夹项只对当前已登记文件夹可用，不提供跨工作区浏览。需要这些能力时应作为独立上下文面板设计，而不是把任意路径注入证据链。
46. **首页字标只是视觉层**：`WA / WELLSRING` 不改变产品名、模块名、机构或能力声明；截图中的字标不能当作署名或品牌授权。
47. **对话建 Skill 是确定性 parser，不是 LLM**：只识别“名称/描述/指令/工具”等字段，复杂自然语言可能提取不全；必须由用户在 Skills 面板确认后保存，不会自动启用。
48. **导入 Skill 是不可信文本**：frontmatter parser 只支持简单单行标量，不支持完整 YAML；`allowed-tools` 只是声明，不是权限授予。后端 `skill_registry.py` 也只是目录/校验层，`execution=not_available`；导入项默认停用、不执行 scripts；启用/调用只生成静态检查占位，不能把外部 skill 当成可信能力或证据。
49. **浏览器不能直接读主目录**：`~/.claude/skills` / `~/.agents/skills` 必须由用户通过文件夹选择器授权；Skills 导入句柄不持久化，刷新后需重选。工作区文件浏览器会把句柄存 IndexedDB，但浏览器仍可能要求重新授权。
50. **工作区文件浏览器是只读的**：没有 write/edit/shell/git，也没有内容级全文搜索；它不能替代 Claude Code 的 coding loop，只能读取、搜索路径、预览和把文件交给后续人工/工具流程。
51. **扫描有边界**：最多 500 个文件/120 个目录，跳过 `.git/node_modules/__pycache__/dist/build/.venv`；超大文件只读取预览上限 512KB，二进制只打开/下载；不保证覆盖超大单仓。
52. **项目说明不会自动注入**：`AGENTS.md` / `README.md` / `CLAUDE.md` 只置顶为可预览入口，不会自动变成系统提示、Claim 或证据；需要人工选择后再进入研究。
53. **权限与临时回退**：File System Access 主要支持 Chromium；`webkitdirectory` 回退只保留本次会话扫描结果，刷新后需重选；未授权/句柄失效会显式提示，不静默读取。
