# 49 · 差异化设计：证据闭合运行时

> 本文回答三个问题：已有科研智能体各自在优化什么；我们凭什么不同；下一步怎样把"设计上的不同"变成"可测量、可验收的不同"。
> 当前事实以 `ARCHITECTURE.md`、`README.md`、`integrations/README.md` 为准；本文不把 roadmap 写成已支持。

## 0. 一句话结论

**别人主要在优化"更快生成一份看起来完整的研究"；我们优化"哪一句、哪个数字、哪张图有资格进入稿件，以及输入变化后谁必须重新签"。**

这不是"再做一个 AI Scientist"，而是给生成式科研系统补一层**可移植的证据闭合与治理运行时**。它可以和 Co-Scientist 式的假设生成、AI-Scientist 式的端到端写作并存：前者负责"想出什么"，我们负责"写进去的能不能站住、谁批准它站住、改动后是否失效"。

### 0.1 与之前预期的对账

| 之前的预期 | 当前实际 | 判定 |

结论：**功能面已经接近"可用"，证据面还没有经历一次真实闭环**。下一步的价值不在再加工具，而在让一次真实实验、一次人签、一次失效演练跑通。

## 1. 复盘：已有工作各自的重心

以下按本项目已完成的调研归纳，不重复外部系统的效果数字；具体出处见 `05-`、`12-`、`23-`、`36-`、`47-`。

| 工作族 | 代表 | 重心 | 已证明/擅长 | 不覆盖或弱项 |
| --- | --- | --- | --- | --- |
| 假设锦标赛 | Google Co-Scientist | 生成—辩论—演化、Elo 排序、邻近去重 | 可检验假设的稳定产出；专家反馈进入循环 | claim 级证据账本、数据/代码变更后的结论失效、开放可复现的完整运行时 |
| 端到端论文 | AI-Scientist v2、ScientistTwo | 想法→实验→手稿→评审→返修 | 少人干预下跑完整条流水线 | 句子级证据绑定、跨版本闭合、人工签核边界 |
| 长程运行与续跑 | ARIS、DeepScientist、CycleResearcher | run state、resume-forward、迭代预算 | 长任务不中断、阶段可恢复 | 证据身份与签核链、稿件与运行的内容寻址绑定 |
| 自进化/RSI | RSI-Anything、OpenRSI、A-Evolve | 改进的准入、评测、保留与回滚 | 改进可被度量、可被拒绝 | 科研产物的 claim/closure 语义、人签门禁 |
| Skill 生态 | ARS、CCFA、scientific-agent-skills | 技能契约、claim/evidence marker、模板 | 流程可复用、静态可检查 | 运行期证据闭合、本地实验与图/表绑定 |
| 独立评测 | PaperBenchX、AGENT4SCI | 隔离评测、复现判定、方法分类 | 防止"自评自过" | 写作—实验联合判定、变更传播 |
| Agent 宿主 | Qoder、Claude Code、Zcode | 工具编排、权限、会话 | 现成的交互与工程接入 | 领域证据模型、人工门禁、可审计产物 |

结论：**生成能力、文献覆盖、实验吞吐都不是我们的主战场**。在这些维度上正面比较，我们既没有算力优势，也没有数据优势。可守的差异在"证据资格 + 完成判定 + 失效传播"三件事的联合。

## 2. 差异化的单位：三个判定，而不是功能清单

功能清单容易被"加一个模块"抹平；判定不会。本系统把科研产出拆成三个可执行的判定：

1. **资格判定：这句话能不能写？**
   每个引用句/定量句/结果句必须能落到已持有的 span，或落到人签的实验证据；摘要-only 只能是线索，不能当证据。稿件还必须与写作包内容寻址绑定（`pack_id` + `pack_sha256` + 正文 marker），包漂移即阻断。
2. **完成判定：这次运行能不能签？**
   本地实验必须走 `approve → run → ingest → claim（人签）→ closure → sign（人签）`；canonical run 必须走 RunCapsule/EA/Claim → closure。MCP/HTTP 不提供 sign、approve、freeze、publish、export。
3. **失效判定：改了一个输入，哪些结论、图、签名失效？**
   spec/data/code/execution/evidence/claim/results table/figure 以 SHA-256 串成链；lineage 与 closure 重新校验；`research_closure_status` 返回 presence/SHA-256 链与 `chain_fingerprint`，`research_lineage_status` 重算节点并返回 fresh/stale，用于发现"文件还在，但已经不是原来那一份"。

已有系统可能各占其一：Co-Scientist 有数值核验，ARS 有 claim/evidence marker，ARIS 有 run state，OpenRSI 有独立 judge。**我们的差异是把三者用同一套产物身份连起来，并让"拒绝"成为默认行为**：包不匹配就阻断审计，claim 未签就不许发布结果数值，closure 未签就不算完成，签名后任一上游变化都可被重新发现。

## 3. 当前设计如何强制这些判定

| 机制 | 强制规则 | 产物/入口 | 不能证明 |
| --- | --- | --- | --- |
| Span-only 证据 | 摘要只作线索；无全文不生成 span | `writing-pack.json`、`selected_spans` | 不证明语义蕴含 |
| 写作包绑定 | 稿件 marker 与当前 pack 不一致即阻断 | `pack_id`/`pack_sha256`、`writing-audit.json` | 不证明论证质量 |
| 句级支持账本 | `[REF-xx]` 逐句三态判定；1–5 票多数；缓存按 draft/pack/judge/votes 失效 | `support_audit.py`、`writing support-eval` | 不是人工 gold，不是 entailment proof |
| 支持感知修订 | 只改目标章节/问题句；A/B 盲评偏好原文则拒绝修订 | `manuscript review --revision-mode section/support --ab-check` | 不证明改写一定更好 |
| 本地实验生命周期 | 批准、执行、ingest、claim、closure、签名逐级绑定哈希 | `execution-approval.json` → `experiment-evidence.json` → `claim.json` → `closure-report.json` | 不证明实验设计正确 |
| 结果表与图绑定 | 论文数值必须来自已验证结果表；结果图 manifest 绑定 spec/execution/evidence/claim | `results-table.csv/.md`、`figure manifest` | 不证明趋势可外推 |
| 三套 closure profile | canonical / local experiment / **search_study** 词汇不互换，各自需要人签；search_study 额外把**功效**（区间全跨零即不可闭合）与**搜索代码不变性**纳入闭合条件 | `closure_profiles.py`、`study_closure.py`、`research_closure_status` | 不证明同行评审通过；结构化闭合不等于结论正确 |
| 多 judge 分歧账本 | 逐句 verdict、pending_human、人工裁决、pairwise kappa；strict 阻断未裁决分歧；canonical 与 local experiment closure 都有 `support_panel_ready` 硬门，local 还绑定最终手稿 hash | `support_panel.py`、`closure.py`、`experiment_closure.py` | profile id 不证明 provider 独立；kappa 不是 human gold |
| 批评角色供给面板 | 审稿角色按 `(provider, model)` 指纹去重排席，提案模型不得兼任；宿主交接的回答者由账本 `host_label` 回读，能否决配置层结论；供给不足时 `--independent` 失败并报告缺几个，不静默单作者；判定结果直接约束稿件措辞 | `independence.py`、`model_catalog.critic_panel`、`innovation review --critic/--independent`、`GET /api/host-model/panel` | 配置与标签都是声明性的：不证明输出独立、不证明 novelty、不通过 G1/G2 |
| 想法被执行而非被描述 | `experiment_plan` 不只是写作素材：`study from-idea` 校验其档位绑定后，把声明的设计真的跑成研究，并写 `study-origin.json` 绑定 idea/否证条件/spec 哈希；未知因子、越界水平、格子数 >12、种子 <4、已有研究未加 `--force` 全部在写文件前拒绝 | `study_from_idea.py`、`study search --factors`、`SEARCH_FACTORS`/`OPERATOR_SETS`、`closure_profiles` 的 `origin=absent/bound/stale` | 执行不等于确认；区间跨零是非结果，`--force` 重跑会把 origin 判为 stale |
| Human gold + panel 对照 | 双人标注 JSON → majority/observed agreement/pairwise Cohen's κ；可选 panel-vs-gold accuracy/confusion/disagreements；writing audit 返回 gold 摘要 | `support_gold.py`、`writing support-gold` | κ 是标注一致性，不是事实正确；gold 不是 closure gate |
| 外部期刊 Skill 投影 | 只取 MIT 许可的 JOS/CJC 写作规范，转成 writer brief + deterministic journal_style checks（摘要四要素/关键词/TP/GB7714/图表/威胁有效性/引言弧线），保留来源与 license | `journal_skill_audit.py`、writing pack/audit | 不是官方模板，不保证语言质量或录用 |
| MCP 只读面 | 39 个工具无签核/执行入口；执行与签核只在本地 CLI | `mcp_server.py`、`framework_api.py` | 不证明客户端不会绕过 |
| **生成能力供给可移植（Host-as-Model）** | 绑 `kind="host_agent"` 后生成步骤不发网络：落 `ModelTurn`（请求原文+请求哈希+期望形状+TTL）→ 抛 `ModelTurnPending`（禁止静默降级）→ 宿主 Agent 用自己的模型作答 → 按哈希绑定、形状校验、一次性消费 → 重跑即重放 | `host_model.py`、`models/gateway.py`、`research_model_turns`/`research_model_respond` | 答案仍要过全部审计；`host_label` 自报且未验证，不证明模型独立性或质量 |
| **想法必须可执行（executable 注册表）** | 每个档位同时声明 supports 与 cannot_test；`experiment_plan.profile` 为必需字段且 dataset/metric 必须属于该档位，不匹配直接拒绝想法；生成提示词与 feasibility 审稿人读同一份注册表 | `executable.py`、`innovation_review.py` | 注册表只约束"能否在本系统执行"，不保证实验设计正确或外部效度 |
| **可执行搜索实验台** | 记忆 × 接受门控 2×2 因子、单位验证算力改进率、按种子配对 95% 区间、完整节点血缘；区间跨零即判"不可判定"，evidence 与人签 claim 绑定同一形状 | `search_lab.py`、`study search` | 改进对象是流水线配置（`analogue=true`），不构成对 DGM/SICA/ACE/SIFT 的复现或反驳 |
| **自进化返回边** | 消费目标必须先注册 `SAFE_SCOPES` 才能激活；每次 `resolve/snapshot` 重读源租约（账本缺失 fail-closed）；`regressed` 确认自动撤销租约——**降级自动、升级人签** | `evolution_active.py`、`evolution_policy.py`、`rsi.py::record_confirmation` | 目前只闭合两个过程参数；不主张能力增益 |
| 证据链 of custody | 只读返回 presence/SHA-256 与链指纹；不改产物 | `research_closure_status` | 不证明正确性、语义或可投稿 |
| Lineage 新鲜度 | 只读重算节点哈希；项目外路径判 stale；不重建 | `research_lineage_status` | 不证明实验有效或 closure 通过 |

设计上的关键不是"有这些字段"，而是**每个字段都有拒绝路径**。例如：`strict_pack_binding` 让漂移直接 blocked；`strict_support` 让 contradicted/unresolved/insufficient 不能进入下一轮；`submit=false` 贯穿 closure signature；`submission_ready` 在写作、修订、审计中始终为 false。

## 5. 为什么不是"加一个模块就能复制"

1. **路径依赖在 schema 里。** `pack_id` 进入正文 marker 后，审计的输入不再是"当前目录里有什么"，而是"稿件声称自己基于哪一份包"。后加这个字段，等于重写审计、修订与写作契约。
2. **拒绝路径比生成路径难。** 生成一句流畅的话很容易；在包漂移、claim 未签、支持不足、A/B 偏好原文时拒绝输出，需要每一步都有明确的 blocker 和可解释的原因。
3. **人签边界必须在架构外。** MCP/HTTP 没有签核工具，不是靠提示词约束，而是工具表里根本没有。把签核加回浏览器或 Agent，会让整条链失去意义。
4. **两种 closure 不能合并。** canonical run 与 local experiment 的产物、词汇、失败模式不同；强行统一会制造"看起来闭合"的假象。我们选择统一语义、分开 profile。
5. **代价是真实的。** 这套设计牺牲吞吐与"演示效果"：真实实验要人执行，claim 要人签，稿件可能停在 `needs_more_work`。这是有意的取舍，不是未完成。

## 6. 诚实差距：差异化的另一面

- **支持校准不是人类 gold。** 12 条 curated case 的 12/12 是回归检查，标签由本项目整理；双人标注/κ 工具已落地，但尚无真实双人标注数据。
- **评审独立性只完成了机制。** 多 judge 面板已能记录逐句分歧并要求人工裁决，但还没有用两个真实提供商 profile 跑过并公开分歧/裁决记录；profile id 仍由调用方提供，无法证明 provider 真的不同。
- **真实实验尚未执行。** `EXP-BREAST-STRONG` 已完成数据审计、5 折 CV、3 seeds 的包与 preflight（569 行），但 approve/run/ingest/claim/closure/sign 仍待用户在本机完成；没有真实 evidence、没有签核 claim。
- **真实文章仍不达投稿质量。** 16 篇来源的中文文章最近评审约 6.2，句级支持仍有大量 partial；这不是"可投稿"。
- **Qoder-native 支持评审（2026-10-28，无外部 API）。** 用 `research_support_items` 取真实稿的 28 个句级项，由 Qoder 自己给 verdict，再经 `research_support_verdicts` 写入 ledger（`judge_model=qoder:qoder-session-20261028`）：4 supported、23 partial、1 insufficient；`research_manuscript_audit` 成功读取该 ledger，section summary 指向引言 5/5、相关工作 4/4、结果 3/3 等最弱章节。随后 Qoder 自己用 `research_manuscript_section_edit` 重写引言（单 REF、窄范围），v2 复审为 10 supported、18 partial、1 insufficient；再重写“与现有工作的关系”子章节，v3 复审为 **17 supported、14 partial、1 insufficient**。`research_next_actions` 会在 ledger 为 partial/blocked 或存在 weak_sections 时返回 `support_review` 动作，指向最弱章节和复用式复审。新增 `reuse=true` 后，未改句按 sentence+evidence 内容键复用同一 judge id 的旧 verdict，只重判变更句；换稿时旧 ledger 自动归档到 `support-ledger-history/`；重写“自我改进与自生成监督”得到 v4（22/11/1），再重写“结果”“多智能体协作与集体决策”“评测范式与能力边界诊断”得到 v7（37/3/0），最后修正“智能体安全与失准评估”“语料与证据审计设计”“对研究共同体的含义”得到 v10（**42 supported、0 partial、0 insufficient**，42/42 句级项）；审计仍为 `ready_for_human_review`、`submission_ready=false`，未签核。v10 的 42 项已生成空白 A/B human gold 模板（`support-gold-annotations-A/B.json`），等待人工独立标注；`--ledger` 可直接对照 Qoder ledger，比较结果标记来源，但仍不是签名。它是 Qoder 自评审，不是独立评审或 human gold。
- **真实 DeepSeek 支持审计（2026-10-28）。** 对 `topconf-review.zh.md` 的 12 个引用句跑真实语义审计：11 个 partial、1 个 not_required、0 个 supported，且没有截断。随后两轮 support-patch 虽拆句/弱化，仍未把任何句子翻成 supported。说明根因是证据 span 与综述性主张的范围不匹配，不是覆盖上限；当前 patch prompt 也不足以修复。改用 claim plan 重新生成后，真实 DeepSeek 审计为 **4/18 supported、11 partial、3 not_required**，审计 `ready_for_human_review`；supported 从 0 提升到 4，但仍不足，说明 claim plan 有效但 span 覆盖仍有限。
- **写作覆盖与文献覆盖有限。** 没有全全文保证，没有完整 proceedings 抓取，venue 接收状态未独立核验；不覆盖湿实验。
- **签名信任边界仍是文件系统权限。** 没有 signers 时是 legacy-unsigned；有 HMAC 时密钥管理仍在本机。系统能证明"产物未被静默替换"，不能证明"签名者一定是授权人"。
- **没有 HPO 自动执行。** sweep 只生成计划；确认性 alpha 仍要人批准、人执行、人签 claim。
- **测试数量不是独立 benchmark。** 479 个测试证明契约与边界，不证明科研质量优于其他系统。

## 7. 下一阶段：把设计差异变成可测量差异

### P0（必须先做，否则差异化只是叙事）

1. **一次真实本地实验闭环。** 用户在本机对 `EXP-BREAST-STRONG` 执行 `approve → run → ingest → claim → closure → sign`；随后用 `empirical paper` 生成同 run 实证稿。验收：真实 evidence、真实 claim、真实 closure signature、结果表与图绑定。
2. **独立人类 gold。** 工具与空白模板生成器已就绪；下一步用 30–50 句、两人独立标注，报告 Cohen's κ、分歧与 panel-vs-gold accuracy；把 12 条 curated case 降级为回归集，不再称校准集。
3. **跨提供商评审。** 面板机制已落地；下一步用两个真实提供商的 profile 跑同一批句子，公开逐句分歧、人工裁决与 pairwise kappa；不一致的句子进入人工复核，而不是取平均。
4. **写作质量对照。** 以 6.2 为基线，比较 support-aware 修订前后的 supported 比例、unsupported 数量、A/B 偏好与 rubric 分数；不达标就停在 `needs_more_work`。

### P1（放大差异）

5. **链校验而不只是链展示。** canonical run 的 `chain` 仍只做 presence/SHA-256 展示；local experiment 已由 `research_lineage_status` 做 fresh/stale 重算，下一步把期望值比对扩展到 canonical run 与图 manifest。
6. **closure receipt。** 为每次人签 closure 生成只读回执：链指纹、签核者、时间、未决事项、明确的 `submission=false`；供 Qoder/Claude/Zcode 读取，不提供签核。
7. **变更演练。** 对已签实验做"改一行数据/换一个 seed/替换一张图"的演练，验证 lineage 与 closure 能把影响面说清楚；这是与"生成型"系统最直观的差异。

### P2（能力扩展，不改变边界）

8. 全文覆盖 adapter、更多 venue、中文期刊模板；
9. HPO 只在确认真实实验之后接入，探索性与确认性证据继续分开；
10. 三端 Skill 与工具契约保持一致，新增能力先过 MCP 只读面。

## 8. 对外表述模板

可以说：

- "evidence-closed research runtime" / "证据闭合运行时"；
- "human-signed closure, read-only MCP surface"；
- "we refuse to publish numbers without signed evidence"；
- "we track which claim, figure and signature become stale after a change"；
- "a portable governance layer for existing research agents"。

不要说：

- "首个/唯一/通用 AI Scientist"；
- "autonomous discovery" / "端到端无人科研"；
- "peer-reviewed" / "submission-ready" / "可投稿"；
- "hallucination-free" / "semantic entailment proven"；
- 任何没有真实执行与人签支撑的实验数字。

## 10. 外部 Skill 接入的反思（Awesome-Journal-Skills）

这个仓库的价值不在“4166 个 Skill”本身，而在**按期刊/会议要求组织的程序性知识与写作规范**。它的强项是 venue-specific checklist、模板经验与评审流程；弱项与所有 Skill 生态一样：没有 claim/evidence 闭合，也没有“写进去的句子是否被证据支持”的判定。

因此接入设计不采用整体复制或自动执行，而采用三层投影：

1. **Instruction 层**：只选目标 venue 的 writing-style / related-work / experiments / reproducibility / review-process，把规范摘要注入 writer prompt；来源、MIT license 与 SHA-256 写入 `journal_skill_profiles.json`。
2. **Check 层**：只把可确定性判断的规则（摘要四要素、关键词数、中图分类号、GB/T 7714 类型标记、图表题注、威胁有效性、引言弧线）变成 `journal_style` 检查；不把“Skill 说了”当成证据。
3. **Execution 层**：不导入或自动运行 457 个脚本；脚本仍只在本地 CLI 显式信任下运行，MCP 不执行。

这与前九仓库调研的关系：ARS/CCFA 强在 Skill 契约与 artifact ownership，ECC 强在 canonical skill 投影，本项目补的是**来源哈希 + 证据审计绑定 + 期刊检查可复验**。`skill journal-verify` 已在本机验证 8 个外部源文件 fresh；但这不是官方模板认证，也不代表文章质量。真正的风险是外部规范漂移与“格式合规冒充学术质量”，所以 profile 必须可重验、check 必须保持浅层且明确标注边界。
