# 设计科学性与各阶段细节创新点（自我评审）

本文不是功能清单，而是回答两个问题：**这套设计在科学方法上站得住吗**，以及
**每个阶段的细节里，哪些是真正新颖的、哪些只是工程整洁**。
每条都给出可核对的位置（模块规格 `modules/<id>/SPEC.md`、验收账目 `58-` 的 §编号、
或 `runtime_data/` 下的真实产物）。写这篇的动机是：本会话连续四次发现
**"工具产出的数字被当成结论读"** 的错误（§106 同分不同含义、§110 跨语种零命中、
§113 精度截断伪造的"17 个无来源"、§116 位数超过证据），说明科学性必须逐阶段钉死，
而不是靠最后通读一遍。

## 1. 判定这套设计是否科学的六条准绳

| 准绳 | 系统里的实现 | 违反时会被什么抓住 |
| --- | --- | --- |
| 可证伪性先于生成 | S2 `idea` 要求 hypothesis + falsification 才进候选 | `idea_review` 的 falsifiability 检查 |
| 度量效度先于结论 | S5 主分析用配对交互 + 归一化 AUC 敏感性；报告 MDE80 与反转率 | 功效阶梯 `high-power`/`power-ladder`；§101 |
| 证据粒度可核 | S1 只允许 Span 级证据；无全文即无 Span、无主张 | `literature-ledger` / `claim-registry` |
| 判定者独立性 | 三评审角色须来自不同 provider+model 供给，否则自报 single_author | `independence.py`；§8/§9 |
| 权威在人不在模型 | G1/G2/S5b/G3/G5、claim/closure 签名、bundle 发布全部 CLI-only | 44 个工具名里命中 sign/approve/freeze/publish/close/claim/verdict 的只有 `research_support_verdicts`（只读投影），核对入口 `research_agent/mcp_server.py` 的 `TOOL_NAMES` |
| 投影不比原像乐观 | 任何面向人的数字必须带分母、截断状态、语言与精度语义 | §106/§110/§113/§116，`by_stage`、`language_mismatch`、`decimals_over_precision` |

前四条是常见科研规范；**第五条与第六条是本系统真正的方法学主张**：
前者把"人门"实现为架构外的必要环节，后者把"报告方式"本身当成可测的偏来源来治。

## 2. 之前的设计哪里不科学（逐条已被现设计取代）

1. **界面内假签核**：早期 Web 把 SIM 通过画成已批准。现在 UI 只生成命令、绝不执行
   （`apps/web/src/.../domain/gateCommands`），签核痕迹只能来自 CLI 的人类身份。
2. **fixture 当证据**：fixture 现在必须显式 `fixture: true` 并在输出携带 `fixture_mode` 警告；
   写作审计把 fixture 源列为 blocker（§写作面）。
3. **摘要线索当全文**：OpenAlex 只给 abstract clue，无全文不得建 Span——这条边界写在
   `modules/literature/SPEC.md` 的不变量里，并由 S1 代码强制。
4. **词法 rubric 当质量分**：三份真实设计打出完全相同的 `scored=7 covered=1`，
   其中两份命中同一条目、第三份命中另一条（§106）——同分不同含义。
   因此 rubric 只能出 punch list；混合 profile 的分母还必须按阶段拆开（§109）。
5. **"字节相同"当唯一溯源**：把 6 位渲染 vs 5 位存储判成"无来源"，
   差点给出方向相反的诚信结论（§113）；现在分三层，且不允许草稿自证（§116）。
6. **能力只长在一个面上**：`figure table`、`skill coverage` 路由、数字溯源都曾先只落 CLI，
   宿主面缺参数（§34、§114）。现在三面对等构，并有断言钉住 `TOOLS/TOOL_NAMES` 同序。

## 3. 各阶段的细节创新点（这才是可发表的部分）

- **S0–S12 task-agent（v0.6.3）**：把科研流程做成**有状态、可续跑、每步落契约文件**的代理，
  而不是一次性 prompt 链。细节创新：`run-context/task-plan/task` 三件套让
  人工门的产物成为下一步的**输入契约**，中断后可由人类文件恢复。
- **S1 literature（v0.9.0）**：**Span 级证据的最小粒度约束** + 覆盖记账（facets、gap、
  saturation 三态）。`by_stage` 之外还有 `scope_like`：像范围陈述的条目由人驳回，启发式不自作判定。
- **S1–S3 orchestrator（v0.2.3）**：scout fan-out→fan-in，且记忆（`literature memory`）
  只做检索次序建议、**可被证明无效时关掉**（RSI 策略面），不自建"经验神话"。
- **S2–S3 idea + innovation（v0.14.1）**：缺口/想法必须**至少引用两篇不同论文的 REF**
  （`research_innovation_review`），把"新颖性"绑在证据拓扑上而不是模型自信上；
  评审供给指纹化，独立不足时**失败并报缺失计数**，不静默单作者。
- **S4 experiment / ccfa-audit（v0.8.2 / v0.4.0）**：设计是数据（声明式因子空间），
  未知因子或格子数越界**直接拒绝生成**；`ccfa-audit` 用顶会清单做设计体检而非打分。
- **S5 run / search-study（v0.7.0 / v0.36.0）**：这是方法学最硬的一层——
  ① RunCapsule+EA 的哈希链；② 功效阶梯让系统**抓住自己**的小样本过度声明
  （`replicate-clean.json` 的 power_audit：79 条本可在更低功效下判定，其中 7 条在更高功效下不再决断或翻转，reversal_rate 0.0886；且 7 次翻转全部集中在 iris，其余三个环境 0 次。同一批数据换判定口径后的实测值是 66/0.1061、44/0.1591、27/0.1111——反转率对"何时判定"敏感，这正是要把功效阶梯写进方法而不是写进脚注的理由）；③ 复现计数把"单数据集轶事"
  变成跨 4 个独立环境的可判定量；④ 归一化带来的**种子选择效应**（图产物 `runtime_data/metric-validity-paper/figures/response-curves-idea03-4env.manifest.json` 的 `selection_warning` 原文："7 of 16 (dataset,cell) series are drawn on fewer than 32 seeds"，而 `normalized_run` 恰好在 run 从天花板起步（headroom<=0）时返回 None，于是这些 run 被从曲线里剔除）
  被作为缺陷公开，而不是藏进图注。
- **S5b–S13 judge（v0.1.2）**：句级支持判定 + 多评审 kappa + 分歧必须人工仲裁；
  `support-eval` 先校准再信任何新 judge。
- **S6 figure（v0.4.1）**：示意图与数据图**在类型上不可互换**——AstraDraw 输出永远
  `schematic=true`，且审计禁止示意图进结果段；渲染器缺失时降级为 scene-only 并警告，
  不假装出图（§设计缺陷清单）。
- **S8–S12 manuscript（v0.9.3）/ writing（v0.8.1）**：`reproduction_map`（主张→由 capsule
  参数**重建**且经真实 argparse 验证的重跑命令→命名产物）+ 三层数字溯源
  （字节 / 舍入 / **超过证据位数**）。这一对是"闭环优势→投稿优势"的最后一公里，
  直接对应可复现清单里 `claim→command→artifact` 的要求。
- **S8–S12 revision（v0.2.2）**：修订**不得新增数字、不得丢引用、不得删图/表引用**，
  未知 spec 字段直接拒绝（曾经的静默降级事故），且 `submission_ready` 恒为 false。
- **S13–S16 closure/lineage/maintenance（v0.17.1 / v0.2.0 / v0.1.0）**：closure profile 不互换
  （`canonical_run` vs `local_experiment` 分别校验），lineage 的 `fresh` 只表示"字节与哈希一致"，
  绝不表示"结论正确"——这类措辞纪律本身就是科学性的载体。
- **META integration（v0.29.0）/ host-model（v0.4.2）**：新增 `workspace preflight`——
  秒级回答"SPEC→导出→工具面这条治理链现在哪一环过期"（SPEC 版本没有对应 Changelog 条目、
  已导出注册表落后于 SPEC 投影、`TOOLS`/`TOOL_NAMES`/SPEC `tools:` 三方不一致）。
  它存在的理由很具体：上一轮一条命令链被中途杀掉，留下一次未写入的 `spec update`，
  而唯一的检测手段是几分钟后跑完全量套件。**治理链必须能自己喊疼，不能靠事后长跑。**
  边界句写死"只查记账、不查行为，fresh 不等于正确"。
- **META host-model**：**宿主即模型**：无 key 时把生成步骤
  挂起为待答轮次（`research_model_turns/respond/void`），void 保留旧答案哈希；
  这把"用宿主 agent 当模型"变成可审计的交接协议，而不是暗箱。
- **META rsi（v0.4.0）/ mandate（v0.1.3）/ waitpoints（v0.1.0）**：自我改进被限制成
  dry-run→public→hidden→人签四段缺一不可；撤销会传播并自动降级；
  委托状态是**只读投影**，`MANDATE_SCOPE_TRUNCATED` 这种"没看全"会被明说。

## 4. 现在仍然不够科学/不够强的地方（诚实清单）

1. **词法代理的天花板**：rubric 覆盖、scope_like、near_miss 全是词法启发式。
   它能列 TODO，**不能排序设计质量**（§106/§109 已量化）。语义评审仍要靠模型 judge + 人。
2. **记忆效果的非自答两臂没跑成**：#20 需要 `AGNES_API_KEY` 或把 `idea` 绑到已设 key 的
   `deepseek`；当前 A/B 的"自答偏差"只在文档里声明，没有对照数据。
3. **强基线调参对照缺失**（§107 缺口①）：顶会清单第一条，需要新的真实跑动，代码补不出来。
4. **一个已定位但未处置的数字**：`-0.033070` 写成 6 位而证据只有 5 位（§116）。
   工具能指出，改不改是论文决定。
5. **WebUI 落后于 CLI/MCP**：`figure table`、`skill coverage` 路由、数字溯源都还没有面板；
   前端只消费 `/api/rsi/story` 快照，其余只读端点闲置。开源包能跑，不等于能力被看见。
6. **发布卫生刚被抓到一次**：`scripts/gen_architecture_scene.py` 曾硬编码本机绝对路径，
   `release_check` 以 `local_path` blocker 拦下（本轮已改为仓库根推导）。
   说明"能导出发行包"必须与"扫描发行包"配对存在。

## 5. 与 CCF-A 高质量论文要求的对照结论

- **已经比一般 agent 论文强的地方**：证据粒度（Span）、跨环境复现计数、
  功效与反转率的自我拦截、主张→命令→产物映射、可核的数字来源层。
  这些恰好是审稿清单里最容易空心的条目，我们有真实产物支撑。
- **仍然可能被拒的地方**：主实验的对照强度（缺调优基线）、记忆增益无独立两臂、
  评估度量的语义有效性论证（归一化 AUC 的选择效应我们披露了，但没给出替代方案的对比）。
- **最短路径**：先补 #4/#5 的处置与 #2/#3 的真实跑动，再把 `reproduction_map` +
  数字溯源导出成论文附录的可复现表；这三件事做完，方法学部分的说服力才与工程量匹配。

## 7. 本篇写作过程中当场抓到的一处自我错误

第一稿在 §3 引了一句"107 条低功效判定、10 条被推翻、反转率 0.0935"。
这是**从会话记忆抄来、而不是从产物读来的**。回读 `power_audit` 字段后，
权威值是 `decided_at_lower_power=79 / overturned=7 / reversal_rate=0.0886`
（`runtime_data/qoder-real-lit/replicate-clean.json`，其 `reading` 字段自己就把这句话写全了），
换口径还有 66/0.1061、44/0.1591、27/0.1111；`0.0935` 只作为与反转无关的数据值出现在个别 study.json。
**原引用不成立，已按逐配置引用替换。**

这条自我错误恰好证明第 1 节第六条准绳为什么必须写成机制而不是口号：
如果"反思设计科学性"这篇文章靠回忆来写统计量，它就变成了自己所批判的东西。
此后本仓库的硬性写作规矩：**引用任何数字必须带产生它的文件路径；带不了路径的数字不进文档。**

第二处自我错误（同一轮内被抓到）：我原本写"28–31 种子才有 7/16 序列可测"，
把 `selection_warning` 的**方向说反了**——产物原文是"7 of 16 序列在少于 32 种子的情况下被绘制"，
即这 7 条是**受影响的那一批**，而不是"只剩 7 条可测"。
两件事都发生在按新规矩逐条回读产物时，说明这条规矩的成本很低（几分钟）而收益是即时的。

## 8. §122 之后对本节的更正：强基线已经补上，并带来一个负结果

第 4 节里"强基线调参对照缺失"这条**已经不再是缺口**：`study baseline` 在同一划分、同一评分函数下
做分层交叉验证调优，并把折数压进研究预算（19 配置 × 3 折 = 57 次拟合 ≤ 预算 60），
与四个环境的既有研究逐种子配对（`runtime_data/tuned-baseline-*.json`）。结果：

- `memory=on 且 gate=on` 在 iris（+0.0156，35 胜 6 负 23 平 / 64 种子）与 wine（+0.0064，13/5/14）
  跑赢调优基线；只开记忆（gate=off）在 wine 上仍为负 ⇒ **机制需要档案与门槛共同作用**；
- breast_cancer 近似平手（−0.0005，15/9/8）；
- **digits 四个臂全部输给基线，16 个种子 0 胜**（−0.0244 至 −0.0329）。

这条负结果改变了本文的结论强度：系统此前的"跨 4 个环境可判定复现"说的是**策略之间的相对顺序**
可复现，而不是**绝对水平**优于强基线。二者必须分开写，
否则就是 §1 第六条准绳禁止的那种"投影比原像乐观"。
另外记一笔方法学收益：如果只有内部四臂对比，digits 上的失败是**看不见**的——
这说明"强基线"不是礼仪性条目，而是能改变结论的对照条件。

## 9. §125 之后再更正一次：digits 的失败被定位到起始点

第 8 节写的"机制在绝对水平上不敌强基线"，在被追问后收窄为更准确的版本：
把搜索的起始配置从随机特征子集换成全特征（新增可声明因子 `root`，incumbent 仍是随机子集、
分数与 cell 命名逐字不变），同一预算 60、基线 57 拟合的配对比较下，
digits 从 **−0.0244（0/16 胜）** 变成 **+0.0030（CI95 [0.000764, 0.005254]，14/6/4，24 种子）**。
所以正确的说法是：**机制不是无效，而是被一个糟糕的起点掩盖了**；
同时效应量很小且经历 8→24 种子时 +0.0051→+0.0030 的缩水，
因此这句只能支撑"在合适起点下不弱于调优基线"，不能支撑"普遍更优"。

这条也说明一个方法学点：**负结果不是终点，而是下一次可证伪实验的入口**。
而我在这上面连着给出两个被证伪的解释（"浪费在翻特征上"、"变慢是因为我污染了被扫描的项目目录"），
所以本文的规矩继续保持：解释必须配一个能推翻它的实验，猜测不计入理解。

## 10. §126 的收获：系统现在能自己发现"度量选错"这件事

起始点因子 `root` 不只是一个新开关，它把论文的度量论点变成了**系统内部可复现的现象**：
同一实验里 `best_score` 配对 +0.0279（CI95 0.0232–0.0326，16 种子），
而主分析用的 `improvement_per_evaluation` 配对 −0.0354（CI95 跨零）。
差的不是统计功效，是**度量的定义对起始条件的敏感性**。
系统现在会把这类情况说出来（`metric_caveats`），而不是把两个矛盾的数一起交出去。

这也是"细节创新点"里我最满意的一条：创新不在于又多跑了一个实验，
而在于**当自己的主指标与结果量矛盾时，工具选择报告矛盾而不是掩盖它**。
范围限制同时记录：目前只有 contrasts 分支会警告，主效应分支不会（§126）。

## 11. §127 定稿的实验结论（四环境）

   系统的处置是自己在结论里输出 `metric_caveats`，而不是把两个矛盾的数一起交出去。
3. 论文层面的可写主张因此收窄为一句可辩护的话：
   *在起点与任务匹配时，档案+门槛的控制在等预算下不弱于、且通常优于调优的交叉验证基线（四环境配对区间不含 0）；
   而把它按"单位评估改进率"排序会得出相反的结论。*
   任何"我们的搜索普遍更强"的写法都不被这些数字支持。

## 12. §136–§137 之后：本轮新增的细节创新点，以及一处被实测推翻的推测

### 12.1 创新点：把"对手"变成包内可哈希产物（S5 / search-study）

此前 `study baseline` 算出的预算对齐调优参照只活在 `runtime_data/` 里，claim 里的数字
实际上仍然只跟研究**内部的参照格**比——期刊 rubric 恰好指这里（NeurIPS design 0/7，
其中一条就是"include strong, current, tuned baselines"）。本轮把外部参照做成研究包的
第四份产物：字节原样复制、`evidence_refs` 记 sha、`verification.baseline_digest` 带
folds / grid_size / fits-per-seed / budget_matched，并进入 `CHAIN_FILES`。

方法论上的新颖点不是"加了个文件"，而是三条约束同时成立：
**(a)** 记录的是**读者能打开的那份字节**的哈希（不重新序列化，否则哈希描述的是渲染结果）；
**(b)** 未提供基线时 `claim_id` 的哈希输入逐字不变，历史主张不漂移（用重算旧规则钉住）；
**(c)** 改基线一个字节就让整条链 stale，即"对手"与"结果"同生共死。
(b) 与 (c) 是相互拉扯的：既要能绑定，又要不能追溯性地改写旧主张。这类"向后冻结 + 向前收紧"
的成对约束，是本框架与一般"加字段"做法的差别。

### 12.2 创新点：面同构从"人工对齐"变成共享常量（META / integration）

接入 Qoder 实测照出第三处面不齐：MCP 的 `coverage` 硬要 `pack_dir`、忽略 schema 里已声明的
`pack_root`+`venue`；`max_items` 默认 CLI 200 / MCP 60；两面都不报路由到哪个 pack。
前两次（§34、§128）都是逐参数手工对齐，这次把默认值收成一个共享常量 `DEFAULT_MAX_ITEMS`，
并让两面都调同一个 `resolve_pack_dir`、都输出 `route`+`route_confidence`，
再用 MCP-vs-库面的逐字段相等断言钉住。**可推广的规则**：跨面一致性不该靠"改一边记得改另一边"，
而应把共用取值抽成单一真源 + 一条面-vs-面断言；否则每次扩展都会再裂开一次。

同时留下一条更不舒服的记录：skills 0.9.2 的 changelog 曾写"CLI 与 MCP 路由已完全一致"，
实测发现那句话只在 `route` 动作上成立。**已声明的 parity 也要被复测**，否则规格本身会变成
一条过期但看起来可信的声明——这比没有声明更危险。

### 12.3 创新点：投影必须区分"没算"和"算了但被扣住"（S5 / 度量有效性）

`to_markdown` 强制表头与数据行同源，并新增两个互不混用的标记：`not computed`
（产物由尚未计算配对区间的版本写出，属版本问题）与 `withheld(low power)`
（区间已算出但种子不足，属功效结论）。此前手工表把两者都写成 `[null, null]`，
读者会把版本差异读成效应不存在。这是 §82"投影不得比证据更含糊"在**表格层**的具体化：
含糊不只来自措辞，也来自空格。

### 12.4 被实测推翻的一处我自己的推测（S1 / RSI 门禁）

我为 #45 写下过两条后来都不成立的判断：

1. "真实智能体上可以复刻 memory × gate 2×2，与类比实验同名同义。"
   查 `evolution_policy.py` 后否证：`gate.decision` 属 `LOCKED_SCOPES`（G1/G2/S5b/G5 只能人工放行），
   可动的只有 `literature.memory_order`。把门禁做成实验因子等于误述自己的安全模型；
   正确写法是把它当**差异卖点**——与 DGM 类系统不同，接受判定不在智能体可写面上。
2. "harness 把更便宜且同等质量的候选全拒了，可能是缺陷。"
   逐 split 打印后否证：b2/b3 确实 `cheaper=True`（15/18 < 21），但 **near_ood 召回从 1.0 掉到 0.667**
   使 `non_inferior=False`，拒收是正确行为。

留下的科学结论比原计划更有价值：**该探针在四个 split 上都饱和（baseline 召回 1.0），
所以任何"提升召回"的智能体级实验都会是结构上的空结果**；而门禁愿意为近域外退化放弃
28.6% 的算力节省，这本身就是"效率主张必须配非劣证据"的可写论据。
据此 #45 的主度量改成"非劣约束下的算力"，主环境改成 near_ood，并把"只有 incumbent 明显低于天花板
才允许注册召回为主度量"写成 SPEC 门槛。

**方法论**：本轮三次因猜键名得出错误读数（`paired_interval["low"]`、`seeds_where_study_loses`、
正则把 `schema_version` 当成耗时字段）。固化下来的收尾动作是：**任何"某指标缺失/异常"的结论，
必须先把该结构的真实键名与逐项数值打印出来**，再据此立任务或写文档。


1. **起点是隐藏变量**：`memory+gate` 机制在同一预算下能否胜过调优交叉验证基线，
   取决于搜索从全特征还是随机子集起步——四个环境在同一种子下配对，全特征起点全部决定性为正，
   随机起点只在 iris 决定性为正、在 digits 为负。这是把"机制无效"的误读纠正过来的关键实验。
