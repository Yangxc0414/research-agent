# 68 · 判定第一次改变下一次行为（自动扩检索回路）

> 2026-11-07。上一轮整体反思的结论是：本系统是**单向投影架构** —— 四种判定
> （资格 / 完成 / 失效 / 供给）的下游全是只读文字（`next_actions` 进 Markdown、
> `closure_status` 只读、RSI regressed 只撤租约、`gate_rejected` 只写事件），
> 唯一回路是人在 CLI 签核后显式重跑。当时给的唯一验收判据是：
> **系统能否在没有人类输入时，因一次判定结果而改变下一次的行为？**
> 本轮把答案从「否」改成「能，但只在一条严格受限的通路上」。

## 1. 落地了什么

| 文件 | 改动 |
| --- | --- |

决策规则（纯函数）：`saturated` → 立即 `converged`；`partial` / `insufficient` → 下一轮预算翻倍（上限 30）；轮数或预算耗尽 → `exhausted` 且 `blocked_by_human` 写明「需人补语料或显式接受部分覆盖」，**不假装收敛**。回路不生成任何文献，只是让既有检索器返回更多它本来已有的全文。

## 2. 整体效果（实测，同一份 7 篇真实语料、同一条 pipeline）

| 指标 | 关闭（原行为） | 开启 | 变化 |
| --- | --- | --- | --- |
| 独立来源 | 3 | **6** | +3 |
| span | 24 | **48** | +24 |
| `coverage_score` | 0.675 | **1.000** | +0.325 |
| `saturation` | partial | **saturated** | 收敛 |
| `coverage.gaps` | 2 | **0** | −2 |
| idea 候选引用的独立来源 | 3 | **5** | +2 |
| 轮次 / 事件链 | — | 2 轮，`cycle_observed → cycle_expanded → cycle_observed → cycle_converged`，链校验通过 | 可核对 |

即：**S1 的「partial」判定真的被消费成了下一次 `max_sources=6` 这个参数**，而不是又一条只读建议。整条流水线的证据池因此翻倍，下游 idea 的证据基础同步变宽。回执原文：

```
adaptive_cycle=rounds:2 status:converged budget:3->6 |
sources:3->6 spans:24->48 coverage:0.675->1.0 saturation:partial->saturated |
loopback changes retrieval budget only; no human gate crossed, no Claim/EA/gate written
```

## 3. 为什么这算框架级改进

对照上一轮的尺子，四种判定里**资格判定（S1 覆盖）第一次有了下游动作**。这不是又一个回执：
`decide_next_cycle` 的返回值直接作为下一次 `LiteratureRequest.max_sources` 传入，
`_ScriptedAgent.budgets == [3, 6]` 这条断言钉死了「判定改变参数」这一事实。
同时它复用了上一轮落地的事件链，所以回路的每一次扩张与停止都可核对、可重放。

## 4. 边界（不粉饰）

- **只有一条通路**：其余三种判定（完成 / 失效 / 供给）仍然只有只读下游。`closure_status` 依旧只读、`lineage.stale` 依旧只改标签、`RSI.regressed` 依旧不接主 pipeline。
- **不改任何门禁**：Q0/G1/G2/G3/G5 判定与 `commit_boundary` 的「只是状态不是放行开关」全部不变；`submission_ready` 仍无置真路径。
- **不写** Claim/EA/gate/signature；**不跨人工门**；**不自动续跑**整个 pipeline（回路只在 S1 内部）；**不编造语料**（只放开既有检索器的预算）。
- **默认关闭**：`adaptive_retrieval=False`，既有 run 与 1280 项测试的行为逐字不变；`--adaptive-retrieval` 是显式 opt-in。
- **MCP 侧没有这个开关**：WorkBuddy 的 `research_run` 参数表未改，属契约变化，未做。
- 这是**证据广度的结构性改进**，不是「创新点质量更好」；`novelty_status` 仍恒 `unverified`，仍无留出集与人工评分。
- 语料不足时回路会 `exhausted` 并明确要求人补语料 —— 它不会用更多的重复查询把 3 篇伪装成综述。
