## 0. 一句话结论

我们的问题不是某个模块写错了，而是**缺四份统一契约**：投影契约、度量注册表、principal 模型、决策记录。
这一会话里反复出现的缺陷族（陈旧读数、不可比的比率、分不清演练与真实、归属靠约定、达标主张签不了）
都是这四个缺口的实例。逐个修实例是对的（每次都有实测），但实例会一直长出来。

## D1 170 个投影，没有统一的投影契约（最普遍，已量化）

**实测**：`research_agent/*.py` 里有 **170 个不同的 schema id**、**88 个文件**声明 `schema_version`；
其中只有 **11 个文件**带 `generated_at`，**26 个**带任何形式的指纹。

**为什么是结构性的**：系统的主要产出就是"只读投影"（story、brief、closure report、README、face matrix、
web 快照、coverage 报告……）。每个投影各自决定要不要带年份、要不要带生成它的代码指纹、
要不要带 fixture/simulation 标记、要不要带分母。于是同一类失效在不同投影上反复出现：

| 本轮/本会话实例 | 缺的槽位 |
| --- | --- |
| #76 宿主连到旧构建 | 投影不带 served build 指纹（后来补了） |
| §235 同一研究读作 0/14 或 8/14 | 读数不带"生成它的构建"（本轮补进 coverage） |
| #92 `rsi-story.json` 是 2026-10-24 且无 fixture 标记 | 快照不带年份/fixture，且不在守卫内 |
| #95 包 MANIFEST 无 `generated_at` | 制品不带年份 |
| §244 story 汇总层丢掉 `simulation` | 演练来源不上汇总 |
| #54 190 个包全部 stale | 制品带的指纹与当前代码不可比，且无重绑策略 |

**改正**：定义一份 `PROJECTION_CONTRACT`（一个字典常量 + 一段边界文字），要求每个投影声明这些槽位：
`schema_version` / `generated_at` / `source_fingerprint`（生成它的代码指纹）/ `read_only` /
`base`（分母或参照，比率类必填）/ `provenance`（fixture、simulation、语言）/ `boundary`。
再配一条**枚举式审计**（不是逐处记忆）：扫描所有声明 `schema_version` 的输出，报告每个 schema 填了哪些槽位、
缺哪些；缺席必须写理由（沿用 `face_coverage.REVERSE_REASONS` 的形状——沉默不算理由）。

**验收判据**：审计枚举出的 schema 数 ≥ 170；把任一投影的 `generated_at` 删掉，审计必须报缺口；
新增一个投影而不填槽位，审计必须红。**不需要**一次性把 170 个投影都补全——先让缺口可见，再按优先级补。

## D2 度量没有注册表：每个子系统各自写死自己的主度量

**实测**：`search_lab.py` 两处硬编码 `"primary_metric": "improvement_per_evaluation"`（735、1255 行），
没有 `--metric` flag（#86）；RSI 回路的判定度量同样是它；而四环境普查里唯一越过事先声明阈值的结论
落在 `best_score` 这个**次度量**上，因此签不了。#62/#83 的"阈值是否按度量分列"至今待定，
根因是同一个：度量不是数据，是代码里的字面量。

**为什么是结构性的**：一个自改进系统若不能声明"我在优化什么、什么算达标、什么算非劣"，
它只能在别人给定的尺子上优化；而我们有三个不同的度量体制（检索探针、搜索任务、最终分数）互不相通。

**改正**：一份**度量注册表**（数据，不是代码）：每条含 `name`、方向（higher/lower）、
阈值语义（ superiority / non-inferiority bound / equivalence ）、功效规则（用哪种 N：精度 N 还是排除阈值的 N，
见 §231 的更正）、允许哪些门使用它、以及"该度量是否饱和"的声明（#45 的探针饱和应当是注册表里的一个属性，
而不是每次靠人记得）。study spec、pre-registration、RSI candidate 都引用注册表条目名，而不是自带字面量。

**验收判据**：一个 study 可以声明 `best_score` 为确证度量，且签核路径接受它（这条要 D2 落地后才可能）；
注册表里删掉某条目，引用它的 spec 在**写入时**就无效，而不是在签核时才发现；
"探针饱和"从注册表可读，`gate_verdict` 与 `#45` 的判断不再各说各话。

**需要你定**：阈值是否按度量分列、效率是否改非劣边界、确证失败能否在同一注册内重定阈值（#62）。
这三条决定注册表的字段语义，我不该替你定。

## D3 没有 principal 模型：归属靠约定，自答在结构上无法被发现

**实测**：活 `host_contract` 显示 S2 ideas / S2-S3 innovation review / S3 review / S4 experiment design /
S8 draft prose 都在 `stages_suspended_for_host_answer`；`host_model.respond()` 记了
`host_label`/`submitted_at`/`text_sha256` 与 `host-model-receipt-0.1`（读过 214-273 行），
但**不记从哪个面答的**，也没有任何字段区分"提供能力增益的人"与"评审这个增益的人"。
#49（归属需 harness 强制）、#46（评审者必须自己独立检索反证文献）、#47（想法阶段应结果脱敏）、
#20（非自答两臂）都是这一个缺口的不同侧面。

**为什么是结构性的**：这是"自改进"这个主张能不能成立的关键。目前的证据链在第一步就是自答的：
提案者、模型供给者、评审者可以是同一个 principal，而产物上看不出区别。
一个审稿人问"你的改进是谁判的"，我们现在只能回答"同一个宿主"。

**改正**：引入 principal 注册表（id、角色：proposer / supplier / reviewer / signer、来源面：cli/mcp/webui），
并让每条产物记录**产生它的 principal**。加一条硬规则：评审类产物的 principal 必须与被评审产物的 principal 不同，
否则拒绝写入（不是警告）。归属写侧由 harness 强制（#49）：产物一旦落盘，其 `origin_principal` 不可被后续写入者改写，
改写即失效并留下记录。

**验收判据**：同一 principal 既写 idea 又写它的 review 时被拒；宿主改写一个已评审的 idea 产物后，
下游能检测到并拒绝；`respond()` 的落盘轮次里能看到 `answered_via` 与 principal。

**需要你定**：principal 是"人/agent 实例"还是"角色+密钥"，以及是否允许一个人扮演多个角色（若允许，
自答就只能被标注而不能被拒绝）。这是政策决定，不是实现决定。

## D4 证据生产快于主张消费：签核路径比证据路径窄

**实测**：库存里有 190+ 个研究包、4 个独立环境、预注册与基线俱全；**已签确证 claim = 0**、
confirmed episode = 0、capability claim = 0。#54：全部包的代码指纹都过期；#86：唯一达标的结论签不了。

**为什么是结构性的**：人工门留在 CLI 是对的（本轮已在 MCP 与 HTTP 两面逐条核验：没有任何路由能
sign/approve/freeze/publish/export）。但"人签"这条路径的**成本**没有被设计过：签核者要读简报、
对照断言、看复现计数、看功效层级、看基线绑定——这些信息分散在不同产物里，而且最强的那条结论
因为 D2 根本进不了签核路径。结果是证据不断堆积、主张恒为零，闭环在最后一公里断开。

**改正**：一个"可签包"（signable packet）：一条命令把 brief + assertions + replication + power tiers +
baseline binding + environment 组装成一份**带哈希清单**的单文件，签核命令只接受这个包；
包内每一项都带它自己的 base（D1）。再配 #54 的重绑策略：以"重跑数值一致"授权重新绑定指纹，
而不是让 190 个包永远 stale。

**验收判据**：对那个越过事先声明阈值的环境，可签包能组装出来、且签核路径接受它（依赖 D2）；
重绑后 `lineage verify` 通过且不改变任何数值；一个不含 base 的包被拒。

**需要你定**：重绑的授权形式（#54/#74）——这属于"人预先授权"的范畴，我不能自己放宽。

## D5 语言不是产物的一等属性

**实测**：`study package --language zh` 产出的 README **CJK 字符数为 0**（8175 字符全英文）；
`language` 在 `study_package.py` 里只用于两处（传给内嵌简报、以及 `== "en"` 时的异脚本披露），
README 骨架硬编码英文（#90）。历史上还有 #63（想法阶段硬编码中文）、#50/#51（venue 与语言隐性耦合，
导致中文产物在英文 rubric 上读 0 分而不被警告）。

**为什么是结构性的**：语言现在是"命令的一个参数"，而不是"产物的一个属性"。
参数可以被忽略（#90 就是被忽略），属性不会。而下游读者（rubric 覆盖、稿件审计）需要的是属性。

**改正**：每个生成产物在 manifest 里记 `language`（由生成器实际输出的文本判定，而不是由参数声明）；
读者一律从产物读语言，不从 venue 推断；一条守卫：`--language zh` 的请求要么产出 CJK，要么明确报错说做不到，
不允许静默产出英文。

**验收判据**：`study package --language zh` 之后，MANIFEST 的 `language` 与 README 实测脚本一致；
若不一致，守卫红。coverage 的 `comparability.artifact_language` 不再恒为 unknown（依赖 #95）。

## D6 文档是事实上的接口，但不可执行

**实测**：AGENTS.md 里 29 个 json 路径有 **19 个不存在**（含全部 `rsi-*-ledger.json`、
`run-capsule.json`、`claim.json`、`protocol-card.json`、`g1-decision.json`、`demo.json`）；
照抄 `rsi real-trial --ledger .../rsi-compare-ledger.json` 立刻报 "no RSI ledger at …"（#93）。
后果已经落地：#81 的验收（真调 `research_evolution_status` 读回 `gate_verdict`）被它挡住。

**改正**：一条可照抄的最短链入口（临时目录里走 `rsi fixture → propose → research-cycle → confirm → story`），
加一条文档守卫：AGENTS.md 与 modules/*/SPEC.md 里出现的每个 `*.json` 路径，要么存在，
要么在带理由的清单里注明"由命令 X 生成"，要么标为 template。

**验收判据**：入口脚本在干净检出上一次跑通；把文档里某个路径改成不存在的名字，守卫必须红。

## D7 门禁决策没有结构化的决策记录

**实测/推断**：签核侧记录的是 `human_reason` 字符串 + 策略 SHA（autopilot 那条路径）；
我没有找到一个 schema 描述"签核者面前摆了哪些证据、考虑过哪些替代、明确拒绝了哪些主张"。
**这一条是推断**，因为我没逐个读签核产物的 schema，标注清楚。

**为什么重要**：对一篇讲"可审计研究"的工作，审稿人真正想看的不是签名，而是**决策记录**：
你看见了什么、你拒了什么、你为什么拒。我们现在把这部分压进一个自由文本 reason。

**改正**：一个 decision-record schema，附在每次签名上：`evidence_presented`（按哈希列文件）、
`alternatives_considered`、`declined_claims`（明确写下"这条不签，因为…"）、`principal`（依赖 D3）、
`decided_at`。没有决策记录的签名应被拒。

**验收判据**：一次签核若不带决策记录则被拒；记录里的证据文件哈希可与包内文件对上。

**需要你定**：决策记录是否成为签核的强制前置（会提高签核成本，但这是"可审计"的实质）。

## D8 库存没有生命周期

**实测**：190+ 个包全部指纹过期（#54）；5 个早期包的哈希不可重推（#61，已按链完整性分层）；
没有 "superseded_by" 链接，没有过期策略。

**改正**：给库存加三个属性：`superseded_by`（哪个包取代了它）、`rederivable`（能否重跑得到同样数值）、
`expires`（探索性库存的有效期）。确证性库存永不过期，探索性库存到期即降权，不进覆盖率分母。

**验收判据**：覆盖率分母只含未过期且可重推的包；一个被取代的包在清单里标出取代者。

## D9 判定不绑代码版本

**实测**：本会话三次——后台套件被中断（退出码 1073807364，日志无 `Ran` 行）；
在套件飞行中两次改被测源码；后台任务通知报 `completed (exit code 0)` 而套件实际 `FAILED (failures=1)`
（因为命令链尾的 grep 吃掉了退出码）。对照：MCP 面早有 `build_info()` 指纹，236 靠一次比较排除了旧构建。

**改正**：判定记录由测试运行器自己写（不是外层 shell 的退出码），带代码指纹、条数、耗时、`truncated` 标记；
一个只读检查回答"最近一次判定覆盖的是哪个指纹、与当前检出是否一致"。

**验收判据**：改一个源文件后，检查必须报"判定过期"；中断的跑不得留下看起来像完成的记录。

## 哪些是已经对的，不要动

不是全盘否定——以下几条本轮是**逐条核验过**的，属于设计里最硬的部分：

1. **人工门只留在 CLI**：MCP 46 个工具无签核类；HTTP 59 条路由里带 gate 词的只有两个只读 GET
   （`/api/project-closures`、`/api/signers`）；通用派发口 `/api/research/tools/{tool_name}` 只能打到
   `TOOL_NAMES`，由 `framework_api.call_tool` 的 `unknown tool` 拒收保证（`framework_api.py:90-92`）。
2. **预注册校验器 fail-closed**：本会话它正确拒绝了我三份草稿（缺 schema_version、seeds 不是列表、
   `baseline.why` 必填）以及一次因子集不匹配（"declared design does not match the command's --factors"）。
   这是反事后诸葛的机器，不是 bug。
3. **负结果保留**：`rsi story` 的警告写"negative results retained; do not retry without new evidence"；
   四环境普查如实报"2 个环境决定性在阈值下、1 个结构性不可判"，而不是只报那个通过的。
4. **枚举式守卫**：凡是有的地方（发布树 `--check`、路由表枚举、工具表枚举）都抓住了我的错；
   凡是没有的地方（写路由守卫、参数卫生、投影槽位）都静默漏了。这条经验应当推广，而不是个案修补。
5. **每个投影都带 boundary 文字**：这习惯是对的，缺的是 boundary 之外的**机器可读槽位**（D1）。

## 优先级与授权边界

**我可以直接实现（不改判定语义，只让缺口可见）**：D1 的枚举审计、D6 的文档路径守卫、
D9 的判定记录、D5 的语言一致性守卫。这四条都不需要你先决定任何政策。

**必须你先定边界**：D2（阈值语义、非劣边界、能否重定阈值 = #62/#86/#83）、
D3（principal 是实例还是角色，能否一人多角 = #49/#46/#47/#20）、
D4（重绑授权形式 = #54/#74）、D7（决策记录是否强制）、D8（探索性库存的有效期）。

**建议顺序**：D2 → D4 → D3。理由：D2 决定"我们在优化什么"，没有它 D4 的可签包仍然装不进最强结论；
D4 决定"证据能不能变成主张"，没有它闭环永远是 0 个已签 claim；
D3 决定"这个主张是谁判的"，没有它前两条的产出仍会被自答污染。
D1/D5/D6/D9 可以并行做，它们是让上述三件事**可见**的仪表。

## 本文档自身的边界

这是设计层反思，**没有执行任何测试**（按你的要求）。文中每条"实测"都来自本轮或本会话已跑过的命令与
已读过的代码行；标注为"推断"的（D7）没有逐个读签核 schema。
本文档不改变任何代码、任何判定语义、任何门禁；它只把缺口写成可实现、可验收的形状。
当前源码有一份全量判定 `Ran 1172 tests / OK`（fingerprint `66cde183ecadae7a`），
它**不覆盖** 243/244 两轮的改动；那两轮的改动目前只有定向与护栏测试背书（189 + 103 + 32 例），
全量重跑在进行中。
