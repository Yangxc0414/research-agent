# 自进化闭环加固

## 0. 结论

之前的 RSI 控制面方向正确，但闭环不够硬：

- `admit` 的通过状态由调用方自报，CLI 甚至直接写 `passed`；
- public/hidden 证据可以在准入时被替换；
- 真实 trial 没有强制 near-OOD/regression；
- 租约撤销后，`capability_claims` 仍可能保留；
- policy 对未知 target 默认放行；
- 没有 append-only 的审计历史，主 ledger 是整文件覆盖；
- proposer/evaluator/approver 身份没有记录。

本轮把这些改成“代码强制”的闭环，而不是提示词承诺。

## 1. 现在的闭环

```text
Observation
  → Candidate (proposer / model / prompt hash)
  → pending_human
  → evaluate: public / hidden / near_ood / regression
  → strict admit (human approver + sealed hashes + all four splits)
  → active lease (scope + TTL)
  → confirmation (sealed, used_for_admission=false)
  → active / expired / revoked
  → MetaTracker：event chain / claims / warnings / next questions
```

状态仍然只有 `pending_human / approved / rejected` + lease `active/expired/revoked`；没有偷偷增加“自动 active”。

## 2. 严格准入（strict admission）

真实 retrieval trial 与 S5 trial 现在默认 `strict=True`。准入必须同时满足：

1. public / hidden / near_ood / regression 四类证据都存在；
2. 四类证据都是 `passed`，且都不是 `simulation`；
3. 每类证据有 `evaluator`、`artifact_sha256`、`task_pack_sha256`；
4. dry-run 回执非空；
5. human reason 与 scope 非空；
6. approver 非空；
7. 已 evaluate 的证据不得在 admit 时被替换（fingerprint 必须一致）。

准入记录新增：

- `admission_mode`: `strict` / `standard` / `fixture`
- `approved_by`: 本地标签，不是外部身份认证
- `evidence_digest`: 四类证据的 canonical SHA-256
- `Candidate.proposer / proposer_model / prompt_sha256`
- `EvalEvidence.evaluator / artifact_sha256 / task_pack_sha256 / evaluated_at`

边界：这些是本地可复核的 provenance，不是 PKI/法律身份。

## 3. 撤销传播

`MetaTracker` 的 `capability_claims` 现在要求 episode 的 `lease_id` 属于 active leases。

- revoked / expired lease 自动从 capability claims 移除；
- 报告新增 warning：`approved episode without an active lease; capability claim withheld`；
- revoked 记录仍保留，用于负结果和 lineage，不会被删除；
- `CandidateArchive` 原本已只用 active lease 选父代，本轮修正了父代打分：不再把 `cost`/`gap`/`failed` 当作越高越好。

## 4. 默认拒绝的 policy

`EvolutionPolicyStore.allows_candidate` 改为：

- master off → 全部拒绝；
- locked target（claim/evidence/gate/rubric/heldout/closure/signature/export）→ 拒绝；
- 只允许三个已登记 safe scope（`literature.memory_order`、`literature.query_planner`、`orchestrator.facet_budget`）及其子路径；
- 允许 `skill:` 命名空间的新 skill 候选（仍需走 eval/version/人工）；
- 其它未知 target → 默认拒绝。

`IMMUTABLE_SURFACES` 也补上 `closure` 与 `heldout`。

## 5. 哈希链事件日志

`StepLedger` 在 `*.events.jsonl` 追加事件：

```json
{"seq":1,"at":"...","type":"propose","payload":{...},"prev_hash":"...","entry_hash":"..."}
```

覆盖 propose / evaluate / actuals / confirmation / admit / reject / lease_revoke。

- `verify_events()` 重算每条 `entry_hash` 与 `prev_hash`；
- `MetaTracker.report()["event_log"]` 返回 `ok/count/last_hash/errors`；
- 事件链断裂时，新的 propose/admit/revoke 直接拒绝；
- 主 `rsi-ledger.json` 仍是当前快照，事件链提供 append-only 历史。

它检测的是“历史是否被改写”，不是证明事件内容真实；内容真实性仍靠 evidence files/hashes 与人工复核。

## 6. 真实 trial 的变化

- `run_retrieval_trial(simulation=False)` 生成 sealed evidence 元数据，并调用 `admit(strict=True)`；
- `s5_trial` 同样 strict，evidence 包含 evaluator、artifact hash、task-pack hash；
- fixture trial 保持 `strict=False`，且 `simulation=True`，capability claims 恒为空；
- CLI `rsi admit` 新增 `--strict`、`--approved-by`、`--evaluator`、`--task-pack`；strict 模式需要四类证据文件存在且可哈希。

## 7. 本轮验证

- `tests/test_rsi_governance.py`：7 项新测试
  - strict 缺 near/regression 拒绝；
  - simulation 证据拒绝；
  - 缺 evaluator/artifact hash 拒绝；
  - 成功 strict 准入记录 provenance；
  - evaluate 后替换证据拒绝；
  - revoke 后 capability claim 收回；
  - 事件链篡改检测 + 篡改后拒绝新提案；
  - policy 未知 target/closure/heldout 默认拒绝。
- 全量 249 tests 通过，ruff 通过。

## 8. 仍未完成

1. **真正的 sealed holdout**：hidden pack 仍在仓库内、可重复读取；需要 hash commitment、一次性读取预算和 clean rerun。
2. **baseline delta 自动判定**：strict 现在验证证据来源/完整性，但不自动重算“候选是否严格优于 baseline”；这仍由 trial gate + 人工判断。
3. **文件级 rehash 尚未闭环**：strict 要求 evaluator 提供 `artifact_sha256`/`task_pack_sha256` commitment，但控制器还没有 artifact root 去重新读取文件并核对；下一步加 `--artifact-root` 与 rehash。
3. **run state / stall ledger**：没有跨进程 resume-forward、连续无改进自动 pivot。
4. **Skill 激活与 RSI ledger 统一**：`SkillLab.activate` 仍独立于 RSI episode/lease；需要把 skill version activation 绑定到 admitted episode。
5. **no-op / oracle-nop 对照**：还没有把“无改动候选”作为固定负对照纳入 admission。
6. **外部 evaluator**：真实 peer-review/fixed corpus 仍未接；当前 real/S5 是本地 deterministic probe。

这些完成前，只能说“受治理的改进控制面更硬了”，不能说“系统已经能自我变强”。
