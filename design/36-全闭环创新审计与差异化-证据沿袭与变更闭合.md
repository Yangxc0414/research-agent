# 36 · 全闭环创新审计与差异化：从「生成」转向「闭合后维护」

> 这份文档不是功能清单，而是一次面向答辩、开源与个人 IP 的系统级对账。结论先说：当前系统最值得放大的，不是“再做一个能写论文的 Agent”，而是**把科研结论的失败模式做成可阻断、可签署、可在变更后重新闭合的运行时**。如果只能展示一个能力，应该展示“数据集/代码变化后，哪些 Claim、图、槽位、closure 与签名立即失效”。

## 0. 一句话定位

**别人优化“生成得多快”，本系统优化“变更后哪一句还成立、哪一个导出必须被拦住”。**

更完整的表述：

> 一个以证据闭合与受治理改进为控制面的科研运行时：S1 产出可定位 span，S5 产出 RunCapsule/EA，Claim 必须人签并绑定 EA，稿件槽位与 closure 决定能否导出；harness 改进只能拿租约，不能写 Claim；闭合后的数据/代码变化沿依赖图传播为 stale，并锁死旧签名。

这不是“端到端 AI Scientist”的正面替代，而是其**证据与治理层**。这个边界越清楚，差异化越可信。

## 1. 系统真实能力审计

审计基于代码、测试与真实运行，不依据设计文档宣称。仓库当前 75 项测试通过；S1/S5/S6 与 RSI 的 S1/S5 是真实执行，S2–S3、S8–S12 仍是确定性骨架。

### 真实数据臂

- S1 CC-BY 文本臂：4 hits / 2287 spans / 0 claims；证明“摘要-only 不产出证据”。
- ChemLab 结果臂：418 train + 22 test，Ridge vs mean baseline；3 seeds；生成了 RunCapsule、EA、数据图、ProtocolCard、BibliographyCard、5 个槽位、closure 11/11 与 signature。
- RSI：`rsi-chemlab-v2` 有 3 episodes、active lease、confirmation；`capability_claims` 对 S5/真实语料保持为空。

## 2. 当前最有价值的真实创新

按“系统级、可验证、难复制”排序，而不是按 UI 观感。

### 2.1 Run-bound claim + 结构闭合门

Claim 只引用 EA；EA 绑定 run；closure 检查 claim/EA 哈希、capsule completed、槽位绑定、图 provenance、protocol、bibliography。没有 EA/未闭合并不会导出。

- 代码：`run.py` 的 claim、`closure.py` 的 check/sign。
- 价值：把“无证据不导出”从提示词变成运行时所有权。
- 不足：closure 仍是结构检查，不判断 claim 文本是否被 span 支持。

### 2.2 ChemLab 留出集协议验证 harness

真实公开数据、固定种子、确定性派生 holdout、Ridge 与 mean baseline、逐 seed 指标与 EA。它不是新颖科学结论，但能证明“执行—证据—签署”链路真的可跑。

- 代码：`run.py`、`modules/run/fixtures/chemlab/`。
- 不足：单一数据集/模型；`model`/`metric` 参数没有完全生效；split 仍非严格 disjoint held-out。

### 2.3 受治理的 harness 租约

候选只能改检索/执行预算；dry-run、public/hidden/near-OOD/regression、TTL、revoke、sealed confirmation；lease 被实际 run 消费；harness 证据显式 `claim_eligible=false`。

- 代码：`rsi.py`、`s5_eval.py`、`real_eval.py`。
- 不足：只有两个 knobs；人工 `rsi admit` 可构造证据；hidden 仍在 repo 可见。

### 2.4 数据图 provenance 与 SVG 审计

结果图与示意图强制区分；manifest 记录 `schematic=false`、SVG/data 哈希、EA refs；SVG 审计拒绝脚本、外部 href 等。

- 代码：`figure.py`、`svg_audit.py`。
- 不足：closure 没有重算 data_sha256；图型仍较单一。

### 2.5 可签署的闭合链（本轮新增真实产物）

本轮实际生成了 `research_agent/web/data/closed-loop/`：

- `run/`：RunCapsule、metrics、EA、结果图；
- `claim/claim.json`：人签理由、scope=S5/demo/chemlab；
- `protocol/protocol-card.json`：冻结且绑定 capsule；
- `bibliography/bibliography-card.json`：4 条冻结元数据；
- `bound/`：重绑 paper 的 5 个槽位；
- `closure/closure-report.json`：11/11 pass，status=ready；
- `signature/`：人签 signature + export manifest。

这是当前仓库第一次把“S5 真实 run → claim → slots → closure → signature”完整落盘，而不是只靠测试重跑。

## 3. 关键弱点与不能宣称的内容

1. **不是预注册**：ProtocolCard 目前在 run 完成后冻结；`RunAgent` 不校验 ProtocolCard；存在“先跑后冻结”。
2. **Closure 是结构门，不是语义支持**：不检查 claim 文本与 span/指标的一致性，不替代同行评审。
3. **S1 与 S5 是两个证据臂**：Claim 只引用 EA，不引用 S1 span；“SourceHit→Span→Claim”在代码里尚未成为一条硬链。
4. **RSI 证据可被人工构造**：`admit` 只检查字符串/状态，不校验 artifact 哈希；hidden 任务仍在 repo；能力增益不能宣称。
5. **S5 split 非严格 held-out**：hidden 只是不同 test_size，sealed pack 未真正移出仓库。
6. **不是端到端论文生成器**：paper 只有槽位，没有正文生成；没有自动投稿。

对外应使用“证据运行层 / 受治理 harness / 闭合后变更维护”这类表述，不使用“首个/唯一/越跑越强/可投稿”。

## 4. 本轮落地的招牌能力：证据沿袭与变更影响

### 4.1 问题

现有 Agent 多在“生成时”把 claim 绑到来源；但科研真正难的是**生成之后**：导师要求换数据集、修代码、撤掉一篇引用、修改图的数据源。旧系统没有 stale 概念，旧的 closure report 和 signature 仍可被复用。

### 4.2 机制

新增 `research_agent/lineage.py`：

- 从 bundle 构建内容寻址依赖图：`dataset/code → run → protocol/EA → figure/claim → paper slots → paper → closure → signature → export`；
- 每个节点有 `sha256` 与 dependencies；`lineage verify` 重算当前哈希；
- `lineage impact` 把变化沿依赖边传播为 stale，输出：
  - `stale_claims` / `stale_slots` / `stale_figures`
  - `requires_reclosure` / `requires_resign`
  - `export_allowed`
- `--fail-on-stale` 返回非零退出码，作为 CI/签署前门禁；
- 签署前 `ClosureAgent.sign` 现在会从当前 demo/claim 重新运行 closure，提交报告的 checks 与当前输入不一致即拒绝，export manifest 记录 checks 哈希与全部可定位输入文件哈希。

### 4.3 真实演示

对已签署的 ChemLab 链复制一份并只改 `dataset_sha256`：

- changed：dataset、run；
- stale：run、protocol、EA、figure、claim、4 个 paper slots、paper、closure、signature、export；
- `export_allowed=false`、`requires_resign=true`；
- 未被数据影响的 bibliography 与 citation.related 槽位保持 fresh，证明传播不是“全量报红”。

产物：

```text
research_agent/web/data/closed-loop/
  lineage/lineage.json
  impact-clean/change-impact.json
research_agent/web/data/closed-loop-changed-impact/change-impact.json
apps/web/public/lineage-demo.json
```

命令：

```bash
python -m research_agent lineage build \
  --bundle research_agent/web/data/closed-loop \
  --output-dir research_agent/web/data/closed-loop/lineage
python -m research_agent lineage impact \
  --baseline research_agent/web/data/closed-loop/lineage/lineage.json \
  --bundle research_agent/web/data/closed-loop-changed \
  --output-dir research_agent/web/data/closed-loop-changed-impact \
  --fail-on-stale
```

### 4.4 前端演示

设置子页新增 **证据沿袭**：17 个真实节点、节点哈希、upstream/downstream、closure 11 checks、signature；“模拟数据集变更”会把 dataset→run→claim→slots→closure→signature 标为 stale，顶部显示 `EXPORT BLOCKED`，并给出重跑/重绑/重闭合/重签的处置顺序。

这不是静态装饰：页面加载 `lineage-demo.json`，节点 ID、哈希、11 项检查、claim/signature 都来自本轮真实运行快照。页面明确标注 SIM 模拟只用于变更演示。

### 4.5 当前边界（必须写清）

- 只覆盖 S5 结果臂 + paper/closure；S1 span 还没有进入 Claim 的显式边。
- 不判断 claim 是否被 span 语义支持；沿袭只决定“谁需要复查”。
- 变更模拟只改哈希，不重跑实验；真实处置仍需 run → claim → bind → closure → sign。
- `closure sign` 已拒绝旧报告绕过输入变化，但签名仍是本地 JSON，不是密码学身份签名。

## 5. 与现有系统的差异化

| 系统类型 | 中心 | 本系统的差异 | 不能声称 |
| --- | --- | --- | --- |
| AI-Scientist / Agent Laboratory | 从问题到论文/报告 | 不追求正文生成；把 claim→EA→槽位→导出做成硬门 | 不是端到端论文生成器 |
| DeepScientist / AutoResearch | 持久工作区、阶段流水线 | 多一层 RunCapsule/EA/closure 与人工租约 | 不能替代它们的工作区能力 |
| RSI-Anything / DGM / HGM | benchmark 上的自我改进 | 改进只能领取有 scope/TTL 的租约；不能写 claim；额外把证据变更维护纳入运行时 | 不能声称能力增益或通用 RSI |
| ARIS / ScientistOne | 生成时证据绑定/审计 | 重点在**闭合后的变更传播**与重新签署，而不是再做一个审计器 | 不是唯一做证据绑定的系统 |
| 普通文献/写作工具 | 写作体验 | 运行、证据、图、书目、closure、签名和 RSI 共用一个 stale 语言 | 不是写作 SaaS |

可对外的交集式表述：

> 在可见的开源与产品范围内，“run-bound claim + 人工 closure + 受治理 lease + 闭合后变更传播”这一组合仍较少见；本系统的贡献是把它们放在同一套 artifact/hash/门禁语义里，而不是发明其中任一单点。

## 6. 三分钟演示脚本（面向流量与答辩）

1. 打开设置 → 证据沿袭：看到真实 ChemLab 的 17 节点图、11/11 checks、claim 与 signature。
2. 点击“模拟数据集变更”：dataset/run 变 changed，14 个下游节点变 stale；claim、4 个槽位、图、closure、signature 全部失效，右上角 `EXPORT BLOCKED`。
3. 点 closure 节点：upstream 指纹显示 EA/capsule/claim，downstream 显示所有待重绑产物；处置顺序明确。
4. 恢复快照，回到使用统计：字体、模型用量、运行轨迹和证据链是同一个工作台，而不是三个 demo。
5. 说明后端：`lineage impact --fail-on-stale` 可直接进 CI；`closure sign` 会重跑检查，旧报告不能混过。

这条演示的钩子不是“AI 又写了一篇论文”，而是“**证据失效时，系统比人更早发现，并且拒绝继续导出**”。

## 7. 下一阶段优先级

### P0（最影响可信度）

1. **Protocol 前置**：run 前校验冻结 ProtocolCard，解决“先跑后冻结”。
2. **RSI receipt 哈希 + sealed pack commitment**：admit 校验真实 artifact，hidden 移出 repo。
3. **Closure 语义抽查**：claim 文本↔指标/EA、槽位期望类型、human reason 身份。

### P1（放大差异化）

4. **S1→Claim 显式边**：让 span/gap 进入 claim 依赖图；先做结构边，再做语义支持评分。
5. **Bundle replay**：按 capsule seeds 离线重跑并比较指标容差，输出 drift。
6. **句子级槽位 / ChangeSet**：从 5 个大槽位下沉到句子级，支持“改数据后只重写受影响段落”。

### P2（产品化）

7. Runtime adapter + SSE：让前端从真实 bundle 读 lineage/SSE，而不是构建时快照。
8. 多数据集/模型 harness：至少两个数据臂、两个模型族，避免单例支撑结论。
9. 账本 append-only 和撤销传播：revoke 自动使关联 claim/closure stale。

## 8. 验证记录

- 后端：`python -m unittest discover -s tests -v` → **75 tests OK**（新增 `test_lineage` 4 项，closure 签署拒绝 stale 的负例）。
- 真实链路：ChemLab 3 seeds → capsule/EA → 人签 claim → protocol → 4 条 bibliography → 5 个槽位 → closure 11/11 → signature。
- 变更传播：dataset hash 变化 → 14 个节点 stale；claim/slots/figure/closure/signature 全部失效；bibliography 与 citation.related 保持 fresh。
- 前端：设置页 10 个分节（含证据沿袭）在 1440/1024/390 无横向溢出；120% 字体、模型用量环形图、沿袭 clean/stale 两态均通过浏览器检查；无 console error。
- 构建：Vite 生产构建通过；产物已同步到 `site/app`。

## 9. 结语

这个项目真正的“创新型”，不应该建立在“模型自己会科研”这种无法证明的叙事上，而应该建立在：**科研过程中最难被自动化、也最值得被产品化的失败边界**——claim 与证据脱钩、协议后置、改进绕过准入、数据变化后旧结论仍被导出。

证据沿袭与变更闭合让这些失败变成可见对象、可计算传播、可阻断门禁。它既是研究贡献，也是一个能拍成三分钟视频、能被工程团队复用的产品楔子。
