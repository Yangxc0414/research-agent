# 中文期刊论文质量反思

## 0. 先给结论

**当前系统不能“确保”产出一篇不错的中文期刊论文。**

它能确保的是：

1. 结论有可定位证据或人签 claim；
2. 结果数字能回到已签 claim，不靠模型编造；
3. 引用能映射到来源元数据，缺引用/缺参考/缺 claim 会显式阻断；
4. 稿件结构、摘要、关键词、参考文献、占位符、过度声明有确定性审计；
5. 不把 fixture、摘要-only 或未核验引用伪装成投稿材料。

它不能确保的是：

- 真实全文是否足够、实验是否成立、结果是否有科学价值；
- 论文故事、论证张力、相关工作批判性、讨论深度；
- 具体期刊的模板、图表排版、作者信息、基金格式；
- 同行评审与编辑判断。

所以本轮的目标不是“让系统自动写出好论文”，而是把“能不能投”变成一份可检查的账，而不是一句模型自评。

## 2. 对照后的差距

| 高星技能的做法 | 我们的旧状态 | 本轮处理 |
| --- | --- | --- |
| 先有 claim-evidence map 再写正文 | 有 slot/claim，但没有逐句论证台账 | 新增 `argument-ledger.json` |
| 引用必须能回到真实元数据 | 正文用 span ID，参考文献未统一渲染 | 编号引用 + GB/T 7714 风格草稿 + 未解析引用阻断 |
| 不臆造卷期页码/DOI | 没有投稿格式层 | 缺字段不编造；未核验条目阻断 |
| 摘要/关键词/章节结构检查 | 有章节，但无关键词、无投稿级摘要检查 | 结构化摘要、关键词、章节/长度/套话检查 |
| 结果数字核验 | 有 claim 数值重算，但稿件级数字未审计 | Results 数字必须来自 span/claim/design/run summary |
| 有限轮修订 | 没有 section-level 修订循环 | 先落地确定性审计；模型修订循环仍是下一步 |
| 具体期刊模板 | 只有 profile 名称 | 仍未实现；不应假装已实现 |

## 3. 本轮实现

### 3.1 新产物

每次 paper 阶段后额外生成：

```text
literature-ledger.json     S1 来源卡与筛选账本（全文/摘要/重复/元数据/时效）
manuscript.md              投稿工作稿：摘要/关键词/章节/参考文献
manuscript.json            编号引用映射与引用清单
manuscript-audit.json      submission_ready、blockers、warnings、checks
argument-ledger.json       逐句 section / refs / numbers / supported / needs_evidence
claim-registry.json        claim×ref×anchor evidence rows、quote/SHA-256、覆盖率
```

实现见 `research_agent/manuscript.py`，在 `pipeline.py` 的 paper 阶段后构建，并由
`write_pipeline_artifacts` 写入。

### 3.2 稿件层做了什么

- 将 `[SPAN-ID]` / `[SOURCE-ID]` 转为顺序编号 `[1]`、`[2]`；
- 通过 DOI/标题把来源映射到 bibliography 条目；
- 生成 GB/T 7714 风格草稿：作者. 题名[J/EB/OL]. 刊名/年份/DOI；缺字段用 `...`，不臆造；
- 中文摘要要求目的/方法/结果/结论，`zh_core_journal` 目标 200–600 字；
- 关键词 3–5 个（中文）；
- S1 来源卡记录 full_text / abstract-only / duplicate / metadata_incomplete / DOI / 近五年分布，peer_reviewed 始终标 unknown；
- claim registry 为每个引用句/定量句/结果句记录 claim×ref×anchor；span anchor 带 quote 与 SHA-256，词法覆盖率与 semantic_completeness=unknown 分开报告；
- 参考文献数量目标 ≥8；
- 结果段数字必须来自 span、claim statement/assertion、design 或 run summary；
- 无已签 claim 时 `result.primary` 阻断；
- fixture、未核验引用、未解析引用、TODO/待补都会阻断；
- 过度声明与中文套话只警告；
- 图表存在但正文未引用时警告；
- 全部检查写入 `manuscript-audit.json`，不改变 Claim/Closure/门禁。

### 3.3 写作 prompt 同步

`paper_writer.py` 与 `_writer_payload` 增加：

- 中文摘要使用目的/方法/结果/结论；
- 摘要结果只能复述已给出的 claim，不新增数值；
- 避免未经证据支持的“首次/突破/显著/最优”；
- 避免“值得注意的是/综上所述”等套话；
- 引言/相关工作每段至少一个允许引用。

## 4. 实测结果

### 4.1 fixture pipeline

命令：

```bash
python -m research_agent pipeline run \
  --topic "钙钛矿界面钝化 湿热稳定性" --venue zh_core_journal \
  --output-dir runtime_data/manuscript-smoke
```

结果：`manuscript-audit.json` 为 `blocked`，阻断项包括：

- 2 个引用缺少已核验 bibliography 元数据；
- 存在待补占位；
- fixture 证据不可提交；
- `result.primary` 未绑定人签 claim。

这正是期望行为：fixture 只能验证流程，不能冒充投稿稿件。

### 4.2 完整合成稿件

用 10 个已核验参考文献、10 个可定位 span、结构化摘要、已绑定 claim、图表引用和合法结果数字构造合成稿件，审计结果为：

```text
status = pass
submission_ready = true
blockers = []
warnings = []
claim_registry: 7 candidates / 13 verified anchor rows / coverage 1.0
```

说明审计不是“永远失败”的摆设；它能在条件齐全时通过。但合成稿件只证明审计逻辑，不证明真实科研质量。

## 5. 对“不错的中文期刊”还缺什么

按优先级：

1. **真实全文与真实实验**：本地 PDF/TXT/MD + 可复现实验/已签 claim，是投稿的前提；
2. **人类写作与修改**：系统可以给骨架、证据和审计，不能替代作者的故事设计与判断；
3. **具体期刊模板**：中文核心期刊的摘要字数、关键词、图表、作者信息、基金、参考文献格式差异很大，目前只做通用草稿；
4. **外部盲评**：需要同任务基准、人工盲评和真实审稿意见，而不是内部结构分；
5. **section-level 修订循环**：建议最多 2 轮，且修订不能新增证据或数字；本轮只做了审计，没有自动修订；
6. **统计与图表规范**：误差线、样本量、显著性、三线表、坐标单位等仍需领域适配。

## 6. 使用建议

把 `manuscript-audit.json` 当作投稿前的“机械检查”，不是“质量评分”：

- `blocked`：不要投；先补全文、bibliography、claim 或修数字/引用；
- `attention`：可以人工审阅；警告项逐条决定接受或修改；
- `pass`：只代表我们的结构/证据条件满足，仍需作者、导师和同行评审。

推荐流程：

```text
full text → spans → idea → G1 → design → G2 → run/EA → claim
→ manuscript.md → audit → human revision → journal template → submission
```
