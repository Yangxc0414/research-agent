## 0. 一页结论

现有文献阅读技能已经解决了"**找得到、读得进、引得真**"的大部分工程问题，但没有解决"**读完之后，证据如何进入研究决策与长文写作，并在证据变化时失效**"。

七个判断：

1. **检索不是难点，检索的可审计性才是。** ARIS 的 `research-lit` 已实现本地优先、多源降级、结果去重与检索前身份核验（`verify_papers.py`）；AutoResearchClaw 已实现 arXiv/OpenAlex/Semantic Scholar 合并去重。可直接借鉴，不必重造。
2. **阅读深度必须分级。** 现有技能大多把"读论文"当成一次性全文摘要；真正的研究阅读是 D0 元数据 / D1 速读 / D2 方法与结果 / D3 复现 / D4 对抗性阅读的分级预算。深度由"这篇文献要承担什么论证义务"决定，不由 token 预算决定。
3. **摘要不是证据，span 才是证据。** 证据单元必须落到"论文—章节—页码/字符区间—原句"，并区分作者结论、我们的转述、我们的推断。没有 span 的 claim 只能进候选池，不能进证据图谱。
4. **引用核验要拆成三层，且互相独立。** 存在性、字段正确性、上下文支持是三件事。ARIS 的 `citation-audit` + `citation-crosscheck` + `paper-claim-audit` 给出了可复用的分工；本项目要把它扩展到中文文献与 GB/T 7714。
5. **冲突不能取平均。** 多篇文献结论不一致时，系统必须记录条件差异（样本、数据、指标、设置），生成"条件化结论"，而不是让模型综合出一句四平八稳的话。这是 01 方向 C 在阅读阶段的落点。
6. **查新是阅读的出口，不是独立工具。** 每条 Idea 进入短名单前，必须回答"最接近的工作是什么、delta 一句话、什么证据会推翻新颖性判断"；查新结论只允许 `PROCEED / PROCEED_WITH_CAUTION / ABANDON`，且 `ABANDON` 必须点名一篇具体论文。
7. **发现、纳入、体检是三件事。** AutoSci 把 `/discover`（只提议、不写入）、`/ingest`（独占写入）、`/check`（只体检、不改内容）拆成三个技能；增量订阅默认只出摘要，只有显式开启且高置信才自动纳入。阅读流水线必须保留同样的权限边界，否则"候选"会被悄悄当成"已核验证据"。

S1 因此从"文献调研"升级为七步主流程，外加一个可选的增量监测环：

```
S1.0 范围与纳入/排除标准
  → S1.1 本地优先检索（Zotero / 笔记 / 本地 PDF）
  → S1.2 外部多源检索与去重（arXiv / OpenAlex / S2 / 中文库元数据）
  → S1.3 身份核验与撤稿/更正检查
  → S1.4 阅读深度路由（D0–D4）
  → S1.5 结构化抽取（论文卡 + claim 卡 + 证据 span）
  → S1.6 综合（主题簇 + 争议矩阵 + gap 卡 + 综述备忘）
  → S1.7 出口审计（Q0：覆盖回执 + 独立复核 + 抽样人审）
  → S1.8 增量监测（P1：新文献候选池；默认只通知，高置信才入图谱）
```

**三条不可妥协的规则**：

- 未通过身份核验的文献，不得进入证据图谱；
- 没有 span 的 claim，不得作为写作证据；
- 生成角色不得给自己的阅读结果放行，Q0 必须由独立 Verifier 判定。

**与现有开源实现的差异**：它们优化"单次检索与单次审计"；本项目优化"**跨文献、跨阶段、跨版本的证据生命周期**"——同一张 claim 卡要同时服务 Idea 收敛、实验设计、写作引用与结论失效追踪。这是 01 判断 2/5 与 00 D1 在阅读层的具体化。

## 2. 现有文献阅读技能的机制拆解

### 2.1 本地优先与多源降级

ARIS `research-lit` 的检索顺序是：

```
Zotero（收藏、标签、批注、BibTeX）
  → Obsidian（用户已消化的笔记与 wikilink）
  → 本地 papers/ 或 literature/（最多 20 篇，每篇先读前 3 页）
  → Web / arXiv
  → Semantic Scholar / DeepXiv / Exa / Gemini / OpenAlex（按需显式开启）
```

三个设计值得直接继承：

1. **用户已有知识优先。** Zotero 批注与 Obsidian 笔记代表"用户已经判断过什么重要"，比通用摘要更有价值。
2. **降级不失败。** 任何 MCP/API 不可用时跳过，不中断整个检索；但本地库为空时必须显式警告，不能静默当作"已覆盖"。
3. **去重有主键。** 依次按 arXiv ID、DOI、规范化标题匹配；正式发表版本优先于预印本；Semantic Scholar 提供 venue/引用数，OpenAlex 提供机构与资助信息。

**局限**：对中文文献只做到"本地 PDF + 通用 web"，没有知网/万方的合规元数据适配，也没有中文期刊版本关系（网络首发、正式刊出、增刊）的处理。

### 2.2 检索即核验（anti-hallucination）

ARIS 在分析前强制执行 `verify_papers.py`，三层核验：

```
arXiv 批量查询 → CrossRef DOI → Semantic Scholar 模糊标题
```

每篇候选被标记为：

| 状态 | 含义 | 下游处理 |
| --- | --- | --- |
| `verified` | 至少一层确认身份 | 可进入分析 |
| `UNVERIFIED` | 核验不可用或未找到 | **保留在结果中**，显式标记，不得静默丢弃 |
| `VERIFY_PENDING` | 临时 API 失败 | 保持待定，下次重试 |
| `ERROR` | 输入缺少 arXiv/DOI/标题 | 单列，不进入综合 |

这条"**不静默丢弃**"规则非常关键：它把"检索失败"与"文献不存在"区分开，避免系统用沉默制造覆盖率假象。

**局限**：只核验身份，不核验撤稿、更正、表达关注（expression of concern）、版本差异；中文文献的核验链基本缺失。

### 2.3 有界并行与证据冻结

ARIS 的 fan-out 约束：

- 最多 8 个分片、并发 4、每个 leaf 最多 8 轮；
- 分片前冻结 canonical paper ID 集合；
- 每个分片只拿到**只读证据文件**（标题、摘要、来源摘录、本地 PDF 路径、核验状态）；
- leaf 只能从证据文件中抽取 claim，不能凭标题推断方法或结果；
- 返回 `covered_unit_ids`，父级对账，生成覆盖率回执；
- 无法处理的论文标为 `UNPROCESSABLE_NO_LOCAL_EVIDENCE`，不得当作"不相关"删除。

这套机制解决的是**上下文窗口与并行一致性**：文献多时不让单个 agent 读全部，也不让多个 agent 各自维护一份不一致的文献表。

**局限**：它优化的是"抽取完整性"，不优化"阅读深度"；所有论文走同一套抽取模板，无法区分核心文献与背景文献。

### 2.4 阅读深度不是二值

现有技能普遍只有"摘要级"与"全文级"两档，或者干脆全部丢给长上下文模型。实际研究阅读至少有五档：

| 深度 | 读什么 | 产出 | 适用 |
| --- | --- | --- | --- |
| D0 元数据 | 标题、作者、venue、年份、DOI | 文献条目 | 背景计数、引文网络 |
| D1 速读 | 摘要、引言末段、结论、图表标题 | 论文卡（问题/方法/结论/相关性） | 大多数相关工作 |
| D2 方法与结果 | 方法、实验设置、主表、消融、限制 | claim 卡 + 证据 span + 条件 | 要直接引用的核心文献 |
| D3 复现 | 代码、数据、附录、超参 | 复现记录 + 偏差说明 | 方法基线、竞争解释 |
| D4 对抗性阅读 | 假设、边界、失败案例、反例 | 反驳卡 + 可证伪条件 | 与本文结论冲突或决定成败的文献 |

**路由规则**：深度由"这篇文献在论证图中的角色"决定，而不是由论文本身的重要性或引用数决定。一条 claim 需要被直接支持 → 至少 D2；需要作为基线复现 → D3；与本文结论冲突 → D4。

### 2.5 写后审计：三个独立层

ARIS 把"论文是否可信"拆成三个互不替代的审计：

| 审计 | 回答的问题 | 输入隔离 | 典型输出 |
| --- | --- | --- | --- |
| `paper-claim-audit` | 论文数字是否忠实于原始结果 | **零上下文**：只给 `.tex` + 原始结果文件，不给日志、总结、对话 | `exact_match / rounding_ok / mismatch / scope_overclaim` |
| `citation-audit` | 引用是否真实、字段是否正确、上下文是否支持 | 全新跨模型线程 + 强制联网查 DBLP/arXiv/OpenReview | 每条 `KEEP / FIX / REPLACE / REMOVE` |
| `citation-crosscheck` | 本地 `.bib` 字段是否与独立重建的记录一致 | 双盲：A 只读本地 bib，B 只凭标题+一作联网重建，C 机械 diff | `MATCH / MINOR / MISMATCH / NEEDS_WEBCHECK` |

`paper-claim-audit` 的 7 类失败模式尤其值得照搬：

1. 数字膨胀（84.7% 写成 85.3%）；
2. 挑最好 seed（声称平均，实际取最优）；
3. 配置错配（对比方法用了不同超参/数据划分）；
4. 聚合口径错（声称 5 seed，实际只有 3 次运行）；
5. 相对增益算错；
6. caption 与图表内容不符；
7. 范围过度概括（两个数据集就写 "consistently outperforms"）。

**局限**：这些审计都是**写作后**的；本项目要把同样的检查前移到阅读与证据卡阶段，避免错误证据进入生成。

### 2.6 查新：结论必须有边界

ARIS `novelty-check` 的流程是：

```
方法描述 → 抽 3–5 条核心 claim
  → 每条 claim 至少 3 种查询、多源检索
  → 读最接近论文的摘要与相关工作
  → 跨模型复核
  → 输出：最接近工作 / delta / 判定
```

其 verdict limits 值得直接采用：

- 邻近工作只是信息，不是否决理由；
- `ABANDON` 的唯一条件是"点名一篇已包含该结果的论文"；
- 拥挤但有 delta → `PROCEED`；delta 薄弱 → `PROCEED_WITH_CAUTION`，并说明"补什么能让它成立"；
- 并发工作不是否决，是竞速；
- 拿不准时选更宽松的判定——错杀的想法不会再回来。

**局限**：查新只对"想法"负责，不对"证据覆盖"负责；也没有把查新结果写回文献地图。本项目要求查新输出同时更新 gap 卡与证据边。

### 2.7 知识沉淀

ARIS Research Wiki 的写入协议：

- 每篇论文生成 `papers/<slug>.md`；
- 每条关系写成边：`extends / contradicts / addresses_gap / inspired_by`，必须带一句证据；
- 自动重建 `index.md` 与 `query_pack.md`。

这是"文献关系记忆"的最小实现。**局限**：只存论文与关系，不存 claim 的置信度、阅读深度、冲突条件与失效状态；也没有与实验运行、稿件 claim 打通。

### 2.8 知识库健康与增量监测

AutoSci 把"知识库长期可维护"拆成三个互不越权的动作：

| 动作 | 技能 | 权限 | 关键约束 |
| --- | --- | --- | --- |
| 发现 | `discover` | 只读 + 输出候选短名单 | **绝不入库**；候选按 anchor/topic/wiki/venue 四种种子模式排序 |
| 写入 | `ingest` | 独占写入论文、概念、方法、人物页与关系边 | 其他技能不得手写这些页面；去重与合并有明确规则 |
| 体检 | `check` | 只报告，`--fix` 只修确定性错误 | 检查断链、孤儿页、必填字段、枚举值、双向链接对称性、图边一致性、novelty 分数合理性、失败原因完整性 |

另外两个机制：

- **基础页是终止页**：`prefill` 把教科书级概念写入 `foundations/`，只允许别人链接它，它不反向链接。避免每读一篇论文就重复创建一个"Transformer"概念页。
- **增量订阅有置信门**：`daily-arxiv` 先用确定性工具构造证据包（arXiv + wiki + S2 + DeepXiv），再由 LLM 逐篇给出 `strong_recommend / maybe / skip / ingest` 与 `high / medium / low` 置信度；默认 `inform` 只发摘要，`auto-ingest` 必须显式开启，且只允许 `ingest + high`，每轮上限 1 篇。**检索信号缺失不能当作纳入证据**；边界候选保持 `maybe`。

**对本项目的启示**：S1 不只是"一次性调研"，而是一个长期维护的证据库。必须把"候选、已核验、已入库、已失效"四种状态分开，并让增量更新只能通过唯一写入通道进入图谱；否则后续的 Q0、写作引用与失效追踪都会建立在无法追责的脏数据上。

| 基础概念终止页 | AutoSci `prefill` | ✅ | 领域基础卡，避免重复概念页 |
| 增量订阅置信门 | AutoSci `daily-arxiv` | ✅（P1） | 默认只通知；自动纳入需显式开启 + 高置信 + 单轮上限 |
| span 锚定诚信审计 | ARIS `integrity-forensics` | ✅ | 作为 Q1 的追加层：证据账本 → 审计建议 → 规则门（BLOCK/WARN） |
| 局限完整性复核 | ScientistTwo `Limitation Verifier` | ✅ | 进入 Q0：对标论文的 limitations、失败案例、后续反驳均需覆盖 |

## 3. 对 01 的反思

### 3.1 五条判断在阅读阶段的落点

| 01 判断 | 现有技能已经验证了什么 | 仍然缺什么 | 本项目的补法 |
| --- | --- | --- | --- |
| 判断 1：程序自主 → 过程自主 | 检索、抽取、审计都能自动执行 | 阅读策略本身不会从成功/失败中学习；技能入库没有适用域 | 记录"深度路由—抽取—复核"的策略效果，按领域/文献类型设适用域 |
| 判断 2：三层可验证 | 身份核验、数字审计、引用审计各自成熟 | 缺少"阅读过程可复现"：检索式、纳入/排除、版本、抽取位置 | 检索日志 + 覆盖率回执 + span 定位 + Q0 |
| 判断 3：反事实脆弱 | 查新能给出 verdict | 没有"什么证据会推翻当前结论"的记录；冲突时倾向折中 | 每条核心 claim 带反证条件；冲突进矩阵并升级人工裁决 |
| 判断 4：功能分化 | fan-out 已有抽取/核验分工；AutoSci 已把发现、写入、体检拆开 | 缺少独立的综合者与裁决者；抽取者常兼任结论作者 | Extractor / Synthesizer / Auditor / Adjudicator 四角色独立上下文；发现/写入/体检三权分离 |
| 判断 5：记忆不协调 | Research Wiki 已有论文与关系记忆 | 论文记忆、claim 记忆、方法记忆、失败记忆各自为政 | 统一到 evidence graph，节点带类型、版本、置信度、失效状态 |

### 3.2 对 01 主线的回应

- **主线一（过程可信底座）**：阅读是第一个"过程可信"必须落地的地方。如果检索式、纳入标准、阅读深度、证据位置都不可复现，后面的实验与写作再严谨也无法追溯。
- **主线二（多样性保持 + 反事实证伪）**：阅读阶段的多样性体现为**来源多样性**（支持/反对/相邻领域/负结果）与**解释多样性**（同一结果的不同机制解释）。只检索支持性文献，会让后续 Idea 天然趋同。

### 3.3 对 01 方向的回应

| 01 方向 | 阅读阶段的落点 | 产物 |
| --- | --- | --- |
| 方向 A：技能迁移适用域 | 不同学科/文献类型的阅读策略不同；策略复用前先测 | 策略卡：适用领域、文献类型、抽取 F1、成本 |
| 方向 B：实验运行→论文陈述 | 文献 claim 与本文 claim 使用同一套证据卡结构 | claim 卡 + provenance 边 |
| 方向 C：证据冲突下的信念修订 | 争议矩阵 + 条件化结论 + 人工裁决记录 | contradiction matrix + decision card |

### 3.4 与 00 机会清单的对应

| 00 机会 | 阅读阶段的实现 |
| --- | --- |
| D1 证据账本 | claim 卡、span、条件、置信度、版本、失效状态 |

## 4. 本项目的阅读契约

### 4.1 七个一等产物

| 产物 | 回答的问题 | 关键字段 | 消费方 |
| --- | --- | --- | --- |
| `reading_plan` | 为什么读、读到什么程度、不读什么 | 研究问题、纳入/排除标准、来源清单、深度预算、时间盒 | S1 全程 |
| `source_record` | 每个来源实际贡献了什么 | 来源、检索式、时间、命中数、去重数、失败原因 | Q0、复现 |
| `paper_card` | 这篇论文是什么、可信到什么程度 | 元数据、核验状态、版本、撤稿状态、venue 类型、阅读深度 | S1.6、S2 |
| `claim_card` | 这篇论文到底主张什么、证据在哪 | claim、span、章节/页码、支持类型、条件、置信度、反证条件 | S2/S3/S9/S13 |
| `contradiction_matrix` | 哪些结论冲突、冲突在什么条件下 | claim × source、方向（支持/反对/混合/不清）、条件差异、裁决状态 | S1.6、S7、S14 |
| `gap_card` | 缺什么、为什么还没被解决、可检验含义 | gap 陈述、缺席证据、相邻工作、可检验推论、价值判断 | S2/S3 |
| `review_memo` | 这个领域现在怎么理解、还有哪些分歧 | 主题簇、流派、共识、争议、gap、覆盖限制 | S2、S8、写作 |

### 4.2 三条硬规则

1. **准入规则**：`paper_card.verification_status != verified` 的文献，不得生成可引用的 `claim_card`；只能作为"待核验线索"存在。
2. **span 规则**：每条 `claim_card` 必须带至少一个可定位 span（PDF 页码 + 字符区间，或 HTML 段落 ID）；转述必须标注 `paraphrase=true`，推断必须标注 `inference=true`。
3. **独立规则**：`claim_card` 的抽取者与复核者必须是不同上下文；Q0 的放行不得由抽取者或综合者执行。

### 4.3 阅读深度路由（D0–D4）

**输入**：研究问题、文献在论证图中的候选角色、与核心 claim 的语义距离、是否存在结论冲突、预算。

**规则**（按优先级）：

```
如果 文献被指定为基线/复现对象            → D3
否则如果 文献与本文结论冲突或决定成败      → D4
否则如果 文献将直接支持某条核心 claim      → D2
否则如果 文献属于主题簇的代表作/综述       → D1 或 D2
否则                                      → D0/D1
```

**预算护栏**：

- 单个项目的 D3 文献默认 ≤ 5 篇，D4 ≤ 10 篇；
- 任何深度升级必须写明"升级理由"与"预期产出"，防止无边界精读；
- 深度可以降级，但降级后必须删除依赖该深度的 claim（例如 D2 降回 D1 后，方法细节类 claim 失效）。

### 4.4 claim 卡结构

```json
{
  "claim_id": "CL-0042",
  "paper_id": "P-0117",
  "claim": "在低标注预算下，课程式自训练提升抽取稳健性",
  "span": {"page": 6, "section": "4.2", "char_range": [1820, 1965], "quote": "..."},
  "claim_type": "author_conclusion",
  "support_type": "empirical",
  "conditions": {"dataset": "D-3", "budget": "10% labels", "metric": "F1-low"},
  "strength": "moderate",
  "paraphrase": false,
  "inference": false,
  "counter_evidence": ["CL-0051"],
  "falsifiable_prediction": "去掉难度调度后，低资源子集增益消失",
  "verification_status": "verified",
  "reading_depth": "D2",
  "version": {"paper_version": "v3", "extracted_at": "2026-10-19"}
}
```

**字段约束**：

- `claim_type`：`author_conclusion / author_hypothesis / background_fact / method_description / limitation / our_inference`；
- `support_type`：`empirical / theoretical / anecdotal / review`；
- `strength`：`strong / moderate / weak / unclear`，必须附判定理由；
- `conditions` 不允许为空；综述性 claim 也要写"覆盖范围"；
- `counter_evidence` 指向同一矩阵中的反向 claim，不能只写"有争议"。

### 4.5 争议矩阵与条件化结论

矩阵不是"支持票数统计"，而是**条件对比表**：

| 字段 | 含义 |
| --- | --- |
| `claim_cluster` | 同一问题的 claim 聚类 |
| `source_id` | 论文/结果 |
| `direction` | supports / opposes / mixed / unclear |
| `condition_diff` | 样本、数据、指标、设置、版本的差异 |
| `explanation` | 为什么在这个条件下结论不同 |
| `resolution` | unresolved / condition_resolved / adjudicated |
| `decision_id` | 人工裁决记录（必要时） |

**处理规则**：

1. 先尝试条件化解释；能解释的写成"在 A 条件下支持，在 B 条件下反对"。
2. 不能解释的标为 `unresolved`，进入 S7 论证骨架的"限制"节点与 S14 评审模拟的必问项。
3. 涉及核心结论且无法条件化的冲突，升级人工裁决（对应 01 方向 C），裁决记录写入项目记忆。
4. **禁止**用"多数文献认为"替代条件分析。

### 4.6 gap 卡

```json
{
  "gap_id": "G-007",
  "statement": "现有方法在跨领域低资源场景缺少可复现的稳健性证据",
  "absence_evidence": [
    {"source": "P-0031", "what_is_missing": "只在同领域评测"},
    {"source": "P-0088", "what_is_missing": "未报告低资源子集"}
  ],
  "adjacent_work": ["P-0042"],
  "why_unresolved": "数据获取成本 + 评测协议不统一",
  "testable_implication": "若统一协议后增益消失，则该 gap 不成立",
  "value": "high / medium / low",
  "confidence": 0.7,
  "status": "candidate / confirmed / rejected"
}
```

**gap 不是"没人做过"。** 它必须说明：缺的是什么证据/能力、为什么现有工作没有覆盖、什么结果能证明这个 gap 真实存在。只有"没人做过"而没有可检验含义的，标为 `opinion`，不得进入 S2 的正式输入。

### 4.7 查新契约

每条进入 G1 短名单的 Idea，必须附带：

| 字段 | 要求 |
| --- | --- |
| `core_claims` | 3–5 条承载 delta 的技术 claim |
| `closest_prior_work` | 至少 3 篇，按接近程度排序 |
| `delta_sentence` | 一句话说明"别人没做到什么、我们做了什么"，可被审稿人验证 |
| `verdict` | `PROCEED / PROCEED_WITH_CAUTION / ABANDON` |
| `abandon_evidence` | 仅当 `ABANDON`：点名一篇已包含该结果的论文 + 具体位置 |
| `revival_condition` | 什么新证据/新条件会让被否定的想法重新成立 |
| `search_log` | 查询式、来源、日期、命中与排除理由 |

**边界**：查新是早期分诊，不是新颖性证明；报告必须写明"未覆盖的来源与语言"，不得把"没搜到"写成"不存在"。

## 5. S1 子步骤与 Q0 出口审计

### 5.1 子步骤

| 步骤 | 做什么 | 产物 | 失败处理 |
| --- | --- | --- | --- |
| S1.0 | 明确研究问题、纳入/排除标准、来源与语言范围、深度预算 | `reading_plan` | 问题不清 → 回 S0/G0 |
| S1.1 | 本地优先检索（Zotero/笔记/本地 PDF），去重 | `source_record` | 本地为空 → 显式警告 |
| S1.2 | 外部多源检索（arXiv/OpenAlex/S2/中文元数据），合并去重 | `source_record` + 候选表 | 单源失败 → 降级并记录 |
| S1.3 | 身份核验、版本确认、撤稿/更正检查 | `paper_card.verification_status` | 未核验 → 保留但禁止引用 |
| S1.4 | 阅读深度路由 | `paper_card.reading_depth` + 理由 | 预算不足 → 降级并记录缺口 |
| S1.5 | 结构化抽取：论文卡、claim 卡、span | `paper_card` + `claim_card` | 无 span → 标 `unverified_claim` |
| S1.6 | 综合：主题簇、时间线、争议矩阵、gap 卡、综述备忘 | `contradiction_matrix` + `gap_card` + `review_memo` | 冲突未决 → 标 `unresolved` |
| S1.7 | Q0 出口审计 + 覆盖率回执 | `Q0_report` | 不通过 → 回补检索/抽取 |
| S1.8 | 增量监测（P1）：订阅/定期检索新文献，进入候选池 | `source_record` + 通知 | API 失败 → 降级并记录；只有高置信候选可申请入图谱 |

### 5.2 Q0 检查项

| 检查 | 规则 | 阻断级别 |
| --- | --- | --- |
| 来源覆盖 | 计划来源实际贡献 ≥ 2 类；本地库为空时有显式警告 | 阻断 |
| 身份核验 | 可引用文献 100% `verified`；未核验文献不得有可引用 claim | 阻断 |
| 覆盖率回执 | 候选文献的 planned/completed/failed/uncovered 全部记账 | 阻断 |
| span 完整 | 核心 claim 100% 有 span；背景 claim ≥ 90% | 阻断（核心） |
| 深度记录 | 每篇 D2 以上文献有升级理由与产出 | 警告 |
| 争议矩阵 | 发现的反向证据 100% 入矩阵；未解释冲突标 `unresolved` | 阻断 |
| gap 可检验 | 进入 S2 的 gap 100% 有 `testable_implication` | 阻断 |
| 独立复核 | 核心 claim 抽样 ≥ 20% 由独立上下文复核 | 阻断 |
| 撤稿/更正 | 已撤稿文献不得作为支持证据；更正需记录版本 | 阻断 |
| 局限完整性 | 对标论文的 limitations、失败案例与后续反驳 100% 检查；漏项入待补 | 阻断（对标论文）/ 警告（其余） |
| 图谱健康 | 断链、孤儿 claim、必填字段缺失、非法枚举 | 阻断（claim 边）/ 警告（其余） |

**Q0 类型**：自动规则 + 独立 Verifier + 人抽样（核心 claim 的 10% 或至少 10 条，取较大者）。Q0 不是新增的固定人工检查点，人只处理例外与抽样。

## 6. 与下游阶段的接口

### 6.1 S2 Idea 发散

- 生成角色必须读取 `gap_card`、`contradiction_matrix`、`claim_card`，不得只读 `review_memo`；
- 每条 Idea 的 `evidence_edges` 必须指向真实 claim ID；
- 来源配额：支持性、反驳性、相邻领域、负结果文献各至少参与一条候选的生成，防止单一叙事。

### 6.2 S3 Idea 收敛

- 辩论阶段只允许引用已登记 claim；无证据论据判负；
- 短名单每条必须附查新报告（§4.7）；
- 查新发现的高相似工作要写回文献地图，成为新的证据边或 gap 修正。

### 6.3 S9 证据卡组装

- 写作证据卡直接从 `claim_card` 派生，保留 span、条件、置信度、反向证据；
- 引用槽位绑定 `claim_id`，不绑定"论文标题"；
- 上下文支持判定复用 §4.5 的 `direction`，不允许写作阶段重新"乐观解释"。
- **S1→S9 交接契约**：只有 Q0 已准入、带可定位 span 的 `literature_claim` 才能进入 S9；`Claim Composer` 据此创建 `manuscript_claim`，必须保留 `conditions`、`strength`（强/中/弱）与 `counter_evidence`，并继承证据等级（`literature`），不得越级为 `confirmed`。
- 每个事实句最多一条 `manuscript_claim`；S10 只绑定槽位，不新建 claim；Q1 检查事实句覆盖率 100%、越级 0、孤儿 0、重复 span 0（与 `09-` §3.6/§6.4 一致）。
- 条件扩大（如把"低标注预算下"写成"普遍"）属于 Q1 阻断项，不回写 claim 卡来迁就文字。

### 6.4 S13 全稿核验

- 引用存在性与字段：复用 `citation-audit` / `citation-crosscheck` 的分层；
- 数字与原始结果：复用 `paper-claim-audit` 的零上下文模式；
- 引用上下文：以 `claim_card.conditions` 为准，检查正文是否扩大了条件范围；
- 发现与阅读阶段不一致 → 回写 claim 卡，触发下游失效标记。

### 6.5 S14 评审模拟

- 必问项包括：`unresolved` 争议、弱证据 claim、深度不足的核心文献、查新未覆盖来源；
- 评审意见必须能定位到 claim 卡或段落；
- 需要补实验/补检索的意见进入计划，不得写成"已补充"。

### 6.6 失效追踪

以下事件触发 claim 卡与下游结论的失效检查：

| 事件 | 影响 |
| --- | --- |
| 论文撤稿/更正/版本更新 | 依赖该 span 的 claim 降级或失效 |
| 本地 PDF 替换 | span 重新定位；失败则 claim 标 `stale` |
| 新增反向证据 | 争议矩阵更新；核心 claim 进入复核 |
| 增量监测命中高相关新文献 | 先入候选池，经核验/抽取/Q0 增量检查后才可入图谱；不得直接写 claim |
| 研究问题变更 | 纳入/排除标准重评；gap 卡重新确认 |
| 写作中扩大条件 | Q1 阻断，回 S12 修订 |

| 伪造引用集 | 100 条（人工构造） | 身份核验召回 |
| 综述种子集 | 20 个主题，每主题 10–20 篇 | 覆盖率、主题簇、gap 有效性 |
| 查新集 | 20 个已知后续工作的想法 | 最近工作命中率、delta 判定 |

### 7.2 指标

| 环节 | 指标 | 目标 |
| --- | --- | --- |
| 检索 | 种子文献召回率、来源覆盖数、去重准确率 | 召回 ≥ 0.90；来源 ≥ 3 类 |
| 身份核验 | 伪造文献召回、字段准确率 | 召回 ≥ 0.98；字段 ≥ 0.95 |
| 解析 | 章节边界 F1、参考文献抽取准确率、span 定位准确率 | F1 ≥ 0.85；≥ 0.90；≥ 0.90 |
| 抽取 | claim 抽取 F1、条件字段完整率、类型判定准确率 | F1 ≥ 0.80；≥ 0.95 |
| 综合 | 争议召回、gap 可检验率、主题簇一致性 | 争议召回 ≥ 0.85；gap ≥ 0.90 |
| 查新 | 最近工作命中率、无据 ABANDON 率 | 命中 ≥ 0.85；无据 ABANDON = 0 |
| 下游 | Idea 证据覆盖率、引用支持率、因证据返工率 | ≥ 0.90；≥ 0.90；≤ 10% |
| 增量监测 | 候选命中率、自动纳入误报 | 命中 ≥ 0.80；自动纳入误报 = 0 |
| 图谱健康 | 断链、孤儿 claim、字段缺失 | 断链/孤儿 claim = 0 |
| 成本 | 每篇 token/时间、每项目人工分钟 | 单篇 D1 ≤ 2 分钟；D2 ≤ 10 分钟 |

### 7.3 基线

1. 通用长上下文模型直接总结；
2. 通用模型 + 向量检索（RAG）；
3. PaperQA2 / OpenScholar 式流程；
4. ARIS `research-lit` 原始流程（作为强工程基线）；
5. 人工文献综述（专家，作为质量上限）。

### 7.4 消融

- 去掉本地优先；
- 去掉身份核验；
- 去掉阅读深度路由（全部 D1 或全部 D2）；
- 去掉争议矩阵（只做摘要综合）；
- 去掉 Q0 独立复核；
- 去掉查新 verdict limits（允许无据否决）；
- 去掉发现/写入/体检分离（允许检索代理直接写图谱）；
- 打开自动纳入并去掉置信门（观察脏数据如何污染下游）。

### 7.5 最小实验

| 实验 | 设计 | 主要终点 |
| --- | --- | --- |
| E1 结构化 vs 摘要 | 30 篇论文，同一模型，比较 claim 抽取 F1、span 准确率、条件完整率 | 结构化显著优于摘要式 |
| E2 伪造引用 | 注入 100 条伪造/错字段引用，测三层核验 | 伪造召回 ≥ 98%，字段准确 ≥ 95% |
| E3 冲突识别 | 30 组争议对，比较"取平均"与"条件化矩阵" | 争议召回 ≥ 85%，错误折中率 ≤ 10% |
| E4 下游增益 | 同一 Idea 任务，有无 gap 卡/争议矩阵，专家盲评 | 有用率提升 ≥ 10 个百分点 |
| E5 成本 | 记录 D0–D4 分布、token、时间、人工分钟 | 单项目成本可预测，D3/D4 不超预算 |

## 8. 实施优先级与分工

| 优先级 | 能力 | 理由 | 对应毕设题目 |
| --- | --- | --- | --- |
| **P0** | 本地优先 + 多源检索、身份核验、论文卡、claim 卡、span、Q0 | 没有这些，证据图谱与写作都不可信 | 题 1、题 2 |
| **P0** | 阅读深度路由、争议矩阵、gap 卡 | 直接决定 Idea 质量与多样性 | 题 1、题 3 |
| **P1** | 查新契约、撤稿/更正检查、条件化裁决 | 差异化与长期可信度 | 题 2、题 3 |
| **P1** | 增量监测与图谱健康（候选隔离、置信门、断链检查） | 长期项目刚需；避免脏数据进入证据图谱 | 题 2、题 8 |
| **P1** | 中文期刊版本关系、GB/T 7714 字段核验 | 中文场景刚需 | 题 1、题 6 |
| **P2** | 系统综述 PRISMA 支持、多语种、非文本材料 | 依赖外部规范与授权 | 题 8 |

**角色分工**（与 02 §10 对应）：

- 题 1：中文 PDF 解析 + span 定位 + Q0 基础设施；
- 题 2：证据图谱 + claim 对齐 + 争议矩阵；
- 题 3：Idea 发散/收敛 + 查新契约；
- 题 6：引用核验 + 上下文支持 + 中文规范；
- 题 8：benchmark + 专家盲评 + 过程指标。
