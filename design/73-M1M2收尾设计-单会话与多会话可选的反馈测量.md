# M1/M2 收尾设计——单会话与多会话可选的反馈测量

> 状态基线：2026-11-11。本文是 71-§5 步 3 收尾的**设计文档**：M1 第二半（多 run 统计测量）与 M2 全量（跨任务收益）都需要"单会话 / 多会话"两种可选模式——单会话是传统 A/B（同 session 答两臂），多会话是每臂独立宿主会话。本文先给出代码改动、测试步骤与结果产物 schema；**按当前指示本轮不执行测量**，后续在此基础上跑通取数。已实现的部分随本文同轮落地（memory-ab 0.2 会话字段 + compare 模式校验 + 前端选择 UI），测量执行与取数明确延后。

## 1. 为什么需要两种模式（诚实的有效性边界）

| 模式 | 定义 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| **单会话**（traditional） | 同一个宿主会话依次作答 A 臂（带记忆块）与 B 臂（不带） | 度量与流程可跑通；同 session 内的成对差异 | 记忆增益本身——同源偏差：同一会话的作答风格/上下文污染会同时影响两臂 |
| **多会话**（multi-session） | A/B 两臂由**不同的宿主会话**分别作答（host_label/session_id 分离强制校验） | 剔除同源偏差后的成对差异；接近 fact-baseline ③要求的"不同会话/不同供给" | 仍非独立人工金标准；供给多样性 ≠ 模型多样性（host_label 自报未验证，52- 号边界不变） |

预注册判据（写死在产物里，不事后挑选）：**多会话模式下，若 compare 的 direction 与单会话模式一致且符号相同 → 记忆效应跨会话稳定；若两模式方向不一致 → 单会话结果是同源偏差的产物，如实记录**。单会话模式单独存在时永远不产生"记忆增益"结论（只产生流程读数）。

## 3. 结果产物 schema

- `memory-ab-0.2`（additive）：`arms[arm].session = {session_id, host_label}`；`compare()` 输出增 `session_mode`、`session_check`（multi 时的校验结果或 blocked 原因）、同源偏差边界文案（single 时）。
- `m1-multi-run-0.1`：`{projects: N, runs: N, flipped: N, flip_rate: x, verdict_action_coverage: y, per_run: [...]}`，判据预注册：flip_rate 必须 = 1.0（凡 baseline 有 stale 重签建议的 run，wired 后必须翻转）；出现未翻转 run 即 verdict=not_supported 如实记录。

## 4. 验收判据（预注册）

1. multi 模式下同 host_label 的两臂 → compare 必须 blocked（不可解读），测试钉住；
2. multi 模式下异 host_label → 正常成对读出 + `session_mode=multi`；
3. single 模式输出必须携带同源偏差边界文案（不产生增益结论）；
4. M1 多 run：flip_rate=1.0 才 verdict=supported；
5. 默认参数（`--sessions single`、无 session 字段）行为与升级前逐字节兼容（旧 ab.json 可读）。

## 5. 边界与不做

- 不做自动选择"哪种模式更可信"——模式由人声明；
- 多会话不伪装成独立人工金标准（host_label 自报未验证）；
- 不在前端直接发测量命令（声明层 only）；
- 单会话模式的同源偏差是设计内的诚实边界，不是缺陷。
