# 53 声明式因子空间：让搜索研究能检验别的假设

> 状态：已实现，并完成一次真实复跑、一个新假设的测量，以及一次真实想法的执行。
> 代码：`research_agent/search_lab.py`（因子注册表与设计校验）、`research_agent/executable.py`
> （档位对外声明因子）、`research_agent/study_closure.py`（两处闭包判定修正）、
> `research_agent/study_from_idea.py`（想法 → 声明式设计 → 执行 + 溯源）、
> `research_agent/study_claims.py`（`origin_state`：bound/absent/stale 判定进入 claim 引用）。
> 规格：`modules/search-study/SPEC.md` v0.7.0–v0.9.0、`modules/closure/SPEC.md` v0.9.0–v0.10.0。
> 证据：`runtime_data/declarative-study/**`（含 `rerun-summary.json`）与
> `runtime_data/from-idea-check/studies/STUDY-IDEA-0{1,2}/**`（含 `study-origin.json`）。

## 1. 为什么这是"效果好"而不是"功能多"

`51-` §5 第 5 条把这件事写成了"因子空间扩展"，但它真正的含义是：
**在此之前，这个运行时只能检验一个假设。** 记忆×门控的 2×2 是写死在 `run_study` 里的两层
`for` 循环里，变异算子写死在 `_mutations` 的 `randrange(3)` 分支里。想问"如果搜索只能改特征位，
接受门控的收益还在吗"，需要改代码——而改代码会让旧结论失效（`code.unchanged`）。
一个只能重复同一个设计的实验台，对科研的贡献接近于零。

现在设计是数据：

```
SEARCH_FACTORS = memory(boolean) | gate(boolean) | operators(operator_set) | min_delta(number)
OPERATOR_SETS  = all | no_switch | feature_only | classifier_only | knob_only
```

`study search --factors operators=all,feature_only,knob_only --factors gate=on` 就是一次新的
研究；`--factors` 的**第一个水平是参照格**，由声明顺序决定，不给隐藏规则。

## 2. 三条必须存在的拒绝路径

| 拒绝 | 触发条件 | 为什么必须有 |
| --- | --- | --- |
| 未知因子 / 未知水平 | `--factors temperature=...`、`operators=randomize` | 拼错的因子会静默产出一个运行器解释不了的格子 |
| 过宽设计 | 格子数 > `MAX_DESIGN_CELLS=12` | 把"一次可复现的研究"变成跑不完的东西，是最容易被忽略的失效 |
| 未变因子不进格名 | 单水平因子只记录在 `design` 里 | 否则格名变成 `…_min_delta_0_005_operators_all`，与**已签署 claim 引用的指标名**断开 |

第三条尤其重要：`memory_off_gate_on` 这类名字已经出现在签署过的断言里（
`improvement_per_evaluation.iris.memory_on_gate_on`）。若因新增控制而改名，历史证据的引用键就
被无声破坏了。测试 `test_default_design_keeps_the_legacy_cell_names` 钉住了这一点。

## 3. 复跑：旧结论按设计失效，新 stream 复现同一符号

RNG 之前按 `dataset:seed:archive:gate` 播种，现在按**完整控制集**播种——两个格在任何因子上的
差异都对应不同的随机流。这必然改变具体数字，因此旧结论被 `code.unchanged` 挡住是**正确的**，
不是回归：

```
runtime_data/high-power/studies/iris（此前人已签署）
closure: blocked | 失败项 = ['code.unchanged']
```

同一设计在新流下重跑（3 数据集 × 64 种子 × 预算 60），主结论没有翻转：

| 数据集 | 记忆×门控交互 | 95% 配对区间 | 判定 | `memory_on_gate_on` |
| --- | --- | --- | --- | --- |
| iris | −0.0932 | [−0.1605, −0.0260] | 可判定 | 可判定 |
| wine | −0.1031 | [−0.1694, −0.0368] | 可判定 | 可判定 |
| breast_cancer | −0.1276 | [−0.1893, −0.0659] | 可判定 | 可判定 |

**负交互在三号数据上仍然是负且仍然可判定**（旧值 −0.165/−0.109/−0.082）。幅度变了、符号与
可判定性没变——这正是一次真实的稳健性检验该给出的答案。我不会把两组数字混起来讲：
表中是**当前代码**的测量值，旧值只在 `51-` 的历史段落里作为改码前的记录存在。

## 4. 新假设：门控开启时，算子空间窄到只改特征位反而更好

`--factors gate=on --factors operators=all,feature_only,knob_only`，64 种子配对，参照 `all`：

| 数据集 | `feature_only` − `all` | 判定 | `knob_only` − `all` | 判定 |
| --- | --- | --- | --- | --- |
| iris | **+0.1117** [0.041, 0.182] | 可判定为正 | −0.0919 [−0.165, −0.019] | 可判定为负 |
| wine | −0.0060 [−0.071, 0.059] | **不可判定** | −0.1549 [−0.216, −0.094] | 可判定为负 |

可以说的：在接受门控已开启的前提下，**只允许旋钮缩放的搜索显著更差**（两个数据集同号且可判定）；
**只允许特征位翻转在 iris 上优于完整算子空间，在 wine 上与完整算子空间不可区分**。

不可以说的：这不是"特征工程比超参搜索更好"的普适结论——测的是这个运行时里配置搜索的
单位算力改进率；wine 上 `feature_only` 的点估计虽小但区间跨零，**它就是没被判定**，
不能写成"无效"也不能写成"趋势"。这一格正好检验了三态呈现是否真的生效。

签署链实测：

```
study claim（iris）  → signable_assertions=2, rejected_comparisons=[]
study closure（iris）→ blocked，唯一未通过项 claim.signed（人工门，我没签）
study claim（wine）  → 记录 feature_only 为不可判定
study closure（wine）→ blocked，同样只差人签
```

## 5. 这次改造顺带暴露的两个闭包判定缺陷

这两个都是**因为 generalize 之后才有机会被看见**：

1. **`has_decidable_comparison` 与签署路径不一致**。闭包只检查 `evidence["comparison"]`，
   而可签署断言（`51-` 之后的版本）把交互项也算进去。于是"唯一可判定的发现是交互项"的研究
   会出现**能签不能闭**。现在闭包改用同一个单点来源 `study_claims.comparison_verdicts()`——
   区间规则从此只有一份实现。（`test_full_chain_closes…` 在新随机流下失败，正是它把这个问题
   暴露出来的方式。）
2. **`claim.records_undecidable` 的语义写反了**。原判定是"claim 里没有 not_signable 清单就告警，
   除非 `evidence.comparison` 整个缺失"。于是一个**所有比较都可判定**的研究会因为"没有拒绝清单"
   被警告，而一个 `comparison` 缺失的研究反而能躲过检查。现在判定条件是：
   *证据里确实存在不可判定的比较* 且 *claim 没有记录它们* 才告警。

## 6. 档位声明随代码同步

`executable.py` 的 `search_factorial` 现在把因子与算子集合本身声明出来，因此 S2/S3 的想法生成
能看到"可以声明 operators/min_delta"，而不只会写 2×2；`validate_plan` 的 dataset/metric 成员校验
不变。提示词渲染仍包含每个档位的 `cannot_test`，声明式扩展没有放宽任何可执行面。

## 9. 因子声明之后，缺的是"想法真的被执行"

做完因子空间才发现更根本的断点：全仓库里 `experiment_plan` **只被写作提示词读过**
（`manuscript_writer.py`），没有任何代码执行它。也就是说 S2/S3 产出"这个想法可以在
search_factorial 上用 iris 检验"，而 S5 对此一无所知——闭环在"想法→实验"这一环是**叙述性**的，
不是执行性的。

新增 `research_agent/study_from_idea.py` 与 `study from-idea`：读 run 的
`innovation-review.json`，取该 idea 的 plan，`validate_plan` 复核后必须满足
`profile=search_factorial` 且 dataset 属于该档位，再把 plan 的 `design` / `min_delta` 交给
声明式跑批；旁边写 `study-origin.json`，记录 `idea_id` / `falsification` /
`experiment_plan` / `resolved_controls` 并绑定 `study_spec_sha256`——数字与它要检验的假设
从此在同一条哈希链上。

拒绝路径与执行同等重要：

| 情况 | 行为 |
| --- | --- |
| plan 没写 profile | 拒绝（沿用注册表的"不是警告，是不可执行"） |
| plan 绑的是 `protocol_run` 等其它档位 | 拒绝并在消息里点名该档位 |
| 种子少于 4 | **在写任何文件之前**拒绝 |
| 目标目录已有研究 | 拒绝，除非 `--force`（否则旧结论被无声覆盖） |
| idea id 不存在 | 拒绝并列出该 run 里真实存在的 id |

实测（真实宿主产出的想法，非测试夹具）：`study from-idea --idea-id IDEA-01
--seeds 1..8 --budget 40` 执行成功，结果是

```
directional_supported: []
interval_covers_zero:  memory_on_gate_off, memory_off_gate_on, memory_on_gate_on
underpowered:          false
```

三项比较在 8 个种子下**全都不可判定**。这不是失败：`boundary` 文案写得很清楚——
"区间跨零的研究是非结果，不是应该重跑到绿灯的失败"。而旧系统在这种情形下能产出的只有一段
"我们计划用 2×2 因子设计检验…"的文字；现在它产出一份标注为非结果的证据，并精确告诉你
下一步是人签 claim 还是加种子。

## 10. 溯源进入哈希链：换过设计就不能继续挂着旧想法

只把 `study-origin.json` 摆在旁边是不够的——它可能与研究脱钩。现在 claim 与 closure 都判它：

- `origin_state(directory)` 把 sidecar 记录的 `study_spec_sha256` 与当前 spec 重算比对，返回
  `absent / bound / stale`；
- **bound**：claim 的 `evidence_refs` 增加到第四条 `study-origin.json#<hash>`，
  `verification.idea_provenance` 记下 `idea_id` 与否证条件；
- **absent**：claim 仍可起草，但 `warnings` 明说"这份数字没有可追溯的想法"；
- **stale**：`build_study_claim` **直接拒绝**；`study closure` 新增 `origin.matches_study`
  （blocker）与 `origin.present`（warning），两者都不依赖 claim 是否存在，且 stale 与 absent
  的措辞分开——把"脱钩"报成"缺失"会引导人去补一个假文件。

实测（wine / IDEA-02，16 种子）：

```
bound   → draft：signable_assertions=1，provenance={'state':'bound','idea_id':'IDEA-02'}
         directional_supported=['memory_on_gate_on']，其余两项区间跨零
改设计重跑同一目录（study search --output-dir 指向同一研究目录）→
  claim  → ValueError: study-origin.json no longer describes this study …
  closure→ blocked；origin.matches_study fail；warning 用 "is stale" 措辞
```

顺带一个复现性观察：第一次 `from-idea`（16 种子）与 `--force` 重跑得到**完全相同**的三态
（−0.1198 [−0.2014, −0.0382] 可判定 + 两项跨零），因为种子、预算、设计与代码指纹都没动——
这条链上的"重跑"就应当如此，而不是每次都冒出新数字。

## 11. 边界与下一步

- 因子空间扩大的是**这个控制回路的假设空间**，不是"任何智能体搜索都可测"；
  `cannot_test` 依旧：源代码自改进、已发表系统复现、语言模型规模搜索；
- `MAX_DESIGN_CELLS=12` 是工程约束，不是科学结论；超出即拒绝运行并要求收窄设计；
- 参照格由声明顺序决定，选错参照会让对比方向看起来"反直觉"，这是设计选择而不是缺陷，
  但报告时必须写清参照是谁；
- `from-idea` 只执行 `search_factorial` 档位的计划；`protocol_run` 与
  `local_tabular_experiment` 的执行仍走各自既有路径（`run execute` / `experiment run`），
  没有把三条路径合成一条万能执行器；
- 本文所有数字来自确定性本地搜索（公开表格数据 + sklearn），无网络、无模型调用；
  `analogue=true`、`exploratory=true`、`submission_ready=false` 全程保持；
- 只读盘点与工作台已带出 `study-origin.json`：研究行显示 `origin=absent|bound|stale`、
  `idea_id`/`idea_title` 与否证条件；用 `--force` 重跑研究会改变 spec 哈希，于是页面直接说出
  "这份数字不再回答当初那个假设"，而不是让旧溯源继续冒充新证据；
- 下一步：多数据集同一设计的横向比较仍未纳入沿袭校验；`origin` 已进入 claim 的
  `evidence_refs` 与 closure 检查，但 lineage 节点还没把 sidecar 当独立节点追踪（脱钩目前由
  claim/closure 拒绝，而不是由 `study lineage --verify` 报 stale）。
