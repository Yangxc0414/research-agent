## 0. 判断

我的判断是：**这份规范最值得学的不是“8 小时、40 分钟、至少 5 轮”这些数字，而是它把“多轮改进”做成了一条可强制执行、可审计、可复算的运行闭环。** 它要求同一个可执行 artifact 在固定问题、固定基线、固定指标和统一预算下，消费自己的父版本、公开评测结果与失败，逐轮产生候选、评测、保留或回滚；最终分数来自冻结后的独立隐藏评测，而不是过程中的自报。

对照之下，我们的 [11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md) 在**准入语法**上其实更细：EV0–EV4、租约、护照、撤销沿 claim → 句 → 图传播、claim 级资产与过程协议两个平面、P8 只产候选。这些是这份规范没有的。但我们的 demo 目前证明的是**准入状态与失效后果**，不是“系统越跑越强”。原因不在四问不够多，而在四问下面缺四件运行件：

1. **固定实例**：没有一个跨轮不变的可执行改进对象，EV4 的“能力增益”只能审理由，不能测增益。
2. **控制器**：租约是控制台状态，不是 P0 前的硬门；回滚不恢复快照，撤销不真正阻断下一次确证运行。
3. **信息边界**：demo 把 EV1–EV4、留出集和能力曲线展示给同一个视角；没有“谁知道什么”的运行时隔离，准入会被选择偏差污染。
4. **步账**：候选没有父版本、完整公开评测收据、对照/消融、成本、负结果与“子实验 vs 完整准入周期”的区分；拒绝也评估没有成为默认。

一句话：**我们缺的不是第五问，而是让四问有东西可问的运行底座。** 自进化不是面板上的状态机，而是运行时属性。补上这四件，[11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md) 才从“准入层设计”变成“可证伪的准入层”。

**边界**：这不否定“我们不是 RSI，而是 RSI 的准入层与证据层”的定位；相反，它说明“层”也需要执行面。也不意味着要照搬该 skill 的出题器身份、8 小时常数或隐藏 RSI 身份的做法——那些是它的评测装置，不是我们的产品。

## 1. 这份规范里的“自进化”到底是什么

### 1.1 三层结构，不是一套算法

| 层 | 载体 | 它做什么 | 不是什么 |
| --- | --- | --- | --- |
| 出题器 | [SKILL.md](../RSI-task-gen-skill-main/SKILL.md)、[authoring.md](../RSI-task-gen-skill-main/references/authoring.md) | 要求作者先研究真实论文/仓库/指标，再构建健康基线、参考解、评分合同与可迭代任务 | 不是自进化算法；是“造一个能考多轮改进的考场” |
| 运行器 | `assets/harbor_runner/run.py`、`rsi_codex_agent.py`、`rsi_supervisor.py` | 单 trial、单会话、统一截止时间、公开反馈续接、checkpoint/restore、最终隐藏 verifier | 不是科研写作平台；是外部调控的持续优化 harness |
| 证据层 | `research/`、`experiments/ledger.jsonl`、`receipts/`、`seal`、`freeze` | 来源账本、step 账本、公开/隐藏分离、版本门槛、冻结与收据 | 不保证“越跑越强”；只保证可审计地判断是否有改进 |

这层拆分对我们很关键：我们一直把“自进化”当**准入层**设计，但准入层要成立，下面必须有一个能产生“可比较的父子版本 + 完整公开评测 + 冻结后独立审计”的运行器。否则四问只是在审一份叙述。

### 1.2 六个可执行约束

| # | 约束 | 规范位置 | 具体做法 | 对我们的意义 |
| --- | --- | --- | --- | --- |
| 1 | 固定实例与统一预算 | `SKILL.md:10`；`authoring.md` §0、§5.2 | 固定问题、资源、评价目标与约束；8 小时总墙钟覆盖同一运行的全部回合，不按 step 重置 | 我们的“轮”目前没有统一时钟和固定实例；租约的“第 3–6 轮”缺少可执行的时间/预算口径 |
| 2 | 子实验 / 完整 step / 合格版本三分 | `SKILL.md:24`；`authoring.md` §5.1 | 子实验不计完整 step；完整 step 必须有假设、实现、完整公开评测、分析、保留/回滚；合格版本还要过冻结的最小实质增益与硬约束 | 我们的候选账本没有这三层；一次“改文案”与一次“完整准入周期”目前不可区分 |
| 3 | 公开反馈与隐藏审计分离 | `SKILL.md:14`；`authoring.md` §5.3、§13.1.2–13.1.3 | 每轮把公开指标/对照/约束/分析带回同一会话；隐藏测试只在最终 artifact 冻结后独立执行，成绩不反馈 | 我们的 EV4 有“判定封存”设计，但 demo 中留出结果与四问在同一面板；没有“冻结前不可见”的运行时保证 |
| 4 | 同会话续接、预算不重置 | `SKILL.md:26`；`rsi_codex_agent.py` 的 `SustainedCodex`；`rsi_supervisor.py` 的 `run()` | 锁定真实 thread ID，按明确 ID 恢复；不新建 trial、不重置时钟；最终整理窗口与清理时间预留 | 我们的跨轮继承只有“下一轮 P0”的设计，没有会话/预算连续性；也就没有“这一轮为什么算同一轮”的证据 |
| 5 | 反馈白名单与收据校验 | `rsi_supervisor.py:103–141` | 只接受 `visibility=public`、`evaluation_split=validation`、`hidden_feedback_used=false` 的 review 文件；非公开或非法证据直接拒绝 | 我们的 `AdmissionRecord.because` 缺这一层 schema 校验；“公开反馈”目前是文档约定，不是可拒绝的输入 |
| 6 | artifact 快照、哈希与回滚 | `rsi_supervisor.py:28–40`、`77–96` | 对 artifact 目录做 hash manifest；拒绝符号链接/特殊文件/空产物，限制文件数与字节数；checkpoint 后 restore 必须 hash 一致 | 我们的租约绑定 `scope_hash`，但没有绑定不可变资产快照；回滚没有恢复快照的动作 |

### 1.3 它自己划的边界（与我们的口径高度一致）

- **不宣称模型智力自我改进**：默认指可执行方法、训练流程或 harness 的持续改进；没有额外证据不把方法提升描述成底层模型能力提升（`authoring.md` §1）。
- **不把外部调控说成自主长程研究**：这是“外部调控下的持续优化”，不能冒称 agent 自主发起的长程计划（`SKILL.md:14`；`authoring.md` §5.3）。
- **不保证单调上涨**：允许失败、回滚、局部退化与平台期；保留完整记录，不靠改评分或挑隐藏结果制造提升（`SKILL.md:22`）。
- **不把工程跑通当多轮改善**：工程可运行、短试验、完整预算多轮证据分别报告；`runtime_ready` 与迭代证据分开（`authoring.md` §15）。
- **不把公开反馈当无偏**：公开评测反复用于开发与选择，承认选择偏差；最终按公开规则冻结后才做隐藏验收（`authoring.md` §5.3）。

这几条对我们尤其重要：我们已经明确“不宣称 RSI”，但**“不宣称 RSI”不等于“不宣称自进化”**。如果 demo 的“能力曲线”与“推进一个周期”被观众读成“越跑越强”，那是另一种过度承诺。口径应改成“受控改进准入与过程协议继承”，并把 E7/E8 标为未运行。

## 2. 映射：规范的对象与我们的对象不是一一对应

| 规范 | 我们 | 是否同构 | 备注 |
| --- | --- | --- | --- |
| 被改进的 artifact（code/weights/harness） | `ProcessProtocol`（PF）包，或 claim 级资产（SK/WF/PL） | 部分 | PF 是“某个阶段下一次怎么跑”，天然是可执行、可加载/不加载的；比“技能文本”更适合做递归对象 |
| 固定基线 + 参考解 | 通用 P0–P8 流程 vs 手工设计的 PF 参考包 | 可构造 | 我们还没有把“通用流程”冻结成基线，也没有一份作者侧参考 PF 包 |
| 完整公开评测 | 开发切片上的阶段指标 + 硬约束 | 可构造 | 我们的指标是领域原生的（无证据句、stale 召回、修复完成率、人工干预），不必借用它的任务分数 |
| 隐藏 verifier | 冻结后的 sealed audit（独立任务/切片） | 可构造 | 我们的“判定封存”目前是 SIM 标签；需要真正的独立角色与冻结顺序 |
| promotion gate + retain | EV1–EV4 + 租约 + incumbent guard | 我们的更细 | 我们多了护照、撤销传播、claim 级失效；它多了“完整 step/合格版本/配对对照/噪声协议” |
| operator / solver 分层 | proposer / executor / admitter / human 的可见性矩阵 | 需改造 | 不能照搬“对用户隐藏”；我们的产品价值是审计透明，边界应在 agent 角色之间 |
| step ledger | `AdmissionRecord` + `InheritanceLease` + 事件流 | 缺一半 | 缺 `CandidateRun`：父版本、行为 diff、完整公开评测收据、对照/消融、成本、负结果 |
| 统一预算 / 同会话续接 | 跨轮继承包 + P0 加载 | 缺运行器 | 没有时钟、没有会话、没有“这一轮从哪来、到哪去”的强制记录 |
| 作者侧 solution 不进包 | 作者侧参考 PF 包 / 隐藏 sealed audit | 可借鉴 | 我们的 demo/文档混在一起；需要区分“可公开演示”和“作者侧评测材料” |

**结论**：PF 是我们最适合做“递归对象”的候选，因为它满足三个条件：同一阶段可重复执行、可版本化、可加载/不加载。claim 级资产更适合做“被准入的产物”，不适合单独做“多轮改进的实例”——一篇稿件的 claim 不能像代码 artifact 一样在固定输入上反复重跑。这个区分应写进 E7/E8 的设计。

## 3. 四个结构性缺口

### 3.1 缺口一：没有固定实例，EV4 只能审理由，不能测增益

**规范的要求**：同一个可执行方法，消费自己的父版本、实测与失败，形成下一轮假设；固定问题、资源、评价目标与约束；step 0 是固定基线；正式版本与“上一合格版本”及“机制消融或同预算强对照”按同一完整协议配对比较；最终在声明的主留出范围上验证总体改善（`SKILL.md:24`；`authoring.md` §5.1、§5.2、§8.1）。

**我们的现状**：[11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md) §3.4 已经写了“留出、归因、扣成本、可撤销”，§3.4.6 写了判定封存与 cohort 隔离；但 E7/E8 未运行。[11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md) §9.1 的九个 PF 全部是 SIM；demo 的“推进一个周期”只改 UI 状态，“能力曲线与基线”明标 SIM，不是实测。于是 EV4 的“是否真的提升后续能力”在演示中是一个**不可证伪的叙述**：没有固定任务、没有配对对照、没有冻结后的审计，观众无法区分“协议真的更好”与“这次任务恰好更容易/选择偏差/数字是编的”。

**为什么这不是再加一个指标能解决的**：没有固定实例，就没有“同一输入上的父子版本”；没有父子版本，就没有“增益”的分母；没有分母，EV1 的 `GAIN_HELD_OUT`、EV2 的 incumbent guard、EV4 的能力曲线都只能引用自报数字。四问会退化成**理由审查**，而不是**证据测量**。

**动作（P0，先做，不碰 UI）**：

1. 定义 `ImprovementInstance`：同一任务族的一组冻结切片（建议 4 类任务 × 3 个切片，共 12 个），固定输入、固定基线（通用 P0–P8）、固定原生指标与硬约束、固定每切片预算、固定开发/封存划分。
2. 把 **PF 包**作为被改进 artifact：每轮只允许改 PF 的阶段行为（检查顺序、模板、预检、失败路由、复跑策略），不改研究问题、门槛、判据与 claim 真值。
3. 四臂对照：`no-inheritance`（每轮从通用流程开始）/ `inherit-all`（不过四问，全部继承）/ `gate-no-lease`（过四问但无租约/无撤销）/ `full`（四问 + 租约 + 撤销 + 封存）。这样能分离“继承本身”与“准入层”的贡献。
4. 每轮公开反馈只带开发切片指标与对照；最终 sealed audit 在候选与选择规则冻结后开启；隐藏结果不进下一轮 proposer 上下文。
5. **不要**把 8 小时/40 分钟/5 轮搬成平台常数；我们的切片预算与“有效工作”应按阶段定义（检索、复现、写作、核验各自的有效动作与耗时证据），否则会把 benchmark 的出题难度误当成科研过程的规律。

**E7/E8 的重写口径**：E7 测“跨轮继承与回滚”（有/无租约、到期、依赖漂移、撤销后的 stale 处置）；E8 测“能力增益的纵向归因”（四臂、配对切片、冻结后审计、成本与负迁移）。两者都必须先有 `ImprovementInstance`，否则仍是 SIM。

### 3.2 缺口二：租约是状态，不是强制

**规范的做法**：`Supervisor` 在主机侧维护 `stop_at` / `final_at`，到点停止 CLI 与残留进程；每次完整返回做 checkpoint，最终 restore 最后完整返回的快照；`run.py` 拒绝 `--n-attempts`、重试、timeout 覆盖，保证单 trial、单预算；`rsi_codex_agent.py` 首次必须是 fresh session，拦截 CLI 启动并上传中性的 `command_runner.py`（`rsi_supervisor.py:56–63`、`77–96`、`180–251`；`rsi_codex_agent.py` 的 `run()` / `exec_as_agent()`；`run.py` 的 controlled options）。

**我们的现状**：[11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md) §3.2 的租约字段、§3.2.7 的控制台动作、demo 的“复评/降为 probation/撤销/回滚”都很完整；但它们是**状态变化**，不是**运行时拒绝**。具体缺口：

- P0 没有在加载资产前检查 `lease.status / valid_until / scope_hash`；demo 中“下一个周期”不会因为租约过期而拒绝加载。
- 回滚只切 `active` 指针，没有恢复不可变快照；如果 v1 的模板/脚本已经被覆盖，回滚不可执行。
- 撤销后的 `stale` 传播是 UI 文案；没有在确证运行/导出时 fail-closed 的硬门。
- 没有“正式候选只做一次完整公开评测”的约束；复评/重跑可以被用来“跑到过为止”。
- 没有为“最终整理/复评/导出”预留时间；租约到期前的复评可能来不及完成。

**动作（P0）**：

1. `ArtifactManifest`：对 PF 包/技能包做文件级 hash manifest；拒绝符号链接、特殊文件、空包；限制文件数与总字节；manifest hash 写入租约。任何文件变化都使租约失效，而不是只比较一个 `scope_hash`。
2. `LeaseSupervisor`：在 P0 前执行 `lease.check(asset_id, scope_hash, dependency_manifest, now)`；`expired`/`revoked`/`probation` 分别走拒绝、回退通用流程、只进 shadow；所有决定写 append-only 事件。
3. `rollback`：从不可变快照恢复，恢复后重算 manifest hash；hash 不一致则 `rollback_blocked`，不得声称回滚成功。保留 [11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md) §3.2.7 的正确语义：**回滚不是撤销的反操作**，已 stale 的 claim/句/图仍需处置。
4. 正式候选评测：一次完整公开评测；只有基础设施故障（非候选问题）允许同一候选重跑，并记录原因；不允许“重跑直到显著”。
5. 预算预留：为复评、最终导出与清理留固定窗口；到期未复评的租约自动转 `probation`，而不是静默续租。

**这一条是 S3（变更与 RSI 微服务）真正的运行时核心**，不是 UI 控件。没有它，租约只是文档里的一个字段；有了它，EV1–EV4 才有“拒绝”的权力。

### 3.3 缺口三：评测信息没有可见性边界

**规范的做法**：operator 持有完整 ZIP、预算、runner、隐藏 tests 与作者材料；solver 首轮只收到普通优化题面、公开环境、基线、公开指标与资源合同；不注入 RSI 身份、未来轮次、八小时预算或自动续接；隐藏测试只在最终 artifact 冻结后独立执行，成绩不反馈（`SKILL.md:10–12`、`14`；`authoring.md` §13.1.2–13.1.3）。`rsi_supervisor.py` 的 `feedback()` 只接受带 `visibility=public`、`evaluation_split=validation`、`hidden_feedback_used=false` 的 review 文件，否则拒绝（`rsi_supervisor.py:103–141`）。

**我们的现状**：demo 的“自进化”视图把候选、EV1–EV4、租约、能力曲线、留出评测放在同一个面板；`P8` 过程反馈也把“预期/本次效果”直接展示。对导师演示这是优点（一眼看懂机制），但对**准入有效性**是风险：如果 proposer/executor 能看到留出集结果或最终审判决议，它就可以针对门槛优化（少写 claim 提高覆盖率、只挑容易的切片、把“预测”写成“已验证”）。我们文档里说“判定封存”“hidden 结果不反馈”，但 demo 没有可见性矩阵，`seal_hash` 也只是 SIM 字段。

**为什么不能照搬“隐藏 RSI 身份”**：我们的用户是作者/PI，审计透明是产品价值；对人类签署者隐藏反而是错的。需要区分两种边界：

- **agent 可见性**：proposer/executor 只看公开开发反馈与证据契约，不看 sealed audit、不看最终审判决议、不看阈值调参记录。
- **人类审计可见性**：admitter 与 human signer 在冻结后可以看全量；导出包保留完整审计轨迹。

**动作（P0/P1）**：

1. `PublicFeedbackReceipt`：字段至少包含 `schema`、`visibility=public`、`evaluation_split=validation`、`hidden_feedback_used=false`、`instance_id`、`slice_ids`、`native_metrics`、`constraints`、`comparators`、`receipt_hash`。EV1 只接受校验通过的 receipt；缺失/非法 → `under_review`，不得 accepted。
2. `SealedAudit` 服务：候选、判据、选择规则与租约状态先 `seal`，再由独立角色在封存切片上执行；结果写入只读审计账本，不进入下一轮 proposer 上下文。
3. 可见性矩阵：proposer 看公开反馈 + 证据契约；executor 看当前阶段输入/工具；admitter 看 admission record + 公开收据；human 看全量（含 sealed audit、撤销影响、AI 使用记录）。这不是“对用户保密”，而是“对执行角色保密”。
4. demo 增加一个“可见性”开关/标注：同一屏可以演示“proposer 视角看不到 sealed 结果”，但导师可以切到 human 视角看全量；不要继续把“全知视角”当成系统默认。

### 3.4 缺口四：候选没有 step 账本，负结果与成本不入账

**规范的做法**：每个完整 step 返回可机读记录：假设/变更、父版本、候选哈希、完整评测范围与收据、原生指标与综合目标、绝对/相对增益、硬门与版本门、预算起止/累计/剩余、状态、有效工作分项、资源、保留/回滚决定、下一步（`authoring.md` §5.2）；失败可以构成完整 step，但门槛以下不算合格版本；门槛只决定保留，不终止运行；最终按冻结的公开选择规则提交最佳可行 artifact（`authoring.md` §5.1、§5.2、§12.1）。`rsi_supervisor.py` 的公开反馈字段还包含 `fixed_baseline_score`、`total_gain_over_fixed_baseline`、`previous_completed_study`、`gain_over_previous_study`、`comparison_gates`、`improvement_criteria_pass`、`declared_effective_work_seconds` 等（`rsi_supervisor.py:106–113`）。

**我们的现状**：[11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md) §3.1 的 `because` 理由链、§3.2 的租约、§3.4 的能力增益都设计了字段，但仍缺：

- 没有 `CandidateRun`：候选的父版本、行为 diff、完整公开评测命令/收据、对照/消融、成本、负结果、`min_practical_gain` 判定不在同一张账上。
- 没有区分“子实验”与“完整准入周期”：一次 dry-run、一次 pilot、一次完整复评可能被混成一个“轮”。
- 没有“拒绝也完整评测”的默认：`rejected` 有理由码，但没有 crossed/bounded evaluation；E1 的拒绝 precision/recall 因此缺少数据来源。
- 没有停止策略：准入成功就停，还是预算到点才停？没有规定；容易在第一个 accepted 处收敛，失去探索。
- 没有把“合同修订”与“方法改进”分开：改门槛/判据/范围如果也被记成一次“改进”，分数就不可比。

**动作（P1）**：

1. `CandidateRun` 最小字段：`candidate_id`、`parent_asset_id`、`behavior_diff`（改哪个阶段/哪条规则/预期效果/回退条件）、`artifact_manifest_hash`、`public_eval_command`、`public_eval_receipt`、`comparators`（上一合格版本 + 一个机制消融/同预算强对照）、`native_metrics`、`constraints`、`delta`、`uncertainty`、`cost`、`negative_result`、`decision`、`next_hypothesis`。字段为空的候选不得进入 EV1。
2. 三分法：`exploration`（子实验，可快）/ `admission_cycle`（完整公开评测 + 分析）/ `qualified_version`（过冻结的最小实质增益 + 硬约束 + 噪声协议）。只有第三类能发租约；第二类失败也保留。
3. 负结果默认：被拒绝的候选仍做一次有界完整评测（至少覆盖主指标与关键退化门），记录 `rejected_reason` 与“如果接受会怎样”；否则准入层永远不知道自己误杀了什么。
4. 停止策略：四问与版本门只决定保留，不决定停止；探索持续到该实例的预算边界，预留最终 sealed audit 与导出时间。
5. `revision_ledger`：凡是改门槛、判据、评分公式、切片范围、预算，都记一次 contract revision；旧结果不与新结果直接连线，必须重校准并保留旧判定。

**这一条直接决定 E1 能不能跑**：没有 `CandidateRun`，E1 的“负迁移率、retention@k、拒绝精度/召回、每接受条目成本”都只能从 demo 文案里抄，不能从账本里算。

## 4. 我们比它多什么：不要为了对齐而丢掉

| 我们的机制 | 为什么保留 | 该规范没有的部分 |
| --- | --- | --- |
| 两个准入平面：claim 级资产（SK/WF/PL） vs 过程协议（PF） | 结论/技能能不能用，与“这个阶段下一次怎么跑”是两种对象；混在一起会导致“技能准入”被误当成“claim 成立” | 它只有一个被改进 artifact，没有 claim 级证据闭合 |
| 撤销沿 claim → 句 → 图传播，导出 fail-closed | 这是“科研写作”与“任务优化”的分水岭；一次撤销必须让受影响的稿句/图进入复核，而不是只回滚代码 | 它的 hidden verifier 只判最终 artifact，不判稿件陈述 |
| 人类签署、AI 使用披露、不自动投稿、不生成假评审 | 这是合规与责任边界，不能被“多轮优化”叙事覆盖 | 它的治理主要在评测隔离与预算，不涉及署名/披露 |
| 中文核刊/国自然场景、六类槽、GB/T 7714、版面锚点 | 是我们首发的验证场景与领域指标，不是通用 benchmark | 它明确不预设领域指标 |
| 适用域护照、三档判定（直接复用/先 pilot/拒绝） | 比单一 promotion gate 更适合“跨任务迁移”的科研经验 | 它用 hidden holdout 判迁移，但没有“护照/范围哈希/越界失效”的对象 |
| 人类可读的失效后果（哪些句子/图被阻断） | 这是作者真正需要的“证据运营”界面 | 它面向 benchmark 作者，不面向稿件作者 |

**判断**：这份规范补的是我们的**运行纪律**，不是我们的**研究对象**。如果为了“像 RSI”而把 claim 级证据闭合降级成一个分数，或者把导出硬门换成“最终 artifact 评分”，那是把护城河拆掉去换一条别人已经修好的路。

## 5. 借 / 不借 / 改造

| 类别 | 内容 | 理由 |
| --- | --- | --- |
| **借** | 公开反馈收据的 `visibility/split/hidden_feedback_used` 校验 | 把“公开反馈”从文档约定变成可拒绝的输入；直接补 EV1 的证据准入 |
| **借** | artifact manifest（文件 hash、拒绝 symlink/特殊文件、空包/大小上限） | 让租约绑定不可变快照；防止“准入后偷偷改资产” |
| **借** | checkpoint / restore / finalization 预留 / 单 trial 不重置 | 让回滚和复评可执行；让“轮”有真实边界 |
| **借** | 子实验 / 完整 step / 合格版本三分 | 防止用一次 dry-run 或一次改文案冒充“一轮自进化” |
| **借** | 拒绝也评测、门槛只管保留不管停止 | 给 E1 的拒绝精度/召回提供数据；避免首个 accepted 就收敛 |
| **借** | contract revision ledger | 把“改判据”与“方法改进”分开；防止事后移动锚点 |
| **借** | 冻结后 hidden audit、选择规则预注册 | 让 EV4 的“能力增益”可证伪；防止用隐藏结果挑版本 |
| **不借** | 8 小时 / 40 分钟 / 至少 5 轮 / 至少 2 次保留，作为平台普适常数 | 这些是出题难度与预算默认值，不是科研过程定律；我们的阶段异构，必须按阶段定义有效工作与预算 |
| **不借** | 出题器/benchmark 产品身份 | 它造考场；我们做证据运营工作台。把平台做成 RSI benchmark 会偏离毕设主线 |
| **不借** | “对 solver 隐藏 RSI 身份”直接搬到用户侧 | 我们的作者/PI 需要审计透明；应分离 agent 角色可见性，而不是对用户隐藏 |
| **改造** | operator/solver → proposer/executor/admitter/human 可见性矩阵 | 保留“执行者不看隐藏结果”，但人类签署者看全量 |
| **改造** | artifact hash → 带 scope/passport/dependency 的资产 manifest | 我们的资产是 PF/技能/claim 资产，不只是代码目录 |
| **改造** | total budget → 每实例/每阶段预算 + 有效工作证据 | 不把等待/重跑/放大计算当难度；也不把分钟数当质量 |
| **改造** | hidden verifier → 冻结后的 sealed audit + 导出硬门 + 人类签署 | 我们的最终对象是稿件与证据包，不只是一个分数 |

## 6. 如果只做三件事

### P0-1：把 E7/E8 从“面板演示”改成“固定实例上的配对实验”

- 产出：`ImprovementInstance` 定义（12 个冻结切片、基线、原生指标、硬约束、预算、开发/封存划分）；PF 参考包（作者侧，不进入公开 demo）；四臂协议；sealed audit 流程。
- 验收：同一候选在四臂上的配对结果、父子版本 hash、每轮公开收据、最终冻结与审计顺序都能复算；未跑完就标 `not_run`。
- 不做什么：不新增 UI，不把 SIM 曲线改个数字就称实验。

### P0-2：把租约变成 P0 前的硬门

- 产出：`ArtifactManifest`、`LeaseSupervisor`、`PublicFeedbackReceipt` 校验器；P0 加载/拒绝/回退三条路径；rollback 快照恢复；过期/撤销/依赖漂移的阻断事件。
- 验收：过期租约不能进确证运行；撤销资产的 claim/句/图导出 fail-closed；回滚后 hash 一致；非法/非公开反馈不能生成 accepted 记录。
- 不做什么：不让控制器自动修复 stale claim；不把回滚当撤销的反操作。

### P1：把候选账本补齐

- 产出：`CandidateRun`、三分法、负结果评测、停止策略、`revision_ledger`。
- 验收：每个 retained 资产都能追到父版本、完整公开评测收据、对照/消融、成本与噪声；每个 rejected 候选都有有界评测与理由；改判据的版本不会被画进同一条改进曲线。
- 不做什么：不把“一次成功”直接晋升；不把 dry-run 计入完整周期。

### P2：把过程协议做成可执行的“行为 diff”

- 产出：PF 候选必须带 `behavior_diff`（改哪个阶段、哪条规则、预期效果、回退条件）+ 固定 dry-run 任务 + `no-op` 检测；纯文案修改判 `NO_SUBSTANTIVE_CHANGE`。
- 验收：同一 dry-run 上，行为 diff 可观察；无行为变化的候选不能进入 EV1；撤销后下一次同阶段确实回退到通用流程。
- 不做什么：不让 PF 改研究问题、假设、门槛、判据或 claim 真值（[11](11-自进化循环设计-准入理由、跨循环继承、迁移与能力增益.md) §9.1 的边界继续保持）。

## 9. 结论

对照这份规范，我们最该承认的一点是：**我们把“准入”写得很细，但还没有把“递归”做成可观测的事实。** 四问、租约、护照、撤销传播都是必要的语法；但没有固定实例、控制器、信息边界和步账，它们无法产生可比较的父子版本，也就无法回答“这一轮到底比上一轮强在哪”。

所以下一步不是再加一个 EV5，也不是把 demo 的曲线做得更漂亮，而是：

1. 用 12 个冻结切片和四臂对照，把 E7/E8 做成真正的配对实验；
2. 用 `LeaseSupervisor` + `ArtifactManifest` + `PublicFeedbackReceipt`，让租约在 P0 前真正拒绝；
3. 用 `CandidateRun` + 三分法 + 负结果 + revision ledger，让每个“留下”都有账可查。
