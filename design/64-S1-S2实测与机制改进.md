## 0. 一句话结论

**文献调研功能跑通、边界守得住；idea 功能跑通，但「证据来源」在 S1→S2 衔接处丢失，且 WorkBuddy 接入后第一次调用任何文献/想法工具都会因项目目录不存在而失败。** 本轮修了这两处；接入面的能力缺口（MCP 没有 S1 run / idea 生成工具）用可照抄路径缓解，新增工具属于契约变化，留待人定。

## 2. 对整体逻辑与机制的三个判断

1. **证据资格链应该是端到端的，不能有断点**。S1 有 `fixture_mode`、span-only、Q0；S2 消费 spans 后产物却看不出证据来自合成语料 —— 下游 `idea.json`、`study from-idea`、`flow g1` 读到的都是「看起来一样」的候选。这不是文案问题，是资格判定链的断裂。已修。
2. **「advisory 校验」和「强制门禁」必须分得清**。实测与 `62-` 一致：`build_idea_review` 的 `reject`、`independence` 的 `admission_eligible=false`、Q0 对 partial 的 pass，都只是提示。它们本身设计如此，但 `q0_decision` 返回 `pass` 时理由里写着 `coverage=partial`，容易让调用方误以为覆盖充分 —— 属于口径问题，不是 bug，**未擅自改门禁语义**。
3. **接入面必须暴露核心能力，或至少说清怎么到达**。46 个工具里没有 S1 run / idea 生成，宿主只能走 `research_run` 全流程或本机 CLI。加工具是契约变化（要动 `TOOL_NAMES`、`mcp_tools.TOOLS`、`dispatch_tool`、`face_coverage`、测试、导出、文档数字），本轮不擅自做；改用 Skill 里的可照抄路径 + 首次调用前置来解决可用性。

## 3. 本轮改动

### 3.1 idea 模块（规格先行，单模块）

| 文件 | 改动 |
| --- | --- |
| `modules/idea/SPEC.md` | `Contract` 新增一条：`IdeaResult.warnings` 必带 `source_mode=...`，按输入 Span 的 `fixture` 标记统计并显式声明演练/真实来源，无 span 时声明无可定位证据；`version 0.19.0 → 0.20.0`，Changelog 一条 |
| `research_agent/modules/idea.py` | `run()` 在生成 warnings 时统计 `fixture` span 数，产出 `source_mode=fixture: N/M ...` / `source_mode=real: ...` / `source_mode=none: ...`；**只改披露，不改候选生成、不改门禁、不写 Claim/EA/gate** |
| `tests/test_idea.py` | 新增 3 例：fixture 输入有披露、非 fixture 输入不继承 fixture 声明、无 span 声明无可定位证据 |

实测改动后：`IdeaResult.warnings` 出现 `source_mode=fixture: 1/1 input spans are synthetic S1 fixtures; ...`，`spec_version=0.20.0`。
