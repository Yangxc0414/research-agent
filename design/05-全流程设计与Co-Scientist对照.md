## 0. 参照对象说明

用户所说的"Science v2 / 谷歌那篇"，本轮按以下三项工作理解：

1. **Google Co-Scientist（Nature 2026）**：基于 Gemini 的多智能体科研协作系统，核心是"生成—辩论—演化"的假设锦标赛，7 类专用 agent，登 Nature（DOI: 10.1038/s41586-026-10644-y）。`[已核验]`
2. **Co-Scientist 端到端扩展（arXiv:2608.26701，2026-08）**：把系统从"假设生成器"扩展为"实验室集成研究伙伴"，覆盖假设→实验方案→代码/机器可读协议→执行→分析→手稿生成，并加入"数值结论对执行日志"的校验模块；在材料、生物、计算机三域验证。`[部分核验]`（预印本/官方博客口径）
3. **Google Cloud AI Research ScientistTwo（arXiv:2609.19644，2026-09）**：把流水线进一步推进到"种子想法→评估→精炼→消融→手稿→元评审→返修"，并以 107 个 ICLR/ICML/NeurIPS 任务做端到端评测。`[部分核验]`（预印本 + 用户提供文章口径，未独立复现）
4. **OpenRSI-Index / RSI-Harness**（本地快照 `oss/OpenRSI-Index-main/`，commit `c80c190`）与 **PaperBenchX**（外部项目，项目口径）：两者不做"从问题到长文"，而是回答"一个 agent 是否真的把结果做出来了"。前者给持久 Work + 一次性干净 Judge + 快照 + 私有测试 + oracle；后者给独立无网重跑 + 三阶段 rubric + 私有参考证据。`[工程参考]` / `[项目口径，未独立核验]`

> 如果所指是 Sakana 的 **AI Scientist-v2**（ICLR 2025 workshop），它是另一条路线：树搜索实验管理 + 自动评审，重点在"端到端产出论文"，不在假设锦标赛与实验闭环。本文在 §2.3 单独对照，避免混为一谈。

## 1. Co-Scientist 的系统解剖

### 1.1 七个 agent

| Agent | 职责 | 对应科研动作 |
| --- | --- | --- |
| Supervisor | 解析目标、分配资源、编排流程 | 课题负责人 |
| Generation | 从文献与数据生成初始假设 | 头脑风暴 |
| Reflection | 以同行评审视角检查正确性、新颖性、可检验性 | 内审 |
| Ranking | 两两比较 + 模拟辩论 + Elo 排序 | 组会排序 |
| Evolution | 对高排名假设做简化、组合、非常规推理 | 迭代改进 |
| Proximity | 计算相似度图、聚类、去重 | 查重与流派识别 |
| Meta-review | 汇总评审与辩论，识别共性问题并反馈 | 元评审 |

### 1.2 三个阶段

```
阶段一：构思
  研究问题 → 生成假设 → 反思/辩论 → Elo 排序 → 进化 → 邻近去重 → 元评审
  循环多轮，测试时计算可放大
        ↓
阶段二：实验
  假设 → 实验方案 → 代码/机器可读协议 → 执行（干实验/湿实验/人执行）
        ↓
阶段三：论文
  结果 → 手稿 → 数值核验（文本数字 vs 执行日志）→ 双盲专家评审
```

### 1.3 关键机制

| 机制 | 作用 | 可迁移性 |
| --- | --- | --- |
| 生成—辩论—演化循环 | 降低单模型确认偏误，提升假设质量 | 高 |
| Elo 锦标赛 | 用相对比较替代绝对打分，适合主观质量 | 高，但需防趋同 |
| Proximity 聚类 | 去重、识别流派、避免"换皮想法" | 高 |
| Meta-review | 汇总共性问题，反馈给生成端 | 高 |
| 测试时计算放大 | 多轮生成/辩论换取质量 | 中，需预算控制 |
| 人机协同 | 专家反馈进入循环 | 高 |
| 数值核验模块 | 文本数字与执行日志交叉核对 | **很高，直接可用** |
| 领域自适应自治 | 材料人执行、生物专家反馈、CS 全自主 | 高，需按场景分级 |

### 1.4 它证明了什么、没证明什么

**已证明**（在其设定内）：

- 多智能体"生成—辩论—演化"可以稳定产出可检验假设；
- 闭环可以从假设走到实验与手稿；
- 数值核验模块能降低编造结果；
- 生成论文可以通过双盲专家评审（30 位专家、450 次评审的规模）。`[部分核验]`

**没有证明 / 不覆盖**：

- 中文长文的体裁、引用规范与版面；
- claim 级证据账本与跨系统 provenance；
- 数据/代码变更后的结论失效追踪；
- 失败归因、负结果复用、技能适用域；
- 开放可复现的完整系统与成本结构；
- 湿实验的通用自主执行（其材料案例仍由人执行）。

> 这六条正好对应 01 的判断 1/2/5 与 00 的 D1/D2，也是本项目的差异化空间。

### 1.5 ScientistTwo：更接近"全流程"的一步

ScientistTwo 是 Google Cloud AI Research 的后续工作（arXiv:2609.19644v1，作者含 Nam、Yoon、Pan、Wang、Meng、Ranganathan、Pfister）。它不再只做假设生成，而是把"读论文—找缺陷—提想法—做实验—写论文—应对评审—补实验"串成一条可执行流水线。以下内容按预印本与用户提供文章整理，`[部分核验]`，数字未经独立复现。

#### 1.5.1 六个阶段

```
① 种子想法生成：读近期论文 → 抽取局限（limitation）→ 生成候选想法
        ↓
② 想法评估：新颖性、可行性、影响力 → 选出值得做的
        ↓
③ 想法精炼：把想法变成可执行方案，明确需要哪些实验
        ↓
④ 消融研究：Subset Coding Agent 先在小规模子集跑通
              → Full-Set Coding Agent 再扩到全量
              → Ablation Planner 规划消融矩阵
        ↓
⑤ 手稿撰写：从结果与消融生成论文
        ↓
⑥ 元评审：Peer-Reviewer 提意见 → Rebuttal Planner 规划回应
           → 需要补实验则回到 ④ → Meta-Review 汇总
```

#### 1.5.2 角色分工

| 角色 | 职责 | 对应本项目阶段 |
| --- | --- | --- |
| Limitation Extractor | 从论文中抽取未被解决的局限 | S1.6 gap 卡 |
| Limitation Verifier | 检查局限是否找全；不足则继续检索 | S1.6 + Q0 局限完整性 |
| Idea Generator | 由局限与文献生成候选想法 | S2 发散 |
| Novelty Checker | 对候选做新颖性评分与排序 | S3 查新 |
| Idea Evaluator / Selector | 评估、排序、选择 | S3 收敛 |
| Idea Evolver | 对入选想法做变异与精炼，保留原始种子 | S3 进化 |
| Baseline Coding Agent | 复现人类 SOTA 基线，保证同协议可比 | S5c 基线复现 |
| Subset Coding Agent | 小规模子集先跑通 | S5e 试跑 |
| Subset Critic | 判定子集结果是否值得扩量；执行者不自判 | S5c 独立 Evaluator |
| Full-Set Coding Agent | 全量执行 | S5c 正式执行 |
| Ablation Planner | 规划消融实验矩阵 | S4 设计卡 |
| Initial Drafter | 从结果与消融生成论文初稿 | S10 逐节生成 |
| Peer-Reviewer | 以审稿人视角提出问题 | S14 评审模拟 |
| Rebuttal Planner | 把意见转成回应与补实验计划 | S14 返修准备 |
| Meta-Review Agent | 汇总分歧、判定质量、决定继续或回退 | S3 元评审 / S14 |

#### 1.5.3 公开结果与限定

| 指标 | 数值 | 解释 |
| --- | --- | --- |
| 评测任务 | 107 个，来自 ICLR/ICML/NeurIPS | 以已发表论文为参照构造任务 |
| 超过人类 SOTA | 86/107（80.4%） | 作者口径；需注意任务构造与数据泄漏风险 |
| 平均提升 | +25.2% | 不同任务指标不可直接平均，仅作总体描述 |
| ScholarPeer 评分 | 7.5（对照 ScientistOne 3.8） | 自动评审器口径 |
| 自动评审接收率 | 91.9%（对照 14.3%） | **不等于真实期刊/会议接收率** |
| Stanford Agentic Reviewer | 72.1% | 另一自动评审器口径；所有 baseline 为 0 |
| 与真实接收论文均分对比 | 自动评审分高于 ICLR 2026 / NeurIPS 2025 接收论文均分 | 是"均分对比"，不是"接收率"；评审器、样本与领域分布不同 |
| 人工评审对照 | 9 位评审员总体打平；实验执行 AI 更受青睐，方法论严谨性人类略优 | 规模小，未报告 ICC/κ |
| 时间/成本 | 约 2.5 天、$3,765/任务 | 作者口径；含全量实验算力，不含人工复核与失败重跑 |

**必须同时读的限制**：

- 不是稳定达到 spotlight/oral 水平；
- 成本远高于日常写作工具；
- 自动评审通过率存在**循环性**：生成器、评审器、元评审可能共享偏好，分数上升不等于科学价值上升；
- 任务来自已发表论文，存在训练数据重叠与"反推已知答案"的风险；
- 不覆盖中文长文、中文引用规范与基金申报体裁；
- 没有 claim 级证据账本、跨版本失效追踪与跨项目记忆。

#### 1.5.4 它证明了什么、没证明什么

**已证明（在其设定内）**：

- "从局限出发"比"从空白出发"更能生成可执行想法；
- 先子集后全量的执行策略能降低无效算力；
- 消融规划可以成为独立的一等产物；
- 评审意见可以驱动补实验，而不是只改文字；
- 端到端流水线在 107 个任务上可运行、可统计。

**没有证明**：

- 自动评审分数与真实同行评审一致；
- 生成论文能达到顶刊/顶会稳定水平；
- 结果可被独立团队复现；
- 成本结构适合学生与普通课题组；
- 证据链可审计、结论可失效追踪；
- 中文长文的体裁与论证义务能被自动满足。

#### 1.5.5 与 Co-Scientist 的分工

| 维度 | Co-Scientist | ScientistTwo |
| --- | --- | --- |
| 起点 | 人给出的研究目标/假设空间 | 近期论文的局限 |
| 核心循环 | 生成—反思—辩论—Elo—进化—去重 | 局限抽取—想法—评估—精炼—消融—写作—评审—返修 |
| 实验 | 方案/协议/执行（含湿实验人执行） | 代码实验，先子集后全量，强调消融 |
| 写作 | 手稿生成 + 数值核验 | 手稿生成 + 自动评审 + 返修 |
| 评审 | 双盲专家评审实验 | Peer-Reviewer / Rebuttal Planner / Meta-Review 内置 |
| 评测 | 假设质量、实验衔接、专家评审 | 107 任务、自动评审、人工对照 |
| 对本项目的价值 | 收敛机制与实验闭环 | **局限驱动、先小后大、消融一等、返修补实验** |

> 两者共同的空白正是本项目的立足点：**证据生命周期**（claim 级账本、跨版本失效、可审计导出）与**中文长文能力**。ScientistTwo 把"自动化程度"又推高了一档，但没有把"可信度"推高到可交付水平。

#### 1.5.6 三个闭环、四类回退与人的角色

ScientistTwo 真正新增的不是"会写论文"，而是把三种反馈接成了闭环：

| 闭环 | ScientistTwo 的做法 | 本项目的落点 | 必须补的约束 |
| --- | --- | --- | --- |
| 实验 → 假设 | Idea Evolver 读取成功/失败记录进化假设，同时保留部分原始 seed 继续探索 | S3 进化 + S5e 负结果记忆 + 种子池保留 | 进化不得只围绕已跑通的 benchmark；保留 ≥ 20% 原始种子，防止局部最优 |
| 评审 → 实验 | Rebuttal Agent 把意见转成补充实验，跑完更新论文 | S14 → S4 → S5c → S9/S12 | 补实验必须走设计卡与独立判定；禁止"已补充"式空话；设置轮次与预算上限 |
| 消融 → 方法 | Ablation Planner 发现组件无用/有害就砍掉并重新优化 | S4 消融矩阵 + S5c 消融回环 | 最多 2 轮；每次简化都要更新 claim 与新颖性论证 |

**四类回退**（评审或核验失败时，不能都用"改文字"解决）：

| 失败层级 | 表现 | 回退目标 | 重新过的门 |
| --- | --- | --- | --- |
| 文本层 | 表述不清、结构松散、引用格式错误 | S12 定向修订 | Q1 |
| 证据层 | 引用不支持、数字不一致、claim 超出条件 | S9 证据卡 / S1 claim 卡 | Q1；改证据则重过 Q0 |
| 实验层 | 缺对照、缺消融、子集失败、结果不显著 | S4 新设计卡 → S5c | G2 |
| 贡献层 | 增量不足、被最近工作覆盖、核心结论不成立 | S2/S3 重新发散收敛 | G1 |

**人的角色**：ScientistTwo 把人的工作从"亲自跑每一步"推向"定方向 + 把关"。这与本项目的 A3 边界一致：人保留问题定义（G0）、短名单（G1）、设计（G2）、大纲（G3）与终审（G4）；系统承担检索、收敛、执行、写作、核验与返修准备。差别在于，本项目要求每次人工把关都绑定版本与证据，而不是"看一眼觉得可以"。

**四个不能直接迁移的前提**：

1. 它的任务是"在已发表论文附近做增量"，不是开放问题；真实科研的搜索空间与失败率更大。
2. 自动评审通过率存在循环性；必须用异构评审器 + 人类盲评校准。
3. $3,765/任务包含全量实验算力，与本项目"写作 + 核验 ≤ 30 元/篇"不是同一成本口径，不能对比。
4. 它不覆盖中文长文、中文引用规范、基金申报体裁与湿实验责任。

### 1.6 对 01 五条判断的再反思（加入 ScientistTwo 后）

| 01 判断 | Co-Scientist 的验证 | ScientistTwo 的推进 | 仍然缺失 / 本项目补法 |
| --- | --- | --- | --- |
| 判断 1：程序自主 → 过程自主 | 多轮生成/辩论可自动运行 | 把"局限→想法→实验→写作→返修"做成固定流程 | 流程固定 ≠ 策略会学习；仍无技能适用域与负迁移控制 → 记录策略效果，先测后用 |
| 判断 2：三层可验证 | 数值核验 vs 执行日志 | 子集/全量执行、消融记录更完整 | 仍无 claim 级证据账本与跨版本失效 → evidence graph + provenance |
| 判断 3：反事实脆弱 | 有实验闭环，但反事实规划弱 | 消融规划前进了一步 | 仍无"什么证据会推翻结论"的强制字段 → 设计卡 + claim 卡反证条件 |
| 判断 4：功能分化 | 7 个 agent 职责清晰 | 10 个角色覆盖执行与返修 | 生成者、评审者、元评审可能同源 → 独立上下文 + 跨模型 + 人类校准 |
| 判断 5：记忆不协调 | 跨会话记忆弱 | 未见跨项目记忆设计 | 文献/claim/方法/失败四类记忆仍未统一 → 统一图谱 + 类型化写入 |

**新增的第五个可证伪问题**：自动评审分数上升，是否只是生成器与评审器共同漂移？本项目的回应是：

- 记录评审器身份、版本与提示词哈希；
- 保留与生成器不同模型的" adversarial reviewer "；
- 用人类盲评做校准，报告自动分与人工分的相关性（ICC/κ）；
- 任何"质量提升"必须同时报告独立留出集与人工评分，禁止只报自动评审分。

### 1.7 执行侧参照：OpenRSI / PaperBenchX 补的是"判定层"

前面三者的共同假设是"执行结果大致可信"，把注意力放在生成、收敛与写作。OpenRSI 与 PaperBenchX 反过来：它们不关心文章写得好不好，只关心**结果是不是真的被做出来、能不能被独立重跑验证**。这正好补上本项目原先只有"同协议复跑 + 结果卡"、没有"独立判定"的短板。

| 机制 | OpenRSI / RSI-Harness | PaperBenchX（项目口径） | 对本项目的含义 |
| --- | --- | --- | --- |
| 执行与判定分离 | 持久 Work 执行；`rsi-submit` 暂停并快照；Judge 从干净镜像起，只读挂载 WORKDIR | 隔离、无网环境重跑；删除 agent 生成物 | S5 拆成 S5e 探索 / S5c 确证；确证运行由 Judge 判，不由执行者自评 |
| 只认重跑产物 | Judge 注入私有测试并运行；候选提交的代码/日志不自动算证据 | 只有重跑产生的产物算证据；日志/原始数据/轨迹只读固定 | 结果 claim 必须绑 `EA(source=rerun)`；Work 自报不算 |
| 失败分类 | run/submission 状态机；`verifier_error`/`infrastructure_error` 不记 0 | success/partial/invalid 校准 | 基础设施失败不得变成科学失败；写 FailureRecord 并重试/路由 |
| 评分结构 | reward 由任务自定义；oracle 验证 Judge、best-of-N 选有效提交 | Modeling / Execution / Validation 三阶段 rubric | R = 0.30 M + 0.30 E + 0.40 V；验证是当前最弱环节 |
| 防作弊 | 隐藏测试、私有 rubric、只读挂载、静态检查、canary | 测试与 agent 可见材料分离、私有参考证据 | Judge 不可被 Work 修改；rubric 与参考解不可见 |
| 写作 | 无 | 无 | **空位：RWJT，把复现结果写成中文核刊段落并联合计分** |

**它们证明的**：长程科研任务可以用"持久 Work + 一次性干净 Judge + 证据固定"来判定；"最佳提交"必须从有效提交中选；复现可以拆成建模、执行、验证三段来评分。

**它们没有解决的**：不写论文，不判断稿件陈述是否被运行证据支持；不做中文核刊/申报书；任务重、成本高（OpenRSI 最高 8×H100 / 13 小时 Judge；PaperBenchX 93 任务 / 10 个原生环境）；两者都不能直接作为本项目的效果基线。

**本项目的增量**：不是再做一个 OpenRSI，而是做**最小可验收的复现判定层**（v1 4 个任务、CPU/单卡、单次 Judge ≤ 30 分钟），并把它的输出接到**中文长文的槽位与导出硬门**上。标志性任务是 **RWJT（复现—写作联合任务）**：先复现一个结果，再把这个结果写成中文核刊段落，每个数字、图、结论都挂到重跑产物；J = 0.55 R + 0.45 W，任一造假直接判 invalid。

## 4. 反思：v0.1 的六个缺口

### 缺口 1：流程不完整

v0.1 的重心是"证据 + 写作 + 核验"，把 idea 收敛、实验设计、绘图、评审返修当作外围。结果是：

- 没有 idea 收敛，写作阶段的"研究方案"只能由人一次性给出，系统无法证明方案优于替代方案；
- 没有实验设计，执行阶段只是"跑代码"，无法判断设计是否有混杂、样本量是否足够；
- 没有绘图，图表只能靠人补，图文一致性无法自动保证；
- 没有评审返修，系统只做内部 critic，缺少"审稿人视角"的证据缺口检查。

### 缺口 2：收敛机制缺失

Co-Scientist 的价值不只在"生成更多"，而在**把候选收敛到可检验的少数**。v0.1 只有"gap 与假设"，没有：

- 两两比较与辩论；
- Elo/相对排序；
- 邻近去重（防止换皮）；
- 组合覆盖（防止全押一个流派）；
- 元评审（把共性问题反馈给生成端）。

### 缺口 3：实验设计不是一等公民

"实验设计"需要独立的产物（设计卡）与检查表，而不是写作时顺手写一段"方法"。缺设计卡会导致：

- 变量、对照、混杂因素不清；
- 样本量与统计检验不匹配；
- 停止规则缺失，出现"跑到显著为止"；
- 可证伪条件事后补写。

### 缺口 4：图表没有 provenance

图表是论文中最容易被"编造"和"改数"的部分。v0.1 的证据图谱只覆盖文本 claim，没有覆盖：

- 图的数据来源与生成代码；
- 图与正文数字的一致性；
- caption 与图内容的语义一致性；
- 期刊风格与可访问性。

### 缺口 5：自治只有一档

v0.1 用 A0–A4 一条轴，但科研场景的风险差异很大：读文献、跑干实验、人执行湿实验、对外投稿，不能用同一档自治。需要 **自治级别 × 验证义务** 的二维刻度（对应 01 判断 3 与 00 D4）。

### 缺口 6：评测偏"写得好"，不偏"研究好"

v0.1 的指标集中在引用、结构、专家写作分。缺少：

- idea 的新颖性、多样性、可证伪性；
- 实验设计的有效性；
- 图表的正确性；
- 评审问题的覆盖度；
- 全流程成本与人工介入次数。

## 5. 采纳 / 改造 / 拒绝

| Co-Scientist 机制 | 决定 | 本项目的改造 | 理由 |
| --- | --- | --- | --- |
| 生成—反思—排序—进化循环 | **采纳** | 用于 idea 收敛；每轮产物落证据卡 | 收敛质量直接决定后续所有阶段 |
| Elo 锦标赛 | **改造** | Elo + 覆盖度/多样性约束 + 组合选择 | 纯 Elo 会奖励"像主流"的想法，放大趋同（01 认知 A） |
| 模拟辩论 | **改造** | 辩论必须引用证据；无证据的论点判负 | 防止"口才好但没证据"获胜 |
| Proximity 聚类 | **采纳** | 机制簇去重 + 流派覆盖统计 | 防止换皮想法占满候选池 |
| Meta-review | **采纳** | 汇总共性问题，反馈到生成与设计阶段 | 把评审变成可学习的信号 |
| 测试时计算放大 | **改造** | 预算感知：只对高价值阶段放大 | 控制成本，避免全流程烧 token |
| 数值核验 vs 执行日志 | **采纳** | 扩展到图表、统计量、摘要数字 | 直接解决"编造结果" |
| 领域自适应自治 | **采纳** | 自治级别 × 验证义务二维刻度 | 干实验/湿实验/投稿风险不同 |
| 双盲专家评审 | **采纳** | 缩小规模，纳入 benchmark 协议 | 证明"好效果"的必要手段 |
| 全自主湿实验 | **暂缓** | P2 只做协议生成与人工执行 | 设备、安全、责任未解决 |
| 全自动投稿 | **拒绝** | 只导出，不代投 | 署名与责任问题 |
| "效率提升 200 倍"类叙事 | **拒绝** | 只报本地实测的成本与时间 | 不可核验，且容易误导 |

### 5.1 对 ScientistTwo 的采纳 / 改造 / 拒绝

| ScientistTwo 机制 | 决定 | 本项目的改造 | 理由 |
| --- | --- | --- | --- |
| 从论文局限反推想法 | **采纳** | Limitation Extractor 只产出带 span 的 gap 卡，不直接产出想法 | 局限是证据，想法仍需发散与收敛 |

| Limitation Verifier | **采纳** | S1.6 gap 卡增加"局限完整性复核"；Q0 抽查对标论文的 limitations、失败案例与后续反驳 | 只抽局限不做完整性检查，会漏掉真正的空白 |
| Novelty Checker | **改造** | 并入 S3 查新；输出最近工作、delta、verdict，不用单一新颖性分数 | 新颖性分数不可解释，且容易奖励"像主流" |
| Baseline Coding Agent | **采纳** | S4 设计卡新增"基线复现"；S5c 在同协议下复现人类 SOTA，记录与论文报告的偏差 | 没有同协议基线，"打赢 SOTA"不可信 |

| 端到端 2.5 天 / $3,765 每任务 | **不设为目标** | 中文长文目标成本 ≤ 30 元/篇；对外只报本地实测 | 成本口径不同（含全量实验算力），不能直接类比 |
| 以自动评审接收率证明质量 | **拒绝** | 自动分只作初筛；质量结论必须有人类盲评与独立留出集 | 生成器—评审器循环性（§1.5.3） |
| 自动补实验后直接改结论 | **拒绝** | 补实验走 S4→S5c→结果卡→claim 更新；结论变更需 G2/G4 或人工确认 | 防止"跑一个 seed 就改故事" |

| AutoSci 机制 | 决定 | 本项目的改造 | 理由 |
| --- | --- | --- | --- |
| `discover / ingest / check` 三权分离 | **采纳** | S1 候选池与证据图谱物理分离；写入只走一个通道；Q0 增加图谱健康检查 | 防止"候选"被当成"已核验证据" |
| `daily-arxiv` 增量置信门 | **采纳（P1）** | 默认只通知；自动纳入需显式开启 + 高置信 + 单轮上限；缺失信号不作为纳入证据 | 长期项目的增量更新必须有边界 |
| `prefill` 基础概念终止页 | **采纳** | 领域基础卡进入记忆；不允许每篇论文重复建概念页 | 降低图谱冗余 |
| `exp-design` 非线性消融回环 | **采纳** | 因子分 essential / contributing / marginal / harmful；后两类触发方法简化与重规划，最多 2 轮 | 消融结果应改变方法，而不是只写进表格 |
| `exp-pilot-run` 与 `exp-pilot-eval` 分离 | **采纳** | 执行者不判定；独立 Evaluator 按预注册判据给三态；失败写入负结果记忆 | 防止"自己跑、自己说成功" |
| `hiera-experiment` 探索 sidecar | **采纳** | 探索性搜索使用不可变候选快照，不写 claim/图谱；确证性运行冻结 protocol 并经人批准 | 防 p-hacking 与探索污染 |
| `paper-plan` 以 idea 图组织大纲 | **采纳** | S7/S8 的章节存在理由必须指向 claim 或证据；增加图计划与引用计划 | 防止"按惯例凑章节" |
| `paper-plan` 的 Review LLM 大纲评审 | **采纳** | G3 前增加独立领域主席视角评审；不替代人审 | 尽早发现叙事断裂 |
| `paper-draft` 分节生成 + BibTeX 核验 + de-AI polish | **改造** | 保留分节与核验；"去 AI 味"只改表达，不改证据与结论；增加中文体裁与槽位 | 表达优化不能变成事实漂移 |
| `rebuttal` 意见原子化 + 压力测试 | **采纳** | S14 每条意见编号并映射 claim/章节/实验；回应只用已有证据 | 防止"礼貌回应"绕开证据缺口 |
| 全量 wiki 健康检查 | **采纳** | 纳入 Q0/Q1：断链、孤儿、字段、枚举、链接对称性 | 图谱坏了，下游全错 |
| "自动科研"效果宣称 | **拒绝** | 只报本地实测；外部数字不进入对外材料 | 未独立复现 |

### 5.3 对 OpenRSI / PaperBenchX 的采纳 / 改造 / 拒绝

> 两者是"执行验证"参照，不是"自动写论文"对标；只借判定机制，不借其任务规模、算力负载与效果数字。

| 机制 | 决定 | 本项目的改造 | 理由 |
| --- | --- | --- | --- |
| 持久 Work + 一次性干净 Judge | **采纳** | S5c 确证车道；Judge 从干净镜像起，只读挂载快照，注入私有 rubric/测试 | 判定者不能与被判定者共享可写状态 |
| 提交即快照、每轮独立 Judge | **采纳** | X3 快照 → X4 重跑 → X5 verdict → X6 恢复迭代；提交上限 5 次 | 让"最佳提交"从有效提交中产生 |
| 私有测试 / 私有 rubric | **采纳** | 任务包 `tests/` 与 `rubric.json` 不进 Work；导出 rubric digest | 防止针对测试过拟合 |
| oracle / nop / partial / invalid | **采纳** | 每个任务先跑 oracle（≥0.90）与 nop（R ≤0.10）；partial/invalid 校准边界 | 先证明 Judge 能给分、能拒分 |
| 隐藏测试 + 静态检查 + canary | **采纳（改造）** | 20+ 静态检查缩到本项目必需项；canary 只用于污染控制，**不用于规避 AIGC 检测** | 保持任务包可维护；守住合规边界 |
| best-of-N 选主 reward | **采纳（改造）** | 只在 `scored` 提交中选；写作分 W 单独报告，不用 J 掩盖 R 失败 | R 与 W 是两种能力，不能被平均掉 |
| 单任务 8×H100 / 13 小时 Judge | **拒绝** | v1 单任务 CPU/单卡，Judge ≤ 30 分钟，成本 ≤ 50 元 | 与 8 个月、现有算力不符 |
| 93 任务 / 10 原生环境 / 公开榜 | **拒绝** | v1 4 个任务（T1–T4）；P1 6–8 个；不做公开排行榜 | 规模不可复制，且我们的目标是产品确证 |
| 只判复现、不判写作 | **改造为 RWJT** | T4：复现后写中文核刊段落；J = 0.55 R + 0.45 W；伪造直接 invalid | 这是两个参照系统共同留下的空位 |
| "General AI Scientist / RSI / 首个复现 benchmark"叙事 | **拒绝** | 不宣称；PaperBenchX 数字只作项目口径引用 | 目标、规模与证据都不支持 |

## 6. 改进后的全流程（v0.5）

### 6.1 状态机

与 `04-` §1 使用同一套编号：

```
S0 接入 ──[G0 人]──────────► 研究问题卡 + 资源/伦理约束
  ↓
S1 文献调研 ──[Q0 自动+抽样]──► 文献地图 + claim 卡 + 争议矩阵 + gap 卡
  ↓
S2 Idea 发散 → 20–50 条候选（每条带机制、证据与可证伪条件）
  ↓
S3 Idea 收敛 → 反思 → 辩论 → Elo → 邻近去重 → 进化 → 查新 → 覆盖度组合 ──[G1 人]──► 短名单
  ↓
S4 实验设计 → 设计卡（变量/对照/样本量/指标/消融矩阵/停止规则/可证伪条件） ──[G2 人]──► 设计确认
  ↓
S5e 探索执行（E 车道）→ 试跑/调参/中间结果；不进 Judge、不进 claim
  ↓
S5c 确证执行（C 车道）→ TaskSpec 冻结 → Work 执行 → 提交快照 → 干净 Judge 重跑 → Verdict ──[EA]──► 结果卡
  ↓
S6a 候选图 → 数据映射 → 代码 → 渲染 → 规则 QA（不绑定 claim）
  ↓
S7 论证骨架 → 问题→gap→方法→证据→结论
  ↓
S8 体裁大纲 ──[G3 人]──► 章节 × 论证义务 × 证据需求 × 图计划
  ↓
S6b 定稿图 → 选图 → 视觉 QA → caption → 绑定 claim/run
  ↓
S9 证据卡组装 → Claim Composer：manuscript_claim + claim ↔ evidence
  ↓
S10 逐节生成 → 引用槽/数字槽/图表槽草稿（只绑定，不新建 claim）
  ↓
S11 多角色批判 → 问题清单
  ↓
S12 定向修订 → 修订稿 + diff
  ↓
S13 全稿核验 ──[Q1 自动]──► 引用/数字/图表/一致性/论证链
  ↓
S14 评审模拟 + 返修准备（P1）
  ↓
S15 人工终审 ──[G4 人]──► 接受/退回
  ↓
S16 导出 + provenance + 使用记录 ──[G5]
```

**研究级回退**：S14 若判定贡献不成立（增量被最近工作覆盖、核心结论不成立），不得进入 S15，也不得只回 S12 改写；应带证据回 S2/S3 重新收敛，并重新过 G1。回退原因与原短名单的淘汰理由一并写入项目记忆。

### 6.2 Idea 收敛的详细机制

**输入**：研究问题、文献地图、**claim 卡、争议矩阵、gap 卡**、约束（领域、资源、时间、伦理）。

**步骤**：

1. **发散**：按机制/方法/场景/数据四个维度生成候选，要求每条包含"主张、机制、证据、可证伪条件、所需资源"；候选必须能回溯到至少一条 gap 卡或反向证据。
2. **证据检索**：为每条候选找支持与反驳证据；无证据的候选降级。
3. **反思**：按正确性、新颖性、可检验性、可行性、影响力打分；给出改进建议。
4. **辩论**：抽取候选两两比较；辩手必须引用证据；无证据论点不计分。
5. **Elo 排序**：多轮比较更新分数；记录比较理由。
6. **邻近去重**：按机制/概念聚类；同簇只保留代表，防止换皮。
7. **进化**：对 top-k 做组合、简化、反向思考；产生新一代候选；保留 ≥ 20% 原始种子继续探索，防止进化把候选池收窄到单一机制。
8. **查新**：每条入围候选按 `06-` §4.7 输出最近工作、delta 与 verdict；`ABANDON` 必须点名论文。
9. **组合选择**：不是只选第一名，而是选一组覆盖不同机制簇的候选（覆盖度 + 新颖性 + 可行性 + 成本）。
10. **人工短名单**：G1 由人确认 3–5 条进入设计。

**输出**：候选卡、Elo 曲线、聚类图、查新报告、组合理由、风险清单与淘汰理由。

### 6.3 实验设计卡

| 字段 | 内容 | 检查 |
| --- | --- | --- |
| 研究问题 | 一句话，可回答 | 与假设一致 |
| 假设 | 可证伪陈述 | 有否证条件 |
| 变量 | 自变量/因变量/控制变量 | 无遗漏混杂 |
| 对照 | 阴性/阳性/消融 | 能区分竞争解释 |
| 基线复现 | 人类 SOTA / 官方实现的代码、数据、超参与环境 | 同协议可比；偏差与未复现原因需记录 |
| 消融矩阵 | 每个增益对应哪组消融；负对照与预期方向 | 增益可归因；缺一项即 G2 不通过 |
| 试跑计划 | 子集、成功判据、扩量条件、终止条件 | 先小后大，避免无效全量 |
| 样本量 | 功效分析或经验依据 | 与统计检验匹配 |
| 指标 | 主指标/次指标/稳健性 | 不事后挑选 |
| 分析计划 | 模型、检验、多重比较校正 | 预注册 |
| 停止规则 | 时间/预算/毒性/无效 | 防止"跑到显著" |
| 资源 | 数据、算力、设备、人力 | 可执行 |
| 风险与安全 | 伦理、隐私、设备安全 | 有缓解措施 |
| 预期结果 | 支持/不支持分别意味着什么 | 避免解释事后化 |

**自动检查**：混杂因素清单、样本量—检验匹配、主指标唯一性、停止规则存在性、可证伪条件完整性。

### 6.4 图表流水线

```
claim/结果卡
  → 图 brief（这张图要证明什么、给谁看、放在哪节）
  → 数据映射（数据源、字段、过滤、统计）
  → 图表代码（matplotlib/ggplot/vega，固定随机种子）
  → 渲染（PNG/SVG/PDF）
  → 自动 QA：数据—图一致性、坐标轴/单位、误差棒、显著性标注
  → VLM 视觉 QA：可读性、遮挡、误导性缩放
  → caption 生成（图说了什么 + 统计信息 + n）
  → 正文数字一致性核验
  → 期刊风格适配
```

**图表证据边**：`figure → dataset/run → code → claim`，任何一环变更都能触发失效检查。

### 6.5 评审模拟与返修

- 角色：方法审稿人、领域审稿人、统计审稿人、写作审稿人、伦理审稿人；各自独立上下文。
- 输出：问题、严重度、所需证据、可能的反驳。
- **Rebuttal Planner**：把意见分为"可用现有证据回应 / 需补实验 / 无法支持应降级结论"；需补实验的进入新设计卡，不得直接改写文本。
- **失败分流**：文本层回 S12；证据层回 S9/S1；实验层回 S4；贡献层回 S2/S3 并重新过 G1。禁止所有问题都用改写解决。
- 回应：每条回应必须绑定证据或补充实验；禁止"已补充"式空话。
- 安全门：无伪造引用、不过度承诺、覆盖所有主要问题（参考 ARIS 三安全门）。
- 定位：评审模拟是自检工具，不模拟真实同行评审、不代替期刊审稿、不生成虚假审稿意见。

## 8. 对 01 四个可证伪问题 + 五个新问题的回应（共九问）

| 问题 | 在本项目中的落点 | 需要记录的量 |

| **问题六**（AutoSci 工程实践引出）：提议、执行、判定合并时，系统是否更容易自证 | S1/S2/S4/S5e/S5c/S11/S13/S14 三权分立；同一上下文不得既产出又放行；探索性运行与确证性运行隔离 | 角色分离 vs 合并的错误率、漏检率、自证率、探索污染率 |
| **问题七**（ScientistTwo 的"打赢 SOTA"引出）：同协议复现基线后，报告的增益是否仍然成立 | S4 设计卡要求基线复现；S5c 同时报告论文数字与本地复现值；增益消失则 claim 降级，不得只报有利的一套 | 基线偏差率、复现前后增益、协议差异、未复现原因 |
| **问题八**（OpenRSI/PaperBenchX 引出）：当执行者同时自报结果时，系统是否会把"跑过"当成"做对" | S5c 由独立 Judge 在干净环境重跑；只有 `scored` verdict 能创建 result_claim；探索 run 不进 claim；基础设施失败不记 0 | Work→Judge 泄漏、oracle/nop、重跑一致性、infra 误记 0、伪造通过 |
| **问题九**（RWJT 引出）：复现成功是否等于写对，写作分是否会被复现分掩盖 | T4 分开报告 R 与 W；J 只作联合指标；数字/图/结论必须绑 `R/X/N/F` 槽；未解析槽阻止导出 | R/W 分差、槽位覆盖率、伪造通过、专家对"写对"的盲评 |

这九问不是附加实验，而是产品日志与评测的**默认字段**。

## 9. 实施优先级

| 优先级 | 能力 | 理由 |
| --- | --- | --- |
