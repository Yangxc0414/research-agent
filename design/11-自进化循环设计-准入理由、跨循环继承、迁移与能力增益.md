## 0. 一页结论

用户提出的四个问题，正好对应自进化最容易被含糊过去的四个判定：

1. **为何被接受**：不是“分数高”，而是一条可复核的接受理由——问题、机制、反事实、独立判定、成本、适用域与异议都要留痕。
2. **能否可靠保留、跨循环继承**：准入不是奖杯，而是**租约**。资产必须带版本、谱系、适用范围、失效条件与复评时间；到期、漂移或冲突时自动进入复核，而不是永久有效。
3. **能否迁移到新任务**：相似度不是迁移证据。每个资产带“适用域护照”，进入新任务只能三选一：直接复用、先 pilot、拒绝复用；负迁移与 pilot 失败都要写回护照。
4. **能否提升后续能力**：必须在**冻结的留出任务集**上，用独立判定与消融/对照测出可归因的增益，并扣除成本；任务分数上升不等于能力提升，更不等于科学有效性。

本文的设计不是给 P0–P8 再加一个阶段，而是把它们放进四个嵌套的环：

```text
L0 单轮执行环：任务 → 协议 → 运行 → 判定 → claim
L1 改进准入环：候选 → 筛查 → pilot → 四问 → 准入/拒绝/延后
L2 跨循环继承环：租约 → 下一轮继承 → 复评 → 续租/降级/撤销
L3 迁移与能力环：新任务 → 适用域判定 → 迁移测试 → 能力增益/负迁移 → 回写
```

一句话：**线性流程回答“这一轮做完了吗”；自进化循环回答“这一轮的什么，凭什么进入下一轮，又凭什么继续留下”。**

**记忆准入的位置（v0.2 的核心修正）**：P8 不是“写入长期记忆”的终点，而是**候选生产**的终点。P8 只能把本轮的成功经验、失败修复、人工建议与反例写成 `EvolutionCandidate`；**长期记忆/下一轮继承包只接受已通过 EV1–EV4 且持有有效租约的资产**。这条边界防止“本轮成功 = 永久经验”的隐性晋升，也解释了为什么记忆准入必须放在四问之后、下一轮 P0 之前，而不是塞进 P8 内部。

**两个准入平面（v0.4）**：claim 级资产（SK/WF/PL）回答“这条结论/技能能不能用”，过程协议（PF）回答“这个阶段下一次怎么跑”。两者共享 EV1–EV4 与租约语法，但对象、作用域和失效路径不同：claim 级资产失效会沿 claim → 句 → 图传播并阻断导出；过程协议失效只让下一次同阶段回退到通用流程，不追溯改判已经产生的 claim。过程协议永远不能生成、修改或替代 claim。

本文能主张的只有设计：四问账本、租约继承、适用域护照、能力增益的因果口径，以及可证伪的 E7/E8。本文不能主张“系统已经会自进化”，也不能把 SIM 演示当成效果证据。RSI-Anything 的机制只作工程参照，其效果数字未复现、不得引用为本项目结果。

## 1. 为什么现在是一条线：缺的不是阶段，而是二阶反馈

### 1.1 现有 P0–P8 已有一阶反馈，但没有二阶反馈

当前 demo 的 P0–P8 并不是完全没有反馈：Run 1 失败会回到修订，claim 失效会传播到句子，P8 会把技能写入记忆。问题在于，这些反馈都发生在**同一轮内部**：

| 已有的一阶反馈 | 它回答的问题 | 它没有回答的问题 |
| --- | --- | --- |
| Run 1 失败 → 预注册范围内修订 → Run 2 | 这一轮怎么继续 | 这次修订方法是否值得保留到下一轮 |
| Q1/G5 阻断导出 | 这一轮能不能交付 | 被阻断的原因是否应改变下一轮的准入策略 |
| P8 五项学习证据 → 技能准入 | 这个技能这一轮是否达标 | 它只是**候选**：下一轮、换任务、换环境后是否仍然成立，尚未判定 |
| claim 失效传播 | 哪些句子受这次变更影响 | 哪个资产应对这次变更负责，是否应撤销 |

所以用户看到的“线性”，本质不是少了 P9，而是少了**选择—继承—迁移—增益**这四类跨轮反馈。再加一个“自进化阶段”只会把线拉长；正确做法是让 P8 **只产出候选**，再由 EV0–EV4 与租约决定哪些候选成为下一轮 P0 的继承包，并给这个入口配一份可审计的账本。

### 1.2 v0.3 的机制增量：三机制 + 两平面

RSI-Anything（[10](10-RSI与自进化反思-科研改进的准入与证据闭合.md) §1.9、[12](12-RSI-Anything深读-执行契约、保留层与领域不对称.md) §2）把“预测候选后果 → 选择 → 评估 → 保留”做成了统一运行时。它停在任务/能力层，但可借的不只三个点；深读后应分两层看：

| 借用项 | RSI-Anything 的做法 | 本文的落点 | 不能借的 |
| --- | --- | --- | --- |
| **EV0 预测预筛（shadow）** | 世界模型预测候选动作后果，用于排序与评估顺序 | 候选进入 pilot 前的预算分配；预测只影响排序，不作为 EV1–EV4 证据 | 把预测当准入证据；把预测分数写进理由链 |
| **incumbent guard** | 候选预测 utility 不优于当前 incumbent 时保留 incumbent | 候选必须相对当前 `active` 资产有增益；未超过写 `INCUMBENT_GUARD` / `NO_INCUMBENT_GAIN` | 用预测值替代真实留出对照 |
| **判定封存 + cohort 隔离** | `public_seal.json` 先封存决策，再开 hidden judge；训练/开发/确认/测试使用互斥 seed | EV4 的留出集开启前冻结候选、判据、排序与预算，记录 `seal_hash`；四个 cohort 不重叠 | 把任务级 hidden judge 当稿件判定 |
| **执行契约（E 层）** | run/source identity、stage receipt、completed 输出哈希、attempts 归档、resume、文件锁、plan dry-run | 新增 E1–E8；接 `07-` RWVH 与 `09-` 调度 | 把“有 run 目录”当“可复现”；E 层必须用失败边界测试验收 |
| **交叉/条件确认（C/A 层）** | 2×2（old/new world × old/new policy）、pilot 过阈值才开 confirmation、独立 `audit.py` 重算 raw 数据 | 新增 C1–C7 与 A1–A6；EV4 用 2×2 分离资产/上下文贡献，confirmation 未过不写 capability gain | 自动 promotion；固定阈值 0.04/1.2×/0.05/630 照搬为普适常数 |

**边界**：RSI-Anything 的 retain 是 world/policy checkpoint 或 pair；本文的 retain 是**带租约、护照、依赖快照与撤销传播的 claim 级资产**。两者不是同一个对象，不能互相替代。它也没有解决：租约到期/复评/回滚、依赖图与撤销传播、句子级证据槽、中文核刊体裁、人类签核。我们的增量在后者，但必须先补 E 层，否则这些记录没有可复核的 run 底座。

### 1.3 四种缺失的反馈

| 反馈 | 触发 | 如果没有 | 本文的接口 |
| --- | --- | --- | --- |
| 选择反馈 | 候选改进完成 pilot | 所有成功都被保留，技术债累积 | EV1 准入理由 |
| 保留反馈 | 周期推进、依赖变化、时间流逝 | 旧经验静默过期，坏条目无法撤销 | EV2 租约与复评 |
| 迁移反馈 | 新任务/新领域到来 | 相似度被当成可复用，负迁移扩散 | EV3 适用域护照 |
| 增益反馈 | 多轮之后回看留出任务 | 只看到局部分数，无法归因 | EV4 能力增益 |

### 1.4 设计约束

- **不新增一条线性主链**：P0–P8、S0–S16 的编号不变；新增的是跨轮账本与四个判定门。
- **不把“自进化”当默认正确**：每个候选都必须先被当作假设，而不是收益。
- **不让人被流程绕过**：高风险准入、远域迁移、阈值修改、撤销后的对外稿件处置，均需人类签核。
- **不把演示当结果**：demo 只展示接口与状态变化，所有数值标 SIM。

## 2. 核心对象与状态机

### 2.1 五个对象

| 对象 | 作用 | 关键字段 | 不做什么 |
| --- | --- | --- | --- |
| `EvolutionCandidate` | 一个待准入的改进候选 | `candidate_id`、类型、来源 run、补丁、预期收益、适用范围、风险、成本 | 不直接写记忆，不直接进下一轮 |
| `AdmissionRecord` | 四问判定与接受理由 | 四门结果、理由码、证据引用、政策版本、角色签名、异议 | 不是一个分数；不可被 Agent 改写 |
| `InheritanceLease` | 跨循环继承的租约 | 资产版本、谱系、范围哈希、生效/到期、复评周期、撤销指针 | 不是永久资格；过期即不可用于确证运行 |
| `ScopePassport` | 适用域护照 | 任务族、前置条件、指标口径、依赖、已知失败、迁移历史 | 不把相似度当许可 |
| `CapabilityDelta` | 对后续能力的因果估计 | 留出任务集、效应、区间、成本、判定者、周期、结论 | 不等于科学有效性 |

辅助记录：`PredictionTrace`（EV0 预测值、区间、校准、真实结果与误差）。它**不是**准入对象，只用于排序与预算；不得进入 `AdmissionRecord.because`。

### 2.2 状态机

```text
                    ┌──────────────┐
                    │  proposed    │  候选提出（来自失败、残差、人工建议）
                    └──────┬───────┘
                           │ 形式检查：类型 / 来源 / 范围 / 风险
                           ▼
                    ┌──────────────┐
              ┌─────│   screened   │─────┐ 缺证据/越界/高风险
              │     └──────┬───────┘     │
              │            │ 通过        ▼
              │            ▼        ┌──────────┐
              │     ┌──────────────┐│ rejected │ 保留理由与再提议条件
              │     │   piloting   │└──────────┘
              │     └──────┬───────┘
              │            │ 四问通过
              │            ▼
              │     ┌──────────────┐
              │     │ admitted     │ 发租约（有期限、有条件）
              │     └──────┬───────┘
              │            │ 下一轮继承
              │            ▼
              │     ┌──────────────┐
              │     │   active     │◄──────────┐
              │     └──────┬───────┘           │ 复评通过、续租
              │            │ 漂移/冲突/到期     │
              │            ▼                   │
              │     ┌──────────────┐           │
              │     │  probation   │───────────┘
              │     └──────┬───────┘
              │            │ 复评失败 / 负迁移 / 下游事故
              │            ▼
              │     ┌──────────────┐
              └────►│   revoked    │ 撤销 + 依赖失效传播
                    └──────────────┘
```

**状态规则**：

1. 只有 `active` 资产可以进入下一轮的确证运行；`probation` 只能在 shadow 模式使用。
2. `admitted` 不等于 `active`：必须完成一次跨循环继承检查（范围哈希、依赖、租约）后才激活。
3. `revoked` 不删除历史；它触发依赖它的 run / claim / 句子 / 图进入 `stale`，并保留旧版本。
4. `rejected` 不是垃圾箱；它带理由码与 `reactivate_when`，新证据出现时可以重新提交，但不能绕过四问。
5. 任何状态迁移都写 `evolution_event`，包含操作者、时间、政策版本与证据引用。

### 2.3 两个账本，不要混在一起

| 账本 | 记录什么 | 准入对象 | 失败后果 |
| --- | --- | --- | --- |
| 证据账本（已有 L4） | run、verdict、EA、claim、span、失效边 | 一句话/一个结论能不能进稿 | 阻断导出 |
| 进化账本（本文） | 候选、四问、租约、护照、能力增益 | 一个改进能不能进入下一轮 | 撤销资产并传播失效 |

两个账本通过 `candidate.source_claims`、`lease.used_by_runs`、`revoke.affected_claims` 交叉引用。**不能把“claim 通过”当成“技能该保留”，也不能把“技能准入”当成“稿件结论成立”。**

## 3. 四问：每一问都要有记录，而不是一个勾

### 3.0 EV0 预测预筛（shadow）：只排序，不判准入

这是 v0.2 从 RSI-Anything 借来的**可选前置步骤**，不是第五道门，也不改变四问。

| 项 | 设计 |
| --- | --- |
| 目的 | 在有限预算下决定先 pilot 哪个候选、如何分配评估预算 |
| 输入 | 候选补丁、当前 `active` incumbent、历史 run 特征、任务元数据 |
| 输出 | 预测效用、预测区间、排序、校准记录、`prediction_trace_id` |
| 允许 | 候选排序；pilot 预算分配；提示需要补哪些证据 |
| 禁止 | 直接准入/拒绝；替代留出对照；写入 `because` 证据链；修改四问结果 |
| 记录 | 预测值、真实结果、误差、同分布/分布外标记、模型版本 |
| 失败码 | `PREDICTION_MISCALIBRATED`（预测高但真实失败）；该码进入复评，不单独否决候选 |

**规则**：

1. **预测不是证据。** EV0 的分数不得出现在 `AdmissionRecord.because` 中，只能出现在 `prediction_trace`。
2. **校准可审计。** 每个周期至少报告一次预测—真实误差；连续高估的预测器降级为“仅排序”，不得用于预算倾斜。
3. **可跳过。** 没有可靠世界模型时，EV0 记为 `not_run`；不能因为缺少预测而阻止候选进入 pilot。
4. **与 incumbent 的关系**：EV0 可以预测候选相对 incumbent 的增益，但**是否真的超过 incumbent 由 pilot/留出对照判定**（见 §3.2.6）。

### 3.1 EV1 为何被接受：从“分数过线”到“可复核的理由链”

#### 3.1.1 接受理由的七个部分

| 部分 | 要回答 | 最低记录 |
| --- | --- | --- |
| 问题 | 它修复的是什么失败/残差 | 失败记录或残差 ID；不是“感觉有用” |
| 机制 | 为什么这个改动应该有效 | 一句可证伪的机制假设 + 预期影响范围 |
| 证据 | 哪些运行支持它 | run/EA/verdict ID；至少一次独立判定 |
| 反事实 | 去掉它会怎样 | 消融或无资产对照；不能只有前后对比 |
| 成本 | 维护、调用、人工复核的代价 | 成本账本；与收益同口径 |
| 范围 | 它在哪些任务/条件下成立 | 适用域护照草案；越界即失效 |
| 异议 | 谁不同意，为什么 | Judge/人类/替代假设的反对记录；不得静默合并 |

#### 3.1.2 理由码

理由码不是装饰，它决定后续复评要查什么。

| 方向 | 理由码 | 含义 | 后续动作 |
| --- | --- | --- | --- |
| 正面 | `GAIN_HELD_OUT` | 留出任务上有可归因增益 | 进入 EV4 复核 |
| 正面 | `TRANSFER_POSITIVE` | 至少两个新任务上正向迁移 | 写入护照 |
| 正面 | `RETENTION_STABLE` | 跨周期保留未退化 | 可续租 |
| 正面 | `NO_NEG_TRANSFER` | 目标范围内无负迁移 | 仍需持续监测 |
| 正面 | `COST_JUSTIFIED` | 成本低于收益 | 进入租约成本条款 |
| 正面 | `JUDGE_INDEPENDENT` | 判定者与执行者分离 | 记录判定者与上下文 |
| 正面 | `HUMAN_SIGNOFF` | 高风险/远域获得人类签核 | 记录签核范围 |
| 正面 | `INCUMBENT_BEATEN` | 在留出对照上超过当前 active 资产 | 才允许替换/新增租约 |
| 负面 | `SINGLE_RUN` | 只有一次成功 | 退回补 pilot |
| 负面 | `INCUMBENT_GUARD` | 候选未超过当前 active 资产，保留 incumbent | 拒绝替换；候选留在反例/再提议库 |
| 负面 | `NO_INCUMBENT_GAIN` | 有绝对增益，但相对 incumbent 的增量不足 | 不替换；按新增资产重新评估 |
| 负面 | `PREDICTION_MISCALIBRATED` | 预测与真实结果显著背离 | 降低预测器权重；补真实对照 |
| 负面 | `SAME_MODEL_JUDGE` | 自评自判 | 换独立判定或降级 |
| 负面 | `IN_DISTRIBUTION_ONLY` | 只在源分布有效 | 只能短租约/ shadow |
| 负面 | `NEGATIVE_TRANSFER` | 新任务上掉点 | 缩小范围或撤销 |
| 负面 | `GAIN_WITHIN_NOISE` | 效应落在等价区间 | 不宣称增益 |
| 负面 | `COST_EXCEEDS_GAIN` | 成本高于收益 | 拒绝或改为人工流程 |
| 负面 | `SCOPE_MISSING` | 没有适用条件/失效条件 | 拒绝入库 |
| 负面 | `CONFLICT_UNRESOLVED` | 与已有证据冲突未解释 | 延后，进入信念修订 |
| 负面 | `BENCHMARK_OVERFIT` | 只对评测集有效 | 拒绝；记录污染风险 |
| 负面 | `HUMAN_REJECT` | 人类基于责任/伦理/安全否决 | 保留理由，禁止自动重提 |

#### 3.1.3 角色分离

| 角色 | 可以做 | 不可以做 |
| --- | --- | --- |
| Proposer | 提出候选、机制假设、预期收益 | 给自己的候选签“接受” |
| Executor | 运行 pilot、产出日志 | 修改判定标准 |
| Judge | 独立重跑、打分、给 verdict | 参与候选设计 |
| Admitter | 汇总四问、检查理由链 | 改写 Judge 的 verdict |
| Human | 高风险/远域/范围扩张签核 | 被系统替代最终责任 |

**接受理由必须是“因为”而不是“所以”**：账本保存的是 `because = [失败记录, 对照, 独立判定, 成本, 范围, 异议]`，而不是一句 `accepted = true`。如果理由链中的任何一环被撤销，准入记录进入 `under_review`。

#### 3.1.4 政策版本与“不许事后改判据”

- 每次准入绑定 `policy_version`（阈值、最小任务数、成本口径、风险等级）。
- 政策可以更新，但**不能追溯性重判**已发生的准入；旧记录保留旧政策，直到下一次复评。
- 政策修改本身是一个 `EvolutionCandidate`（类型 `policy`），需要人类签核与影响分析。
- 这条规则防止“这轮没过，就把门槛调低”的隐性刷分。

### 3.2 EV2 能否可靠保留、跨循环继承：准入是租约，不是奖杯

#### 3.2.1 租约字段

| 字段 | 含义 | 例子（SIM 结构，不是结果） |
| --- | --- | --- |
| `asset_id` / `version` | 资产与版本 | `SK-0014@v2` |
| `lineage` | 父版本、替代关系 | `supersedes SK-0014@v1` |
| `scope_hash` | 适用域护照的哈希 | 任务族 + 指标口径 + 前置条件 |
| `valid_from` / `valid_until` | 租约窗口 | 第 2 轮至第 6 轮 |
| `revalidate_every` | 周期复评间隔 | 每 2 轮或依赖变更时 |
| `depends_on` | 数据/代码/模型/协议版本 | `analysis@2.1`, `model@frozen` |
| `state` | `active/probation/revoked` | 只有 active 可用于确证运行 |
| `revoke_pointer` | 上一稳定版本 | 回滚目标 |
| `used_by_runs` | 消费该资产的运行 | 用于失效传播 |

#### 3.2.2 复评触发器

| 触发器 | 例子 | 复评内容 |
| --- | --- | --- |
| 时间 | 租约到期 | 回归任务 + 保留率 |
| 依赖变化 | 数据/代码/模型/指标口径变更 | 重跑 canary + 失效传播 |
| 新冲突证据 | 新文献或新运行反驳 | 信念修订与范围收窄 |
| 下游失败 | 使用该资产的运行失败 | 归因：资产 / 执行 / 环境 |
| 迁移异常 | 新任务负迁移 | 护照更新或撤销 |
| 政策变更 | 门槛或风险等级变化 | 仅对下一次复评生效 |

#### 3.2.3 继承规则

1. **版本钉住**：下一轮继承的是 `asset@version`，不是“最新技能”这一模糊对象。
2. **范围匹配**：只有 `scope_hash` 兼容才允许直接继承；不兼容进入 EV3。
3. **依赖快照**：继承包包含数据/代码/模型/协议快照；任一变化触发复评。
4. **shadow 优先**：`probation` 资产先在 shadow 模式跑，不影响确证结果。
5. **继承上限**：同一资产连续续租需要至少一次独立复评；不能无限自动续租。
6. **回滚可用**：任何时刻可回退到上一稳定版本；回滚不是删除，而是切换 `active` 指针并保留撤销记录。

#### 3.2.4 撤销与失效传播

撤销不是把条目改成 `revoked` 就结束。它必须做三件事：

1. **定位依赖**：`used_by_runs` → 结果 claim → 稿句/图。
2. **分类处置**：结果需要重跑的标 `rerun`；叙述需要改写的标 `rewrite`；仅需人工复核的标 `review`。
3. **阻断导出**：受影响且未处置的 claim/句/图使导出 fail-closed；旧导出保留并标 `stale`。

这与 [09](09-系统架构与流程编排设计.md) 的 F5 传播是同一套机制，只是触发源从“数据/代码变更”扩展为“资产撤销/租约到期/负迁移”。

#### 3.2.5 保留指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| `retention@k` | 第 k 轮仍通过复评的资产比例 | 判断是否可靠继承 |
| `lease_survival` | 租约按期存活的平均周期数 | 判断是否频繁撤销 |
| `stale_rate` | 因资产失效而 stale 的 claim/句比例 | 判断技术债 |
| `rollback_latency` | 从发现问题到完成撤销传播的时间 | 判断可运维性 |
| `revalidation_pass` | 复评通过率 | 判断门槛是否过松/过严 |

#### 3.2.6 incumbent guard：有增益还不够，必须超过当前资产

一个候选在绝对分数上提升，不代表它值得替换当前 `active` 资产。采用 RSI-Anything 的 incumbent 思路，但把比较对象从预测 utility 改为**留出对照上的真实结果**：

| 判定 | 条件 | 处置 | 理由码 |
| --- | --- | --- | --- |
| 替换 incumbent | 候选留出增益 ≥ guard margin，且成本 ≤ 成本上限（如 ≤1.2× incumbent） | 发新租约；旧版本转 `superseded`，保留回滚指针 | `INCUMBENT_BEATEN` |
| 保留 incumbent | 候选未超过 incumbent，或增益落在等价区间 | 候选不替换；保留为反例/再提议 | `INCUMBENT_GUARD` |
| 新增而非替换 | 候选与 incumbent 适用域不重叠，且各自在域内有效 | 两者并存，护照分别限定 | `SCOPE_DISJOINT` |
| 无 incumbent | 首个资产；或 incumbent 已撤销 | 按绝对门槛与留出对照判定 | `NO_INCUMBENT` |

**硬约束**：

- guard margin、成本上限与等价界必须在**候选选择前**写入政策版本，不能看到结果后调。
- “候选赢了预测”不等于“候选赢了真实结果”；EV0 只用于排序。
- 被 guard 拦下的候选仍要报告结果，不能只展示成功替换的案例。
- 成本必须写成相对 incumbent 的比值（调用、人工复核、环境适配），不能只报绝对成本。

#### 3.2.7 租约管理动作：用户在控制台能做什么

demo 的资产租约控制台对应以下动作。每个动作只追加事件，不删除历史。

| 动作 | 允许状态 | 权限 | 结果 | 传播 |
| --- | --- | --- | --- | --- |
| 发起复评 `revalidate` | `active` / `probation` | Judge + Admitter | 续租、维持或降级；追加 `AdmissionRecord` 新版本 | 复评失败则进入 `probation` |
| 降为 probation | `active` | Admitter | 只能在 shadow 使用；确证结果不得引用 | 使用它的未导出 claim 标 `review` |
| 撤销 `revoke` | `active` / `probation` | Admitter；高风险需 Human | `revoked`；保留旧版本 | `used_by_runs → claim → 句/图` 全部 stale，导出 fail-closed |
| 回滚 `rollback` | `revoked` / `probation` | Human | 切回上一稳定版本并恢复 `active` | 旧版本造成的影响仍需处置；新版本增益作废 |
| 收窄范围 | 任意 | Admitter + Human | 更新护照与 `scope_hash`，缩短租约 | 越界使用立即失效 |
| 重新提议 | `rejected` | Proposer | 生成新候选，不覆盖旧拒绝记录 | 必须重走 EV1–EV4 |

**回滚不是撤销的反操作**：回滚只恢复“上一稳定版本可用”，不会自动修复已 stale 的 claim/句/图，也不会恢复被撤销版本的增益结论。控制台必须同时显示“当前 active 版本”和“仍待处置的 stale 影响”。

### 3.3 EV3 能否迁移到新任务：相似度不是迁移证据

#### 3.3.1 适用域护照

| 字段 | 要写什么 | 为什么必要 |
| --- | --- | --- |
| 任务族 | 任务类型、输入输出、评价目标 | 防止“都是科研任务”式泛化 |
| 数据条件 | 分布、规模、标注/测量方式 | 分布变化是负迁移主因 |
| 指标口径 | 指标定义、阈值、排除规则 | 口径不同会把掉点看成提升 |
| 依赖 | 工具、模型、运行环境、权限 | 环境漂移会让技能失效 |
| 前置条件 | 必须成立的条件 | 不满足就不能直接复用 |
| 已知失败 | 观察到的负迁移与边界 | 防止重复踩坑 |
| 迁移历史 | 哪些任务成功/失败、证据 ID | 作为下一次判定依据 |
| 安全边界 | 高风险操作与人工确认点 | 迁移不能绕过安全门 |

#### 3.3.2 三档判定

| 判定 | 条件 | 预算 | 失败去向 |
| --- | --- | --- | --- |
| 直接复用 | 护照匹配 + 至少两个近域任务正迁移 + 无负迁移 + 低风险 | 常规运行预算 | 出现掉点 → 降为 pilot |
| 先 pilot | 部分匹配 / 远域 / 新指标 / 中高风险 | 固定 pilot 预算与 kill 标准 | 失败 → 拒绝复用，写回护照 |
| 拒绝复用 | 缺前置条件 / 安全边界不允许 / 历史负迁移 | 0 | 保留理由，等待新证据 |

**“先 pilot”不是拖延**：pilot 必须有任务集、对照、预算、停止条件与人类签核；没有这些，pilot 就是无期限试用。

#### 3.3.3 迁移测试

- **目标任务留出**：pilot 任务不得来自准入时用过的任务集。
- **有/无资产对照**：同一模型、同一协议、同一预算，只改资产是否存在。
- **近域与远域分开报告**：不能用一个平均分掩盖远域掉点。
- **负迁移单列**：负迁移不是“噪声”，而是范围护照需要收窄的证据。
- **成本同口径**：迁移收益要扣除额外调用、人工复核与环境适配成本。
- **人类签核**：远域迁移与高风险任务必须人类批准，不能由 Admitter 自动放行。

#### 3.3.4 迁移指标

| 指标 | 定义 |
| --- | --- |
| `near_transfer_gain` | 近域留出任务上的有/无资产差值 |
| `far_transfer_gain` | 远域留出任务上的差值 |
| `negative_transfer_rate` | 出现显著掉点的任务比例 |
| `pilot_kill_rate` | pilot 未达 kill 标准而终止的比例 |
| `scope_mismatch_detected` | 前置条件不满足被正确拦截的比例 |
| `transfer_cost` | 环境适配 + 额外调用 + 人工复核成本 |

### 3.4 EV4 能否提升后续能力：留出、归因、扣成本、可撤销

#### 3.4.1 三个概念必须分开

| 概念 | 测什么 | 不能推出什么 |
| --- | --- | --- |
| 任务增益 | 某个任务/基准上的分数变化 | 能力提升；跨任务有效 |
| 能力增益 | 冻结留出任务集上的可归因变化 | 科学有效性；论文结论正确 |
| 科学有效性 | 结论在真实世界/理论上的成立程度 | 由上述两者自动保证 |

本文只设计前两层的测量；第三层仍由证据账本、专家判断与真实复现负责。

#### 3.4.2 测量协议

1. **先冻结留出集**：在进化开始前冻结任务、指标、预算与判定者；留出集不得用于候选选择。**开启 hidden judge 之前**先封存候选名单、排序、判据与预算，记录 `seal_hash`；封存后不得改判据。
2. **钉住混杂因素**：模型、harness、工具版本、预算与人工介入规则保持一致；只改变资产。训练 / 开发 / 确认 / 留出使用**互斥 cohort**（任务或 seed 不重叠），并记录 cohort 清单。
3. **有/无资产对照**：A/B 或 shadow；不能只有“进化前 vs 进化后”的时间序列。
4. **消融**：移除单个资产，确认增益确实来自它，而不是同期其他变化。
5. **跨周期重复**：至少两个周期或两个任务族重复出现同向效应；单周期结果只算 pilot。
6. **独立判定**：Judge 不参与候选设计；评分细则与留出集分离。
7. **成本扣除**：报告 `Δscore`、`Δcost`、`Δhuman_intervention` 三个分量，不合成一个不透明总分。
8. **区间与等价检验**：报告置信区间；效应落在等价区间内时，结论是“未观察到增益”，不是“有提升”。

#### 3.4.3 增益结论的门槛

| 条件 | 要求 | 不满足时 |
| --- | --- | --- |
| 效应方向 | 留出集上同向 | 记为无增益/负结果 |
| 统计 | 区间排除等价界 | 不宣称 |
| 归因 | 消融支持资产贡献 | 降为相关性 |
| 范围 | 近域/远域分开 | 不得合并宣称 |
| 成本 | 成本调整后仍为正 | 拒绝或改为人工流程 |
| 复现 | ≥2 周期或 ≥2 任务族 | 仅作 pilot |
| 判定 | 独立 Judge + 人类签核 | 不得进入租约 |
| 退化 | 保留任务不掉点 | 撤销或收窄范围 |

#### 3.4.4 能力曲线与衰减

- 每个周期在**同一留出集**上记录能力值；留出集轮换时，新旧版本用锚点任务对齐。
- 同时记录“无准入”“全部准入”“四问准入”三条对照，避免把任何提升都归功于机制。
- 曲线必须显示不确定性；不能用一条平滑线暗示稳定提升。
- 资产撤销后，曲线要标出断点与回滚，而不是把历史抹掉。

#### 3.4.5 反 Goodhart 约束

- 留出集与准入集分离；留出集定期轮换并保留锚点。
- 不允许针对准入指标反复调参；候选选择要有探索配额。
- 准入指标本身要接受审计：假接受率、假拒绝率、人工推翻率。
- 任何“通过少写/少做来提升指标”的行为，都要用覆盖率与任务完成度约束抵消。
- 发现 benchmark 污染或评测集泄漏时，相关增益结论作废。

#### 3.4.6 判定封存与 cohort 隔离：防止“看到结果再改判据”

RSI-Anything 在 `tasks/code_repair/src/evaluation.py` 里先写 `public_seal.json`，断言 `all_decisions_sealed_before_hidden_judge=True`，再开启 hidden judge；在 `tasks/gui/docs/PROTOCOL.md` 中，训练/开发/确认/RSI test 使用互斥 cohort seeds。我们吸收这两条，但把判定对象换成 `(run, claim, 稿件槽)`：

| 控制 | 我们怎么做 | 记录 |
| --- | --- | --- |
| 判定封存 | 留出集开启前冻结候选、排序、四问判据、预算与 Judge 版本 | `seal_hash`、`sealed_at`、`frozen_by` |
| 开启顺序 | 先封存，再跑 hidden judge；封存后只能追加异议，不能改判据 | `judge_started_at > sealed_at` 断言 |
| cohort 隔离 | 训练 / 开发 / 确认 / 留出任务或 seed 互斥；轮换保留锚点 | `cohort_id`、`anchor_tasks` |
| 污染审计 | 检查留出任务是否出现在候选生成、prompt、few-shot 或检索结果中 | `contamination_scan` |
| 拒绝也报告 | 被 guard 拦下或被拒绝的候选仍记录留出结果（若已运行） | `rejected_results` |

**这不是“防 AIGC 检测”**：封存与隔离只用于保证评测有效性，不用于规避任何检测，也不改变 AI 使用披露义务。

## 4. 反馈图：从一条线到四个嵌套环

### 4.1 四个环

| 环 | 时间尺度 | 输入 | 输出 | 停止条件 | 失败去向 |
| --- | --- | --- | --- | --- | --- |
| L0 单轮执行 | 一次研究 | TaskSpec、继承资产 | run、verdict、claim、稿件 | 达门槛/预算耗尽 | 修订、重跑、open question |
| L1 改进准入 | 一轮结束 | 失败记录、候选补丁、pilot | 四问记录、准入/拒绝 | 四问完成 | 拒绝理由入约束记忆 |

## 5. 接进现有架构：不改主链，只加一层跨轮账本

### 5.1 与 P0–P8 的关系

| 现有阶段 | 保留 | 新增的跨轮动作 |
| --- | --- | --- |
| P0 任务编译 | TaskSpec | 读取 `InheritedAssetPack`；声明本轮允许继承的资产与范围 |
| P1–P6 执行与写作 | 不变 | 资产使用记录写入 `used_by_runs` |
| P7 核验导出 | 不变 | 导出包附带“本轮使用的资产租约”清单 |
| P8 记忆准入 | 五项学习证据 | **只产出 `EvolutionCandidate`**；不直接写长期记忆、不直接进下一轮 |
| P8 之后 | 原流程结束 | EV0 预筛（可选）→ EV1–EV4 → 发租约 → 写入 `InheritedAssetPack`；然后进入下一轮 P0 |
| 下一轮 P0 | TaskSpec | 只载入持有有效租约且 `scope_hash` 兼容的资产；其余留在候选/反例库 |

**关键变化**：P8 不再是终点，也**不是记忆写入点**。它只把本轮经验转成候选；真正的长期记忆写入发生在**四问通过并发出租约之后**。P0 必须显式声明“这轮继承了哪些资产、为什么允许继承”，不能隐式把上一轮的记忆全部载入。

### 5.2 与 S0–S16 的关系

- **不新增业务阶段**。S0–S16 仍是一轮内的主链。
- 新增 **L4.5 进化账本服务**（或作为 L4 的子模块）：`evolution_candidate`、`prediction_trace`、`admission_record`、`inheritance_lease`、`scope_passport`、`capability_delta`、`evolution_event`。
- 在 S5c/S9/S16 的现有钩子上增加：
  - S5c 启动时记录使用了哪些资产（`used_by_runs`）。
  - S9 写作时禁止引用 `probation/revoked` 资产的结论。
  - S16 导出时检查租约状态；过期/撤销资产影响到的 claim 未处置则阻断。
- 现有 9 个门禁不变；新增 4 个**跨轮门** `EV1–EV4`，只在 P8 之后与下一轮 P0 之前生效。

### 5.3 建议的数据表

| 表 | 主键 | 关键外键 | 写入者 |
| --- | --- | --- | --- |
| `evolution_candidate` | `candidate_id` | `source_run_id`, `source_claim_id` | Proposer |
| `prediction_trace` | `trace_id` | `candidate_id`, `model_version` | EV0 预筛器（只追加） |
| `admission_record` | `admission_id` | `candidate_id`, `policy_version`, `seal_hash` | Admitter |
| `inheritance_lease` | `lease_id` | `asset_id`, `admission_id`, `supersedes` | Admitter |
| `scope_passport` | `passport_id` | `asset_id`, `task_family` | L3 服务 |
| `capability_delta` | `delta_id` | `asset_id`, `heldout_suite_id`, `cycle` | L3 + Judge |
| `evolution_event` | `event_id` | 上述任意对象 | 所有角色（只追加） |

### 5.4 建议接口

| 接口 | 作用 | 权限 |
| --- | --- | --- |
| `POST /v1/evolution/candidates` | 提交候选 | Proposer |
| `POST /v1/evolution/{id}/prediction` | 记录 EV0 预测（不判准入） | 预筛器 |
| `POST /v1/evolution/{id}/pilot` | 启动 pilot 并冻结对照 | Executor + Judge |
| `POST /v1/evolution/{id}/admit` | 四问判定与发租约 | Admitter；高风险需 Human |
| `POST /v1/evolution/{id}/revalidate` | 复评并续租/降级 | Judge + Admitter |
| `POST /v1/evolution/{id}/revoke` | 撤销并触发传播 | Admitter/Human |
| `POST /v1/evolution/{id}/rollback` | 回滚到上一稳定版本 | Human |
| `GET /v1/evolution/ledger?cycle=` | 查看某轮账本 | 审计只读 |
| `GET /v1/evolution/{id}/passport` | 查看适用域护照 | 所有复用者只读 |

**接口纪律**：`admit` 不能由 Proposer 调用；`revoke` 不能删除历史；`revalidate` 不能修改旧记录，只能追加新版本。

### 5.5 一个周期的顺序

1. P0 读取继承包，声明使用范围。
2. P0–P7 完成本轮研究；所有资产使用写入 `used_by_runs`。
3. P8 **只汇总候选**：成功经验、失败修复、人工建议、反例 → `EvolutionCandidate`；**到此为止，不写长期记忆**。
4. EV0 预测预筛（可选）：排序与预算，不进入理由链。
5. 筛查：类型、来源、范围、风险、是否重复。
6. Pilot：固定预算、对照、kill 标准；相对 incumbent 记录增益与成本。
7. 四问：EV1 理由、EV2 租约、EV3 护照、EV4 增益；留出集开启前完成判定封存。
8. 决策：接受/拒绝/延后；高风险人类签核；guard 未过则保留 incumbent。
9. 发租约；**写入下一轮继承包（这是长期记忆写入点）**；更新护照与能力基线。
10. 到期/漂移/冲突时复评；失败则降级/撤销并传播 stale；必要时回滚到上一稳定版本。

## 6. 可证伪实验：E7 与 E8

> E1–E6 见 [10](10-RSI与自进化反思-科研改进的准入与证据闭合.md) §6。E7/E8 是本文新增的跨轮实验，不改变 E1–E6 的口径；所有结果尚未产生。

### E7 跨循环继承与回滚

| 项 | 设计 |
| --- | --- |
| 针对问题 | 能否可靠保留、跨循环继承 |
| 干预 | 四种策略：不留存 / 全部留存 / 只按时间续租 / 四问 + 租约 + incumbent guard + 复评 |
| 场景 | 4 个周期；第 2 轮注入依赖漂移，第 3 轮注入冲突证据，第 4 轮注入负迁移 |
| 指标 | `retention@k`、租约存活、`stale_rate`、回滚正确率、回滚时延、人工复核时间 |
| 基线 | 全部留存；时间续租；手工台账 |
| Kill | 四问租约与手工台账无差异，或回滚传播漏掉关键 claim/句 |
| 对应 | EV2；W2 扩展 |

### E8 能力增益的纵向归因

| 项 | 设计 |
| --- | --- |
| 针对问题 | 能否提升后续能力 |
| 干预 | 三条对照：无准入（每轮从零）/ 全部准入 / 四问 + guard 准入；每条跑 4 个周期 |
| 任务 | 冻结留出集 + 轮换锚点；近域与远域分开；cohort 互斥 |
| 指标 | 留出集 Δscore、相对 incumbent 增量、成本调整后增益、负迁移率、保留任务退化、消融贡献、区间、`seal_hash` 一致性 |
| 基线 | 无准入；全部准入；单周期前后对比（用于暴露混杂） |
| Kill | 四问准入与全部准入无差异，或增益在成本调整后消失，或无法通过消融归因 |
| 对应 | EV3/EV4；W1/W3 扩展 |

**建议顺序**：先 E2/E3/E5（单轮证据闭合与判定），再 E7（继承与回滚），最后 E8（纵向能力）。没有单轮闭合，跨轮能力曲线没有可信的 claim 作为锚点。

## 7. 指标看板：分开报告，不合成一个“自进化分数”

| 维度 | 指标 | 类型 | 读法 |
| --- | --- | --- | --- |
| 准入 | 接受率、拒绝率、延后率 | 过程 | 低接受率不一定是坏事 |
| 准入 | 假接受率、假拒绝率、人工推翻率 | 质量 | 需要专家抽样 |
| 准入 | incumbent guard 拦截率、被拦候选的真实增益 | 质量 | 防止“有绝对增益就替换” |
| 预筛 | 预测—真实误差、高估率、排序有效性 | 校准 | 预测只排序，不作证据 |
| 理由 | 理由码分布、理由链完整率 | 过程 | 防止“空理由接受” |
| 封存 | `seal_hash` 覆盖率、封存后改判次数 | 完整性 | 改判次数必须为 0 |
| 保留 | `retention@k`、租约存活、复评通过率 | 结果 | 跨轮才可读 |
| 保留 | `stale_rate`、回滚正确率、回滚时延 | 运维 | 撤销是否真的传播 |
| 迁移 | 近域/远域增益、负迁移率、pilot kill 率 | 结果 | 近远分开 |
| 迁移 | 范围误判率、迁移成本 | 质量 | 相似度不能替代 |
| 能力 | 留出集 Δ、成本调整后 Δ、消融贡献 | 结果 | 区间与对照必需 |
| 能力 | 保留任务退化、能力衰减 | 风险 | 不能只看上升 |
| 循环健康 | 候选产出率、多样性、技术债、每保留增益成本 | 健康 | 防止局部锁死 |
| 治理 | 人类签核率、AI 使用记录完整率、政策变更审计 | 合规 | 不是科学主张 |

**禁止**：把上述指标加权成一个“自进化指数”对外宣称。权重会掩盖失败维度；审稿人无法复核。

## 8. 边界、风险与不可宣称

### 8.1 不可以宣称

| 不可以写 | 原因 | 可以改成 |
| --- | --- | --- |
| “我们的系统会自进化 / 是 RSI 系统” | 本文只有设计；没有跨轮实验结果 | “We design an admission and inheritance layer for self-improving research agents.” |
| “四问准入提升后续能力” | E7/E8 未运行 | “We propose and operationalize four admission questions; their effect is untested.” |
| “准入通过 = 结论正确” | 准入判的是资产，不是科学真值 | “Admission gates what may be reused; claim validity is handled by the evidence ledger.” |
| “租约 = 永久保留” | 租约有期限、可撤销 | “Admission is a revocable lease, not a permanent status.” |
| “相似任务 = 可迁移” | 相似度不是迁移证据 | “Transfer requires a passport match and a held-out pilot.” |
| “能力曲线上升 = 科学进步” | 任务增益不等于科学有效性 | “We measure task-level capability deltas on held-out suites.” |
| “demo 证明闭环有效” | demo 全部为 SIM | “The demo visualizes states and feedback; it is not an experimental result.” |
| “RSI-Anything 的 31.2% / 46.37% 证明我们的方向” | 作者/项目口径，未复现；任务层结果不等于中文长文科研 | “We borrow its prediction/incumbent/seal mechanisms; its reported numbers are not our results.” |
| “P8 写入 = 长期记忆准入” | P8 只产出候选；四问 + 租约才是写入点 | “P8 produces candidates; long-term memory is written only after EV1–EV4 and a lease.” |
| “EV0 高预测 = 应准入” | 预测不是证据 | “EV0 only ranks candidates; admission uses pilot and held-out evidence.” |

### 8.2 主要风险

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| Goodhart | 候选针对准入指标优化 | 留出集分离、轮换、探索配额、人工审计 |
| Evaluator capture | Judge 与 Proposer 同源 | 三权分离、独立上下文、外部模型对照 |
| 范围蔓延 | 技能被过度泛化 | 护照前置条件、远域人审、负迁移写回 |
| 技术债 | 资产越积越多、无人复评 | 租约、复评队列、撤销传播、成本账本 |
| 假保留 | 只续租不复评 | 继承上限、shadow、独立复评 |
| 归因错误 | 同期模型/数据变化被算作资产收益 | 钉住混杂、A/B、消融、跨周期重复 |
| 政策漂移 | 为过门槛而改阈值 | 政策版本、不可追溯、人类签核 |
| 责任扩散 | 多角色没人负责 | 人类终审、签核范围、审计日志 |

### 8.3 什么会证伪本文的设计

- 四问准入与“全部准入”在 E8 中无差异；
- 租约机制在 E7 中不能降低 stale 或回滚错误；
- 适用域护照不能预测负迁移，pilot 与直接复用结果无差异；
- 独立判定与自评无差异，导致 EV1/EV4 失去意义；
- 成本调整后增益消失，或增益无法通过消融归因。

出现以上任一情况，应撤回对应的强主张，保留工程描述或负结果报告。

### 9.1 过程级反馈面板（v0.4 演示）

原有候选账本与资产租约控制台把准入放在 **claim 级资产**（技能补丁 SK、工作流 WF、策略 PL）：它回答“这条经验能不能留下”。但 P0–P8 的每一段内部还存在另一类经验——**这次检索式、假设裁决顺序、冻结流程、重跑模板、写作槽位、导出预检到底哪种跑法有效**。如果这类经验只停留在 run log 里，下一轮同一个阶段仍然会重新试错；如果直接把上一次答案存下来复用，又会把“这一次碰巧有效”误当成可复用能力。

v0.4 在 demo 中新增 `#process-feedback` 面板，把准入单位下沉到**阶段执行协议**：每个阶段 P0–P8 各自保留“上一次怎么跑、哪种跑法有效/无效、下一次同阶段是否加载”的记录。它回答的是“这个阶段下一次怎么跑”，不回答“这条结论是否成立”。

**对象：`ProcessProtocol`（PF-…）**

| 字段 | 含义 | demo 示例 |
| --- | --- | --- |
| `stage_code` | 只作用于哪一个阶段 | `P0`…`P8` |
| `domain_scope` | 适用域；超出即失效或重新 pilot | 中文核刊 · 材料/文本 |
| `evidence_budget` | 该协议允许消耗的样本/运行/成本 | 3 次运行 + 1 个留出任务 |
| `protocol_version` | 协议版本与谱系 | `PF-P0@v1` |
| `last_run` | 上次尝试、有效/无效观察、成本与样本 | TaskSpec 六字段模板 |
| `counterfactual` | 去掉该协议后的反事实 | 完整度回落到 0.71 |
| `gates` | EV1–EV4 的 pass / pilot / fail | 4/4 或 2/4 |
| `lease` | 生效/到期轮次、复评触发、撤销指针 | 第 3–6 轮 · 每 2 轮复评 |
| `next_run` | 下一次加载什么、改什么、预期什么、何时回退 | 六字段检查，缺项标 NEEDS-INPUT |
| `boundary` | 有效条件、失效条件、明确不改变什么 | 不改研究问题与门槛 |

**状态与加载规则（demo 口径）**

| 状态 | 进入条件 | 下一次同阶段 | demo 中的颜色 |
| --- | --- | --- | --- |
| `active` | 4/4 门通过，租约生效 | 加载协议；结果计入阶段指标 | 青绿 |
| `pilot` | 部分门只到 pilot，租约仅 shadow | 只跑 shadow；不写正式记忆 | 琥珀 |
| `rejected` | 预注册冲突或证据不足 | 不加载；拒绝理由与反例保留 | 玫瑰 |
| `revoked` | 人类撤销或复评失败 | 回退通用流程；历史记录不改判 | 玫瑰 |

**它改什么、不改什么**

- 改：同一阶段的检查顺序、模板、预检项、失败路由与复跑策略。
- 不改：研究问题、假设选择、显著性门槛、判据、署名与最终责任。
- 不生成、不修改、不替代任何 claim；过程协议的失效不会把已产出的 claim 自动判真或判假。
- 仍走 EV1–EV4；单次成功不构成候选，反事实与成本必须一起记录。
- 撤销或拒绝都保留理由；下一次不会静默加载，也不会静默回退到“上一次答案”。

**九个阶段的过程协议（全部为 SIM 演示）**

| 阶段 | 上次观察（SIM） | 协议候选 | 下一次加载的行为 | 状态 |
| --- | --- | --- | --- | --- |
| P0 任务编译 | TaskSpec 完整度 0.68；人工回改 2 次 | 六字段模板：主指标/门槛/预算/停止/数据边界/责任边界 | 缺项标 NEEDS-INPUT；完整度 0.86 | active |
| P1 检索与阅读 | span 转化率 31%；Q0 0.71 | 测量方法检索式 → 标题去重 → 摘要只筛 → 全文才建 span | span 42%；Q0 0.78 | active |
| P2 假设裁决 | 可证伪 2/3；自评分被当新颖性 | 先过否证条件，再做新颖性排序；自评只作 ranking_only | 可证伪 3/3；新颖性仍待外部评审 | pilot |
| P3 设计冻结 | 冻结后改判 2 次 | 变更双签；旧协议留版本，不覆盖 | 近域改判 0 次；耗时 +6 min | pilot |
| P4 复现执行 | 重跑成功率 58%；EA 孤儿 1 | 失败 → 预注册内修订 → 重跑；依赖漂移即复评 | 重跑 71%；EA 孤儿 0 | active |
| P5 判定与 Claim | 提议把门槛 0.05→0.10 | 拒绝移动预注册门槛；保留为反例 | 不加载；原门槛与判据不变 | rejected |
| P6 写作与图表 | 无槽位事实句 9/章 | claim 槽位预绑定 + 图规格前置检查 | 无槽位句 3；G3 首次 3/3 | active |
| P7 核验与导出 | 越级/孤儿导出 2 次 | 数字白名单 + stale 预检 + 图表哈希规范化 | 泄漏 0；误报 1 次，人工复核 | active |
| P8 记忆准入 | 误准入 1 次 | 一次成功不晋升；pilot + 反事实 + 成本门槛 | shadow 运行；人工复核 +2 | pilot |

**与 RSI 的关系（可宣称边界）**

- 相似之处：都在“运行之后”学习，而不是只优化单次输出；都有候选—评估—保留—再使用的结构。
- 我们的差异：保留单位是**某个阶段的执行协议**，且与 claim 级资产分开；协议必须带阶段作用域、反事实、阶段指标、租约与失效条件；撤销只回退该阶段，不追溯改判 claim。
- 不能宣称：这九个协议还没有在真实任务上做跨轮对照；表中数值是 SIM；`active` 不等于“已被证明有效”，只表示演示状态；C1–C4、E7/E8 仍未运行。

## 10. 一句话总结

> **线性流程把一轮研究做完；自进化循环要回答：这一轮的什么值得留下、凭什么留下、能带到哪里、又是否真的让下一轮更强。**
