## 0. 一页结论

**方向合理，但当前的创新叙事过载：主贡献、支撑、扩展与工程四层混在一起。**

正确的层级是：

1. **主贡献（N1+N4）**：定义并测量 **RWJT / 证据闭合稿件**——给定研究问题、代码/数据快照与冻结协议，系统必须同时交付可复核复现与一份“经验句绑 confirmed rerun、文献句绑可定位 span、否则导出被阻断”的稿件；用预注册指标测量硬门、传播与联合判定。
2. **支撑（N2+N3）**：claim–run–artifact 契约、六类槽、统一 claim ID、只认重跑、导出硬门、三类处置。它们使主任务可判定、可复现，但不单独宣称“首创”。
3. **扩展（自进化层）**：EV1–EV4 四问、租约、适用域护照、撤销传播、过程协议（PF）。设计完整，但 **E7/E8 未运行**，目前只能作为“设计与待验证扩展”，不能与 N1/N4 并列为主创新。
4. **工程（N0）**：9 阶段、18 阶段编排、可调工作流、demo、UI。它们是产品成熟度与实验装置，不是论文创新；可调工作流尤其不应写进创新点表。

**一句话**：主线是“证据闭合的科研写作任务 + 测量”，自进化是这条主线的下游治理层；两者不能同时当主标题。若导师要求毕设必须落在“自进化”上，则把证据闭合降为 testbed，先跑 E7/E8，再谈自进化。

## 1. 评审方法

### 1.1 三条 novelty gate

沿用 [08- §3.3](08-反思与差异化工作方案.md) 的三问：

1. **去掉它，基线还能解这个任务吗？** 若还能，它是工程优化，不是任务贡献。
2. **有没有基线与效应量？** 若只有“我们实现了”，它是功能描述。
3. **能不能不提系统名字，用一句话说清贡献？** 若不能，它是集成工作。

### 1.2 证据等级

| 标记 | 含义 |
| --- | --- |
| `[已核验]` | 论文/期刊/官方页面元数据经 arXiv/DOI 核对 |
| `[部分核验]` | 论文存在，但会议/数字未独立核对 |
| `[工程参考]` | 只读代码/技能文档，确认机制存在；未运行、未复现 |
| `[项目口径]` | 对方项目/厂商自报，未独立核验 |
| `[设计]` | 本文档体系内的设计，未实测 |
| `[SIM]` | demo 中的模拟演示，不是实验结果 |
| `[估算]` | 人周/成本估算，非实测 |

### 1.3 对照范围

- 本轮只对照公开材料与 `oss/` 快照中可核对的机制，**不比较效果数字**。
- “未见完整实现”只表示本轮核验范围内未见，不表示历史上不存在；并发工作随时可能推翻。
- 任何“首个/唯一/首创”都必须先过 §3.3 三问；不能过，就改成“我们定义/我们测量/在本轮核验范围内未见”。

## 4. 与当前需求的对齐

### 4.1 需求基线

[02- §0/§2](02-需求书-科研自动化与写作平台.md) 的定位是：面向中文核刊（自科）与项目申报书的首发验证，能力层保持通用，本期目标 **A3（全流程草稿 + 自检 + 人工终审）**，机器承担检索、收敛、设计草案、起草、绘图、核对与修订，人保留科学判断、实验安全、署名与最终责任。

### 4.2 对齐表

| 需求 | 来源 | 创新栈提供什么 | 现在的缺口 | 验收口径 |
| --- | --- | --- | --- | --- |
| A3 全流程草稿 + 自检 + 人工终审 | 02- §2 A3；FR-4/FR-22 | N1 任务 + N2 契约 + N3 硬门 | 端到端未跑；人工签核点未实现 | T4 旗舰任务 + 导出包 + 人签 |
| 中文核刊与申报书双体裁 | 02- §5/§6；D4 | 六类槽 + 页—段—句锚点 + 体裁契约 | 只设计核刊；申报书 schema 未做 | 20 篇留出集 claim 可定位；体裁合规报告 |
| 证据可追溯、可阻断 | FR-20/FR-22 | 只认 rerun；未解析槽位阻断导出 | 运行时未实现 | 计分数字 100% 绑 EA；伪造通过 0 |
| 跨版本失效传播 | FR-10；D2 | 四类边 + 三类处置 + 50 场景 | C3 未跑 | 召回 ≥85%、误报 ≤20%、处置 ≥80% |
| 技能/模板复用与适用域 | FR-11 | 租约 + 护照 + pilot/拒绝复用 | 未实现；E7/E8 未跑 | 复用决策 ≥75%；负迁移下降 ≥30% |
| 论文轨道与产品轨道分开 | 02- §4.2.6；08- §5.5 | W1/W2/W3 与 215 人周产品轨道 | 数字容易混用 | 论文 100–112；MPU 79–85；产品 215 |
| 合规 A3 边界 | 02- §2；全库约束 | 人工终审、AI 使用记录、禁止代投/假评审 | 需要运行时审计字段 | 终审签核 100%；AI 记录完整 |

**结论**：创新栈覆盖了需求的“证据层”，但没有覆盖全部产品验收；反过来说，产品验收项也不都是论文创新。必须在文档与汇报中分开：**产品能不能用**看 FR/验收；**研究有没有新意**看 N1/N4 与 C1–C4。

### 4.3 需求层面的三个风险

1. **中文核刊是验证场，不是能力边界。** 若中文体裁效应不显著，应把中文降为领域实例，不能把“中文”当主卖点；英文对照集必须预留。
2. **A3 不是无人化。** 任何“自动投稿/自动署名/自动终审”的实现都越界；机器只能起草与自检。
3. **9+1 产品轨道不能用来证明论文创新。** 215 人周是产品集成预算；论文关键路径是 5–6 人 / 100–112 人周，MPU 79–85。两套数字不得混算。

## 5. 创新点审计

### 5.1 站得住的部分

- **N1 的任务定义改变了可行集**：在“论文生成”里，没有运行证据但写得顺的稿件是可行解；在 RWJT 里不是。这不是“再加一个模块”，而是换了评分对象。
- **N4 的测量是主贡献**：R/W/J 分开、5 项预注册过程指标、κ 校准与负结果承诺，使“联合判定是否有效”成为可证伪问题。没有 N4，N1 只是一个 demo。
- **运行时阻断 vs 事后审计**：相对 ARIS/Auto-Empirical 的“警告/CSV/STALE”，导出硬门 + 句级传播是真实差异；但它是机制支撑，不是单独首创。
- **自我限制做得对**：文档明确不宣称 RSI、SOTA、首个中文 benchmark，也不把外部数字当自己的结果；这是可信度的基础。

### 5.2 站不住或需要降级的部分

| 主张 | 问题 | 处置 |
| --- | --- | --- |
| “自进化”与“证据闭合”并列为主创新 | 两个叙事；E7/E8 未跑；读者不知道论文主问题 | 把自进化降为扩展，或另起一篇 |
| 过程协议（PF）作为创新点 | 目前只有 SIM；没有跨轮对照；与 workflow tuning 难区分 | 只进设计章节；E7/E8 后再升级 |
| 租约/护照本身是首创 | 租约、过期、撤销是通用软件概念；RSI-Anything 已有任务级 promotion gate | 差异锚在“claim 级 + 句/图传播 + 中文稿件槽”，不锚在“租约”二字 |
| 中文核刊作为主卖点 | 可能只是领域实例；效应可能弱 | 设英文对照；不显著就降级 |
| 可调工作流作为创新 | 产品能力，不是研究贡献 | 归入 N0；最多作为迁移实验变量 |
| “只写已经复现的内容” | 文献句、背景、方法不需要重跑，口号过宽 | 改成“经验句只认 confirmed rerun；文献句只认可定位 span” |
| “证据闭合 = 结论正确” | 槽位只保证结构可追溯，不保证语义支持 | 定义成“结构闭合 + 语义支持审计”，后者单独报告 |
| J 作为主评分 | 权重是设计选择；C1 未跑；R/W 可能高度相关 | C1 通过前，R/W/闭合率为主，J 只作次要/探索 |

### 5.3 三个叙事问题

1. **主贡献不唯一**：`08-` 明确“不是 RSI”，`11-` 与 demo 以自进化为主标题。必须二选一，或明确“一篇论文一个主问题”。
2. **证据状态与措辞不匹配**：C1–C4、E7/E8 未跑，demo 全 SIM；作为开题成立，作为毕设结论不成立。至少跑 C2+C3。
3. **自进化与主任务脱节**：E8 写“留出集 Δscore”，但没有说明 score 是什么。若 score 是任务分，过程协议会优化“跑得快/跑得对”，而不是“无证据句比例、claim 覆盖、stale 召回”。必须把适应度锚到证据闭合指标。

### 5.4 概念精度

- **结构闭合**：句 → claim → run → EA 可追溯；未解析槽位阻断导出。可自动检查。
- **语义支持**：claim 是否真的支持该句；需要专家抽样审计，不能由槽位保证。两者分开报告，不能合成一个“闭合率”。
- **经验句 vs 文献句**：经验句只认 confirmed rerun；文献句只认可定位 span；方法与背景句按各自契约处理。
- **J 的地位**：C1 通过前，J 只作次要指标；主报告 R、W、闭合率、覆盖率、伪造通过数。不要用加权总分掩盖失败维度。
- **准入 ≠ 真值**：租约/四问只决定“能不能复用”，不决定“结论是否正确”；claim 有效性仍由证据账本与人工终审负责。

| 层级 | 主张 | 证据 | 写在哪里 |
| --- | --- | --- | --- |
| **主贡献** | 我们定义并测量“证据闭合的科研写作”：经验句绑独立重跑，文献句绑可定位 span，否则导出被阻断；并报告硬门、传播与联合判定的效应 | C1/C2/C4 | 标题、摘要、引言、主图 |
| **支撑** | 我们形式化 run–claim–sentence–export 契约，并实现运行时阻断与三类传播处置 | C2/C3 | 方法、系统、消融 |
| **扩展** | 我们设计并待验证阶段级过程协议的准入、租约、迁移与撤销 | E7/E8（未跑） | 讨论、未来工作，或第二篇 |
| **工程** | 9 阶段、模板、可调工作流、demo | 产品验收 | 系统实现/附录，不进创新点表 |

### 6.2 一句话版本

> 我们不是再做一个论文生成器；我们定义并测量“只写有证据槽支持的内容”这一任务，并把写错变成可阻断、可传播、可评分的失败。

更精确的英文版：

> We define and measure evidence-closed scientific writing: every empirical sentence must trace to a confirmed rerun, every literature sentence to a locatable span, and unresolved slots block export. We report R, W and closure separately, and measure the effects of rerun-only admission, slot gating and cross-version propagation.

### 6.3 如果毕设必须落在“自进化”

则翻转层级：

- **主问题**：阶段级过程协议能否跨轮保留、迁移，并提升证据闭合率，而不产生负迁移？
- **testbed**：RWJT/ECM 与 C1–C4 的单轮闭合。
- **必跑**：E7（继承/回滚）+ E8（能力归因）；没有它们，不要用“自进化”作标题。
- **不能做**：同时把“证据闭合”和“自进化”都写成主贡献；审稿人/答辩委员会会问“到底哪一个”。

## 7. 自进化层如何接回主线

### 7.1 两个准入平面

- **claim 级资产（SK/WF/PL）**：回答“这条结论/技能能不能用”；失效沿 claim → 句 → 图传播并阻断导出。
- **过程协议（PF）**：回答“这个阶段下一次怎么跑”；失效只让下一次同阶段回退到通用流程，不追溯改判已经产生的 claim。
- 两者共享 EV1–EV4 与租约语法，但对象、作用域、失效路径不同；过程协议永远不能生成、修改或替代 claim。

### 7.2 适应度必须锚定证据闭合

E8 不能只写“留出集 Δscore”。建议主指标：

1. 无证据句占比（越低越好）；
2. 核心 result claim 覆盖率（≥90%）；
3. stale 召回与误报；
4. 人工干预次数；
5. 成本调整后增益；
6. 任务分 Δ 只作次要指标。

否则过程协议会退化成 workflow tuning，优化了任务分却破坏证据纪律。

### 7.3 与 RSI-Anything 的差异

- 它已有：run identity/receipts、resume、attempts、cost、任务级 promotion gate、hidden judge、incumbent guard、判定封存、2×2 交叉、独立审计。
- 我们的增量：**claim 级租约 + 适用域护照 + 撤销沿句/图传播 + 中文稿件槽 + 过程协议与 claim 分离**。
- 不能再说“它没有准入/审计”；也不能把它的效果数字当我们的结果。

### 7.4 不可宣称（自进化）

- “我们的系统会自进化 / 是 RSI 系统”——只有设计，无跨轮实验。
- “四问准入提升后续能力”——E7/E8 未运行。
- “准入通过 = 结论正确”——准入判资产，不判科学真值。
- “相似任务 = 可迁移”——需要护照匹配 + held-out pilot。
- “能力曲线上升 = 科学进步”——任务级增益不等于科学有效性。
- “demo 证明闭环有效”——demo 全 SIM。

## 8. 可调工作流的定位

可调工作流是产品能力，不是论文创新；归入 N0。

它解决的是：不同任务（完整论文、快速复现、综述、国自然申请书、自定义）不应强制跑满 9 阶段；模板决定阶段组合、顺序、重复与人工检查点。实现上需要：

- `STAGE_TYPES`（九种能力）+ `WORKFLOW_TEMPLATES`（模板）；
- 运行实例钉住 `workflow_id@version`，模板编辑不改写历史；
- 阶段用 `stage_type/id` 绑定过程协议，不用数组下标；
- 跳过阶段自动禁用对应证据权限（跳 P1 不得生成 literature_claim；跳 P4 不得生成 result_claim；跳 P7 不得导出）；
- 运行中改模板需人工签核并生成新 revision。

它唯一可能的研究用途，是作为 E7/E8 的迁移变量：同一过程协议在不同模板/体裁上是否产生负迁移。但这属于自进化实验的扩展，不是独立创新点。

## 9. 最小验证顺序与 kill criteria

### 9.1 顺序

1. **M0 基线 + 预注册**：先测无证据句基线比例，再登记相对阈值；冻结任务集、指标、基线、排除规则。
2. **C2 硬门效应**（最便宜、最核心）：B1 事后审计 vs B5 完整 RWJT；指标：无证据句相对降低 ≥50%、伪造通过 = 0、核心 claim 覆盖 ≥90%。
3. **C3 传播效应**：50 个变更场景；召回 ≥85%、误报 ≤20%、三类处置准确 ≥80%。
4. **C1/C4 任务效度与经验发现**：≥12 个任务、≥2 位专家、κ ≥0.60、R–W 相关 ≤0.70；4 个 v1 任务只作校准。
5. **E7/E8**：4 个周期；继承/回滚、能力归因、负迁移、成本调整后增益；必须在单轮闭合之后。

### 9.2 Kill criteria

| 条件 | 处置 |
| --- | --- |
| C2 不成立（硬门只挡语法，不降无证据句） | 硬门降为工程贡献；论文转 W2 |
| C3 不成立（传播不如 STALE/手工 diff） | 收窄到“结果变更→摘要句” |
| C1 不成立（κ <0.60 或 R–W 高度相关） | 拆报 R/W；J 降为参考；不做联合判定旗舰 |
| C4 零结果 | benchmark 仍可发表；删除“验证瓶颈”强叙事 |
| E7/E8 无差异或成本调整后增益消失 | 撤回自进化强主张；保留设计/负结果 |
| 并发工作先发表 RWJT | 转 W2/W3；或增加 claim 条件化复现作为增量 |

### 9.3 规模建议

- **单人毕设**：只承诺 C2+C3；用 4–6 个任务做校准；不要承诺 κ 与泛化。把“自进化”放未来工作。
- **团队论文轨道**：先 W1+W3（MPU，79–85 人周），再 W2；E7/E8 另立。
- **产品轨道**：9+1、215 人周；但论文主张仍锚在 W1–W3，不能把平台交付当研究结论。
