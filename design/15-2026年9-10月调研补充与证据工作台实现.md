## 0. 一页结论（补充版）

`14-` 已经把产品主线收窄为 **证据运营工作台（Evidence Operations Workbench）** 与 **RWMT**：不是再做一个论文生成器，而是让稿件在数据、代码、协议、引用变化后仍能被修复、复核、签署和导出。本文不重复这个定义，只补三件事：

1. **2026 年 9–10 月的竞争态势**：harness/loop 递归扩展（SoL-Pi、RRSI、EnvHarness、RSI-Anything）、证据/过程评测（TruthInsightBench、Agent Traces、BenchShield、NeuroTaint）与科研工作台产品化（OpenScience、OpenAI4S）三条线同时推进；“有 provenance”正在变成基线。
2. **两个可补充的研究点**：**Evidence Debt**（把“还缺什么证据”变成可计算、可排序、可驱动动作的债务）与**双轴审计**（结构闭合可阻断 vs 论证完整性建议），都需 pilot，不能当结论。
3. **Demo 工作台实现**：本次把 `#workbench` 做成“体检—检索—复现—变更—签署”的产品界面；检索过程可见、来源可点、句子可追、债务可操作、变更可回放、导出可阻断。所有数字为 SIM。

**一句话**：`14-` 回答“产品是什么”；本文回答“外部边界到哪、还缺哪两个研究点、工作台怎么把它演出来”。

## 2. 三条迁移的含义

### 2.1 harness 越强，证据缺口越明显

SoL-Pi 的 Evidence-Preserving Reducer 说明：长程 agent 已经需要“在压缩上下文时保留证据”。但这是**为了继续推理而保留证据**，不是**为了导出稿件而证明证据足够**。两者可以共享数据结构，却不是一个契约：

- harness 的证据保留：让模型不忘记刚才看到的观察；
- 我们的证据闭合：让稿件不能写入没有 `confirmed rerun + EA` 的经验句。

**差异点**：我们把“证据”从上下文对象提升为**有义务、有状态、可阻断的运行时对象**。这是 I1 的基础。

### 2.2 discovery 评测越成熟，写作忠实度越需要单独评

TruthInsightBench 评的是“开放发现是否成熟”，RWJT 评的是“给定重跑，稿件是否忠实”。二者不是替代关系：

| 维度 | TruthInsightBench | RWJT / ECM |
| --- | --- | --- |
| 问题 | agent 能否从冻结数据做出成熟发现 | 写进稿件的每一句是否有资格 |
| 证据对象 | 分析 artifacts | `result_claim + EA + 槽` |
| 判定 | 6 维证据成熟度 | R/W/J + 结构闭合 + 导出门 |
| 失败 | 缺对照、不可证伪、执行强但推断弱 | 过度外推、证据孤岛、跨版本失配、引用错配 |

**可借的**：TruthInsightBench 把“对照、可证伪、替代解释”显式评分。我们的 W 目前偏“覆盖/追溯/引用/体裁”，缺少论证质量维度。这就是 I2 的动机。

### 2.3 provenance 越通用，越需要“导出决策”

From Agent Traces to Trust、NeuroTaint、BenchShield 都在回答“如何看见/追踪/审计”。看见不等于阻断。我们的差异不是“有图”，而是：

> **当证据不足、过期或冲突时，系统必须拒绝导出，并列出受影响句子。**

这把 provenance 从 observability 变成 governance。也是产品工作台的中心交互：不是“看日志”，而是“处理证据义务”。

### 2.4 工作台越像 IDE，越需要“以 claim 为中心”

OpenScience/OpenAI4S 的组织中心是项目、文件、内核、运行、产物；这对计算科研很自然。但论文写作的失败往往不在“代码没跑”，而在：

- 这个数字来自哪次 run？
- 这句话是否超出 run 的条件？
- 这张图与正文数字是否一致？
- 数据/代码变了，哪些句子失效？
- 这条文献 claim 的 span 是否还在？

因此我们的工作台应以 **claim / 句 / 图 / 证据义务** 为中心，执行只是下层。这是产品差异化的核心，不是再加一个聊天框。

## 4. 候选创新点

> 以下 I1–I4 是“可补充的创新点”，不是已成立结论。每条都给出差异化、可证伪设计与 kill criterion；在跑之前只能写成设计。

### I1 Evidence Debt：把“还缺什么证据”变成可计算对象

**定义（草案）**：对稿件 `M`，证据债务

`D(M) = w1·U + w2·S + w3·C + w4·G + w5·O`

- `U` unresolved slots（未解析的 N/F/X/R 槽）；
- `S` stale claims/sentences（依赖已变更）；
- `C` conflict edges（来源冲突未处置）；
- `G` semantic gaps（结构绑定但语义支持未审计/不通过）；
- `O` orphan claims（有 claim 无句/图使用）；
- 权重按“阻断导出/影响结论”排序，预先登记，不事后调。

**研究问题**：在固定预算下，按 Evidence Debt 选择下一步（补 run / 补 span / 重跑 / 重写 / 请求人工），是否比按 claim 覆盖率或随机选择更快达到可导出状态？

**差异化**：

- OpenScience 有产物 provenance，但没有 claim 级债务与动作策略；
- TruthInsightBench 评一次性的证据成熟度，不评“债务如何随行动下降”；
- SoL-Pi 的 evidence-preserving 是上下文压缩，不是稿件义务；
- RSI-Anything 的 cost/attempts 是任务级，不是稿件级。

**实验（P1）**：

- 任务：4–6 个 RWJT 任务；三种策略：覆盖率优先 / 全部重跑 / 债务优先；
- 指标：达到可导出的成本、债务下降曲线、人工干预次数、未解析槽位残留、伪造通过数；
- 基线：覆盖率优先、随机、全部重跑；
- 证伪：债务优先不优于覆盖率优先，或在成本调整后优势消失 → 降为 UI 功能，不作研究主张。

### I2 双轴审计：结构闭合 vs 论证完整性

**轴 1（阻断）**：结构闭合——句 → claim → run → EA → 槽全部可解析，无 stale/conflict；未通过则不能导出。

**轴 2（建议）**：论证完整性——四个检查：

1. **对照/消融**：结论是否有 baseline / control / ablation；
2. **替代解释**：是否排除了至少一个竞争解释；
3. **可证伪条件**：是否写明什么结果会推翻结论；
4. **范围**：结论的条件、样本、边界是否与 run 一致。

**研究问题**：结构闭合与论证完整性是否可分？若专家评分相关 ≤0.7，双轴提供额外信息；若 >0.7，合并为单一维度。

**差异化**：TruthInsightBench 的“discriminating acts”在 discovery artifact 层；我们把它绑定到稿件 claim/句，并且明确“阻断 vs 建议”的不同治理语义。**注意**：这不是说我们首创“论证质量评分”；我们的增量是双轴分离与导出语义。

**实验（P2）**：

- 20–30 条 claim，2 位专家盲评两轴；计算相关、κ、与“是否过度外推”的一致性；
- 基线：单一闭合分、自动评审分；
- 证伪：两轴相关 >0.7，或第二轴不提升专家一致性 → 合并，只保留结构闭合。

### I3 检索决策溯源（Retrieval Decision Provenance）

把检索过程做成可审计链：

`query seed → query expansion → source hit → dedup → title/abstract screen → full-text → span → literature_claim → sentence slot`

每一步记录：纳入/排除理由、版本、时间、操作者（人/模型）、覆盖回执。它本身更像产品/评测能力，不单独作为主创新；但它能支撑：

- Q0 覆盖率回执；
- 来源冲突矩阵；
- “为什么这篇被排除”的可解释性；
- 人工复核时间与信任校准的 HCI 评测。

### I4 过程协议的反事实回放

同一阶段、同一输入，跑两次：一次加载 PF 协议，一次不加载；比较：

- 证据债务下降；
- 任务分变化；
- 成本/时延；
- 负迁移（近域/远域）。

这把 11- 的过程协议从“演示状态”变成可证伪实验；属于 E7/E8 的扩展，不是新主贡献。

### I5 证据工作台（产品/HCI）

不是新的科学主张，而是产品形态：以 claim/句/图/债务为中心的三栏工作台。可做 HCI 评测：定位一个失效句的时间、错误发现率、信任校准、人工签核时间。若做，单独成 HCI 论文，不混入 Paper A。

## 6. 证据工作台：最终产品 UI 设计

### 6.1 布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ 项目 / 第 3 轮 · 模板    P6 写作    闭包 78%    债务 7    待签 1   │
├──────────────┬──────────────────────────────────────┬──────────────┤
│ 阶段 / 运行   │  体检 / 变更 / 签署（三幕）           │ 证据检查器    │
│ P0 … P8      │  检索 / 复现（支撑视图）              │ claim / run  │
│ 运行日志      │  - 句槽 / 双轴 / 闭包报告             │ EA / span    │
│ 产物          │  - 检索漏斗 / 来源卡 / span 高亮      │ 论证审计      │
│              │  - ChangeSet → 传播 → 重跑队列        │ 签署 / 导出   │
├──────────────┴──────────────────────────────────────┴──────────────┤
│ 证据债务：2 缺 span · 1 stale run · 1 未解析槽 · 2 冲突 · 1 语义缺口 │
└────────────────────────────────────────────────────────────────────┘
```

### 6.2 五个视图（三幕 + 两个支撑）

1. **体检（默认）**：稿件句子列表 + 槽位徽章（E/R/N/F/X）+ 双轴状态；未解析槽位红色，点击显示“缺什么、下一步做什么”；导出按钮 fail-closed。这是首屏，对齐 `14-` 的“维护侧”叙事。
2. **变更**：ChangeSet（数据快照 v3 → v4）→ claims → 句 → 图 → 导出；动画传播后显示“需重跑 / 需重写 / 仅复核”三类处置与队列。
3. **签署**：闭包报告（结构闭合、语义抽样、未解析、stale、成本、AI 使用）+ 作者/PI 角色 + 模板证据权限 + 导出包 manifest；重新闭合后 PI 才能签署。
4. **检索（支撑）**：query → 312 hits → 去重 87 → 全文 24 → span 11 → literature_claim 6 → 冲突 2。来源卡显示“为什么纳入/排除”；点击来源卡，右侧显示 span、版本、关联 claim/句。
5. **复现（支撑）**：Run 1 未过门槛 → 在预注册范围内修订 → Run 2 过门槛 → EA 绑定 → result_claim 创建；RunCapsule 展示 env/seed/代码/数据/命令/产物/成本。展示“探索 run 不得进入稿件”。

### 6.3 关键交互（本次已实现，全部 SIM）

- **检索动画**：不是 loading，而是可读的阶段推进；每一步的计数、来源、排除理由都变化；结束时回填最终值，避免隐藏标签页 rAF 不执行。
- **点击来源 → span 高亮 → 绑定句**：让“这句话从哪来”在 2 次点击内可见。
- **点击债务 chip → 右侧显示缺口**：让“还缺什么”可操作；重新闭合后债务归零，但保留历史详情。
- **双轴徽章**：同一句在“结构闭合”通过但“论证完整性”警告时，颜色/徽章不同；阻断句不显示“结构通过”。
- **变更回放**：一个按钮触发 stale 传播，受影响节点逐条出现，导出按钮变为 blocked；点击“执行重跑队列”会跳到签署页并完成一次 SIM 重新闭合。
- **contested claim**：S-31 以 `contested · 冲突未处置` 显示，而不是把冲突平均成一句话。
- **三幕签署**：重新闭合 → 切换 PI → 签署 → 导出 manifest；作者角色不能签署。
- **模板切换**：完整论文 / 快速复现 / 综述 / 国自然 / 自定义；签署页显示当前模板的阶段组合、跳过阶段与 claim/export 权限，并注明“只影响下一轮”。

### 6.4 与现有 demo 的关系

- 现有 `#console` 保留为“9 阶段叙事运行”，继续讲 P0–P8；
- `#workbench` 是本次实现的产品工作台：默认体检页，三幕 + 检索/复现支撑视图；不是新的后端；
- `#workbench` 与 `#console` 共享同一套 SIM 数据口径，但工作台更强调“证据操作”而非“流程讲解”；
- 所有数字标注 SIM；没有真实导入、后端运行、真实导出或密码学签名。
